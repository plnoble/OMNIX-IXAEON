## 阅读原则

旧聊天不是最高指令，也不是开发者可以随意遗忘的废纸。用户明确希望：方案可以改变，但必须更成熟、有证据，不能越来越像狭窄的资料管理工具。

这里区分三种东西：用户目的、当前技术选择、已实现事实。目的约束选择；选择须接受实测；事实看当前代码和证据。不能把文档里的未来时改成完成时。

## ADR-01：用户中心，而不是项目中心或单一兴趣中心

依据：用户要理解所有获准想法和项目的 Agent，同时明确反对把一次 PPT 要求、旧会议和买手机话题都变成长久原则。

决定：当前问题与语境优先；项目是实现目标的载体，多个目标可以互不关联。个人总览不是一份强制注入所有对话的全局画像。

验收：相关跨会话回忆 + 无关话题不提旧兴趣 + 旧事件不复活为当前待办 + 项目正反关联。技术方案必须服务这些行为。

## ADR-02：Hermes 首选，但 Core 不归 Hermes 所有

依据：需要真实 Agent 循环和工具能力；目前自研统筹代码未接进产品，维护负担已超过当前收益。初始构想也保留 Runtime 可替换边界。

决定：保留 Electron/TypeScript Core，首选专属受控进程中的锁定 Hermes，通过薄适配器对接；不全面 fork、不同时自研另一套通用循环、不建设三个发动机的完整平台。默认先验证本机 stdio TUI gateway，实际协议以候选版本与探针为准。

代价：增加 Python/依赖交付、协议适配、上下文和工具约束工作。更换引擎可以不迁移核心资产，但不保证零修改或恢复未完成执行栈。

改选条件：B1 的会话/工具/取消/权限/交付探针无法通过；或候选在同等任务与预算下有明确优劣。先记录最多一个有依据的协议替代验证，再报告决定，不能无限修 fork 或静默降级成聊天 API。

事实来源：[Hermes 程序化接入](https://hermes-agent.nousresearch.com/docs/developer-guide/programmatic-integration)。这些是上游接口说明，不是本机已接通证明。

## ADR-03：长期资料独立于检索技术

决定：原始导出/附件引用不因 Markdown 转换丢失；SQLite 保存消息结构、有效版本、权限、纠正、业务状态；Markdown 为可读导出；LanceDB 作为首选语义索引候选，与现有关键词检索做对比。

单一写入口、事务内待索引事件、异步幂等更新、返回前回查权威版本/权限；删除/撤权立即禁止提供结果。更换嵌入模型或索引可以重建，不迁移用户身份与核心事实。

代价：增加索引一致性、模型下载/外发许可和运行成本。不承诺数据库选型自动带来正确理解，不以“向量相似”替代适用范围。

改选条件：中文/精确匹配/负向样本、重建与 Windows 打包对比未体现收益，或成本明显不合理。保留语义检索目标，更新适配方案和验收。

## ADR-04：降低打扰，不丢失可纠正性

决定：Agent 自动处理资料，形成事件记录和有范围的暂定理解。重大歧义、风险/权限和用户标记才进入待决定；普通理解无需逐条确认。是否认可、作者来源、可否执行分别存储。

旧确认/纠正/搁置/拒绝历史仍保留；改变日常队列不等于清空 needs_reasons 或将所有条目确认。来源归档与撤销长期原则分开。

Hermes 内置记忆是持久存储，不能只改名为临时记忆。专属 profile 的长期用户事实必须受 Core 管理；禁止双份画像独立演化。[上游外部记忆说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory-providers)

## ADR-05：权限、预算和运行真相有唯一归属

决定：Core 管理许可、计划、研究队列、执行状态与事件。Runtime 请求受控工具；身份和批准不由模型自报。内置终端/文件/代码/MCP/自动安装旁路默认关闭或纳入同样的强制边界。

本地保存、模型外发、公共搜索、编码执行、Skill 启用和软件发布分别授权。在明确预授权范围内可自主工作，不逐网址请求；新的数据/费用/代码范围仍须批准。

避免重复 cron 和重复工作任务表。取消/撤权在最终写入和副作用前校验；未知状态不盲目重做。独立目录不是 OS 沙箱，Runtime 的安全宣传不能代替实际边界测试。

## ADR-06：研究必须回答“这对我有什么用”

决定：用户给领域/方向，Agent 自己搜索、选择资料、研读、比较、判断并按授权持续跟进；资料页面是证据，不是工作成果的全部。

已知缺口：历史清单没有配置搜索服务。本版需真实接通一个入口；缺账号/额度时向用户提出具体需求，不把完成条件改成手工提供网址。

主动触发来自已获准方向和可观测失败线索；无变化不提醒，无价值可拒绝采用。用户一个随口问题不自动授权长期监控。

## ADR-07：Codex 是编码工具，不是验收员

决定：真实调用 + 实际背景/范围 + 可追溯项目副本 + 独立产物检查 + 全部必要测试 + 工作记录反馈。CLI/协议可随版本演进，不绑定某个模型名称。

证据：本仓库独立审核发现无条件成功命令；后续现场任务核查发现 Codex 拒绝写文件也被标完成。历史记录须保留并追加失信注记，不删失败、不要求模型“回答成功”。

编码与验证都需要隔离；不能为了让写入成功而开启无限权限。人工接受结果不等于批准部署。

## ADR-08：能证明改进，才允许升级

决定：先保存可重复失败案例、客观产物判据和独立验收集，再做经验/Skill 候选对照。记录模型/提示/工具/检索版本、成本和旧能力回归；候选不能修改验收答案或批准政策。

本轮实现低风险 Skill 候选批准使用与回退，以及真实代码候选；正式应用自升级是随后明确阶段，不从路线删除，也不冒称当前已有。

Hermes Self-Evolution 是研究输入，不是自动值得信任的评分器；无需立即引入 DSPy/GEPA 大流水线。简单而真实的任务对照先于大规模优化。

## ADR-09：欠项必须有去向

V0.3 最终仍含四平台各一种实际历史格式、ChatGPT 可见增量、至少三个项目统筹、无 URL 研究和真实编码执行。缺样本/额度可继续其他部分，最终标未完成，不能偷偷改下一阶段。

随后逐步实现正式受控升级、更广自动接入、长期在线、Door 能力感知、云/本地/手机/NAS 模型池和多终端行动。阶段顺序可调整，但必须保留目标、依赖和验收，不退化为纯交接工具。

## ADR-10：真实行为先于目录和页面

开发顺序 B0–B5 见主计划。B1 必须在真实桌面入口使用真实引擎和工具；数据可用明示合成样本。之后补自动理解、质量、主动性、真实项目和交付覆盖。

每批报告实现、自动化、真实环境、用户接受、未完成五类事实。通过辅助函数测试不证明实际路径接通；验收目标不能在失败后被改成更容易通过的措辞。

## 决策更新格式

新增记录或给已有编号追加修订，不抹掉旧理由。填写：日期、触发事实、原决定、备选、推荐、用户影响、数据/权限/费用变化、验收变化、回退办法、决策状态/批准依据。

“当前推荐”“用户已批准实施”“实现并验证”分别标识。架构记录是防止遗忘与随意漂移的工具，不是禁止改进的宪法。
