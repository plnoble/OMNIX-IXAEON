# 对话身份与任务状态设计记录（v0.1.1 M0）

> 依据：四次验收报告 F1–F4 与《下一阶段开发计划》第 3 节。
> 本文是身份与任务生命周期的单一权威说明；实现必须与本文一致。

## 1. 三个概念

| 概念 | 标识 | 规则 |
| --- | --- | --- |
| 对话身份 | 正式对话 = `/c/<id>` URL；草稿 = 采集会话标识 `sessionId`（扩展同标签页内生成，`page:<hash>` 只是它的临时 URL 表现） | 不同对话身份 = 不同来源；标题与正文相似不构成合并依据 |
| 采集实例 | 每次页面加载/刷新生成的新 `sessionId` | 正式对话的采集实例变化不影响来源归属；草稿以 sessionId 找回自己的来源 |
| 内容版本 | 来源级 `content_hash`（全部片段哈希联结）+ `imported_at`（最近一次成功追加） | 「已收到」与「已分析」分别表达（见第 3 节） |

## 2. 身份判定（`LocalServer.handleCaptureBatch`）

1. 正式 URL（`/c/<id>`）：按 `external_id` 查找，**任意 sessionId 都落到同一来源**
   （刷新、重开、新标签页不换 sourceId —— U1/U2）。
2. 草稿（`page:`）：按「同 external_id 且 metadata.sessionId === 批次 sessionId」精确
   找回（草稿 A→B→A 各自归位 —— U3）。找不到则新建来源并持久化 sessionId。
   旧客户端（无 sessionId）仅在「同路径只有一条且同样无标识」时延续，否则保守新建。
3. 合并候选（草稿转正）：仅当双方 sessionId 一致（可靠绑定）才合并；
   合并把片段、依据、项目归属、暂停状态一起迁移，转正后旧临时来源删除。
   双方都有 sessionId 但不一致 → 一律保留为两个来源。
4. 建源 + 片段登记、建正式源 + 合并，都在同一数据库事务中（失败完整回滚）。

### 场景表

| 场景 | externalId | sessionId | 结果 |
| --- | --- | --- | --- |
| 正式对话刷新 | 不变 | 变 | 同一来源，内容去重 |
| 正式对话重开+新消息 | 不变 | 变 | 同一来源，追加 |
| 两个标签页同一正式 URL | 相同 | 各异 | 同一来源（URL 即身份） |
| 同路径草稿 A→B→A | 相同 `page:` | a→b→a | 三个批次两个来源，第二次 A 回到 A |
| 草稿转正 | `page:`→`/c/` | 不变（同文档） | 合并为正式来源，sourceId 为新的正式来源 |
| 暂停后转正 | 同上 | 不变 | 403，暂停随会话延续 |
| 转正后点「继续」 | — | — | 别名全清，恢复采集（T4/U-闭环） |
| 不同正式对话相同首句 | 不同 | 不同 | 两个来源，不合并 |

## 3. 自动分析任务生命周期

- 触发：来源有新内容（accepted>0）且 `capture.enabled` 且 `capture.autoAnalyze`
  且域授权有效 → 入队 `extract {sourceId, auto:true}`；防抖窗口（60s）内同一
  **来源**的后续更新合并为窗口结束后的一次补分析（按 sourceId，不按 URL —— F2）。
- 执行前复查（F4）：auto 任务执行时重新检查 autoAnalyze、capture.enabled、
  来源授权、所属会话暂停状态；不满足 → 任务 `cancelled`（可见状态，不调模型）。
  手动任务只受授权约束。
- 执行中复查：每个模型块前与结果提交前再复查（`shouldContinue` 注入提取器）；
  取消后不发新块、不提交结果（JOB_CANCELLED/IXA0023）。
- 恢复衔接（F3/N3/N4/N5）：凭证校验失败等早期失败 → 原运行时与待分析状态
  完整保留；校验通过后、关库前停止全部补分析计时器；回滚完整 → 重建运行时；
  回滚未完成 → 恢复故障态，不建空库。
- 已知边界：已发出的模型请求无法收回；界面与文档如实说明。

## 4. 后续演进（v0.1.1+）

按下一阶段计划 M0.2，将引入持久化版本三元组 `contentRevision /
analyzedRevision / targetRevision`（来源表列），使「还欠一次分析」不依赖内存
计时器，崩溃重启后可恢复待处理工作。本记录中的身份规则不变。
