# IXAEON V0.3 重整开发计划：个人 Agent 内核与 Hermes 接入

日期：2026-09-11。计划版本：2.0。基线：`a9e6eb7`，包版本 `0.2.6`，已发布迁移截至 17；实施前重新检查实际状态。

用途：交给开发 Agent 分批实施，交给独立审核者按真实行为验收。本文是开发方案，不是实现完成或发布批准。

## 0. 先读这一页

**IXAEON 是持续理解同一个用户、按情境使用记忆、主动研究、调用工具办事并积累经验的个人 Agent。资料库、项目和设备都是它的能力，不是产品的主角。**

本轮选择：保留现有 Electron / TypeScript / SQLite 基础；自有 IXAEON Core 掌握资料、权限、任务和能力资产；首选通过适配器接入锁定版本的 Hermes，复用其 Agent 循环。用真实接入验证决定具体协议，不全面 fork Hermes，也不另写一套平行的通用 Agent 循环。

记忆自动形成、按需使用，不以逐条人工确认作为日常工作前提。原始资料保留；Markdown 是可读表示；SQLite 是结构化记录与状态的权威；LanceDB 是首选待验证的语义检索索引，不是永久记忆的唯一载体。

先交付一条能从桌面实际使用的完整路径，再增加规模和覆盖。第一条路径必须触及真实引擎、自己的资料接口和真实工具，不能只有测试中的类。

### 0.2 用户最终应感受到什么

1. 我导入聊天后继续正常生活，不需要替 AI 整理几十条记忆。
2. 换一个窗口，它知道相关往事；换一个话题，它不会硬扯回同一兴趣。
3. 我给研究方向，它自己寻找资料、判断价值，不让我先搜好网址。
4. 我给目标和必要授权，它组织执行；我看结果、处理关键决定，不充当任务调度员。
5. 它记住做成和没做成的事情，能提出并验证改进；不会偷偷改生产版本。

### 0.3 第一个开发交付

完成 B0 的止损与接入准备后，立即做 B1：在桌面对话里，通过真实 Hermes 读取一条 Core 资料、调用一次获准搜索，再派发并核验一个文件任务。背景资料可用明确标注的合成数据，外部引擎和执行不得伪造。

不要先花一整轮做新的总览、记忆卡片、Platform Manager 或多 Agent 管理页面。B1 证明接线，B2–B5 证明实际理解、主动性、可靠性和可交付性。

## 1. 当前真实起点与本轮授权边界

### 1.1 已有价值与缺口

已有可继承的来源库、消息片段、项目登记、人工纠正、备份、MCP、桌面和扩展。已有个人/研究/任务结构，但不能据此认定 Agent 完成。

2026-09-11 独立审核发现：统筹器未进入实际桌面调用路径、问答与摘录权限旁路、人工范围丢失、空目录冒充项目快照、无条件成功验证、取消与网络边界问题。原始独立检查为 20 项中 3 项对照通过、17 项针对性失败；这是已知问题的复现集，不是产品随机失败率。

同日后续只读核查日用任务，发现两条写 `note.txt` 的任务均显示完成/验证 passed，却都没有文件；其中最新一条执行回复为“只读模式，不能写入”，另一条为 `codex exit 1`。此事实来自前一轮针对该任务的现场核查；本次编写计划没有重跑、修改任务或复查全库。不要把错误状态改名或覆盖原记录来制造通过证据。

### 1.2 本计划不自动授权的事情

编写/接收本计划不等于授权扫描全部账号、发送私人聊天、购买服务、无限使用订阅额度、安装系统组件、迁移唯一日用库、改主工作区、发布或升级。实际开发授权和产品运行授权分开。

可先做代码、合成数据及隔离测试。新增安装、账号、预算或真实数据使用，在 B0 汇总具体请求，一次说明所需范围；不要求用户重新讲述历史。缺少某项授权只阻塞依赖它的真实验证，不取消交付条件。

## 2. 为什么采用这个方案

| 方案                                   | 本轮判断        | 原因与代价                                                             |
| -------------------------------------- | --------------- | ---------------------------------------------------------------------- |
| 继续完全自研 Agent 循环                | 不作为当前主线  | 当前短板是完整行为与可靠接入；继续造循环增加测试、工具管理和恢复负担   |
| 全面 fork Hermes，直接承载全部个人资产 | 不采用          | 易与上游耦合；双份记忆、迁移、升级和权限边界更难管理                   |
| 自有 Core + Hermes 适配器              | 首选，须通过 B1 | 复用运行能力，保住数据所有权；增加 Python 运行环境、协议兼容和打包成本 |
| 同时接多个通用 Agent 发动机            | 暂不实施        | 先验证一个，保留能力声明与适配接口；不凭空实现通用平台                 |

“首选 Hermes”不是信仰。B1 若证明取消、工具控制、上下文接入或可交付性存在根本阻碍，提交证据、已尝试路径与替代方案，更新决策后再换。不得静默退回单轮问答或 RSS 抓取并声称目标完成。

Hermes 官方提供外部程序驱动接口，其中 TUI gateway 使用 JSON-RPC，API server 使用 HTTP/事件流；本轮默认先验证 **本机 stdio 的 TUI gateway**，减少额外监听端口。它不是无需兼容验证的永久标准；具体启动方式、事件和能力以锁定版本代码及探针为准。[官方集成说明](https://hermes-agent.nousresearch.com/docs/developer-guide/programmatic-integration)

## 3. 最小架构：一套资产、一套任务账本、一个运行循环

```text
桌面对话 / ChatGPT 采集 / 历史导入
                  │
             IXAEON Core
      资料、记忆、项目、权限、任务、经验
           │                    │
      Runtime Adapter       受控工具接口
           │                    │
         Hermes ──请求工具──→ Core Tool Broker
                                ├─ 记忆/原文/项目查询与写回
                                ├─ 搜索/网页读取
                                └─ Codex 编码执行与验证

Core 保存运行事件和结果；Hermes 根据工具结果继续处理。
```

### 3.1 职责不能重复建设

- Core：领域数据、授权判断、持久任务/研究队列、上下文选择、事件与版本。不要在它里面再写一个与 Hermes 平行的通用思考循环。
- Hermes：根据目标选择工具、结合返回结果继续工作；不拥有个人资产的唯一副本，不自行授予权限。
- Codex：第一款编码执行器，和通用 Runtime 分属不同职责。未来某工具可兼任角色，但接口不要因名字相同就混为一谈。
- 调度只有一个持久账本：本版由 Core 领取到期任务并唤起 Runtime；不同时开启 Hermes 和 Core 两套相同 cron。
- 模型政策由 Core 保存：获准提供方/模型、隐私范围、预算、失败处理。Runtime 复用已有模型调用机制；不得静默改用更贵或权限更宽的模型。

### 3.2 Runtime Adapter 的最小契约

只为本版真实需求定义：能力探测、开始运行、订阅事件、响应批准、取消、查询状态、释放资源。续跑仅在目标 Runtime 明确支持时启用；不承诺跨发动机恢复内存中的执行栈。

运行输入至少含 `runId`、用户/会话身份、目标、上下文包引用、获准工具集合、权限版本、预算、模型选择、幂等键。凭证不放进模型提示词。

规范化事件至少含 `runId / eventId / seq / timestamp / kind`；区分文本输出、工具请求/结果、需批准、用量、产物、失败、取消、终态。收到事件不等于已完成；重复事件不能重复执行工具。保存最小必要的操作轨迹与依据，不要求或依赖模型隐藏思维链。

能力声明是实测结果，不是固定填 true。会话、停止、工具白名单、用量、恢复、流式事件各自记录支持情况；缺能力如实报错。

### 3.3 工具与权限接入

复用 Core 服务实现少量工具：`search_memory`、`get_evidence`、`get_project_context`、`record_observation`、`search_web`、`read_web`、`propose_task`、`dispatch_coding_task`、`get_task_result`。名称是本产品设计，不是假称 Hermes 已自带这些函数。

工具通过受限 MCP 或所选版本支持的工具扩展接入，同一后端鉴权。工具接收身份和本轮权限，不能从模型参数相信 `approved=true`。批准只能由桌面真实用户动作或有效的预授权策略产生。

本版默认关闭 Hermes 自带的无限制本地 Shell、通用代码执行、任意文件读写、动态加载 MCP/插件及自更新；需要的能力经 Broker 提供。不得让这些旁路绕过 Core。关闭工具是功能约束，不等于 OS 沙箱；编码和验证仍须独立落实运行隔离。

Hermes 的 `local` 终端后端并不是主机隔离沙箱；Skills 也可能影响凭证传递。接入时必须检查实际工具集、环境变量、自动安装与凭证透传，而不是把“使用 Hermes”视为安全证明。[官方安全说明](https://hermes-agent.nousresearch.com/docs/user-guide/security)

### 3.4 Runtime 本身的交付

用 IXAEON 专属配置/工作目录，不复用或改写用户个人 Hermes home。B0/B1 确定受支持的 Windows 启动方式和依赖；引入 WSL/Docker 等系统组件须说明并获准，不把“请用户自己研究安装”当成交付。

固定 Hermes commit/tag、依赖锁、适配器版本、工具配置与许可证清单；记录于开发时新增的 `docs/runtime-lock.json`。本计划不虚构已验证版本。首次安装/启动不得偷偷拉取 latest、技能或安全辅助程序；依赖预装、显式批准或报告缺失。

## 4. 记忆：自动理解，按情境取用

### 4.1 三层内容，避免一切都变成用户目标

| 层            | 保存什么                                 | 默认用法                                 |
| ------------- | ---------------------------------------- | ---------------------------------------- |
| 原始资料      | 消息、分支、时间、角色、文件与来源版本   | 需要时回看，不全部塞进提示词             |
| 事件/主题记录 | 某次 PPT、一次购买比较、会议、项目阶段   | 与对应事件相关时检索；过去不等于当前待办 |
| 可复用理解    | 有范围的偏好、长期目标、约束、已验证经验 | 与当前问题相关且有效时使用               |

长期理解至少记录来源、适用范围、有效时间/状态、确定程度、用户是否明确表达/纠正。作者 `origin` 与认可程度分开；AI 提取即使被认可也不能改成伪造的用户原话。

自动理解默认可以成为有标识的暂定认识，用于回答与建议；不能自动成为执行授权、正式决策或已启用的长期监控。陌生人/网页/助手建议不自动成为用户偏好。

### 4.2 日常体验与提取规则

- 按完整对话段落/事件理解，保留相邻语境、角色、否定、假设与改口；不机械地每句话生成待确认卡。
- “马来西亚放中间”默认是当次 PPT 要求；“去年开会”不是今天待办；谈一次手机不是永久订阅。
- 同一事件重复聊多轮不是长期偏好的多份独立证据；不能只按提及次数升格。
- 存储全部获准原始资料，不等于立即对每条历史做昂贵精提取。增量先索引，后台分批形成事件摘要与可复用理解；按当前任务补充读取，标明未处理覆盖，不冒充全量已理解。
- 导入、后续聊天、任务反馈自动驱动处理；队列有进度、暂停、幂等与重试，不要求用户逐个点“分析”。
- 用户说“这个只针对上次 PPT”，应限定该认识的范围；说“以后都不要”则保存更广范围。模糊且影响重大时问一次具体问题。
- “我如何理解你”保留为可选查看/纠正入口，不是首页等待用户批改的作业。
- 待处理列表只放确需用户决定的事项：关键冲突、缺少行动授权、用户主动标记等；普通暂定理解不自动刷屏。

### 4.3 兼容旧确认/待处理模型

保留 items/evidence/corrections 和历史人工动作；新增独立的记忆语义/适用范围元数据及“是否需要打扰用户”的选择规则。不能为消除卡片而批量清空 `needs_reasons`、假装全部 confirmed、覆盖用户 manual 标记。

旧 `needs_review` 是历史工作流信息，不再直接等同于“必须在首页让用户确认”。修改 UI 队列查询及相关契约，并用等价回归保留人工纠正、重要冲突、搁置/恢复语义。具体迁移映射先在旧库副本报告数量与样例；来源归档不默认撤销其中长期有效的原则。

### 4.4 上下文选择是独立能力

一次请求的处理顺序：识别当前任务与事件 → 在权限范围内检索候选 → 核对范围、时间、纠正/否决 → 相关性排序 → 只提供有帮助的材料。历史回顾问题可以取旧事件；当前行动问题不得把历史要求当现行要求。

不固定注入完整用户画像；只保留极少量必要交互设定。主题偏好不能跨领域无条件生效。允许返回零条个人记忆；当前明确要求优先于旧偏好，但不能覆盖真实安全/授权边界。

纠正后同会话、跨会话、重启后都生效。来源撤权后清理检索缓存和 Runtime 上下文；无法从活跃会话安全移除时终止该运行，以获准材料开启新会话。已发往外部的数据不能承诺撤回。

### 4.5 Hermes Memory 不是第二套权威

Hermes 外部记忆接入默认是叠加，内置记忆仍存在，不能假定配置外部服务就替换了全部记忆。[官方 Memory Providers 说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory-providers)

B1 必须用专属 profile 实测：禁止独立长期写入/全局画像注入，或用薄桥接将相关写入纳入 Core。无法彻底关闭时仅保存可重建的短期运行信息，并验证不会重新注入已纠正/撤权内容。不得允许两套永久用户画像各自演化。

事件历史、技能来源、经验和批准最终均需回到 Core。更换/停用 Runtime 后仍可读、导出、恢复这些资产；恢复的是任务事实与背景，不保证迁移未完成执行栈。

## 5. 存储与检索：可靠优先，避免三份互相矛盾的记忆

### 5.1 数据权威与写入方向

- vault 保留获准原始内容/导出，SQLite 管规范化消息、版本、引用与业务状态，二者共同进入备份。
- Markdown 是稳定可读导出/视图，不是丢弃原始 JSON、分支和附件的理由。用户主动编辑后再导入须走版本化入口，不在本版实现三方随意双向同步。
- LanceDB 储存片段 ID、版本、向量和必要检索字段，是从权威资料产生的索引。清空/重建索引不应丢资料、权限或纠正。
- SQLite 事务内提交业务变化和待索引事件，再异步更新索引；任务幂等、可恢复。不能跨 SQLite/LanceDB 双写失败后仍显示“全部同步”。
- 每条检索结果回查当前权限、有效版本和删除标记后才能提供给模型；撤权立即阻止使用，后台再清理派生副本。

### 5.2 LanceDB 的采用门槛

本版必须评估并实现一个可切换的 LanceDB 检索适配器，和已有 SQLite 关键词检索对比；不是要求把现有全文检索立即全部重写。LanceDB 支持混合检索与过滤，可用来改善同义表达召回，但不会替代记忆判断。[官方混合检索说明](https://docs.lancedb.com/search/hybrid-search)

记录中文效果、文件名/数字精确查询、否定/时间、重建、Windows/Electron 兼容、模型与索引版本、占用和延迟。嵌入计算不放在 UI 线程；向量索引失败可退回关键词检索并显示能力降级，不能退回无权限全量注入。

默认优先评估合适的本地多语言嵌入模型，但不静默下载模型；没有获准本地资源或云端嵌入时，继续关键词路径并保留语义检索未验收。若对比表明 LanceDB 在本环境无收益或交付代价过高，依据 ADR 变更机制更换；不得无记录删除语义检索验收。

### 5.3 多来源覆盖不后退

四平台各验收一种实际取得的导出/保存格式；原始消息 ID、角色、分支、时间尽量保留，缺失明示。允许一次导入多份聊天/多个项目，不强制先选项目。相同内容重导不重复；编辑/再生成不改写旧版本。

ChatGPT 日常增量沿用并验证现有扩展，明确仅覆盖当前支持的可见对话。其他平台实时采集和手机未打开对话同步仍是后续明确项目，不谎称本版全账号同步。缺真实样本需一次性索取最小脱敏样本；合成样本不替代真实格式验收。

项目登记和代码执行分开。已授权项目提供目录/说明/能力与状态背景；Agent 按任务读取进一步获准文件，不每次全仓库灌入模型。多个项目可以互相提供能力，也可以保持独立，不能强迫所有事情服务 IXAEON 自身。

## 6. 主动研究：给方向，不必给网址

### 6.1 搜索是本轮真实交付，不再是可有可无

接通一个实际可用搜索入口，优先复用 Hermes 可接入的工具能力，但调用须落入 Core 的预算、隐私、事件和取消控制。无法控制内置搜索时，包装一个受控搜索工具；不自建全网爬虫。

B0 查明服务、认证、费用和返回格式，B1 跑真实搜索。无服务/额度时集中向用户请求配置，继续无依赖工作；不能把缺项改成“用户给网址即可完成研究”。模型自带知识、模拟页面和当前开发宿主的隐藏搜索工具均不能冒充安装产品的真实搜索入口。

Agent 应自己拟定不含私人细节的查询、选择来源、读取必要正文、比较证据，产出：什么变化、为什么与当前目标有关、可信度/限制、是否值得行动、最小验证办法。报告允许“无关/不值得采用”，不自动把每篇新闻变成待办。

### 6.2 主动性来自目标和可观察问题

持久研究任务有三类触发：用户明确关注；在已授权方向里发现值得跟进的新来源/版本；运行记录显示能力不足。能力不足应有具体证据，例如连续检索不到已知文件、同类任务反复失败，而不是凭模型自我评价创造问题。

用户首次开启一个方向时，确认领域、可外发主题范围、服务、频率、预算、通知和是否允许隔离实验。Agent 在此范围内自行选搜索词和公开网站，不逐 URL 审批。跨新领域、新外发数据、新付费或扩大代码范围，才请求新授权。

Core 调度器持久化到期时间、租约、暂停/撤权代次和去重；按事件或到期唤起同一 Runtime。没有明确关注时，可以形成少量内部候选，但不擅自长期监控一次闲聊兴趣。

本版自动任务只在应用/配套进程实际运行时执行；关闭或休眠时不冒充在线。恢复合并错过周期，不补发大量请求。24 小时在线迁移到后续主节点阶段。

前台会话优先于后台研究；第一版可以串行排队并允许取消后台任务，不要求为证明主动性引入多 Agent 并发。切换不同主题/任务时使用独立运行上下文，不能用同一个不断追加的全局对话串处理所有工作。

### 6.3 网络和预算要求

搜索外发文本、网页读取、模型分析、嵌入与编码连接分别记录服务和许可。私人原文不自动拼进公共查询；自动生成公开描述后由本地规则检查，不能用“摘要”当作天然脱敏证明。

公开 Web 工具拒绝私网/回环/元数据和非预期协议，重定向、DNS/连接、代理/fake-IP 分别验证。默认每请求 20 秒（含正文）、2 MiB 流式限额、3 次重定向；按实际来源需要变更时记录，不通过关闭全部防护解决访问失败。

网页是资料，不是命令授权。下载、安装、执行、账号登录不由网页文本触发。网络失败不得写成“没有新消息”；正文版本检测与展示摘录分开，不能只比较前 800 字。

起始运行上限由首次启用界面展示：研究每轮最多 3 次查询、10 页、8 次模型调用、5 分钟；自动每方向默认每日最多一轮；重试计入预算。上述为可调整的产品上限，不是服务能力承诺。模型另设输入/输出 token 上限；可计价时预留成本并限制金额，不可计价订阅明确按次数/用量限制。预算不足返回部分结果与缺口，不静默换提供方。

只对实质新发现、需决定或持续故障做去重提醒，不制造每日必报。用户可以说“暂停这个方向”“这个不用再提”，并在界面查到实际状态。

## 7. 执行与成长：实际办成，再谈进化

### 7.1 编码入口与成功判据

首个编码执行器沿用 Codex CLI 的非交互入口，读取结构化事件、退出码和必要日志。官方支持 `codex exec --json`；实施须验证本机锁定版本的参数、认证、有效权限与事件，而不是直接抄示例。[OpenAI 官方非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode)

新建小实验可使用空工作区；修改现有项目必须准备真实、可追溯的 Git worktree 或受控副本，记录起点、内容清单/哈希和用户未提交改动处理办法。不自动 stash/reset，不用目录名冒充快照。

Agent 根据用户目标拟定任务与可检验产物，不让用户编写验证命令。批准卡展示简明目标、项目、文件范围、背景摘要、服务/预算、成功条件；详细命令和权限可展开。对于本版编码，先按具体任务批准；预授权研究不自动取得编码权。

实际派发须含获准背景包、目标/范围、约束和成功条件；背景包由 Core 按上下文和受众过滤，不能给执行器全局数据库/token。找不到 Codex 或权限不符就报告受阻；产品真实模式不自动切 Fake。Fake 仅用于显式测试/演示。

### 7.2 独立验证和停止

- 执行与验证都在可核验的运行隔离中；工作目录与 `workspace-write` 名字本身不能证明所有步骤受限。验证程序不继承主进程全部环境、密钥或任意文件访问权。
- 通过固定程序/参数数组启动，Windows 窗口隐藏；记录子进程树，取消/超时等待其停止，不杀用户其他进程。
- Codex 正常退出、自然语言说成功、结构化 claimedSuccess 都不单独构成完成证据；执行失败不能被一个成功检查覆盖。
- 独立计算实际文件变化，拒绝范围外变更；不能相信执行器固定返回空 diff。检查测试是否被修改。
- 运行全部必要检查；验证器和独立验收用例置于执行器不可修改位置。没有有效判据显示未验证，绝不使用 `process.exit(0)` 作为占位验收。
- `note.txt` 需验证文件存在、UTF-8 内容符合本次约定、实际只改获准目标。固定一句话只用于连接探针，不能作为现有项目开发的最终验收。
- 状态区分执行成功/失败、验证通过/失败/未运行、用户接受、部署状态。取消代次在每次工具执行与最终写入前核对；完成任务不可重复派发；不明状态先核对，不盲目重试。
- 默认单编码任务、15 分钟上限可调整；修复重试必须受原范围和预算约束。派发接口立即返回任务标识，UI 可实时观察并取消，不一直禁用停止按钮。

### 7.3 经验进入下一轮工作

每次运行的产物、失败、验证、用户反馈统一写入 Core 工作历史并关联来源/项目。复用或扩展现有 `work_runs`，不能再形成问答看不到的孤立编码表。

Agent 从结果提出可复用经验，标记适用条件和证据。一次成功不自动证明通用方法可靠；归档聊天前几句话不等于学会技能。

本版交付一个低风险的经验到 Skill 候选流程：真实失败/用户纠正 → 固定评测案例 → 候选方法 → 对照执行 → 展示差异与结果 → 用户批准 → 下次实际使用，支持禁用和回退。新 Skill 不能自行扩权、安装依赖、转发凭证或改变评测/批准规则。

Hermes Self-Evolution 可作为研究对象，不作为本版强制依赖。其 README 将 Skill 优化列为已实现、持续循环等列为计划；本次检查的主分支入口使用词语重合评分，不能作为“实际能力提高”的验收器。[项目状态](https://github.com/NousResearch/hermes-agent-self-evolution)、[评分代码](https://github.com/NousResearch/hermes-agent-self-evolution/blob/main/evolution/core/fitness.py)、[调用入口](https://github.com/NousResearch/hermes-agent-self-evolution/blob/main/evolution/skills/evolve_skill.py)

### 7.4 软件自我升级的明确接力

V0.3 必须能从一个真实缺口发起研究、准备隔离代码候选、收回 diff/测试/收益与风险，不只生成开发提示词。候选无收益应拒绝，而不是凑一份“优化成功”。

正式替换运行中的 IXAEON 放在紧接其后的受控发布阶段：候选版本 + 独立评测 + 用户批准 + 签名/哈希校验 + 数据备份/兼容迁移 + 健康检查 + 可执行回退。现有安装器更新不等于这条自主改进流程已打通。

本版不宣称完整软件自我升级已实现；但经验改进和代码候选必须真实完成，不能把全部成长能力推给未来。

### B0 的具体边界

优先修 F01/F02/F03/F05/F08 中会让 B1 不可信或越权的路径。其余 F04/F06/F07 分别随 B2/B3 修复，但进入真实数据/网络使用前必须完成相关边界。无依赖的隔离接入探针可与修复穿插，不能把 B0 变成永远不接 Agent 的大重构。

保留前述失败证据，复跑另存。对历史错误完成记录追加“验收不可信/待复核”审计注记和提示，不删原执行报告、批准和时间。日用库改动须另获准；先在副本验证。

B0 一次汇总待用户提供的最小材料：Hermes 依赖安装范围、一个主推理服务、一个搜索入口、Codex 专属调用/额度上限、一组脱敏聊天与项目副本。不要逐个卡片反复索取相同授权，也不假设已有订阅包含所有服务。

### B1 的完成门槛与止损点

锁定一个候选版本/协议，实际测通运行开始、事件、Core 工具、取消、失败、权限拒绝及重启状态。用户能从桌面对话发起整个探针并看到文件结果，开发者不手工搬提示词。

若首选协议失败，最多验证一个有明确依据的替代接入方式；仍缺关键能力即提交适配决定/阻碍报告，沟通替换方案。不要无限改上游、同时启动三套引擎，或把真实调用替换为回放。配好引擎但未接产品路径不算 B1。

### B2–B4 的重要验收情境

- 混合材料含一次 PPT、旧会议、手机比较、稳定交互偏好和至少三个项目。旧具体细节不会变成全局原则，稳定原则不会随来源归档丢失。
- 用户可以同时有互不关联的目标；至少一组项目提出有价值的复用建议，也能解释另一个为何保持独立。
- 研究先用已知可达真实公开来源证明检索/研读，再用受控更新源证明去重/调度；二者证据分列，不能伪造真实网站发布。
- 真实项目任务必须从实际基线出发；探针 note 文件不替代项目开发验收。
- 至少一个真实失败结果被下一次问答/任务读取；一次 Skill 候选通过后确实被后续任务调用，无收益的候选保持未采用。不能只改 status 和文案。

### B5 的交付和分支策略

每批可交付 `0.3.0-alpha.N`，新功能默认实验开关，使用隔离数据目录；不能因包号仍写 0.2.x 就混进日用升级。修复维护包和新内核候选分别记录变更与验证。

优先渐进替换生产入口，旧模块在等价回归通过后退役，不做整库重建。Git 中保留他人改动；计划不要求现在提交、推送或发 Release。

### 9.1 记忆质量评测的起始门槛

B0 固定与模型无关的样本及评分说明，B2 扩展为至少 60 个平衡场景：相关召回、无关话题、临时要求、否定/纠正、跨项目、权限各类都有，包含中文及中英混合。分开发集与未用于调参的验收集；执行器/优化器不能读写验收答案。

起始准入目标（不是已实现的能力承诺）：应召回事实正确率 ≥90%，无关记忆不侵入率 ≥95%，一次性要求不被升为长期约束 ≥95%；确定性的权限拒绝、纠正链保留和证据 ID 有效性必须全部通过。单列每类错误，不能用总体均分掩盖隐私或临时记忆污染。

实际模型至少独立运行三轮，固定记录模型/配置/语料/检索版本、每轮原始结果和波动；不得只保留最好一次。相较现有基线报告结果；阈值若需调整先写原因与用户影响，不在失败后偷偷降门槛。用户实际感受仍单独验收。

用不少于 10,000 条合成混合消息测索引/查询/重建，另以获准真实小样本测语义。报告参考机器、数据量、P50/P95 延迟（检索与模型分开）、内存/磁盘、后台导入对 UI 的影响；不得假称已覆盖十年全部资料规模。

### 9.2 真实外部验证与自动回归分开

默认 verify 不自动消耗模型/搜索/编码额度。确定性与隔离集成回归加入默认入口；真实验收另设显式入口、预算和授权，保存输出/事件/产物。缺真实测试时不能宣布阶段全通过。

完整 V0.3 需 R01–R15 对应证据、历史有效回归，以及用户对记忆分寸与研究价值的接受。真实数据迁移、安装器、账户与引擎演示不能靠模拟补齐。

## 10. 工程落点与交付记录

保留现有目录组织，优先增加小模块而非全仓库搬迁：

- `packages/contracts/src/`：Runtime/工具/上下文/权限/事件共享契约。
- `packages/core/src/runtime/`（拟新增）：适配器接口与 Hermes 桥接；不要复制完整上游。
- `packages/core/src/memory/`（拟新增或整合现有模块）：事件/理解语义、上下文选择和索引适配；避免独立于 corrections 的另一套库。
- `packages/core/src/storage/`、`extraction/`、`import/`：继承资料与人工历史，增加自动流程和适用范围。
- `packages/core/src/research/`、`jobs/`：持久研究/主动任务、受控联网与取消。
- `packages/core/src/execution/`：真实副本、权限与验证；对接 `work_runs`。
- `packages/core/src/experience/`（拟新增）：候选经验/Skill、评测、版本、启用/回退。
- `apps/desktop/src/main/`、`preload/`、`renderer/src/pages/`：真实 Runtime 连接、流式过程与停止；逐步把 Ask 变成主要入口，来源/任务保留为可查看的支撑页面。
- `apps/mcp/src/`：面向调用者/运行的受限工具，旧项目背景接口保持可用且不能越权。
- `apps/extension/src/`：保留已支持站点与权限范围，新增站点另作明确适配。

只追加迁移，起点检查最新账本，不改已发布 1–17。旧库副本核对来源/片段、纠正链、人工标记、授权与任务数量；失败可恢复。备份包含权威资料、配置版本、关系、研究队列、运行与技能资产；恢复后自动任务暂停、执行批准失效、不重跑不明任务。

每批更新现有 `docs/dev-log-v03.md`、`docs/v03-acceptance-map.md` 和 `REVIEW_PACKET.md` 的新章节；不重写旧“通过”段落来抹掉历史。新增证据放独立批次目录；私人聊天与密钥不提交到仓库。

## 11. 防止再次失忆与随意变窄

目标可以成熟，技术可以替换；任何人都不需要维护旧 AI 的面子。重大变更须写：旧方案为何不足、证据、新方案、代价、对用户行为/权限/验收的影响、回退方式、需要的批准。

每批开始读 AGENTS、长期路线最新修订、架构决策、本文与最新审核；每批结束明确下一批和仍欠的行为。一个名字叫 Orchestrator 的类、一个 Memory 页面、一次网页 GET，均不等于对应能力完成。

以下变化需与用户沟通，不能当作实施细节：更换主 Runtime、取消真实搜索/执行/四平台覆盖、要求迁移全部资料到第三方、扩大云外发/费用、把自动记忆改回人工逐条整理、取消正式升级批准。

局部重构、错误修复、增加等价测试可自行推进。发现文档冲突先依当前用户目标和最新显式决策处理并记录，不让历史条目压倒当前需要，也不拿“用户曾同意”证明代码正确。

长期后续顺序保持：V0.3 用户中心 Agent → 受控软件升级 → 更广持续接入/长期运行 → Door、模型池与多终端调度。相关能力可按依赖穿插试验，但要列出准入和欠项，不能把长期内容偷偷删除。
