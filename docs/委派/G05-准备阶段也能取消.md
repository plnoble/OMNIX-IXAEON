# 规格 G05：「准备中」点停止也真的停

档位：**A**（修 bug：只减少外发，不改提示词、不碰权限）。大小：小（≤100 行源码）。依赖：无。来源：[全局审核 2026-09-20](交付/全局审核-2026-09-20.md) G05。
v2 规格：把验收条件写成测试（`apps/desktop/test/acceptance/g05-*.test.ts`），测试和实现一起交，Codex 审查时核对测试有没有漏掉条件。

## 要什么

`AppRuntime.ask()` 在语义补齐（`awaitSemanticBackfill`）完成之后才把这一轮登记进可取消集合。界面在「准备中」已经给了「停止」按钮，但这时后端找不到这一轮，取消返回失败；准备结束后照样启动模型——你已经说停了，还在外发、还在花钱。

## 契约

1. `ask()` 一开始（语义补齐、组装上下文之前）就把这一轮登记成可取消。
2. 每一次外发之前（启动 Hermes、调用 Core 模型）检查这一轮是否已被取消；已取消 → 不外发，这条回答收尾成 `cancelled`。
3. 准备阶段调用 `cancelAsk` 返回成功。界面不得把没生效的取消显示成「已停止」。

## 约束

- 不改提问的正常流程和已有的「回答中取消」行为。

## 验收条件

1. 阻塞语义补齐 → 点取消，返回成功 → 放行补齐：模型（替身）调用 0 次；这条回答的状态是 `cancelled`。
2. 正常提问、不取消：行为不变（相关锁定验收照过）。
3. 回答进行中取消：行为不变。

## 真机检查

不需要：受控替身覆盖。交付里写「规格不要求真机检查」。
