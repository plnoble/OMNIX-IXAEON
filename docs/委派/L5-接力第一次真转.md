# 规格 L5：接力第一次真转前的最后两件（DSH 推得上去、配置一条命令生成）

档位：**B**（改开发角色起 git 的方式；生成调度器真用的配置；往公开仓库推一次探测分支）。大小：小（约 120 行源码）。依赖：L4 ✅。来源：L4 真机检查丁（[交付说明](交付/L4.md)）：DSH 的沙箱不挡联网，推不上去是因为 Windows 自带的 TLS（schannel）在它的受限令牌下拿不到凭据；git 改用自带的 OpenSSL 就连得上（`git -c http.sslBackend=openssl ls-remote` 通了），带登录的推送还没验。

v2 规格：先把验收条件写成测试（`packages/relay/test/acceptance/l5-*.test.ts`），**先只推测试**，整合方锁定后再写实现。真机检查「甲」不依赖实现，可以和测试一起先做。

## 要什么

1. **DSH 里的 git 走 OpenSSL**：不改用户的 git 设置，只在启动器起 DSH 时，通过环境变量让它（和它拉起的所有 git）用 `http.sslBackend=openssl`。
2. **一条命令生成真用的配置**：`relay init` 在数据目录里写出 `config.json`——整合方用 Claude（L2 的配方），开发用 DSH（L4 的启动器），路径都按这台机器现算。整合方要有自己的工作目录 `<工作目录根>/relay-int`，不和交互里的整合方（`int`）、开发 agent 的操作目录（`ops`）共用。

做完这两件，整合方就可以在用户看着的情况下，让调度器在真仓库上跑第一棒（那一步整合方亲自做，不在这一单）。

## 契约（接口写死，不改名、不加字段）

1. **启动器加环境变量**（`packages/relay/bin/dsh.mjs`）：起 DSH 时在环境里追加一项 git 配置——`GIT_CONFIG_COUNT` 原来是 `n`（没有就当 0）→ 设 `GIT_CONFIG_KEY_<n>=http.sslBackend`、`GIT_CONFIG_VALUE_<n>=openssl`、`GIT_CONFIG_COUNT=n+1`；原来的第 0…n−1 项原样保留。别的照 L4，不加任何权限相关的东西。
2. **`relay init`**（`packages/relay/bin/relay-main.ts` 里加这个命令）：
   - 数据目录里已经有 `config.json` → 什么都不改，打印「已经有配置了，没改：<路径>」，退出码 0。
   - 没有 → 写一份，形状照 `config.example.json`，占位符换成：
     - 整合方 `argv[0]`：Claude Code 的可执行文件。依次找 `%APPDATA%/npm/node_modules/@anthropic-ai/claude-code/bin/claude.exe`（照 `scripts/real/l2-claude-turn.mjs`）、PATH 里的 `claude.exe`；都没有就写 `claude`，并打印「没找到 Claude Code 的可执行文件，配置里先写 claude，要手动改」。
     - 整合方 `cwd`：`<工作目录根>/relay-int`。不存在就在调度器所在的仓库里 `git worktree add --detach <路径> origin/main` 建出来；已经存在就不动。
     - 开发 `argv`：`["node", "<仓库根>/packages/relay/bin/dsh.mjs", "--profile", "headless", "--json", "读 {prompt_file}，照里面做。"]`（仓库根是调度器所在的这个仓库，绝对路径）；`cwd`：`<工作目录根>`。
     - `--add-dir` 的占位符换成 `<数据目录>/turns` 的绝对路径。
     - `localUserCheck` 照样例。
   - 写完用 `checkConfig` 检查一遍，不过就删掉刚写的文件、打印原因、退出码 1。
   - 写完打印「写好了：<路径>」和两个角色的 `cwd`。**不打印、不写任何密钥**；`feishu.json` 不碰。
   - **工作目录根**照 `scripts/worktree.mjs` 现算：`IXAEON_WORKTREES` 有值就是它（它指的就是 `Worktrees/IXAEON` 这一层），没有就是主检出往上两级的 `Worktrees/IXAEON`（本机 `D:AgentWorktreesIXAEON`）。

## 约束

- 测试全用临时目录：`IXAEON_RELAY_DIR`、`IXAEON_WORKTREES` 指到临时目录，`APPDATA` 指到临时目录（里面放或不放一个假的 `claude.exe`）。**不读、不写用户本机真的数据目录。**
- `relay init` 的测试会在真仓库里加一个工作目录（建在临时目录下）：测试收尾一定 `git worktree remove --force <它>` 并 `git worktree prune`。
- 不改 `~/.dsh`、`~/.claude`、`~/.codex`、用户的 git 全局设置。不跑 `dsh --dump-config`。
- L1–L4 已锁定的测试不改，要和这一单一起过。

## 验收条件

1. **启动器的 git 配置**：替身（照 L4 的假安装目录）打印自己收到的环境：没有 `GIT_CONFIG_COUNT` 时 → `COUNT=1`、`KEY_0=http.sslBackend`、`VALUE_0=openssl`；原来有 `COUNT=1`（`KEY_0=core.autocrlf`、`VALUE_0=false`）时 → `COUNT=2`、第 0 项原样、第 1 项是 `http.sslBackend=openssl`。
2. **`relay init` 写配置**：写出的 `config.json` 是合法 JSON；整合方 `argv[0]` 是假 `claude.exe` 的路径（`APPDATA` 下放了它时）；整合方 `cwd` 是 `<IXAEON_WORKTREES>/relay-int` 且是一个 git 工作目录、停在 `origin/main`；开发 `argv` 有启动器的绝对路径和 `--profile headless --json`，`cwd` 是 `<IXAEON_WORKTREES>`；`--add-dir` 后面是 `<数据目录>/turns`；没有任何「跳过所有权限」的开关；`checkConfig` 放行。
3. **没找到 Claude**：`APPDATA` 下没有 `claude.exe`、PATH 里也没有（测试把 PATH 缩成只剩 node 所在的目录）→ 整合方 `argv[0]` 是 `claude`，输出里有「没找到 Claude Code 的可执行文件」。
4. **已经有配置**：数据目录里放一份合成的 `config.json` → `relay init` 不改它（内容逐字节不变），输出「已经有配置了，没改」，退出码 0。
5. **配置检查不过就不留文件**：把 `IXAEON_RELAY_DIR` 设成 `<IXAEON_WORKTREES>/relay`（开发的 `cwd` 就会包着数据目录）→ 退出码 1、数据目录里没有 `config.json`。

## 真机检查

**甲：DSH 在沙箱里带登录推送（不依赖实现，可以先做；DSH 真调用不超过 2 次）**——`scripts/real/l5-dsh-push.mjs`：照 `l4-dsh-push.mjs`，但起 DSH 时环境里带上第 1 条那三个变量（脚本里自己加，不等实现）。临时目录里 `git clone --depth 1` 真仓库，让 DSH 建分支 `relay-probe/<时间戳>`、`git commit --allow-empty -m "接力探测：DSH 沙箱里推送（会马上删掉）"`、`git push`。脚本最后**一定删掉这个远端分支**（`git push origin --delete`，失败重试），打印删没删成。推不上去就如实记下报错（遮掉用户目录）：多半是凭据管理器在受限令牌下读不到登录态，**不许**改 git 的凭据设置、不许把令牌写进任何文件或环境变量——写清楚卡在哪，交给整合方和用户定。

**乙：`relay init` 在临时目录里跑一遍**（要实现）：`IXAEON_RELAY_DIR`、`IXAEON_WORKTREES` 指到临时目录，看输出、看写出来的配置（遮掉用户目录），再 `relay once --help` 之类不开棒的命令确认它读得进这份配置。收尾删掉建出来的工作目录。

## 整合方审测试时的改正与补充（2026-10-22）

整合方写了一份一次性的 `relay init`（没提交）把测试跑通，挑 5 处改坏都有测试变红，然后锁定（只锁 `l5-init.test.ts`）。

- **契约第 1 条（启动器设 `GIT_CONFIG_COUNT/KEY/VALUE`）作废，挪到 [L6](L6-调度器替开发推送.md)**：真机检查甲发现 DSH 会把名字里带 `KEY`、`TOKEN`、`SECRET`、`PASSWORD` 的环境变量擦掉，`GIT_CONFIG_KEY_0` 被擦，git 直接起不来。这是整合方规格写错了。`l5-launcher.test.ts` 不锁、删掉；验收条件 1 不算这一单的。
- **带登录的推送在 DSH 沙箱里走不通**：git 调凭据助手一定经过 `sh.exe`，受限令牌下 `sh.exe` 起不来。用户 2026-10-22 定了：**调度器替 DSH 推**（L6）。
- **`relay init` 建 `relay-int` 之前先 `fetchMain`**：GitHub 上跑临时分支的 CI 只拉触发的那个分支，没有 `origin/main`；拉不下来就打印「拉不下来 origin/main，建不了整合方的工作目录」、退出码 1。
- 测试里改正的：原来拿 `git worktree list` 的输出（正斜杠、长路径）去比反斜杠的临时路径，本机就对不上，CI 上还有 `RUNNER~1` 短写法——改成问 git「这个目录属于哪个仓库」。
- 开发提的两处接受：条件 3 的 PATH 除了 node 还留 git 所在的目录（`relay init` 要用 git）；条件 5 加的「输出里有 `developer`」保留。
