# 规格 V1：应用里跑验证命令，不再拉起一个新的 Electron 窗口

档位：**A**（修 bug：只补子进程环境变量与一句日志文案，不改验证规则、不放宽沙箱）。大小：小（≤60 行源码）。依赖：无。来源：[D2 沙箱实验](交付/D2-沙箱实验.md) §5、§7（调研 agent 2026-09-29 发现，整合方核实）。
v2 规格：验收条件写成测试（`packages/core/test/acceptance/v1-*.test.ts`），测试和实现一起交，Codex 审查时核对测试有没有漏掉条件。

## 要什么

编码任务的独立验证（`CodingOrchestrator.verify` → `defaultCheck`，`packages/core/src/execution/executor.ts`）用 `process.execPath` 当 node 跑验证命令。IXAEON 不管是开发版还是打包版都跑在 Electron 里，`process.execPath` 是 Electron 的可执行文件。派生子进程时，环境变量（`minimalChildEnv`）里没有 `ELECTRON_RUN_AS_NODE=1`，Electron 就不会当 node 跑，而是再启动一个应用实例——验证命令根本没跑，还多出一个窗口。

整合方核实：记忆桥（`hermesBridge.ts`）和 MCP 片段（`mcpSnippet.ts`）派生 Electron 当 node 用时都设了 `ELECTRON_RUN_AS_NODE=1`，唯独验证这里漏了。现在编码任务的默认验证命令（`DEFAULT_NOTE_VERIFY`、`propose_task` 的缺省命令、研究发现开的草案）都用 `process.execPath`，D2 往后的验收测试也要走这里。

顺带一处文案：`stopServer` 在正常退出时也写「本地服务已停止（数据恢复）」，读日志的人会以为在恢复数据（09-24 整合方排查时就被误导过）。

## 契约

1. `defaultCheck` 派生的程序是 Electron 本身时（`exe === process.execPath` 且 `process.versions.electron` 有值），子进程环境加上 `ELECTRON_RUN_AS_NODE=1`；在普通 node 里跑时不加。其余保持不变：只认 node、剥离命令自带的 `--permission` / `--allow-fs-*`、强制工作区读写边界、环境变量白名单。
2. `stopServer` 的日志文案按原因区分：正常退出写「本地服务已停止」；只有数据恢复前调用时才写「本地服务已停止（数据恢复）」。

## 约束

- 不改验证的判定规则、不放宽 Node 权限模型、不加新的可执行程序。
- 不加迁移。

## 验收条件

1. 模拟在 Electron 里（`process.versions.electron` 有值）跑验证命令：子进程拿到的环境里有 `ELECTRON_RUN_AS_NODE=1`；验证命令照常执行，退出码如实反映（通过 / 失败各一例）。
2. 在普通 node 里：子进程环境里没有 `ELECTRON_RUN_AS_NODE`。
3. 环境变量白名单以外的变量照旧不带进子进程（现有相关测试照过）。
4. 正常退出的日志是「本地服务已停止」，数据恢复路径的日志是「本地服务已停止（数据恢复）」。

## 真机检查

用临时数据目录（`IXAEON_DATA_DIR`）启动开发版应用，用执行器替身（不调用真 Codex）建一个带默认验证命令的编码任务，派发到验证：确认没有多出窗口，任务的验证结果是「通过」或「失败」而不是卡住或「未运行」。描述或截图，脚本放 `scripts/real/`。
