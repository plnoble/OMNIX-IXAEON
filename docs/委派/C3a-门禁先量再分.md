# 规格 C3a：门禁瘦身第一步——量一量、分一分（不删）

档位：**A**（只交一份分析，不改门禁、不删测试）。大小：不改源码。依赖：无。来源：三周任务单第 0 周的 C3「测试套件合并」一直没做；整合方 2026-10-19 排的无人值守任务。

## 要什么

C3 的目标是门禁降到 12 步以内，一直没做。现在 `node scripts/verify.mjs` 是 35 步，本机跑一遍十来分钟，每一轮验收、复审都要跑好几遍。里面有 27 套按审核编号命名的回归套件（`apps/desktop/test/review/` 等），是「自己写代码自己判对错」那段时间留下的，其中不少测的东西后来已经有锁定的验收测试管着，或者功能已经改掉了。

删哪套要整合方逐条定。这一单只做定之前的功课：**量清楚每一步花多少时间，把每套回归测了什么、有没有别的测试管着同一件事查清楚，给出分类和理由。**

## 步骤

1. 在一个干净的工作目录里，对最新的 main 跑 3 次 `node scripts/verify.mjs`（门禁自己会打印每一步的用时），每一步取中位数。
2. 列出每一步：做什么、用时、CI 上跑不跑（看 `.github/workflows/`）。
3. 对每一套回归（门禁里按审核编号命名的那些步骤，以及它们对应的测试文件）：
   - 读一遍，写一句话说它测了什么；
   - 找有没有**锁定的验收测试**（`docs/委派/锁定验收.json` 里登记的）已经管着同一件事——写出是哪个文件、哪一条；
   - 它测的功能现在还在不在——不在了的，写出是哪次提交删掉或改掉的（`git log` 查）。
4. 每一套归一类：
   - **保留**（理由：没有别的测试管着、管的东西还重要）；
   - **可以并进**某个现有的测试项目（理由、并到哪）；
   - **可以删**（理由：被哪条锁定测试覆盖，或测的功能在哪次提交里已经不在了）。
5. 照这个分类估一下：做完之后门禁剩几步、大约多久。

## 范围

- **不改 `scripts/verify.mjs`，不删、不改任何测试**，不动 CI 配置。只交分析。
- 不跑花钱的东西（门禁本身不花钱，照常跑）。

## 验收标准

1. 交付说明 `docs/委派/交付/C3a.md`：每一步一行（做什么、三次的用时和中位数、CI 跑不跑）；每一套回归一行（测了什么、分类、理由）。
2. 「可以删」的每一条都写出能核对的依据：被哪个锁定测试文件的哪一条覆盖，或者功能在哪个提交里删掉了。整合方要能逐条去看。
3. 最后估一个数：照这个分类做完，门禁剩几步、大约多久。
4. A 档：`node scripts/codex-review.mjs C3a`，照 AGENTS.md 合并（只合并这份交付说明）。

## 风险

- 并行跑会互相抢 CPU，用时不准：三次一次一次跑，跑的时候别的事停一停。
- 本机杀毒软件占 CPU 时，有几步（Ollama、计时的测试）会超时变红：单独重跑那一步，别把偶发的红当成测试本身的问题。
