# 规格 D7：编码任务可以交给你自己的模型（网关执行器：只改批准范围内的文件，不跑命令）

档位：**B**（新的一类外发：项目副本里的文件内容会发给你选的模型；还有新写的提示词）。大小：中（≤300 行源码，超了把设置页那部分拆出去）。依赖：M2（编码用的模型从已保存的清单里选）。来源：用户 2026-10-01 试场景一，Codex 没额度。用户定：

> Codex 没额度的时候，用我自己的模型网关。以后这个软件也可以调用 Codex、Claude 和其他的 agent。

v2 规格：先把验收条件写成测试（`packages/core/test/acceptance/d7-*.test.ts`，接线与设置部分放 `apps/desktop/test/acceptance/d7-*.test.ts`），**先只推测试**，整合方看过并锁定后再实现。

## 要什么

场景一里真正动手改文件的执行器现在只有 Codex（`createCodingExecutor`：本机装了 Codex 用它，没装就是测试替身）。Codex 没额度，场景一就走不到底。用户要的是：用自己在设置里配的模型网关，也能把一件小事改完。

这一单只加「我的模型」这一种执行器。Claude Code 和别的 agent 以后再说，但写法要留出位置：执行器按设置选，不写死成二选一。

## 契约

1. **设置**：配置加 `coding.executor: 'codex' | 'model'`（默认 `'codex'`，现有行为不变）和 `coding.modelName: string`（只能从 M2 的已保存清单里选）。设置页加一栏「编码任务交给谁」：
   - 「Codex（本机装了才能用）」；
   - 「我的模型」，选它之后再从已保存的模型里选一个。
2. **按设置选执行器**：派发时按当前设置取执行器（改了设置不用重启）。选了「我的模型」时，D3 自动派发里那道「本机没装 Codex 就不派发」的检查不适用；改成：没选模型或没配 Key，就不派发，在原对话里回报缺什么、去哪设置，写法同现在「没装 Codex」的回报。
3. **网关执行器**（`packages/core/src/execution/modelExecutor.ts`，实现现有的 `CodingExecutor`）：
   - **发什么**：只从这个任务的隔离副本里取，副本本来就不含密钥文件和依赖目录（`copyProjectWorkspace` 的规则）。给模型的内容只有这些：
     - 派发时的任务目标（里面已带可修改范围、获准背景、获准 Skill，与给 Codex 的相同）；
     - 副本的文件清单（相对路径和大小，最多 400 条）；
     - 文本文件的内容：先放批准范围里点了名的文件，再放 README、目标里提到名字的文件；单个文件不超过 64 KB，总共不超过 12 万字符；二进制文件不发。
   - **要回什么**：经现有的 `chatStructured`，按 zod schema 返回 `{ changes: [{ path, action: 'write' | 'delete', content? }], summary, claimedSuccess }`。最多 20 处改动，单个文件内容不超过 20 万字符。
   - **怎么改**：先把所有改动都核一遍，有一处不合格就一处都不写，整单失败，原因写明是哪个路径。不合格包括：
     - 绝对路径、带 `..`；
     - 不在批准范围里；
     - 路径上有符号链接。
       都合格再用现有的 `safeWrite` 写进副本，删除同样查符号链接。编排层现有的范围核对还会再核一遍。
   - **不跑任何命令**，除了这一次模型请求不联网。
   - **报告**：`changedPaths` 是实际写了或删了的文件；`summary`、`claimedSuccess` 照模型说的；`testsModified` 按路径判断；`raw` 存截短后的原始返回。执行器名记成 `model:<模型名>`。
   - 模型没按格式返回、请求失败或超时：整单失败，原因写明（比如「模型没按格式返回」），副本里什么都不写。
   - 取消：模型请求本身停不下来，编排层现有的「取消后晚到的成功不覆盖取消」照旧兜底。
4. **之后照旧**：独立验证（D2）、回报（D3）、接受后建分支（D4）全部不变，都认这份报告。
5. 任务页和对话回报里，执行器显示成「我的模型（<模型名>）」。

## 约束

- 不加迁移（`executor_name` 已有）。
- 只在用户点「要做」批准之后才发文件给模型（批准流程不变）。
- 提示词要写清：只能返回文件改动、只能改批准范围里的文件、不要编造没给过的文件内容、做不到就把 `claimedSuccess` 设为 false 并说明原因。

## 验收条件

1. 默认（`coding.executor = 'codex'`）：行为与现在一模一样，现有测试照过。
2. 选了「我的模型」并选好模型：派发用网关执行器；本机没装 Codex 也照常派发。
3. 模型返回批准范围内的改动：文件写进副本，报告的 `changedPaths` 正好是这些文件，之后的验证、回报、接受落地照常走通（合成 git 项目里接受后建出分支，提交正好是这些改动）。
4. 模型要改范围外的文件、给绝对路径或带 `..`：一处都不写，任务失败，原因里有那个路径；真实项目和副本都没变。
5. 模型没按格式返回、改动超过 20 处、单个文件超过上限：一处都不写，任务失败，原因写明。
6. 发给模型的内容只来自副本：副本里没有的文件（比如 `.env`、`node_modules` 里的东西）不出现在提示里；内容遵守单文件和总量上限；文件清单不超过 400 条。
7. 网关执行器不起任何子进程。
8. 选了「我的模型」但没选模型或没配 Key：不派发，原对话里回报缺什么、去哪设置；任务留在排队里，补好设置后能接着派。
9. 任务页和回报里，执行器显示成「我的模型（<模型名>）」。

## 真机检查

用合成的小 git 项目（只有 README），在用户自己配置的模型网关上跑（内容全是合成的）：

1. 目标「在 README.md 末尾加一行……」，批准范围 `README.md`：副本里 README 多了这一行；接受后建出分支，提交正好改了 README。
2. 同一个项目，批准范围只给 `README.md`，目标却要新建 `other.txt`：没写任何文件，任务失败，原因里有 `other.txt`。
3. 原样贴出两次的回报和任务页显示的执行器名。

## 整合方审测试时的改正与补充（2026-10-03，锁定前）

### 拆成两单

原规格一单做完要动四百多行源码，超过 300 行的硬规矩。拆开：

- **D7（本单）**：只做网关执行器本体——`packages/core/src/execution/modelExecutor.ts` 和从核心包导出。原契约 3，原验收条件 3（执行器那一半）、4、5、6、7。
- **D7b**（`docs/委派/D7b-按设置选执行器.md`）：设置、按设置选执行器、缺东西时不派发并回报、显示、设置页。原契约 1、2、4、5，原验收条件 1、2、3（整条流程那一半）、8、9。

锁定的测试：本单是 `packages/core/test/acceptance/d7-model-executor.test.ts`。执行方原来的 `d7-executor-selection.test.ts` 归 D7b，重写后改名。

### 发什么（改正：原规格会把整个项目的文件内容都发出去）

原规格写「先放批准范围里点了名的文件，再放 README、目标里提到名字的文件」，没说范围外又没点名的文件发不发。定死：

1. **内容只发三类文件**，按这个顺序放，放不下的就不发：
   - 批准范围内的（范围条目是文件就是它；是目录就是目录下的；是 `.` 就是整个副本）；
   - 副本根目录下文件名以 README 开头的（不分大小写）；
   - 任务目标的文字里出现了它的相对路径的（用 `/` 分隔的写法）。
     其余文件只进清单（相对路径和大小），内容不发。
2. **这些永远不发内容**，在批准范围里也不发：
   - 二进制文件（开头 8 KB 里有 NUL 字节）；
   - 密钥类文件名（与复制副本时跳过的同一套：`.env*`、`*.pem`、`*.key`、`*.p12`、`*.pfx`、`id_rsa*`、`id_ed25519*`、`*.cookie`）。副本里本来不该有，万一有也不发；
   - 链接那头的东西：遍历副本时不进链接，链接里面的文件不读、不列进清单。
3. 上限照原规格：单个文件超过 64 KB 只发开头并标明截断；文件内容合计不超过 12 万字符；清单最多 400 条，超出的不列并标明清单已截断。
4. 一次任务只发一次模型请求。开工前已经取消的，不发。

### 怎么改（补充）

5. 路径先规范化：反斜杠当正斜杠。不合格的情形在原规格三种之外加：
   - 写入的目标已存在但不是普通文件（比如是目录）；
   - 删除的目标不存在，或者不是普通文件；
   - 路径上任何一段（含最后一段）是链接。
6. **不许盲改**：要写入的文件已经存在，但它的内容没有完整发给模型（被截断、放不下、是二进制、不在可发之列）→ 不合格。模型没看全就整份重写，等于把没看到的部分删掉。提示词里要告诉模型：只能整份改写已经给了完整内容的文件，或者新建文件。
7. 上限（最多 20 处、单文件内容 20 万字符）由执行器自己核、自己给出原因，不写进交给模型客户端的 schema：写进去的话真模型客户端会当成格式错误重试，最后只剩一句看不出原因的报错。schema 只描述结构；`content` 可以不带或为 null（删除时）。
8. 模型自己说没做成（`claimedSuccess = false`）：它给的改动一处都不写，`changedPaths` 为空，`summary` 照它说的。
9. `raw` 截短到 8000 字符以内。

### 超时与取消（改正：原规格只靠编排层兜底，晚到的响应仍会写进副本）

10. 模型请求超过任务的 `timeout_ms`：到时限就失败（原因写超时），不等模型回来；之后响应回来也不写。
11. 等模型的时候被取消：不写。模型回来之后先看取消标记，再决定写不写。

### 新增验收条件

10. 范围外又没在目标里点名的文件：内容不发，只进清单。二进制、密钥类文件名、链接那头的东西：内容不发；链接里面的文件不进清单。
11. 不许盲改：要覆盖一个内容没完整发给模型的已有文件，一处都不写，任务失败，原因里有那个路径。
12. 路径上有链接、写到目录上、删不存在的文件或目录：一处都不写，任务失败，原因里有那个路径。同一批里本身合格的改动也不写。
13. 超时到时限就失败；超时或取消之后才回来的响应不写。开工前已取消的不发模型请求。
14. 模型自己说没做成：它给的改动不写。

### 真机检查（本单）

已保存的 Key 只能在应用主进程里解密，本单的执行器还没接进应用，所以**真模型网关上的检查并到 D7b**（原规格的两步都在那里跑）。本单只跑不联网的一步：

`scripts/real/d7-model-executor.ts`：用一个本机的假上游（`http.createServer`，监听 127.0.0.1 的临时端口，照 `/chat/completions` 的格式回一段写死的 JSON）加真的 `OpenAIResponsesProvider`，对临时目录里的合成小项目（一个 README、一个 `.env`，内容全是合成的）跑一次 `ModelCodingExecutor`。打印：假上游收到了几次请求、请求体的字符数、里面有没有出现 `.env` 的内容（应为没有）、副本里 README 的改动。这一步查的是执行器和真的模型客户端接得上（schema 能转成提示、返回能解析），不是模型本身的表现。
