# 规格 A5：模型出错的那一轮记成失败——不当回答显示、不进记忆、不进下一轮的上下文

档位：**B**（改变什么进记忆、什么给模型看）。大小：小（≤120 行源码）。依赖：无。来源：A4 执行方查出、交整合方（`docs/委派/交付/A4.md`「已知缺口」）。
v2 规格：先把验收条件写成测试（`apps/desktop/test/acceptance/a5-*.test.ts`），**先只推测试**，整合方看过并锁定后再实现。

## 要什么

没装 Hermes 时，问答走核心层自己的工具循环（core-bounded）。这一轮里模型调用失败时（网关不通、模型报错……），现在的收尾是：
- 消息记成 `complete`，回答正文就是「模型动作失败：……」这段错误文字；
- 问答照常存档进记忆（回报里还写着「问答已存入 IXAEON 记忆」），并排队提炼；
- 下一轮的上下文（`priorTurns` 只取 `complete`）会把这段错误文字当成助手说过的话带上。

用户看到的像一条普通回答；错误文字可能被提炼成记忆；下一轮模型还会读到它。

## 契约

1. **判定**：这一轮的回答来自模型调用失败——核心层工具循环的结果里，模型那一步失败、而且没有拿到正常的最终回答。判定要靠结构化的结果（比如步骤里的失败标记，或者让工具循环直接返回一个失败字段），**不许靠匹配回答里的文字**。
2. **收尾**：这种轮的消息记成 `failed`，`error_message` 写模型那一步的错误；回答正文不放这段错误文字，已经答出的半截正常回答照常保留。
3. **不进记忆**：这一轮不存档、不排提炼，回报里不写「问答已存入 IXAEON 记忆」。
4. **不进下一轮的上下文**：现有规则「`priorTurns` 只取 `complete`」照旧，这一轮自然不会被带上。
5. **不误伤**：
   - 某个工具失败、但模型最后正常回答了的轮，照旧是 `complete`；
   - Hermes 引擎这边出错，现在本来就走抛错、收尾成 `failed` 的路，不变。
6. **界面**：照现有的失败显示（「失败：」加错误信息、不转圈），不用另做。

## 约束

- 不加迁移（`status`、`error_message` 都已有）。
- 不改 Hermes 那条路，不改发给模型的提示词。
- 用户重新问一遍的流程不变。

## 验收条件

1. 核心层工具循环里模型调用失败（测试用会抛错的假模型）：消息是 `failed`，`error_message` 有这次的错误，正文里没有当作回答的错误文字。
2. 这一轮没有存档，也没有排提炼（没有新建或更新的问答来源、没有新的提炼任务），回报里没有「问答已存入」。
3. 下一轮的上下文里没有这一轮助手的内容（错误文字不进去）；用户自己的那句提问照现有规则留着。
4. 工具失败、但模型最后正常回答了：照旧是 `complete`，照常存档。
5. Hermes 引擎出错：行为与现在一样（现有测试照过）。
6. 判定不靠回答文字：模型正常回答的内容里恰好含有「模型动作失败」字样，照旧是 `complete`。

## 真机检查

设 `IXAEON_DATA_DIR=<临时目录>`、清掉 Hermes 的环境变量，用假模型启动应用：
1. 让模型调用出错（假模型脚本不给响应）：对话里显示失败和错误信息；用 `scripts/real/last-ask-status.mjs` 看这条消息是 `failed`、有错误信息；来源页没有多出这一轮的问答存档。
2. 再问一句正常的：照常回答、照常存档。

## 整合方审测试时的改正与补充（2026-10-03，锁定前）

1. **条件 3 改正**：现有规则（`recentTurns` 只取 `complete` 的消息）下，失败那一轮里用户自己的提问本来就留在下一轮的上下文里，Hermes 出错的轮也是这样。这条规则不改。要保证的是：失败轮的助手内容（错误文字、那段「未形成最终回答」的话）不进下一轮。
2. **判定范围加一种（新增条件 7）**：到了轮次上限还没形成最终回答。工具循环自己已经把这一轮记成失败，返回的是「已达轮次上限，未形成最终回答……」这段话。同样记成 `failed`、不存档；`error_message` 写明是轮次上限，这段话不当回答正文。
3. **只判核心层工具循环的结果（新增条件 8）**：Hermes 的结果里本来就没有 `answer` 步（它的步骤是 `text`、`terminal`），不许因此误判成失败。
4. `error_message` 要带原始错误。可以用现有的 `explainModelFailure` 给出人看得懂的说明，它会把原始错误附在后面。
5. **测试里要有真的工具循环**：执行方的用例全靠替身会话手写结果，替身的步骤和真引擎对不上时测试照过、线上永远触发不了。整合方补了用真的 `AgentSession`（core-bounded）加假模型的用例，从引擎一路测到 `ask` 收尾。

### 新增验收条件

7. 到了轮次上限还没形成最终回答：消息是 `failed`，`error_message` 写明轮次上限，那段话不在正文里；不存档。
8. Hermes 引擎的正常回答（步骤里没有 `answer` 步）：照旧 `complete`，照常存档。
