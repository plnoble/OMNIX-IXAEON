# 规格 CF0：聊天先能用（模型没渠道时说清楚、能换个模型重问）

档位：**A**（错误说明、界面；换的是网关里你已经检测过、存下来的模型，同一个网关、同样的内容，不是新的外发）。大小：小（约 150 行源码）。依赖：无。来源：整合方 10-31 升级审计（[三周任务单](../三周任务单.md)「总体升级」一节）——用真 Hermes 问 5 个合成问题，全部返回 `HTTP 503: No available channel for model <模型> under group default …`，界面上的说明却是「暂时出错，稍后再试」——这种情况重试没用。（整合方更正：那次是实测脚本没指定聊天模型、Hermes 用了它自己配置文件里的默认模型；用户应用里的聊天是通的。但网关里某个模型没渠道时，聊天整条断、说明还误导人，这一单照做。）用户 10-31 定做这一单。升级第 1 阶段的第一单。

v2 规格：先把验收条件写成测试（`packages/core/test/acceptance/cf0-*.test.ts`、`apps/desktop/test/acceptance/cf0-*.test.ts`），和实现一起交，Codex 审查。

## 要什么

1. **说对原因**。`packages/core/src/runtime/modelErrors.ts` 的 `explainModelFailure` 现在把所有 5xx 都说成「模型网关或它的上游暂时出错，稍后再试」。网关回的是「这个模型没有可用渠道」「模型不存在」这一类时，**重试没用**，要说清是哪个模型、该怎么办：
   - 认这几种（不分大小写）：`No available channel for model <名字>`（new-api / one-api 的说法）、`model_not_found`、`The model \`<名字>\` does not exist`、`model <名字> not found`。
   - 说明写成：`网关里「<模型名>」现在没有可用渠道（常见原因是那条渠道的套餐或额度失效了）。去网关后台给它补一条渠道，或者在聊天里换一个模型重问。`（取不到模型名就写「这个模型」），后面照旧接 `（原始错误：…）`。**不出现「稍后再试」**。
   - 别的 5xx、429、超时、401/403 的说法一个字不改。
   - 另外导出 `isModelUnavailable(detail: string): { model: string | null } | null`：是上面这几种就返回模型名（取不到为 `null`），否则 `null`。界面靠它决定要不要给「换个模型重问」。
2. **在聊天里就能换模型重问**。一条回答因为上面那种原因失败时，失败的那条消息下面出现一个小控件：
   - 一个下拉框，列出设置里已检测并保存的模型（`config.savedModels`），**去掉刚失败的那个**；
   - 一个按钮「用这个模型重问」：把聊天模型（设置里的 `chatModelName`，和「设置 → 模型接入 → 聊天模型」是同一个）改成选中的，再在**同一个对话**里把刚才那句原话重新问一遍。
   - 失败的那条消息照旧留着（状态 `failed`），不删、不改写——历史不丢。
   - 已保存的模型里除了失败的那个没有别的 → 不出下拉框，改出一句「设置里还没有别的可用模型」和一个跳到设置页「模型接入」的按钮。
   - 不是「没有渠道 / 模型不存在」的失败 → 不出这个控件（照现在的样子）。

## 契约

- `explainModelFailure(detail)` 签名不变；新增导出 `isModelUnavailable(detail)`（`packages/core/src/index.ts` 一起导出）。
- 改聊天模型复用现有保存设置的通道，不另开写配置的 IPC；如果现有通道必须连同 Key、地址一起传，就新加一个只改 `chatModelName` 的 IPC `setChatModel(input: { model: string }): Promise<{ ok: true }>`，主进程校验 `model` 必须在 `savedModels` 里，不在就拒绝。改完之后的下一问用新模型（现有改聊天模型的路径怎么让 Hermes 换模型，照它来）。
- 重问复用现有的发送路径（和用户在输入框里按发送一样），不另造一条。

## 约束

- 只用已保存的模型，**不自动换、不自动重试**：换不换由用户点（自动选模型是模型路由，按用户 10-29、10-31 的决定还锁着）。
- 不加新的外部服务；不发别的请求去探测哪个模型能用（「检测」照旧在设置页由用户点）。
- 不加迁移；不改消息表。
- 原始错误里可能带网关地址：说明文字照现在的做法截到 120 字；测试、交付说明、截图里不出现真实网关地址和模型清单（用合成的）。

## 验收条件

1. `explainModelFailure('HTTP 503: No available channel for model demo-a under group default (distributor)')` 含 `demo-a`、`没有可用渠道`、`换一个模型`，不含 `稍后再试`；`isModelUnavailable` 返回 `{ model: 'demo-a' }`。
2. `model_not_found`、`The model \`demo-b\` does not exist` 两种也认（后一种模型名取到 `demo-b`）；取不到模型名时说明里写「这个模型」。
3. `HTTP 502: Bad Gateway`、`HTTP 429 …`、超时、`HTTP 401 …` 的说明和改之前**逐字一样**；`isModelUnavailable` 对它们返回 `null`。
4. 聊天页：一条消息以「没有可用渠道」失败、已保存模型有 `demo-a`（失败的）、`demo-b`、`demo-c` → 失败消息下面出现下拉框，选项正好是 `demo-b`、`demo-c`。
5. 选 `demo-b` 点「用这个模型重问」→ 聊天模型设置变成 `demo-b`；同一个对话里多出一问一答，问的是原话；失败的那条还在、状态还是 `failed`。
6. 已保存的模型只有失败的那个 → 不出下拉框，出「设置里还没有别的可用模型」和跳设置的按钮。
7. 失败原因是超时或 429 → 不出这个控件。
8. `setChatModel`（如果加了）：传不在 `savedModels` 里的模型 → 被拒、设置不变。
