# 规格 P7：来源页加「撤销读取」

档位：**B**（权限与隐私：新增一个撤销读取授权的入口）。大小：中（≤150 行源码）。依赖：无。来源：P6 复审时查到的缺口；用户 2026-10-09 同意加。

v2 规格：先把验收条件写成测试（`apps/desktop/test/acceptance/p7-*.test.ts`），**先只推测试**，整合方看过并锁定后再实现。

## 要什么

IXAEON 读本机的文件和文件夹之前都要有一条读取授权。授权是这几处发的：

| 在哪儿                                   | 发的是什么                         |
| ---------------------------------------- | ---------------------------------- |
| 来源页「导入文档」                       | 每个选中的文件一条**文件**授权     |
| 来源页「导入文件夹」「导入编码代理会话」 | 选中的文件夹一条**文件夹**授权     |
| 项目页「绑定文件夹」、首次设置登记目录   | 项目文件夹一条**文件夹**授权       |
| 浏览器扩展采集、保存提问                 | 一条**域名**授权（不是读本机文件） |

发得出去，收不回来：界面上能收回授权的只有项目页的「解除绑定」（P5），而且只管绑在项目上的那个文件夹。在来源页导入过的文件、没绑在项目上的文件夹、编码代理的会话目录，用户想让 IXAEON 不再读，没有地方点。接口其实早就有（`revokeSourceReading`：撤销一份资料所在的那条授权，并让对话上下文失效），只是界面上从来没有按钮。

这一单：来源的详情里加一个「撤销读取」。点了先说清楚会连带多少份资料，确认之后撤销。

## 契约（接口写死，不改名、不加字段）

1. **类型**（`packages/contracts/src/entities.ts`）：

   ```ts
   /** 撤销一份资料所在的读取授权之前，先看一眼后果。只读，不改任何东西。 */
   export interface RevokeSourceReadingPreview {
     /** 这条授权是哪一类：本机的文件、本机的文件夹，还是域名（网页采集、保存的提问）。 */
     scope: 'file' | 'folder' | 'domain';
     /** 授权的是哪个文件或文件夹（授权记录上存的路径，原样）；域名授权时是域名。 */
     locator: string;
     /** 这条授权现在的状态。 */
     status: 'active' | 'revoked';
     /** 这条授权下一共多少份资料（含这一份；归在哪个项目、归没归项目都算）。 */
     sourcesUnderGrant: number;
     /**
      * 靠这条授权读自己文件夹的项目（项目名，按名字排序）：项目绑着的文件夹在这条授权之内，
      * 而且撤销之后它就不在任何有效授权之内了。有这样的项目就不在来源页撤销。
      */
     dependentProjects: string[];
   }
   ```

2. **一个新接口**（`packages/contracts/src/ipc.ts`、`apps/desktop/src/main/ipc.ts`、`apps/desktop/src/preload/index.ts` 三处；业务逻辑放在 `AppRuntime` 上的同名方法，IPC 只转一下）：

   ```ts
   previewRevokeSourceReading(sourceId: string): Promise<RevokeSourceReadingPreview>;
   ```

   - 资料不存在：拒绝（「来源不存在」，和 `revokeSourceReading` 现在报的一样）。
   - `dependentProjects` 怎么算：所有绑着文件夹的项目（不管什么状态），它的 `root_path` 在这条授权之内（照 `permissions.activePermissionForPath` 判断「在不在里面」的办法），并且除了这一条之外没有别的有效授权覆盖它。文件授权、域名授权、已经撤销的授权，这一项是空的。
   - 只读：不改任何表，不记审计，不让对话上下文失效。

3. **`revokeSourceReading` 不动**（签名、行为都不改）。它只会收回授权，界面以外的调用（比如真机脚本）照旧可用。「有项目靠着这条授权就不在这里撤」是界面的规矩，由预览告诉界面，不在这个接口里拦——P6 已经保证了即使撤了，没授权的项目也派不了任务。

4. **界面**（`apps/desktop/src/renderer/src/pages/Sources.tsx`，来源的详情卡片）：

   - 详情卡片的按钮里多一个「撤销读取」（`data-testid="source-revoke-reading"`），放在「重新分析」后面。
   - 点了先调预览，按结果三选一：
     - **域名授权**（`scope === 'domain'`）：不问、不撤销，在详情卡片里显示一句（`data-testid="source-revoke-note"`）：

       > 这份资料不是读本机文件得来的（是网页采集或者保存的提问），没有本机的读取授权可撤。不想留着它，用「删除来源」。

     - **有项目靠着这条授权**（`dependentProjects` 不是空的）：不问、不撤销，显示一句（同一个 `source-revoke-note`），多个项目名用「、」隔开：

       > 项目「<项目名>」正靠这条授权读它的文件夹：到项目页对它点「解除绑定」，会一并撤销这个文件夹的读取授权。

     - **其余**：用 `window.confirm` 问一次。文字照下面写，`<这个文件 / 这个文件夹>` 按 `scope` 二选一：

       ```
       撤销<这个文件 / 这个文件夹>的读取授权？

       <路径>

       撤销之后：
       - IXAEON 不再读它：这条授权下的 <N> 份资料不再读原文，已经提炼出的理解保留。
       - 要再用得重新导入。重新导入发的是一条新授权，现在这 <N> 份资料恢复不了。
       ```

   - 取消确认：什么都不发生。
   - 确认：调 `revokeSourceReading`；详情卡片关掉（撤销之后原文读不了了）；来源列表重新读一遍，这条授权下的资料都显示「授权已撤销」（现有的显示，不改）；页面上显示一句结果（`data-testid="source-revoke-result"`）：「已撤销读取授权：<N> 份资料不再读原文。」
   - 出错（预览出错、撤销出错）：显示在这一页现有的报错条里，详情卡片不关，资料的状态不变。
   - 预览返回的 `status` 已经是 `revoked`（别处刚撤销过、这一页还没刷新）：不问、不撤销，把列表重新读一遍。

## 约束

- 不加迁移。不删数据：资料、片段、提炼出的条目都留着，只是授权状态变了。
- `revokeSourceReading` 不改；撤销授权之后「不返回原文」这些现有的行为不改。
- 域名授权不在这一单里处理（采集的开关在设置页，是另一回事）。
- 测试、交付说明里的路径、项目名用合成的。

## 验收条件

1. 预览一份「导入文档」得来的资料：`scope` 是 `file`，`locator` 是那个文件，`status` 是 `active`，`dependentProjects` 是空的；同一个文件导出过多份资料时 `sourcesUnderGrant` 是总数。
2. 预览一份「导入文件夹」得来的资料（这个文件夹没绑在项目上）：`scope` 是 `folder`；`sourcesUnderGrant` 把这条授权下归在别的项目的、没归项目的都算进去；`dependentProjects` 是空的。
3. 这个文件夹正绑在某个项目上、项目没有别的授权：`dependentProjects` 是这个项目的名字。项目已归档也算。
4. 这条授权是某个项目文件夹的**上级**文件夹：项目自己另有一条有效授权 → `dependentProjects` 是空的；项目自己没有授权（或者那条已经撤销）→ 有这个项目。两个项目都靠着这条授权时两个名字都在，按名字排序。
5. 域名授权下的资料：`scope` 是 `domain`，`dependentProjects` 是空的。
6. 预览不改任何东西：调用前后授权、资料、审计都不变，正在用的对话上下文没有被作废。资料不存在时拒绝。
7. 界面，可以撤销的情况：点「撤销读取」先调预览、再问；确认框的文字照契约 4 逐字（文件、文件夹两种说法各一条）；取消确认不调 `revokeSourceReading`；确认之后调了、详情卡片关掉、列表重新读过、结果那句话里的数字对。
8. 界面，不在这里撤的两种情况（域名授权；有项目靠着）：不出确认框、不调 `revokeSourceReading`，显示的那句话照契约 4（项目名带上；两个项目用「、」隔开）。
9. 界面，出错：预览出错不问、不撤销；撤销出错详情卡片不关；两种都显示在报错条里。
10. 界面，预览说已经撤销了：不问、不调 `revokeSourceReading`，列表重新读了一遍。
11. IPC：`registerIpc` 注册了 `previewRevokeSourceReading`，调它得到的和 `AppRuntime` 上的方法一样。
12. 从界面这条路撤销之后（预览 → 确认 → `revokeSourceReading`）：这条授权是 `revoked`；这条授权下的资料在列表里的授权状态都是已撤销，资料和提炼出的条目一条不少；别的授权下的资料不受影响。

## 真机检查

`scripts/real/p7-revoke-reading.mjs`，照 `scripts/real/p5-unbind-folder.mjs` 的规矩（临时数据目录、随机端口、`IXAEON_EMBED_MODEL=none`、`IXAEON_CODEX_EXE=none`、对话框用 `IXAEON_TEST_DIALOG_RESPONSES` 替身、打印遮掉临时目录、`RESULT` 和退出码一致、脚本出错非零；库里只输出条数和状态）：

1. 来源页导入一个合成文件夹（**不**绑到项目上）。打开其中一份资料的详情，点「撤销读取」，**先取消确认**：打印库里这条授权的状态（应当还有效）。
2. 再点一次，确认。打印确认框里的文字、结果那句话、库里这条授权的状态、这条授权下资料的授权状态各几条、列表里那一行显示的状态。
3. 新建一个项目，绑定另一个合成文件夹，从来源页把它也导入一次；打开其中一份资料的详情，点「撤销读取」：打印显示的那句话（应当是叫去项目页解除绑定），并确认库里那条授权还有效。

结果不对就以非零码退出。输出原样贴进交付说明。
