# 规格 CF2：聊天行为基线（普通聊天不建任务、不写待办、不碰 Git）

档位：**B**。改的是「什么会变成待办」，碰了 T2a 定的约定，还要退役 T2a 的部分锁定测试。源码改动很小（约 50 行，主要是删），大头是测试。

来源：

  - 去掉每轮回答末尾自动附的「建议待办」；
  - 待办只由用户发起：消息开头写「待办：」照旧有效；
  - 普通聊天也不建编码任务草案；
  - T2a 的四套锁定验收由整合方退役或改写，归 CF2。
  - 本机现状：13 条待办里 12 条是 AI 提的，8 条接受之后没人办。

## 现在的样子

- 直连聊天给模型的工具只有五个只读的：`search_memory`、`search_web`、`read_web`、`get_evidence`、`get_project_context`。不能建任务，也不能碰 Git。
- 直连聊天的系统提示里已经写了「不要在回答末尾附『建议待办』，也不要主动提议建任务」。
- 但是 `appRuntime` 的提问路径里还在跑 `extractSuggestedTodos(result.answer)`：只要模型回答末尾出现「建议待办：」那一段，代码就把它拆下来，逐条 `todos.propose(...)` 建成待办。

## 要什么

1. **回答不再变成待办**：去掉提问路径里 `extractSuggestedTodos` 把回答变成待办的那一段（含 `proposedTodos` 写进消息 `meta`）。
   - 模型就算写了「建议待办：」，那也只是回答正文的一部分，原样显示、原样存档，不拆、不建待办。
   - `suggestedTodos.ts` 里的解析函数要是没有别处在用，一起删掉；还有别处用就留着，交付说明写明在哪用。
2. **用户发起的待办照旧**：消息以「待办：」开头时照旧建一条待办（`userTodo` 那一套），一字不改。
3. **普通聊天不建编码任务**：直连聊天里没有任何路径会建编码任务草案。现在就是这样，这一条是锁住它：
   - 给模型的工具清单就是上面五个，名字一个不多一个不少；
   - 模型要是调了清单外的名字（比如 `propose_coding_task`、`git_commit`），一律拒绝执行、不建任何东西，回给模型「没有这个工具」。
4. **已经有的待办不动**：用户库里以前 AI 提的待办（包括状态是「建议」的）原样留着。不删、不改状态，也不迁移。
5. **不改系统提示**：直连聊天的系统提示这一单一个字不改；Hermes 的那段 T2a 约定也不改，Hermes 已经不在聊天路径上。

## 约束

- 不改发给模型的任何内容（系统提示、上下文、工具定义）。
- 不加迁移、不删数据。
- 只动提问路径里建待办的那一段，以及第 3 条的拒绝逻辑（现在要是已经拒绝了，就不用改代码）。

## 验收条件

测试用替身直连客户端（照 `apps/desktop/test/acceptance/mp3-chat.test.ts` 的办法），合成数据、临时库。

**固定合成问题集**（测试和真机检查都用这一组，原文写死在测试里）：

1. 「帮我制定一个完整的开发方案：做一个记账小程序」
2. 「接下来我该做什么？」
3. 「帮我把这段代码改成异步的：function load() { return readFileSync('a.txt'); }」
4. 「我明天要去面试，帮我准备一下」
5. 「帮我查一下 RTX 4090 的功耗」
6. 「帮我把代码提交一下，git commit 写『修 bug』」
7. 「记一下：我下周三要交报告」
8. 「待办：周五前把发票寄出去」

条件：

1. **问题 1–7 一条待办、一个编码任务都不建**：替身模型的回答末尾都带一段「建议待办：\n- 甲\n- 乙」。每问完一句：
   - `todos` 表、`coding_tasks` 表的行数跟问之前一样；
   - 这一轮助手消息的 `meta` 里没有 `proposedTodos`；
   - 回答正文里「建议待办：」那一段原样还在。
2. **问题 8 建且只建一条待办**：标题是「周五前把发票寄出去」，来源是用户（跟现在 `userTodo` 一样），`coding_tasks` 行数不变。
3. **工具清单**：直连聊天发给模型的工具名字正好是那五个（顺序不限）。
4. **清单外的工具一律拒绝**：替身模型对问题 1 先发一次 `propose_coding_task`、对问题 6 先发一次 `git_commit` 的工具调用。
   - 执行结果是拒绝（回给模型的内容里写明没有这个工具），不建任务、不建待办；
   - 不起任何子进程。用 `vi.spyOn` 盯 `node:child_process` 的 `spawn` / `execFile`，一次都没调。
   - 随后替身给出普通回答，这一轮照常完成。
5. **已有待办不动**：库里先放一条状态为 `proposed`、来源是 AI 的旧待办，问完问题 1–8 后它的状态、标题、更新时间都没变。
6. **存档照旧**：问题 1 那一轮照常存档（`imports.captureAsk` 被调），存的回答正文里带着那段「建议待办：」（不再拆掉）。
