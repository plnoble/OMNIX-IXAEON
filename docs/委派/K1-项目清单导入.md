# 规格 K1：从清单批量登记项目和状态

档位：**A**。大小：小（≤300 行源码）。依赖：无。
v2 规格：先把验收条件写成测试（`packages/core/test/acceptance/k1-*.test.ts`；界面部分放 `apps/desktop/test/acceptance/`），和实现一起交，Codex 审查。

## 要什么

用户有十几个项目，IXAEON 里几乎都没登记，所以驾驶舱和总览页显示不出来。用户已经确认了一份清单（`项目清单.json`，由 Claude 起草、用户修改）。

项目页加一个"从清单导入"按钮：
1. 选一个 JSON 文件；
2. 显示预览：新增几个、状态有变化的几个、不变的几个、无效的几个（附原因）；
3. 用户点"确认导入"后才写入。

已有项目按 `name` 匹配。

## 契约

- 清单格式（zod，放 `packages/contracts`）：

  ```ts
  ProjectImportList = {
    version: 1,
    projects: Array<{
      name: string,                       // 1..80 字，清单内不重复
      root_path?: string,
      status: 'active' | 'paused' | 'archived',
      description?: string,
      note?: string                       // 只在预览里显示，不入库
    }>
  }
  ```

  未知字段丢弃。

- `packages/core/src/projectImport.ts`：
  - `planProjectImport(db, list) → { create: ProjectImportEntry[], update: { project: Project; status: ProjectStatus }[], unchanged: Project[], invalid: { index, name?, reason }[] }`：纯计算，不写库。`Project` 是 `packages/core/src/projects.ts` 的项目（`projects` 表），不是记忆里的 `items`。
  - `applyProjectImport(db, plan) → { created: number, updated: number }`：只用现有 `ProjectService`（`packages/core/src/projects.ts`）的 `create` / `createMany` 和 `updateStatus`，不直接写 SQL。
- 界面：项目页标题栏加按钮"从清单导入"，弹出预览，"确认导入"后刷新列表。

## 约束

- **不做目录登记读取**：`root_path` 只登记，不读目录内容，不产生 `project_snapshot` 来源。登记读取仍由用户在项目页逐个同意。
- 不删除、不改动清单里没有的项目。
- 已有项目只更新 `status`，别的字段一律不动（`ProjectService` 没有改描述的方法，不为此加接口、不直接写 SQL）；`description` 只在新建时写入。
- 库里有不止一个同名项目 → 这一条进「无效」（「库里有 N 个同名项目」），不猜是哪个。
- 用户的真实清单（项目名、路径）**不进仓库**：测试、真机检查、交付说明一律用合成清单。
- 不加迁移（status 已有 `active / paused / archived` 三种；界面上 `archived` 显示为"放弃"）。

## 验收条件

1. 合成库里已有 2 个项目（A 为 active、B 为 paused），清单 3 条：A 改为 archived、B 不变、C 新增 → 预览为"新增 1、变化 1、不变 1、无效 0"；确认前数据库不变。
2. 确认后：C 已新建且状态对；A 的状态是 archived；B 不变。
3. 无效条目（status 不合法、name 为空、清单内 name 重复）进"无效"并给出原因；其他条目照常导入。
4. 同一份清单再导入一次 → 全部"不变"（幂等）。
5. 库里有、清单里没有的项目 D → 导入前后完全一致。
6. 导入后没有任何新的 `project_snapshot` 来源。
7. 库里已有两个都叫 E 的项目，清单里有 E → E 进「无效」、原因写同名；两个 E 都不变。
8. 清单里已有项目的 `description` 和库里不同 → 库里的 `description` 不变。

## 真机检查

设 `IXAEON_DATA_DIR=<临时目录>` 启动应用，用一份 5 条的合成清单导入：截图预览弹窗和导入后的项目页。不用用户的真实清单。
