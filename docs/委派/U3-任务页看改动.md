# 规格 U3：任务页看得到改了什么

档位：**A**（只读、只在本机显示；不改任务流程，不改发给模型的内容，不动授权）。大小：中（≤300 行源码）。依赖：无。来源：整合方 2026-10-05 查任务页时发现。

v2 规格：验收条件写成测试（核心层的放 `packages/core/test/acceptance/u3-*.test.ts`，界面的放 `apps/desktop/test/acceptance/u3-*.test.ts`），测试和实现一起交，Codex 审查时核对有没有漏条件。

估计两百多行。超过 300 行就拆成两个分支交：先核心层和 IPC（条件 1–11、13），再界面（条件 12）。

## 要什么

任务做完，对话里的回报写着「去任务页看改动，点接受」。可任务页的卡片上只有状态、验证输出和几个按钮，**看不到改了哪些文件、改成了什么**。用户点「接受」之前没有地方看改动，只能接受之后自己去仓库里 `git diff`。回报叫用户去做一件页面上做不了的事。

这一单：任务卡片上加「看改动」，列出这次任务改了哪些文件，每个文件能看到差异。

## 契约（接口写死，不改名、不加字段）

1. **类型**（`packages/contracts/src/entities.ts`）：

   ```ts
   export interface TaskChangedFile {
     /** 相对路径，正斜杠。 */
     path: string;
     kind: 'added' | 'modified' | 'deleted' | 'same' | 'unknown';
     /** 差异正文（格式见契约 4）。看不了，或者没有差异时是 null。 */
     diff: string | null;
     /** 看不了的原因，或者要提醒用户的话。没有就是 null。 */
     note: string | null;
   }
   export interface TaskChanges {
     /** 按路径排序，最多 50 个。 */
     files: TaskChangedFile[];
     /** 改动文件的总数。 */
     total: number;
   }
   ```

2. **核心层**（新文件 `packages/core/src/execution/taskChanges.ts`，从核心包出口导出）：

   ```ts
   export function readTaskChanges(db: CoreDatabase, task: CodingTask): TaskChanges;
   ```

   - 改动文件清单取执行报告（`executor_report_json`）的 `changedPaths`：过一遍 `normalizeRel`，去重，按路径排序。
   - 比的是**副本里现在的文件**（`task.workspace_path` 下）和**项目文件夹里现在的文件**（`projects.root_path` 下）。
   - 任务没有副本、没有执行报告、`changedPaths` 是空的 → `{ files: [], total: 0 }`，不报错。

3. **每个文件怎么定**：

   | 情况                                        | kind       | diff                 | note                                                 |
   | ------------------------------------------- | ---------- | -------------------- | ---------------------------------------------------- |
   | 项目里没有，副本里有                        | `added`    | 每行以 `+` 开头      | 无                                                   |
   | 项目里有，副本里没有                        | `deleted`  | 每行以 `-` 开头      | 无                                                   |
   | 两边都有，按行比有不同                      | `modified` | 见契约 4             | 无                                                   |
   | 两边都有，内容一模一样                      | `same`     | null                 | 和项目里现在的文件一样（可能已经合并过了）           |
   | 两边都有，只差行尾的 `\r` 或文件末尾的换行  | `same`     | null                 | 只有换行符不同                                       |
   | 两边都没有                                  | `unknown`  | null                 | 项目里和副本里都没有这个文件                         |
   | 路径是绝对路径、带 `..`、是空的             | `unknown`  | null                 | 路径不合规（**这种路径一个文件都不读**）             |
   | 文件名是密钥类（`FORBIDDEN_NAME`）          | `unknown`  | null                 | 密钥类文件，不显示内容（**不读**）                   |
   | 路径上有链接，或者文件本身是链接（任一边）  | `unknown`  | null                 | 是链接，不显示（**不读**）                           |
   | 任一边不是普通文件（比如是目录）            | `unknown`  | null                 | 不是普通文件                                         |
   | 任一边超过 256 KB                           | 照实       | null                 | 文件太大，不显示差异（**不读内容**，只看大小）       |
   | 任一边是二进制（开头 8 KB 里有 NUL）        | 照实       | null                 | 二进制文件，不显示差异                               |
   | 任一边超过 2000 行                          | 照实       | null                 | 行数太多，不显示差异                                 |

   「照实」：两边在不在看得出来，就按 `added` / `deleted` / `modified` 写。

   另外两条：

   - **没有授权就不读项目里的文件。** 判断和落地同一条（`landing.ts`）：项目有 `root_path`、那个目录还在，而且它在某条有效的文件夹授权之内。不满足（没绑文件夹、目录没了，或者授权撤销了）→ 每个文件都是 `unknown`、diff null、note「没有这个项目文件夹的读取授权，不显示内容」，副本里的也不读。
   - **基准变没变。** 执行报告的 `baseHashes[path]` 是任务开始时这个文件的指纹（换行归一成 LF 之后的 SHA-256，新文件是 null；用 `landing.ts` 导出的 `toLf`）。报告里有这一项，而项目里现在的文件按同一算法算出来不一样（原来有现在没有、原来没有现在有，也算不一样）→ 差异照给，note 写「项目里的这个文件在任务开始之后变过，下面是和现在的文件比的」。只对给得出差异的文件做这个核对：上表里 diff 是 null 的（看不了的、`same` 的）不做、不写这句。

4. **差异正文的格式**：

   - 一行一条，第一个字符是 `+`（新加的）、`-`（去掉的）或空格（没变的），后面跟这一行的内容，行与行之间用 `\n` 连。
   - 只出有改动的段。每段前后各带最多 3 行没变的；两段带上的行连上了或重叠了，并成一段。段与段之间隔一行 `@@`。
   - 比较按行。行尾的 `\r`、文件末尾有没有换行都不算差异，输出里也不带 `\r`。
   - 算法自己写，按行求最长公共子序列就行。不加 npm 依赖，不起进程。

5. **上限**：`files` 最多 50 个（`total` 是总数）。差异正文合计超过 200 000 字符之后，后面的文件 diff 是 null，note「改动太多，后面的不显示差异」。

6. **IPC**：`getCodingTaskChanges(id: string): Promise<TaskChanges>`。三处照现有的写法加：`packages/contracts/src/ipc.ts`、`apps/desktop/src/main/ipc.ts`、`apps/desktop/src/preload/index.ts`。任务不存在照 `store.get` 现有的方式报错。

7. **界面**（`apps/desktop/src/renderer/src/pages/Tasks.tsx`）：

   - 执行报告里 `changedPaths` 不是空的任务，卡片上显示「改了 N 个文件」和一个按钮「看改动」（`data-testid="task-changes-toggle-<任务号>"`）。
   - 点了调 IPC，在卡片里（`data-testid="task-changes-<任务号>"`）列出每个文件：路径、种类（新增 / 修改 / 删除 / 没有变化 / 看不了）、note、差异。差异用 `<pre>`，`+` 行和 `-` 行颜色不同。`total` 比列出来的多时写一句「共 N 个，只列了前 50 个」。
   - 按钮变成「收起」，再点收起。再点开重新读一次。
   - 读取出错：错误显示在这张卡片里，不用整页顶上的报错条。
   - `changedPaths` 是空的、或者没有执行报告的任务：不显示这一行和按钮。

## 约束

- 只读。不改项目文件夹和副本里的任何文件，不起子进程，不联网，不把内容发给模型。
- 从副本根、项目根一段段往下看，不跟链接（写法参照 `modelExecutor.ts` 的 `checkChange`）。
- 不加迁移，不加 npm 依赖。
- **不动 `executor.ts`**（D5a 正在改它）。要的东西都有现成的导出：`normalizeRel`（`patchPack.ts`）、`toLf`（`landing.ts`）、`FORBIDDEN_NAME`（`workspaceCopy.ts`）、`isPathInside`（`paths.ts`）。
- 测试、交付说明里的文件内容用合成的。

## 验收条件

1. 改了一个已有的文件：`modified`；diff 里有去掉的行（`-`）和新加的行（`+`）；离改动 3 行以外的没变的行不出现；相隔很远的两处改动分成两段，中间有一行 `@@`；挨着的两处改动并成一段。
2. 新加的文件：`added`，每行以 `+` 开头，内容齐全。
3. 删掉的文件：`deleted`，每行以 `-` 开头。
4. 副本和项目里一样：`same`，diff 是 null，note 写明。
5. 只差 CRLF / LF、只差末尾换行：`same`，note 写「只有换行符不同」；内容真有改动的文件，CRLF 和 LF 混着也只出真改动的行。
6. 看不了的每一种（路径带 `..`、绝对路径、密钥类文件名、链接、不是普通文件、超过 256 KB、二进制、超过 2000 行）：diff 是 null，note 写原因。用带标记的内容验证：**项目里那个文件的内容不出现在返回值里**。
7. 没有授权（项目没绑文件夹；授权撤销了）：diff 全是 null，note 写明没有授权，项目里和副本里文件的内容都不出现在返回值里。
8. 基准变过：任务开始之后项目里的文件被改了 → 差异照给，note 写明是和现在的文件比的。没变过的不写这句。
9. 上限：改动超过 50 个文件只列 50 个，`total` 是总数；差异合计超过 200 000 字符之后的文件不给差异、note 写明。
10. 没有副本、没有执行报告、`changedPaths` 是空的：返回空清单，不报错。
11. IPC：`registerIpc` 注册了 `getCodingTaskChanges`，调它得到的和 `readTaskChanges` 一样；不存在的任务报错。预加载和接口类型也接上（少接一处，类型检查过不了）。
12. 界面：有改动的任务显示「改了 N 个文件」和「看改动」；点开列出文件、种类、note、差异；再点收起；读取出错显示在卡片里；没有改动的任务不显示。
13. 只读：调用前后，项目文件夹和副本里每个文件的指纹不变。

## 真机检查

`scripts/real/u3-task-changes.mjs`，照 `scripts/real/u2-tasks-page-live.mjs` 的做法（临时数据目录、`IXAEON_CODEX_EXE=none` 用替身执行器、合成的 git 项目，里面放一个有十来行字的 `note.txt`）：

1. 建一个任务（替身执行器会把 `note.txt` 改写掉），等它做完。
2. 打开任务页点「看改动」，打印：列出几个文件、每个文件的种类、差异里 `+` 行和 `-` 行各多少。
3. 点「接受」，再点开一次，打印同样的东西（这时分支建好了但没合并，差异应当还在）。
4. 在合成项目里把那个分支合并进来，再点开一次，打印（应当是「没有变化」）。
