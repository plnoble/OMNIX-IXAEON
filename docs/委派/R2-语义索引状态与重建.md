# 委派单 R2（余项）：语义索引的状态、重建与及时补向量

任务来源：[三周任务单](../三周任务单.md) R2。大小：**小（≤150 行改动）**。

## 背景

聊天选记忆时会先用本机 Ollama（`qwen3-embedding:0.6b`）算「意思像不像」。现在的两个缺口：

1. 新资料分析出的记忆要等**下一次提问**才补向量；
2. 用户看不到索引状态：补了多少、Ollama 没开时为什么退回了关键词、想重建也没有入口。

相关代码：`packages/core/src/memory/semanticIndex.ts`（`backfill()`、`coverage()`），`apps/desktop/src/main/appRuntime.ts`（`semanticIndex`、`kickSemanticBackfill()`，失败时只记一次日志，带 `reasonCode`）。

## 契约（已定死）

```ts
// packages/contracts/src/ipc.ts 的 IxaIpcApi 新增
getSemanticIndexStatus(): Promise<{
  enabled: boolean;          // IXAEON_EMBED_MODEL=none 时 false
  model: string | null;      // 如 'ollama:qwen3-embedding:0.6b'
  indexed: number;
  total: number;
  lastError: string | null;  // 最近一次补向量失败的原因（给人看的中文），成功后清空
}>;
rebuildSemanticIndex(): Promise<{ embedded: number; remaining: number }>;
```

## 要做的

1. 提取任务成功后立刻 `void this.kickSemanticBackfill()`（`appRuntime.ts` 注册 `extract` 任务处理器的末尾）。
2. `kickSemanticBackfill()` 失败时把原因存进运行时（替换现在的只记日志），成功时清空；`getSemanticIndexStatus` 读它。
3. `rebuildSemanticIndex`：删掉**当前模型**的全部向量（`DELETE FROM item_embeddings WHERE model = ?`），再补一遍。别的模型的向量不动。
4. 设置页新增卡片「语义检索（本机）」：显示「已建 N / M 条」、模型名、`lastError`（有才显示）、「重建」按钮（进行中禁用并显示「正在重建…」）。Ollama 没开时的提示文案：「本机向量服务没开，聊天会退回按关键词选记忆。开着 Ollama 后点重建。」

## 验收条件（写死）

1. 集成测试（用 `packages/core/test/integration/hybrid-memory-eval.test.ts` 里的 `TableEmbedder` 写法做假向量服务）：
   - `getSemanticIndexStatus` 的 `indexed/total` 与实际一致；
   - 重建后当前模型的向量全部重算，另一个模型名下的向量行数不变；
   - 向量服务抛错时 `lastError` 有中文原因，下次成功后变回 `null`；
   - 提取任务成功后会触发补向量（spy 断言被调用）。
2. `IXAEON_EMBED_MODEL=none` 时状态为 `enabled:false`，重建直接返回 `{ embedded: 0, remaining: 0 }`，不报错。
3. `node scripts/verify.mjs` 全过。

## 不要做

- 不改选材规则、阈值、向量表结构。
- 向量服务地址只能是本机（`OllamaEmbedder` 已强制），不要加任何可配置的远程地址。
