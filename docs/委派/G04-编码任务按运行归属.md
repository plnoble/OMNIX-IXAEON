# 规格 G04：编码任务记住是哪一轮提问产生的，不再按时间猜

档位：**B**（决定哪个编码任务出现在哪次对话里、被谁批准）。大小：小（≤120 行源码）。依赖：迁移 35（整合方已加 `coding_tasks.origin_run_id`）。来源：[全局审核 2026-09-20](交付/全局审核-2026-09-20.md) G04。
v2 规格：先把验收条件写成测试（`apps/desktop/test/acceptance/g04-*.test.ts`），**先只推测试**等整合方看过并锁定，再实现。

## 要什么

提问答完后，`AppRuntime.ask()` 用「创建时间晚于本轮开始、且有项目」的全局查询找这一轮产生的编码任务，把它们变成回答下面的待办卡。没有限制到本轮运行、本对话，甚至本项目。对话 A 在等回答时，对话 B 建的任务会被当成 A 的建议——你可能在错误的对话里批准一个真实的编码任务。

这是整合方 T2b 规格里写的「沿用现有查询」留下的缺口，不怪执行方。

## 契约

1. 迁移 35 已加 `coding_tasks.origin_run_id`（**不要再加迁移**）。
2. `propose_task`（`packages/core/src/runtime/broker.ts`）建任务时写上这次调用的 `ctx.runId`。
3. `ask()` 找这一轮的任务改成按 `origin_run_id = 本轮 runId`，删掉时间窗口查询。
4. 没有 `origin_run_id` 的任务（旧数据、任务页手动建的）不会出现在任何一轮回答上。

## 约束

- 不改编码任务的执行、批准、验收流程；不改 T2b 的「拍板即批准」规则。

## 验收条件

1. 对话 A 等回答时，另一个运行（对话 B、项目 B）建了一个任务：A 的回答里没有它，B 的回答里有。
2. 同一个项目两轮并发，各自建了任务：各归各的，不串。
3. A 这一轮自己建的任务照常出现在 A 的回答上，并照 T2b 进待办（T2b 的锁定验收照过）。
4. 没有 `origin_run_id` 的旧任务不出现在任何回答上。

## 真机检查

不需要：纯本地归属，受控替身覆盖。交付里写「规格不要求真机检查」。
