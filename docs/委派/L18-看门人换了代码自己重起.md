# 委派单 L18：看门人换了代码自己重起（`relay forever`）

档位：**A**（调度器自己的进程管理；不放开权限、不碰用户数据、没有新的外发）。大小：小（约 80 行源码）。依赖：L16（L16 也改 `relay-main.ts` 的看门人，等它并入再做，免得冲突）。来源：接力第 29 棒（规划棒），[三周任务单](../三周任务单.md)「接下来一周」第 2 件。

## 要什么

`relay run`（看门人）每一轮会把 `<工作目录根>/relay-run` 换到最新 `origin/main`，所以**每一棒**用的都是新代码；但看门人进程**自己**的代码是它起来时那一份，L11、L16 这种改看门人的单子并入后，要用户手动停掉再起。改成：

1. 新命令 `relay forever`：一直起 `relay run`；`relay run` 用一个专门的退出码（75）退出时马上再起一个，别的退出码照原样退。
2. 在 `relay forever` 底下跑的看门人，每一轮换完代码之后、起下一棒之前，比一比 `relay-run` 里看门人那层的代码和自己起来时的是否一样；不一样就用 75 退出。
3. README 让用户以后起 `relay forever`。

## 为什么

接力要一直转，用户不在电脑前。看门人这一层的改动并入后不生效、要用户回来手动重起，跟 L10 解决的「每棒用最新代码」是同一件事的最后一截。

## 契约（接口写死）

1. **`relay forever`** 写在 `packages/relay/bin/relay.mjs` 里，在找 jiti **之前**分出去（它自己不用 jiti、不读配置、不拿锁，所以它本身永远不需要换新）：
   - 要起的入口：`<工作目录根>/relay-run/packages/relay/bin/relay.mjs` 在就用它，不在就用自己这一份（第一次起时 `relay-run` 还没建）。工作目录根照 `packages/relay/src/datadir.ts` 的 `worktreesRoot()` 算（`IXAEON_WORKTREES` 优先；在 `.mjs` 里照写一份，不 import TS）。`IXAEON_RELAY_CODE` 有值时入口就是 `<IXAEON_RELAY_CODE>/packages/relay/bin/relay.mjs`。
   - 起法：`process.execPath <入口> run <forever 后面的其余参数>`，`cwd` 是入口所在的那份仓库根，`stdio: 'inherit'`，环境变量多一个 `IXAEON_RELAY_FOREVER=1`。
   - 子进程退出码 75 → 打一行 `relay run 的代码换了，重起`，马上再起（每次重新挑入口）；别的退出码 → `relay forever` 用同一个码退出。
   - 防转圈：10 分钟里第 6 次碰上 75 → 打 `10 分钟里重起了 6 次，停下：看门人的代码和 relay-run 里的对不上`，退 1。
2. **看门人这边**（`relay-main.ts` 的 `watchdog`）：
   - 只在 `IXAEON_RELAY_FOREVER=1`、并且没设 `IXAEON_RELAY_CODE` 时做；别的情况行为一点不变（直接起 `relay run` 的人不受影响）。
   - 「看门人那层的代码」= 一份仓库里 `packages/relay/bin/` 和 `packages/relay/src/` 下所有文件，按相对路径（`/` 分隔）排序，逐个把「路径 + `\0` + 内容」喂进 sha256，得到的十六进制串。起来时对**自己所在的仓库**（`REPO_ROOT`）算一次；之后每一轮在 `updateCodeCheckout`、`ensureDeps` 都成功之后、起 `once` 之前，对 `relay-run` 算一次。
   - 两个不一样 → 打 `看门人自己的代码换了（<旧的前 8 位> → <新的前 8 位>），退出让 relay forever 重起`，`process.exitCode = 75` 后返回（照文件末尾那条：不用 `process.exit`）；锁照常在 `finally` 里放掉。
   - 这一轮 `updateCodeCheckout` 有 `note`（没换成）或拉不下来 `origin/main` 时不比、照常起棒。
3. 函数 `relayCodeHash(root: string): string` 放在 `packages/relay/src/selfupdate.ts`，从 `src/index.ts` 导出（测试直接测它）。
4. 75 这个数写成 `selfupdate.ts` 里导出的常量 `RESTART_EXIT_CODE`；`relay.mjs` 里写同一个数，旁边注释指过去。

## 约束

- 只改 `packages/relay/`（含 `README.md`：「怎么起」一节改成 `relay forever`，写清 `relay run` 照样能用、只是看门人那层换代码要手动重起；L10 那条开机自启的命令跟着改成 `forever`）。
- 已锁定的测试一个字不改。`l10-watchdog`、`l16-watchdog` 等照过（它们设了 `IXAEON_RELAY_CODE` 或没设 `IXAEON_RELAY_FOREVER`，行为不该变）。
- 不建计划任务、不改系统设置。

## 验收

新测试 `packages/relay/test/acceptance/l18-forever.test.ts`（看门人那几条照 `l10-watchdog.test.ts` / `l10-harness.ts` 的合成仓库做法）：

1. `relayCodeHash`：同样的文件两次算出来一样；改 `src/` 下一个文件的一个字、在 `bin/` 下加一个文件、改一个文件名，各自都变；改 `packages/relay/test/` 下或 `packages/relay/README.md` 不变。
2. 看门人在 `IXAEON_RELAY_FOREVER=1`、没设 `IXAEON_RELAY_CODE`：合成 `origin/main` 上看门人那层的代码和它自己所在的仓库不一样 → 退出码 75、输出含 `看门人自己的代码换了`、**这一轮没起 `once`**（记账没有新的一棒）、锁文件放掉了。
3. 同 2，代码一样 → 照常起棒（记账有这一棒），不以 75 退。
4. 没设 `IXAEON_RELAY_FOREVER` → 代码不一样也照常起棒（和现在一样）。
5. `relay forever`，入口用替身（`IXAEON_RELAY_CODE` 指到一个临时目录，里面 `packages/relay/bin/relay.mjs` 是替身：第 1、2 次被起时退 75，第 3 次退 4，每次把收到的参数和 `IXAEON_RELAY_FOREVER` 记进文件）→ `relay forever --exit-when-idle` 退 4；替身被起了 3 次，每次参数是 `run --exit-when-idle`、`IXAEON_RELAY_FOREVER` 是 `1`；输出里 `relay run 的代码换了，重起` 正好 2 行。
6. 替身一直退 75 → `relay forever` 退 1，输出含 `重起了 6 次，停下`，替身被起了 6 次。
7. 替身退 0 → `relay forever` 退 0、替身只被起 1 次。

## 真机检查

`scripts/real/l18-forever.mjs`（照 `scripts/real/l10-watchdog.mjs`：临时裸仓库当 `origin`、`IXAEON_WORKTREES` 指到临时目录、角色用替身，**不碰用户真实的 `relay-run` 和数据目录**）：起 `relay forever --exit-when-idle`；第一轮跑完一棒后往临时 `origin/main` 推一笔只改 `packages/relay/src/` 里一行注释的提交；核对输出里先有 `看门人自己的代码换了`、再有 `relay run 的代码换了，重起`，第二个看门人的进程号和第一个不一样，最后退 0。每步不符打「结论：不通过」退 1，遮掉临时目录。原样输出贴进交付说明。另外写一句：`relay-run` 里正跑着的看门人自己换 `relay-run` 的依赖（`ensureDeps`）在 Windows 上有没有撞上文件被占——真机上看到了就写下来，转整合方。
