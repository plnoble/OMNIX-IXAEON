# 规格 U4：对话里的回报，点一下就到那条任务

档位：**A**（只改页面之间怎么跳；不改回报的文字，不改任务流程）。大小：小（≤100 行源码）。依赖：U3。来源：整合方 2026-10-05 查任务页时发现。

v2 规格：验收条件写成测试（`apps/desktop/test/acceptance/u4-*.test.ts`），测试和实现一起交，Codex 审查时核对有没有漏条件。

## 要什么

任务做完，对话里出现一段回报：「……做完了，等你验收。……去任务页看改动，点接受。」这是一段纯文字。用户得自己点左边的「任务」，再在一串卡片里找到这一条（任务多了要往下翻）。

这一单：回报消息下面加一个按钮，点了就到任务页，页面停在这条任务上，改动已经展开（U3 做的「看改动」）。

## 契约（接口写死，不改名、不加字段）

1. **按钮**（`apps/desktop/src/renderer/src/pages/AskMessage.tsx`）：消息的 `meta.kind === 'task_report'`、`meta.taskId` 是字符串时，消息下面显示按钮「到任务页看这条任务」，`data-testid="task-report-open-<任务号>"`。回报的每一种都显示（等你验收、没做成、取消了、落地结果、缺执行器……）。别的消息不显示。

2. **怎么跳**（`App.tsx`，照 `openConversationId` 的现成写法）：

   ```ts
   /** 要任务页停在哪条任务上。每点一次按钮给一个新的对象。 */
   interface TaskFocus {
     taskId: string;
     /** 点按钮的时刻（Date.now()），同一条任务连点两次也能再生效。 */
     at: number;
   }
   ```

   - `AskPage` 多一个属性 `onOpenTask: (taskId: string) => void`，一路传给 `AskMessage`。
   - 点按钮 → `App` 记下 `{ taskId, at: Date.now() }`，切到任务页。
   - `TasksPage` 多一个可选属性 `focus?: TaskFocus | null`。

3. **任务页怎么停**（`Tasks.tsx`）：收到 `focus`、任务清单读回来之后，对那条任务做一次：

   - 卡片滚进视野（`scrollIntoView`）；
   - 它有改动的话，「看改动」是展开的（和用户自己点开一样，读一次 `getCodingTaskChanges`）。

   `focus` 换了新的对象（`at` 变了）就再做一次。那条任务已经不在了（删掉了）：页面照常显示，不报错、不提示。

## 约束

- 回报的文字一个字不改（`taskReport.ts` 不动；D1、D3、D7b 的锁定测试照过）。
- 不加 IPC，不加迁移。
- 用户自己从左边点「任务」进来的：和现在一样，不滚、不自动展开。

## 验收条件

1. 回报消息下面有这个按钮，`data-testid` 带任务号；普通的回答、用户说的话下面没有。
2. 点按钮：切到任务页；那条任务的卡片调了 `scrollIntoView`；它的改动是展开的，`getCodingTaskChanges` 以这个任务号调了一次。
3. 那条任务没有改动（`changedPaths` 是空的）：照样切过去、滚到它，不调 `getCodingTaskChanges`。
4. 那条任务已经删掉：切到任务页，页面正常，不报错。
5. 回到对话再点同一个按钮：又滚一次、改动又是展开的（哪怕中间用户把它收起了）。
6. 从左边导航进任务页：不滚、不自动展开任何一条。
7. 回报的文字没变（现有的回报测试照过）。
