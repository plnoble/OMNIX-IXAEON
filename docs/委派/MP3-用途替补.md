# 规格 MP3：聊天和后台分析各自一串替补，这一个不行换下一个（MP3 / MP3b）

档位：**B**。替补会把同一份问题和上下文发给另一家供应商（用户自己配的），发给模型的东西去哪变了。大小：拆两支，各自源码不超过 300 行。

- **MP3**：配置、主进程、IPC，不动界面，约 220 行；
- **MP3b**：「模型」页「用途」那一块加替补列表，聊天里显示「这次是替补答的」，约 150 行。

依赖：队列第 163 行（MP2 / MP2b）、第 162 行（CF3c）已并入。

来源：用户 2026-11-03（[三周任务单](../三周任务单.md)「模型池」一节）：

- 「每个用途是一个有顺序的列表，额度用完或连不上就换下一个」；
- 「不自己做 magpie / newapi……IXAEON 只做『这一个不行换下一个』」。

**这一单只管聊天和后台分析两个用途。** 编码任务、开发、审查、整合要选「开发工具 + 模型」（Claude Code / Codex / DSH），一起放到下一单 MP3c（队列第 165 行，规格另写），这一单不碰 `uses.coding`、不碰驾驶舱的调度器面板。

## 为什么

现在聊天、后台分析各自只能选一个模型。那家额度用完、网关没开、Key 过期，聊天直接失败，后台分析整批停下，要等用户发现了再去换。用户想要的是事先排好顺序，第一个不行自动用第二个，并且告诉他这次是谁答的。

## 要什么

### MP3（配置 + 主进程 + IPC）

1. **替补存在新的 `config.fallbacks`**，`uses` 和旧字段一个不改：
   - 主选还是 MP2 那套（`uses.<用途>` 或旧字段）；替补是主选之后按顺序排的列表，每个用途最多 4 项。
   - 每一项是 `{ providerId, model }`，`providerId` 可以是 `default`。只能选那一家勾选保存过的模型，否则拒绝。
   - 同一个列表里不能有重复；也不能跟这个用途现在的主选相同。两种都拒绝，提示写明是哪一项。
   - 保存时传了哪个用途就整个换掉哪个用途的列表，传空数组等于清空；没传的不动。
2. **按顺序取一串候选**，规则只写在一处：`resolveModelUseChain(config, use)`，跟 `resolveModelUse` 放在同一个文件里。
   - 第一个是 `resolveModelUse(config, use)` 的结果，后面依次是 `fallbacks[use]` 里的各项。
   - 解析不出来的跳过：那家没了、那家没 Key。主选解析不出来，就从第一个能解析的替补开始。
   - 按「哪家 + 哪个模型」去重，保留先出现的。
   - **聊天没单独选过的**（`uses.chat` 没有，`chatModelName` 也是空的）：整串跟着后台分析走，包括后台分析的替补。聊天自己的替补列表这时不生效。
   - 一个都解析不出来：返回空数组。对用户来说跟今天「没配模型」一样。
3. **什么算「不行」**：调用还没给出任何一个字就出错，并且是下面几种之一，才换下一个：
   - 连不上或超时（没有 HTTP 状态、`retriable` 为真）；
   - HTTP 401、403（Key 不对或没权限）；
   - HTTP 402、429（额度用完、被限流）；
   - HTTP 5xx（那家服务出错）。

   下面几种**不换**，照今天的样子收尾：
   - 用户取消；
   - 其他 4xx，包括「不支持工具调用」那种 400（它已经有自己的降级）；
   - 已经流出过正文之后才出错（不能换个模型把半句话接上）。

   为了分得清，`ModelError` 加一个可选的 `status`（HTTP 状态码）。凡是现在由 HTTP 响应生成 `ModelError` 的地方，都把状态码带上。测试用的 `FakeStreamChatClient` 剧本每一步可以多写一个 `status`，抛出的 `ModelError` 带上它（端到端要靠它造 429）。

4. **后台分析**：`getProvider()` 按第 2 条的那一串，依次建 `OpenAIResponsesProvider`。
   - 只有一个候选时，返回的就是它本身，跟今天一样。
   - 两个以上时包一层：某个候选按第 3 条「不行」，就试下一个。
   - 全不行时，抛最后一个错误，交给后台任务现有的重试和失败处理。
   - 每次换都记一条日志：用途、从哪家哪个模型换到哪家哪个模型、原因（状态码或「连不上」）。不记地址、Key、提示词。
5. **聊天**：直连按同一串依次建客户端，建客户端仍然走 `chatStreamClient(launch)`。测试照 CF3c 的接缝换假客户端，不另开接缝。
   - 某个候选按第 3 条「不行」，这一问换下一个。换过之后，这一问后面几轮工具调用都用换上的那个，不回头。
   - 记下这一问实际是谁答的：回答消息 `meta.modelName` 写实际答的模型。
   - 答的不是第一个候选时，`meta.notice` 写：「「<供应商名> · <模型>」这次不行（<原因>），由替补「<供应商名> · <模型>」回答」。原因只用这四种说法：额度用完、Key 不对或没权限、服务出错、连不上或超时。跳过了几个就写第一个跳过的。
   - 全不行：这一问照今天失败的样子收尾（failed、不存档）。错误说明逐个列出试过的候选和各自的原因，例如「「A · x」：额度用完；「B · y」：连不上或超时」。
6. **短时间记住不行的那个**：某个候选因第 3 条「不行」被换掉，这个用途接下来 5 分钟内都把它排到最后再试，不是删掉。
   - 只记在内存里，不落盘。重启，或者保存了用途、替补、供应商，都清空。
   - 这一串全在 5 分钟里头：照原来的顺序全部再试一遍，不因为「都不行过」就不发请求直接失败。
7. **删除供应商**：别的家被某个用途的替补用着，照 MP2 第 7 条拒绝，提示写明是谁在用（例如「聊天的替补在用它，先在用途里换掉」）。
8. **审计**：保存替补记一条，只记用途和项数，不记模型名之外的东西。

### MP3b（界面）

9. **「模型」页「用途」那一块**：后台分析、聊天两个用途下面，各加一个「替补（这一个不行按顺序换下一个）」列表。
   - 每项显示成「供应商名 · 模型」，有「上移」「下移」「删掉」三个按钮。
   - 列表下面有一个下拉框加「添加」按钮。选项是所有供应商勾选过的模型，去掉现在的主选和已经在列表里的。满 4 项时「添加」不能点。
   - 和主选共用那个「保存」按钮，一次存主选和替补。保存失败把主进程给的提示原样显示出来。
   - 聊天选「跟着后台分析」时，聊天的替补列表收起，原地写一行「跟着后台分析，替补也用后台分析的」。
10. **聊天里**：回答带第 5 条那句 `meta.notice` 时，照现有的提示样式显示在这条回答下面，不弹窗。
    - 实际答的模型名，照现有显示模型名的地方显示实际那一个。

## 契约（写死，不改名、不加字段）

```ts
// packages/contracts/src/config.ts：appConfigSchema 加一项（有默认值，旧配置照样能读）
fallbacks: z
  .object({
    analysis: z.array(modelChoiceSchema).max(4).optional(),
    chat: z.array(modelChoiceSchema).max(4).optional(),
  })
  .default({}),

// packages/contracts/src/ipc.ts：IxaeonApi 加一个方法；SettingsView.settings 加一项
saveModelFallbacks(input: {
  analysis?: Array<{ providerId: string; model: string }>;
  chat?: Array<{ providerId: string; model: string }>;
}): Promise<{ ok: true }>;
// SettingsView.settings：
fallbacks: { analysis?: Array<{ providerId: string; model: string }>; chat?: ... }  // 原样回给界面

// packages/core/src/models/resolveModelUse.ts
export function resolveModelUseChain(config: AppConfig, use: 'analysis' | 'chat'): ResolvedModelUse[];

// packages/core/src/extraction/model/provider.ts
export class ModelError extends Error {
  constructor(message: string, readonly retriable: boolean, readonly status?: number) { … }
}

// packages/core/src/runtime/chatStream.ts：FakeStreamChatClient 剧本的一步
{ deltas?: string[]; toolCalls?: ChatToolCall[]; error?: string; status?: number }
```

IPC 通道名 `ixaeon:saveModelFallbacks`，照现有的写法在 `registerIpc` 和 preload 里注册。

## 约束

- 不动 `uses.coding`、`coding.*`、编码任务的执行器、驾驶舱的调度器面板和接力配置（这些归 MP3c）。
- 不发任何新的请求：替补就是对另一家已配好的供应商发同样的调用。不探测、不预热、不查额度。
- 不改提示词，也不改发给模型的内容。换到替补时发的是同一份消息。
- 不加迁移（全在 config.json 里，有默认值）。
- 公开仓库：测试里的地址只用 `127.0.0.1` 加端口，Key 用合成的，模型名用 `demo-a`、`demo-b` 这类。

## 验收条件

1. `saveModelFallbacks`：
   - 合法的列表存进 `config.fallbacks`，`getSettings()` 原样读回来。
   - 下面几种都拒绝，配置不变：没勾选过的模型、不存在的供应商、超过 4 项、有重复、跟主选相同。
   - 只传 `chat` 时 `analysis` 的列表不变；传空数组清空。
2. `resolveModelUseChain`：
   - 顺序是主选在前，替补依次在后。
   - 主选那家没了或没 Key 时，从第一个能解析的替补开始。
   - 去重。
   - 聊天没单独选过：整串等于后台分析那一串，聊天自己的替补不生效。
   - 一个都解析不出来：返回空数组。
3. **聊天换替补**：两家都用本机 `127.0.0.1` 的合成地址。主选的假客户端分别抛 429、401、5xx、连不上（各测一次），替补正常回答：
   - 这一问 complete、照常存档；
   - `meta.modelName` 是替补的模型；
   - `meta.notice` 是第 5 条那句，原因分别是额度用完、Key 不对或没权限、服务出错、连不上或超时；
   - 替补客户端收到的消息跟主选收到的一样。
4. **聊天不换**：主选抛一般的 400、用户取消、流出过正文之后才出错：三种都不调替补，收尾跟没有替补时一样。只有一个候选时，行为跟 MP3 之前完全一样，现有锁定测试不用改。
5. **聊天全不行**：两个候选都「不行」：这一问 failed、不存档，错误说明里两个候选和各自的原因都在。
6. **一问之内不回头**：主选第一轮就不行、换了替补之后，这一问后面几轮工具调用都发给替补，主选只被调过一次。
7. **记住 5 分钟**：主选不行、换过一次之后，同一用途下一问先试替补。把时间往后拨过 5 分钟（假时钟），又先试主选。保存一次用途或替补，立刻恢复先试主选。整串都在 5 分钟里时，下一问照原顺序全部再试，不会不发请求直接失败。
8. **后台分析换替补**：起两个本机 HTTP 假服务，第一个回 429（或直接关掉端口），第二个正常回答。后台分析一条导入的合成资料：
   - 提炼成功，条目来自第二个；
   - 日志里有一条「换替补」，带两边的供应商和模型、原因；
   - 日志里没有地址、Key、提示词。

   两个都不行：后台任务照现有的失败处理走，不建条目。

9. **删供应商**：某家被聊天或后台分析的替补用着，`deleteModelProvider` 拒绝，提示写明是哪个用途的替补。
10. **`ModelError.status`**：聊天客户端和后台分析的客户端收到 HTTP 错误时，`status` 等于那个状态码；连不上、超时时没有 `status`。
11. **界面（MP3b）**：
    - 「用途」里两个替补列表能添加、上移、下移、删掉，保存后刷新页面顺序不变；
    - 满 4 项时「添加」不能点；
    - 下拉框里没有主选和已在列表里的；
    - 聊天选「跟着后台分析」时，替补列表收起，显示那一行说明；
    - 保存被拒时，主进程的提示原样显示；
    - 聊天里，带替补提示的回答下面显示那句话。
12. **端到端**（MP3b，`apps/desktop/e2e/`）：用 `IXAEON_FAKE_MODEL` 的假聊天剧本，让第一个候选回 429、第二个正常回答。在「模型」页配好替补，问一句，对话里出现替补答的回答和那句提示。

## 真机检查

- MP3：`scripts/real/mp3-fallback.mjs`。脚本在本机起两个假 OpenAI 兼容服务：一个回 429，一个正常流式回答。用临时数据目录配两家供应商、排好替补，各问一次聊天、跑一次后台分析，只打印：
  - 每次实际答的是第几个候选；
  - 换了几次；
  - 提示句子的样子（模型名是合成的，可以打印）。

  临时目录路径要遮掉。不连任何外网。

- MP3b：设 `IXAEON_DATA_DIR=<临时目录>` 启动应用，在「模型」页配两家合成供应商（地址指向上面那两个假服务），排好替补，问一句。描述或截图：替补列表、聊天里那句提示。
