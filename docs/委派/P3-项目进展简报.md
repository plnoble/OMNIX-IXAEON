# 规格 P3：聊天时带上「项目近况」，问「做到哪了」答得对

档位：**B**（改变发给模型的内容）。大小：中（≤300 行，超了就把界面那条拆出去）。依赖：S1、S2（已完成）。
v2 规格：你先把验收条件写成测试（`packages/core/test/acceptance/p3-*.test.ts`，需要界面的放 `apps/desktop/test/acceptance/`），**先只推测试**等整合方看过并锁定，再实现。

## 要什么

场景一的第二步：用户在聊天里选了一个项目，问「这个项目做到哪了」「上次卡在哪」「接下来该做什么」，IXAEON 要答得出来。现在给模型的只有精选的 8 条记忆（零散的事实），没有时间线。

做法：对话选了项目时，派给 Hermes 的这一轮在记忆之后再带一段「项目近况」，由代码现查、现拼：

1. **最近的提交**：项目登记了目录、并且**已经做过目录登记读取**（有这个项目的 `project_snapshot` 来源）时，实时跑 `git -C <根目录> log --since=14.days -n 20 --pretty=format:%ad %s --date=short`。只读，超时 10 秒；不是 git 仓库、失败就跳过这一块。
2. **最近的编码代理会话**：这个项目下 provider 为 `coding_agent` 的来源，按时间最新的 5 个：标题、日期、这个会话里最后一句用户的话（前 100 字）。
3. **编码任务**：这个项目的编码任务，最新的 5 个：目标第一行、状态（中文，同待办页的对照表）。

## 契约

- 新函数放 `packages/core/src/runtime/projectBrief.ts`：`buildProjectBrief(db, projectId, opts?)` 返回 `{ block: string; counts: { commits: number; sessions: number; tasks: number } }`；`block` 为空串表示没什么可带的。整段最长 2000 字。超了先截提交这一块，从最旧的一条截起；提交截光了还超，再截会话（最旧的先截），最后才截任务。`counts` 是实际带上的条数。
- `session.ts` 的 Hermes 路径：有 `projectId` 且 `block` 非空时，接在记忆那段后面。Core 兜底路径不加。
- 这一轮回答的 `meta.projectBrief = counts`（有带才写）。回答下面（记忆那行附近）一行灰字：「本轮给模型看了项目近况：N 条提交、M 个会话、K 个任务」。

## 约束

- **登记读取是门槛**：没做过目录登记读取的项目不跑 git（用户登记时就同意了把 git 摘要交给模型分析，这里不扩大范围）。会话和任务本来就是 IXAEON 里已经分析过的数据，可以带。
- 不改记忆选材；不加迁移；不引入新的网络访问。
- 只在对话选了项目时带；「全部项目」或没选时不带。

## 验收条件

1. 合成项目（临时 git 仓库里造几条提交，含一条 20 天前的）+ 这个项目的 `project_snapshot` 来源 + 2 个合成的编码代理会话 + 2 个编码任务：派给 Hermes 的文字里有项目近况，14 天内的提交都在、20 天前的不在；会话的标题和最后一句话在；任务的状态是中文。（用假的 Hermes 适配器截下 `prompt.submit` 的文字，照 `t2a-hermes-instruction.test.ts`。）
2. 同一个项目没有 `project_snapshot` 来源：没有提交那块，会话和任务照带。
3. 没选项目：没有项目近况。
4. 整段超过 2000 字时按规则截断，截后不超过 2000 字。
5. 目录不是 git 仓库、或 git 超时：跳过提交那块，不报错、不影响回答。
6. 回答的 `meta.projectBrief` 计数对；界面那行灰字显示对，没带时不显示。

## 真机检查

在 `scripts/real/` 加一个脚本（照 `hermes-ask.ts`）：临时库 + 合成的项目（临时 git 仓库、合成提交、合成会话与任务），真 Hermes 问「这个项目做到哪了？」和「接下来该做什么？」，贴回答。如实写模型有没有用上这些近况。
