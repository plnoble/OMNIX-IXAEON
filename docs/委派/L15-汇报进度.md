# 委派单 L15：做完一件就告诉用户；「没活」一天只说一次，说清要不要用户做什么

档位：**A**（飞书汇报的内容和次数；发的还是任务一栏、状态这些已经在发的东西）。大小：小（约 70 行源码）。依赖：无。来源：用户 2026-10-24：

- 「IXAEON 的开发都走调度器……定期向我汇报开发进度。」现在只有晚上 9 点一份日报，中间做完了什么，用户不知道。
- 「半夜我收到一堆飞书通知『剩下的都被依赖或暂停挡着，等你看一眼。』我不知道我能做什么。」调度器空转时这条每 30 分钟发一次（凌晨 3 点到 7 点发了一串），又不说要用户做什么。其实那会儿只剩一件暂停的 V4，用户什么都不用做。

## 要什么

1. **做完一件就发一条**：一棒做完、队列里那一行变成「已完成」，飞书发一条：哪一行、什么任务、前后一共几棒、几个小时、整合方花了多少钱。
2. **「没活」一天只发一次**（每种原因各一次，按北京时间算日子）。
3. **「被挡着」那条说清要不要用户做什么**：把队列里「等用户」的行列出来（这些才要用户回答）；一行都没有，就直说「没有要你回答的，你不用做什么」。
4. 晚上 9 点的日报照旧；**早上 9 点再发一份**：昨晚 9 点到现在做了什么（用户 2026-10-24：「可以定期用飞书向我汇报开发的进度」）。

## 契约（接口写死，不改名、不加字段）

1. **做完一件**：`RelayEvent` 加 `{ kind: 'done'; taskId: string; task: string; turns: number; hours: number; costUsd: number }`。`runOnce` 里一棒结束、没停下：`statusAfter` 以「已完成」开头、`statusBefore` 不以「已完成」开头 → 发它。`turns` 是记账里 `taskId` 等于这一行序号的棒数（含这一棒），`hours` 是这些棒 `endedAt − startedAt` 加起来、换成小时、保留一位小数，`costUsd` 是这些棒 `usage.costUsd` 加起来（没有就 0）。`formatEvent` 写成两行：
   - `第 <taskId> 行做完了：<task>`
   - `一共 <turns> 棒、<hours> 小时`，`costUsd` 大于 0 时接 `，整合方花了 <costUsd 保留两位> 美元`。

   `done` 不限频（`rateKey` 回 `null`）。规划棒（`taskId` 是 `plan`）不发。
2. **「没活」一天一次**：`RelayState` 加可选 `idleDay?: Partial<Record<'queue-empty' | 'all-blocked', string>>`（北京时间的日子，照 `daily.ts` 的写法）。`runOnce` 要发 idle 时：`idleDay[why]` 就是今天 → 不发；否则发，发出去之后记下今天。原来「只有 `run` / `--under` 才发」的规矩不变。
3. **「被挡着」列出要回答的**：`{ kind: 'idle' }` 加可选字段 `waiting?: Array<{ no: string; task: string; status: string }>`。`runOnce` 发 `all-blocked` 时带上主表里状态以「等用户」开头的行（按表里的先后）；`queue-empty` 不带。`formatEvent`：**没有 `waiting` 字段时和现在一字不差**；有的时候在原来那句后面接：
   - `waiting` 不空：一行 `要你回答的：`，之后每行 `- 第 <no> 行 <task>：<status 去掉开头的「等用户：」或「等用户」>`；
   - `waiting` 是空数组：一行 `没有要你回答的，你不用做什么。`
4. 飞书的限频（30 分钟、按 kind 加 taskId / role / why 分）不改。
5. **早报**：`RelayConfig` 加可选 `morningReport?: boolean`（没有或 `false` → 不发早报：锁定的 L2b 测试把「现在」定在北京时间 10 点，默认开着会多出一条）；`relay init` 生成的配置、`config.example.json` 写 `true`。`RelayEvent` 加 `{ kind: 'morning'; turns: number; done: string[]; costUsd?: number; doing: string[] }`，`RelayState` 加可选 `lastMorningDate?: string`。开着、北京时间 9 点之后、今天还没发过 → 在定下一棒之前发（和日报同一处），记下今天。`turns`、`done`、`costUsd` 照日报的算法，只是算的是「北京时间昨天 21:00 到现在」开始的棒；`doing` 是主表里状态以「进行中」「测试待审」「待复审」开头的行的任务一栏。`formatEvent`：
   - `早报 <月>月<日>日：昨晚 9 点到现在跑了 <turns> 棒`，`costUsd` 有值接 `，整合方花了 <两位小数> 美元`；
   - `done` 不空：`做完了：` 接 `、` 连起来的任务；空：`这段时间没做完新的`；
   - `doing` 不空：`在做：` 接 `、` 连起来的任务。
   `morning` 不限频。

## 验收

新测试 `packages/relay/test/acceptance/l15-report.test.ts`：

1. `formatEvent` 的 `done`：有花费、花费是 0 两种，原样比对。
2. `formatEvent` 的 idle：不带 `waiting` → 和原来一字不差；`waiting` 两行 → 原话后接「要你回答的：」和两行；`waiting: []` → 原话后接「没有要你回答的，你不用做什么。」。
3. 合成仓库（照 `l2b-notify` 的做法，假飞书）：替身把一行改成「已完成（…）」→ 假飞书收到一条 done，`turns`、`hours`、`costUsd` 照记账算对（事先往记账里放一条同一个序号的旧棒）；替身改成「待复审（整合方）」→ 不发 done。
4. 合成仓库：队列里只剩一行「暂停（…）」和一行「等用户：要不要 X」，`relay run --exit-when-idle` 跑两次（同一个北京日，`IXAEON_RELAY_NOW` 定死）→ 一共只收到一条 idle，里面列着「第 <序号> 行 …：要不要 X」；把 `IXAEON_RELAY_NOW` 换成第二天再跑 → 又收到一条。
5. 早报：`formatEvent` 的 `morning` 几种组合原样比对；合成仓库、配置 `morningReport: true`、`IXAEON_RELAY_NOW` 定在北京时间 9:30、记账里有一条北京昨天 22:00 开始、做完了的棒和一条昨天 20:00 的 → 早报里 `turns` 是 1、`done` 是 22:00 那一棒的任务；同一天再跑一次不发第二份；8:30 跑不发；配置没有 `morningReport` → 不发。`relay init` 生成的配置、`config.example.json` 里 `morningReport` 是 `true`。
