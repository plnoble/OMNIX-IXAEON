# 委派单 K1：技能候选的「运行受控对照验证」表单

任务来源：[三周任务单](../三周任务单.md)「已知未通的入口」。大小：**小（≤150 行改动）**。

## 背景

「任务」页技能候选卡片上的「运行受控对照验证」按钮，原实现连续调用三次 `window.prompt` 收集参数；Electron 不支持 `prompt`，点下去直接报错，这个入口在真实应用里**从未生效**。现在按钮只弹一句「表单还没做」（`apps/desktop/src/renderer/src/pages/Tasks.tsx` 约 300 行处）。

后端接口早就在了，不用改：

```ts
evaluateSkillWithEvidence(input: {
  id: string;                 // 技能候选 id
  method?: string;
  command: string[];          // 验证命令（argv）
  taskId?: string | null;     // 可选：在该编码任务的隔离工作区里执行
  benefit: string;            // 收益说明
}): Promise<{ ok: true }>;
```

验证命令由主进程沙箱真实执行，退出码与输出以真实执行为准；失败基线取自候选关联的真实失败运行（没有就会报错——把后端的报错原样显示给用户即可）。

## 要做的

1. 点按钮在卡片内展开表单（不是弹窗）：
   - 关联任务（可选）：下拉框，选项来自已有编码任务（显示目标文字，值为任务 id）；
   - 验证命令（必填）：单行输入。按空格拆成参数，双引号内的空格不拆；下方实时显示拆分结果（如 `npm` · `test` · `a b`）；
   - 收益说明（必填）：多行输入。
2. 必填项为空时「运行」按钮禁用；运行中禁用并显示「正在验证…」。
3. 成功后收起表单、刷新候选列表（证据会显示在卡片上）；失败时在表单下方显示后端报错原文，表单内容保留。
4. 删掉现在那段 `setError('…表单还没做…')` 的占位逻辑。

## 验收条件（写死）

1. 拆分函数单元测试：
   - `npm test` → `['npm','test']`
   - `node "my script.js" --x` → `['node','my script.js','--x']`
   - 多个连续空格不产生空参数；首尾空格忽略
   - 引号未闭合时视为输入错误，禁用运行并提示
2. 界面测试（jsdom，mock `api`）：填齐三项点运行 → `evaluateSkillWithEvidence` 收到正确参数；后端抛错 → 错误原文出现在表单下方且表单内容还在。
3. 全仓不得出现 `window.prompt` / `prompt(`（已有 lint 规则会拦）。
4. `node scripts/verify.mjs` 全过。

## 不要做

- 不改 `evaluateSkillWithEvidence` 与后端校验规则。
- 不加新依赖。

改动文件与行数、测试输出、verify 结果。**不要提交。**
