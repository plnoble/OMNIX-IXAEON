# 规格 L11：两条道同时跑（DSH 开发的同时，整合方复审、规划）

档位：**B**（越界核对改成按提交者分账；改调度器给角色的提交署名）。大小：中（约 250 行源码；超过 300 行就拆，L11c 放契约第 3、4 条看门人那一段）。依赖：L11b。来源：用户 2026-10-24 定「IXAEON 的开发都走调度器：Claude 统筹、DSH 开发」。现在调度器一次只跑一棒：DSH 一棒常常一个多小时，这期间整合方能做的复审、规划都在排队；反过来整合方一棒半小时，DSH 也干等着。

v2 规格：先把验收条件写成测试（`packages/relay/test/acceptance/l11-*.test.ts`），**先只推测试**，整合方锁定后再写实现。

## 要什么

1. **两条道**：配置写 `lanes: 2` 时，看门人同时转两条道，一条只跑开发的棒、一条只跑整合方的棒（复审、规划）。没写或写 `1`，和现在一模一样。
2. **状态不互相覆盖**：两条道是两个进程，同时读写 `state.json`。每次写都改成「加锁 → 重读 → 只改这一棒自己改的那几个字段 → 写回 → 放锁」，不再把开棒时读到的整份旧状态写回去。
3. **越界按提交者分账**：调度器起角色时给它设好 git 的署名（开发是 `dev`、整合方是 `relay-integrator`）。核对开发那一棒，只看这期间**开发署名**的提交；核对规划棒，只看**整合方署名**的提交。另一条道同时推上来的东西，不算到这一棒头上。
4. **两份代码**：两条道各用一份调度器代码（`relay-run-developer`、`relay-run-integrator`），每一轮各自更新到最新的 main，换代码时不会动到另一条道正在用的文件。

## 契约（接口写死，不改名、不加字段）

1. **配置**：`RelayConfig` 加可选 `lanes?: 1 | 2`；`RoleConfig` 加可选 `gitIdentity?: { name: string; email: string }`。`checkConfig`：`lanes` 不是 1 或 2 → 不过；`lanes: 2` 时两个角色都要有 `gitIdentity`、两个 `name` 不一样 → 否则不过。`relay init` 生成的配置写 `lanes: 1`，开发 `gitIdentity: { name: 'dev', email: 'dev@ixaeon.local' }`，整合方 `{ name: 'relay-integrator', email: 'integrator@ixaeon.local' }`；`config.example.json` 同。
2. **署名**：`runTurn` 起角色时，`gitIdentity` 有值 → 环境里设 `GIT_AUTHOR_NAME`、`GIT_COMMITTER_NAME` 为 `name`，`GIT_AUTHOR_EMAIL`、`GIT_COMMITTER_EMAIL` 为 `email`。
3. **看门人**（`relay run`，`lanes: 2`）：
   - 两条道各是一个循环、同时转。每条道一轮：更新自己那份代码（`<工作目录根>/relay-run-<角色>`，照 L10 的 `updateCodeCheckout` + `ensureDeps`；`IXAEON_RELAY_CODE` 有值时两条道都用它、不建不更新）→ 起子进程 `relay once --under <看门人的进程号> --role <角色>` → 退出后打一行 `子进程 <进程号> 退出 <退出码>（<角色>）`。
   - 每条道自己数崩了几次、自己等（照 L10 的 1、5、15 倍）；任何一条道连着崩 3 次 → 照 L10 写 `stoppedReason`、发 stopped。
   - 每一轮之后重读 `state.json`：`stoppedReason` 有值 → 这条道不再起新的子进程。两条道都停了，看门人退出。`--exit-when-idle`：两条道这一轮都没跑棒 → 退出。
   - `lanes: 1` 或没写：和 L10 一模一样（包括那一行输出的写法）。
4. **`once --role <角色>`**：`decideNextTurn` 的 `opts` 加 `role?: Role`：给了就只看这个角色的活（整合方：复审、规划；开发：接着做、领新的），另一个角色在不在歇都不管。发不发 idle：只有整合方那条道发，而且要「不分角色也没活」才发（免得开发在干活时说没活）。
5. **状态**：`store.ts` 导出 `updateState(dataDir: string, change: (s: RelayState) => void): RelayState`：
   - 锁是 `<数据目录>/state.lock`，独占地新建；已经有了 → 每 100 毫秒再试，最多 10 秒；锁文件超过 30 秒还在，当它是崩掉的进程留下的，删掉再拿。
   - 拿到锁后重读 `state.json`、调 `change`、写回、删锁，返回写回的那份。
   - `runOnce` 里改状态的每一处都走它，只改自己那一项：开棒时分配棒号（`turns += 1`，用分到的那个号）、撞额度时的 `pausedUntil[自己的角色]`、规划棒的 `plan`、日报的 `lastDailyDate`、飞书限频新记的那几条 `notify.sent`、停下的 `stoppedReason`。看门人写 `stoppedReason` 也走它。
   - 开棒时的 `origin/main`（核对用的起点）留在这一棒自己的进程里传给 `verifyTurn`，不靠两条道共用的 `state.mainShaAtTurnStart`（这个字段照旧写，`lanes: 1` 时照旧用）。
6. **核对**（`verifyTurn`）：
   - 开发那一棒，开发有 `gitIdentity` → 「并入 B 档」「B 档锁定改了」只看 `起点..现在` 里作者邮箱是开发 `email` 的提交（`git log --author=<email>`）；「改了哪些文件」也只算这些提交改的。没有 `gitIdentity` → 照原来看整段。
   - 规划棒，整合方有 `gitIdentity` → 只看作者邮箱是整合方 `email` 的提交：改了 `docs/` 以外的文件 → `plan-touched-code`；主表的行，按这些提交**每一笔自己**（它和它的父提交比）改了什么来算：改了、删了已有的行 → `plan-changed-rows`；加的行合起来超过 3 行、或者新行状态不对 → `plan-changed-rows`。没有 `gitIdentity` → 照原来。
   - `local-user` 照旧。

## 约束

- 只改 `packages/relay/`（含 `README.md`，写清 `lanes: 2` 怎么开、两份代码目录）。
- **看门人自己那一层的代码（`relay run` 那个进程）不会自己换新**：L11 并入之后，要用户在终端里把 `relay run` 停掉重起一次。README 写清。
- 已锁定的验收测试不改。`lanes` 没写时一切照旧，L10 那几条应该原样能过；撞上了就停下写进交付说明。

## 验收条件

1. **同时跑**：合成仓库（照 `l2b-notify` 的做法）、`IXAEON_RELAY_CODE` 指向本仓库、`lanes: 2`；开发替身领一行、睡 5 秒再改状态，整合方替身复审另一行、马上改状态。`relay run --exit-when-idle`：两棒都记了账、棒号不一样；整合方那一棒的开始时间早于开发那一棒的结束时间；两行状态都改了；没停下。
2. **分账**：开发那一棒跑着的时候，整合方那条道推了一笔「并入 X」（X 是 B 档）→ 开发那一棒不算越界；开发替身自己推「并入 X」→ 照原来 `b-tier-merged-by-developer`、停下。规划棒跑着的时候，开发推了 `packages/` 下的改动、改了另一行的状态 → 规划棒不算越界；规划棒的替身自己改 `packages/` 下的文件、或者改已有一行 → 照 L9 的两种越界。
3. **署名**：替身把收到的 `GIT_AUTHOR_NAME`、`GIT_AUTHOR_EMAIL`、`GIT_COMMITTER_NAME`、`GIT_COMMITTER_EMAIL` 写下来 → 和配置里那个角色的一样；没配 `gitIdentity` → 不设这几个（替身收到的是外面原来的值）。
4. **状态锁**：两个进程同时各调 50 次 `updateState(s => { s.turns += 1 })` → 最后 `turns` 是 100。锁文件超过 30 秒的 → 被当成留下的、能拿到锁。
5. **配置**：`lanes: 3`、`lanes: 2` 但缺一个 `gitIdentity`、两个 `name` 一样 → `checkConfig` 不过。`relay init` 生成的配置照契约第 1 条。
6. **停下**：开发那条道的子进程连着崩 3 次（`IXAEON_RELAY_CODE` 指向一个开发道一跑就崩的假代码目录也行）→ `stoppedReason` 照 L10 写；整合方那条道跑完手上那一棒就不再开新的；看门人退出。
7. **只有一条道**：`lanes` 没写 → 输出、行为和 L10 一样（L10 的锁定测试照过就算）。
