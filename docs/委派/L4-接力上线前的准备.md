# 规格 L4：接力上线前的准备（DSH 起得来、写得对地方、推得上去）

档位：**B**（改调度器的数据目录位置；定开发角色在沙箱里的写入范围；往公开仓库推一次探测分支）。大小：小（约 120 行源码）。依赖：L2 ✅。来源：L2 真机检查「丙」（[交付说明](交付/L2.md)）：DSH 能改、能提交，推到工作目录外面被它的沙箱挡住；`dsh.cmd` 是批处理，调度器不经 shell 起不了。

v2 规格：先把验收条件写成测试（`packages/relay/test/acceptance/l4-*.test.ts`），**先只推测试**，整合方锁定后再写实现。真机检查「甲」「乙」不依赖实现，可以和测试一起先做。

## 要什么

调度器下一步就要在用户的电脑上真的转。开发角色用 DSH（用户 2026-10-20 定的分工；凭据 2026-10-22 已经打开）。还差四件：

1. **起得来**：`dsh.cmd` 是批处理，Node 不经 shell 起不了；要一个仓库里的启动器，直接起 DSH 的可执行文件。
2. **写得对地方**：DSH 默认的沙箱只许写它的工作目录。开发要照 AGENTS.md 在 `<Worktrees>/IXAEON/<任务号>` 建工作目录，所以开发的工作目录得是 `<Worktrees>/IXAEON` 这一层。可调度器的数据目录现在就在这一层底下（`<Worktrees>/IXAEON/relay/`），开发碰得到 `state.json`（停下的原因记在那里）、`config.json`、`feishu.json`。**数据目录挪出去**。
3. **推得上去**：生产里开发要推到 GitHub（走网络、要用户本机的 git 凭据）。DSH 的沙箱里推不推得上去，还没验过。
4. **额度字样**：L2 丙的第二次输出里出现了 `usage_limit_reached`，跑满 10 分钟被杀。要查清是 DeepSeek 真撞了额度，还是别的东西里带着这串字。

## 契约（接口写死，不改名、不加字段）

1. **启动器**：`packages/relay/bin/dsh.mjs`。找 DSH 的安装目录：环境变量 `IXAEON_DSH_INSTALL` 有值就用它，否则依次试 `D:/Agent/DeepSeek Harness/Install`、`%LOCALAPPDATA%/Programs/DeepSeek Harness`（照 `scripts/real/l0b-dsh-probe.mjs` 的 `dshBin()`）；直接起 `DeepSeek Harness.exe --expose-internals <app.asar 里的 cli.js>`，环境里设 `ELECTRON_RUN_AS_NODE=1`；**自己收到的参数原样接在后面**，标准输出、错误输出原样转发，退出码原样返回。找不到安装目录：错误输出写「没找到 DSH 的安装目录」，退出码 2。不加、不改任何权限相关的参数和环境变量（不设 `DSH_PERMISSION_MODE`）。
2. **数据目录**：默认改成 `%LOCALAPPDATA%/IXAEON/relay`（Windows；别的系统 `~/.local/share/ixaeon/relay`）。`IXAEON_RELAY_DIR` 有值时照旧用它。L3 的 `loadFeishuTarget()` 默认路径跟着改（`IXAEON_RELAY_DIR` → 新的默认）。**旧位置有文件时不自动搬**：`relay status` 发现 `<Worktrees>/IXAEON/relay/` 里有 `config.json`、`state.json` 或 `feishu.json`，就多打一行「旧的数据目录里还有文件：<旧路径>，请挪到 <新路径>」（只打路径，不打内容）。
3. **配置检查加一条**：任何角色的 `cwd` 把数据目录包在里面（数据目录在 `cwd` 里面，或者就是它）→ 拒绝启动，说清是哪个角色。（模型在自己的工作目录里能写，不能让它够到调度器的状态。）
4. **配置样例**：`developer` 换成 `["node", "<仓库>/packages/relay/bin/dsh.mjs", "--profile", "headless", "--json", "读 {prompt_file}，照里面做。"]`，`cwd` 写 `<Worktrees>/IXAEON`。DSH 读得到交代文件吗（数据目录在它的工作目录外面）——见真机检查甲，结论写进样例。

## 约束

- 测试用替身和临时目录，不调真模型。启动器的测试用一个假的安装目录（里面放一个替身可执行文件，比如把 `process.execPath` 复制或链接成 `DeepSeek Harness.exe`，再放一个假的 `resources/app.asar/.../cli.js`），不起真的 DSH。
- 数据目录的测试一律用 `IXAEON_RELAY_DIR` 或改 `LOCALAPPDATA` 指到临时目录；**不许读、写用户本机真的数据目录**（新旧两个位置都不许）。
- 不改 `~/.dsh`、`~/.claude`、`~/.codex`；不跑 `dsh --dump-config`（会打出凭据）。
- L1、L1b、L2、L2b、L3 已锁定的测试不改，要和这一单一起过。

## 验收条件

1. **启动器**：假安装目录 + 替身 → 替身收到的参数是 `--expose-internals <cli.js 路径> <原样的参数…>`（中文参数不乱码）、环境里有 `ELECTRON_RUN_AS_NODE=1`；替身的标准输出、错误输出、退出码（比如 3）原样回来；`IXAEON_DSH_INSTALL` 指到不存在的目录且默认两处都没有 → 退出码 2、错误输出有「没找到 DSH 的安装目录」。
2. **数据目录**：没有 `IXAEON_RELAY_DIR` 时，`relay status` 用的是 `LOCALAPPDATA` 下的 `IXAEON/relay`（测试把 `LOCALAPPDATA` 指到临时目录）；有 `IXAEON_RELAY_DIR` 时用它；`loadFeishuTarget()` 的默认路径跟着走。
3. **旧位置提醒**：旧数据目录里放一个合成的 `state.json` → `relay status` 多打那一行，输出里不含那个文件的内容；旧目录是空的 → 不打。（测试里把「旧位置」指到临时目录：`IXAEON_WORKTREES` 指到临时目录即可。）
4. **配置检查**：开发的 `cwd` 是数据目录的上一层 → 拒绝、原因里写清是 `developer`；整合方的 `cwd` 就是数据目录 → 拒绝；都不包着 → 放行。
5. **配置样例**：合法 JSON；没有「跳过所有权限」的开关；`developer.argv` 里有 `packages/relay/bin/dsh.mjs`、`--profile`、`headless`、`--json`、`{prompt_file}`。

## 真机检查

**甲：DSH 在新布局下跑一棒（不依赖实现，可以先做；DSH 真调用不超过 3 次）**——`scripts/real/l4-dsh-layout.mjs`，全在临时目录里：开发的工作目录是一个临时的「Worktrees/IXAEON」（里面一个裸仓库当 origin、一个 ops 克隆），数据目录在它外面。让 DSH 照合成的交代：在这一层底下新建一个工作目录（`git worktree add`）、改一行、提交、推到裸仓库。看：读得到交代文件吗（读不到就试启动参数里有没有类似 `--add-dir` 的办法；`dsh --help` 可以看，不许看 `--dump-config`）；建得了工作目录吗；推得上去吗；碰得到数据目录吗（交代里让它试着往数据目录写一个文件，**应当被拒**）。

**乙：DSH 的沙箱里推 GitHub（不依赖实现；DSH 真调用不超过 2 次）**——`scripts/real/l4-dsh-push.mjs`：在临时目录里克隆真仓库（`git clone --depth 1`），让 DSH 建一个分支 `relay-probe/<时间戳>`、提交一个空提交（`git commit --allow-empty -m "接力探测：DSH 沙箱里推送（会马上删掉）"`）、推上去。脚本最后**一定删掉这个远端分支**（`git push origin --delete`，失败重试），并打印删没删成。推不上去就如实记下报错（遮掉用户目录），不要改 DSH 的权限设置、不要改 git 的凭据设置。

**丙：额度字样**——读 L2 丙第二次留下的输出（在当时的临时目录里，已经删了就看交付说明里贴的原样输出），查清 `usage_limit_reached` 出现在哪一行、是谁说的；甲、乙两次真跑的输出里有没有再出现。结论写进交付说明：是真额度（多久恢复、看哪里查用量）还是误认（误认的话，建议把 DSH 的 `quotaPatterns` 改成什么）。

## 整合方审测试时的改正与补充（2026-10-22）

整合方写了一份一次性实现（没提交）把测试跑通，再逐处改坏 21 处，全部有测试变红；然后锁定。

### 真机检查改变了的认识

- **DSH 的沙箱关不住写文件**：甲里让它往数据目录写文件，它写成了。它的沙箱实际挡住的是联网和凭据（乙：`SEC_E_NO_CREDENTIALS`、`No such host is known`）和 `sh.exe` 的管道。所以第 2、3 条（数据目录挪出去、配置检查）**防的是手滑，不是围栏**，照样做。
- **DSH 在沙箱里推不上 GitHub，也就调不了 Codex 审查（要联网）**。怎么解，要用户拍板，另开一单（L5），不在这一单。
- **额度字样是真的**：DSH 自己把模型接口回的 `usage_limit_reached` / `rate_limit_exceeded` / HTTP 429 当额度。配置样例里开发的 `quotaPatterns` 用 `["usage_limit_reached", "rate_limit_exceeded", "session limit"]`，不要加裸的 `429` 或「usage limit」。

### 定下来的说法

1. **`IXAEON_DSH_INSTALL` 有值就只认它**，不再回退到默认的两处（开发提的；不然这台机器上「指到不存在的目录 → 退出码 2」测不到）。
2. 启动器结尾用 `process.exitCode`，不用 `process.exit`（见下一条）。
3. **退出时崩溃（整合方已修）**：这台机器上 jiti 跑 TS、做过真 HTTPS 请求、结尾 `process.exit(n)`，进程退出时断言失败（退出码 0xC0000409）。整合方把 `packages/relay/bin/relay-main.ts` 和 `scripts/real/l3-feishu-send.ts` 的结尾改成了 `process.exitCode`，真发了一条飞书确认退出码 0。实现这一单新写的入口照这个写。
4. 旧位置的提醒只打路径，不打内容（测试补了「旧位置里只有 `feishu.json`」——用户本机就是这样）。并入之后，整合方征得用户同意再把用户的 `feishu.json` 挪到新位置（只挪文件，不读内容）。

### 整合方补的

- 数据目录在开发的 `cwd` 下面好几层、大小写不同，也拒绝。
- 旧位置里只有 `feishu.json` 也提醒，提醒里不带出地址和密钥。
