# 规格 W2：研究的发现与搜索候选显示中文

档位：**B**（新的发给模型的提示词）。大小：中（≤250 行源码）。依赖：迁移 37（整合方已加 `research_findings.title_zh`、`summary_zh`）。来源：用户 2026-09-24 验证 N1。
v2 规格：先把验收条件写成测试（`packages/core/test/acceptance/w2-*.test.ts`，界面部分放 `apps/desktop/test/acceptance/`），**先只推测试**等整合方看过并锁定，再实现。

## 要什么

用户验证 N1 时说：「全英文，可以增加转换功能么，显示中文。」整合方按字段统计（只数中文字符占比，不看内容）：发现的标题 3 条全是英文，摘录一半英文；「立即检查」列出的搜索候选来自英文网页；N1 的判定理由和研读写的「局限」已经是中文。

用户不想逐条点「翻译」：**默认显示中文，原文保留、可以展开看**。

## 契约

1. 核心层新增 `translateFindings(db, provider, topicId)`：
   - 找这个主题里 `title_zh` 为空、且标题加摘录**不是中文为主**的发现。中文为主 = 去掉空白后中文字符（`一-鿿`）占比 ≥ 30%，这个判断写成一个函数，候选也用它。
   - 按批发给模型（每批最多 10 条），每条只给 id、标题、摘录（截到 800 字），要求逐条返回 `title_zh`（≤ 40 字）和 `summary_zh`（≤ 120 字）。摘要只根据给的摘录写，不添加摘录里没有的内容；只输出 JSON。
   - 返回里不在这一批的 id 忽略；超长截断；`title_zh` 为空的那条不写。
   - 中文为主的发现不发给模型、不写任何字段，界面照旧显示原文。
   - 失败（没配模型、模型出错）：什么都不写，下次检查再试；发现照常入库，不报错打扰用户。
2. 调用时机：检查器每次检查成功后，在 N1 的 `judgeFindings` 之后调一次，与它同样包在 try/catch 里（「翻译失败不影响发现入库」）。旧的英文发现（迁移前入库的）在下一次检查时补上。
3. 搜索候选：`checkNow` 返回的 `SearchCandidate` 加 `titleZh`、`snippetZh`（可空）。不是中文为主的候选合成**一次**模型调用翻标题和摘要；失败时两项为空，候选照常返回。候选不入库，不存翻译。
4. 发给模型的只有网页上的公开文字（发现的标题与摘录、候选的标题与摘要）。**不带**主题的内部问题（`question` 可能带用户背景）、出门说法、用户的记忆或要求。
5. 界面：
   - 研究页的发现：标题显示 `title_zh`（没有就原标题），链接照旧打开原网址；有 `summary_zh` 时正文显示中文摘要，下面「原文」可展开（`<details>`），里面是原标题和原摘录；没有中文时照旧显示原摘录。
   - 研究页的搜索候选：同上，`titleZh` / `snippetZh` 优先，原文可展开。
   - 总览三块（「符合你要求的新发现」「最近的新发现」「研究里你标过值得行动」）：标题有中文就显示中文。
6. N1 的判定照旧用**原文**标题与摘录判断，不改判定和提醒规则。

## 约束

- 不新增外发类别：发现的标题与摘录本来就发给核心模型研读和判定；候选是公开网页内容；用的是设置页的核心模型，不是新服务。按规矩新提示词走 B 档。
- 不加迁移（迁移 37 已由整合方加好）。
- 不翻译用户自己的内容（记忆、问题、要求、主题名）。

## 验收条件

1. 英文发现：检查后写入 `title_zh`、`summary_zh`；再检查一次不重复翻译（模型替身调用次数不增加）。
2. 中文为主的发现：不发给模型（替身调用 0 次），两个字段为空。
3. 发给模型的文字里只有发现的标题和摘录：主题的内部问题里放一个合成标记，替身截下的请求里没有它；也没有要求的文字。
4. 模型出错：发现照常入库，字段为空；下一次检查再试并成功写入。
5. 模型返回了不在这一批的 id、或超长文字：前者忽略，后者截断到上限。
6. 一批最多 10 条：15 条英文发现分两次调用。
7. 搜索候选：`checkNow` 返回的英文候选带 `titleZh` / `snippetZh`；中文候选不发模型；翻译失败时为空、候选照常返回。
8. 界面：研究页的发现和候选显示中文、原文可展开；总览三块的标题显示中文；没有中文时显示原文。

**整合方复审测试时补（2026-09-26）**：出门说法换成独立的合成标记并断言不外发；补「检查前就在库里的英文发现，检查后也有中文」（只翻新发现的实现过不了）；补「研究页用的 `listFindings` 和总览三块（`buildPersonalOverview` 的 `matchedFindings`、`recentFindings`、`researchFollowUps`）拿到的数据里带中文」——界面测试是把中文字段直接喂给页面，核心层不带中文也能过。字段名照执行方的测试：发现上是 `title_zh` / `summary_zh`，总览条目上是 `titleZh`，候选上是 `titleZh` / `snippetZh`。

## 真机检查

翻译用的是设置页配置的模型（Key 在 Electron 加密存储里，脚本进程解不开）——**执行方跑不了模型那一段**，交付里如实写「待用户在应用里验证」。能跑的照跑：临时数据目录启动应用，往库里塞合成的英文发现（翻译结果直接写表），确认研究页和总览的中文显示、「原文」展开，贴截图或描述。
