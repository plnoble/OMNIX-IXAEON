# 规格 U5：任务卡片说人话

档位：**A**（只改任务卡片上显示什么；对话里回报的文字不变，不改任务流程）。大小：小（≤100 行源码）。依赖：D5a（卡片要显示 D5a 写进执行报告的验收测试情况；D5a 的端到端测试也认卡片上的字）。来源：用户 2026-10-05 试场景一时贴回来的卡片。

v2 规格：验收条件写成测试（`apps/desktop/test/acceptance/u5-*.test.ts`，两句共用的话也在这里测），测试和实现一起交，Codex 审查时核对有没有漏条件。

## 要什么

用户贴回来的卡片是这样的：

> 完成（未部署） · 版本 1 · 执行器 我的模型（……） · 独立验证 not_run

查下来卡片上有四处不说人话，或者该有的没有：

1. 「独立验证 not_run / passed / failed」是库里的英文状态原样贴上来的。对话里的回报早就写成「验证通过」「验证没跑：……」「还没有独立验收」了，卡片没跟上。
2. 模型自己说做不到的时候，对话里的回报有一句「它的说明：……」，卡片上只有「执行器未声称成功，不把验证命令当成完成」。
3. 设置里选了「我的模型」，排队的任务按钮上写的还是「派发（Codex）」；缺模型或者缺 Key 时写的是「派发（Fake）」。
4. 卡片上看不到这个任务的验收条件。D5a 之后也看不到验收测试写了几个、锁没锁定。

## 契约（接口写死，不改名、不加字段）

1. **两句共用的话**放进 `packages/contracts/src/entities.ts`（和 `executorLabel` 放一起），卡片和回报都用它们，只留一份：

   ```ts
   /** 验证结果的一句话。 */
   export function verifyLabel(row: {
     verify_status: string | null;
     verify_output: string | null;
   }): '验证通过' | '验证没通过' | '验证没跑' | '还没有独立验收';

   /** 执行器自己说没做成时，它给的说明。没有就是 null。 */
   export function executorExplanation(row: {
     status: string;
     executor_report_json: string | null;
   }): string | null;
   ```

   - `verifyLabel`：`passed` → 验证通过；`failed` → 验证没通过；`not_run`，而且 `verify_output` 去掉首尾空白之后不是空的、也不含「没有有效验证命令」→ 验证没跑；其余 → 还没有独立验收。
   - `executorExplanation`：`status` 是 `failed`、执行报告里 `claimedSuccess === false`、`summary` 去掉首尾空白之后不是空的 → 返回去掉首尾空白的 `summary`；其余返回 null。执行报告是空的或者不是合法的 JSON 也返回 null，不抛错。
   - `apps/desktop/src/main/taskReport.ts` 的 `verifyLine`、`modelLines` 改成用这两个。**回报的文字一个字不变**：「验证没跑」后面照旧接「：<原因>」；「它的说明」照旧只在「我的模型」做的任务的回报里出现。

2. **卡片**（`apps/desktop/src/renderer/src/pages/Tasks.tsx`）：

   - 状态那一行里的「独立验证 xxx」换成 `verifyLabel` 的话。`verify_status` 是空的（还没验证过）不显示这一段。
   - 失败的任务，`executorExplanation` 有内容：在原因下面显示「它的说明：<说明>」（`data-testid="task-explanation-<任务号>"`）。哪个执行器做的都显示。
   - 排队的任务的按钮：现在生效的执行器是「我的模型」时写「派发（我的模型）」；别的照旧。
   - 验收条件：`acceptance_json` 里有条件时列出来——一行「验收条件：」，下面每条一行（`data-testid="task-acceptance-<任务号>"`）。
   - 验收测试：执行报告里有 `acceptanceTests` 时显示一行（`data-testid="task-acceptance-tests-<任务号>"`）。锁定了写「验收测试 N 个，已锁定」；没锁定写「验收测试没锁定：<原因>」，原因是空的就只写「验收测试没锁定」。

3. D5a 的端到端测试（`apps/desktop/e2e/d5a-acceptance-first.spec.ts`）里认卡片上「独立验证 passed」的地方，跟着改成认「验证通过」。

## 约束

- 对话里回报的文字一个字不变：D1、D3、D5a、D7b 的锁定测试照过。
- 锁定的验收测试里要是有哪条认的是卡片上的旧写法：停下，写进交付说明（整合方查过一遍，没有）。
- 「完成（未部署）」「接受结果（不部署）」这几个字不动。那是另一回事（接受不等于上线），这一单不改。
- 接受之后写进项目仓库提交说明里的那句「独立验证 not_run」（`landing.ts`）也不动：那是写进用户仓库的内容，不顺手改。
- 不加 IPC，不加迁移。

## 验收条件

1. `verifyLabel` 的四种结果各一条；`not_run` 的两种情况（有原因、没有有效验证命令）分得开。
2. 回报里验证那一句和改之前逐字一样：验证通过；验证没跑：<原因>；还没有独立验收。
3. `executorExplanation`：失败、执行器自己说没做成、带说明 → 返回说明。没失败的、`claimedSuccess` 是 true 的、说明是空的、执行报告缺失或不是合法 JSON 的 → null。
4. 回报里「它的说明」仍然只出现在「我的模型」做的失败任务里；Codex、替身做的任务，回报一字不变。
5. 卡片状态那一行：四种验证结果各显示对应的话；`verify_status` 是空的不显示；卡片上不再出现 `not_run`、`passed`、`failed` 这几个英文状态词。「验证没跑」的原因照旧在下面那块输出里看得到。
6. 失败且有说明的任务：卡片显示「它的说明：……」。没有说明的不显示这一行。
7. 排队的任务：现在生效的是「我的模型」时按钮写「派发（我的模型）」；是 Codex、是替身时和现在一样。
8. 有验收条件的任务：卡片上每一条都列出来。没有的不显示这一块。
9. 执行报告里有 `acceptanceTests`：锁定的写明几个、已锁定；没锁定的写明没锁定和原因。没有这一项的任务不显示这一行。
10. D5a 的端到端测试改完照过。

## 真机检查

照 `scripts/real/u2-tasks-page-live.mjs` 的做法（临时数据目录、替身执行器、合成项目）：做完一个任务，打开任务页，打印这张卡片状态那一行的文字，并核对里面没有英文状态词；不对就以非零码退出。输出原样贴进交付说明。
