# 规格 L2：接力调度器接上真的命令行和飞书

档位：**B**（它把任务交给真的模型；定了模型在后台能跑哪些命令；新接上飞书外发）。大小：中（约 200 行源码，超过 300 行就拆 L2 / L2b）。依赖：L1、L1b、L3 ✅。来源：用户 2026-10-20 定的方向（24 小时接力，见 [L1 规格](L1-接力调度器核心.md)），L0b 的结论（[交付说明](交付/L0b-补完实验.md)）。

v2 规格：先把验收条件写成测试（`packages/relay/test/acceptance/l2-*.test.ts`），**先只推测试**，整合方锁定后再写实现。真机检查的「甲」（白名单写法实验）不依赖实现，可以和测试一起先做。

## 要什么

L1 / L1b 的调度器现在只会调替身。这一单让它能真的转起来：

1. **认得真命令行的输出**：Claude 的 `--output-format json` 是一整个 JSON，`RELAY-DONE` 在 `result` 字段里面（字符串里的换行是 `\n`），按行找不到；DSH 的 `--json` 是 JSONL，最终回答在 `{"type":"final","text":…}` 的 `text` 里。
2. **网络抖的时候不漏查**：这台机器上 `git fetch` 隔三差五握手失败。现在 fetch 失败了不管，核对就会漏掉这一棒推上去的东西。
3. **要用户拍板时停下来、找用户**：模型碰到要用户定的事，不能自己定，也不能干等。
4. **接上飞书**（L3 做好的模块）：停下来、要拍板、歇着、没活了、每天一条日报。
5. **配置样例换成真的**：整合方用 Claude（L0b 的配方），开发先也用 Claude；DSH 等用户定了凭据再换上。

## 契约（接口写死，不改名、不加字段）

1. **输出解析**：`parseRoleOutput(stdout: string): { doneLine: string | null; usage?: { costUsd?: number; inputTokens?: number; outputTokens?: number } }`，放 `packages/relay/src/output.ts`，`runTurn` 改用它。
   - 先看有没有一整行是 JSON 且带字符串字段 `result`（Claude）→ 在 `result` 里按行找；再看 JSONL 里 `type` 为 `final` 的行（DSH）→ 在 `text` 里按行找；都没有 → 照旧按标准输出的行找。几处都有时，取**最后出现**的那个 `RELAY-DONE` 行。
   - 用量照 L1 第 7 条，不变。
2. **拉 main**：`fetchMain(cwd): Promise<boolean>`（放 `src/git.ts`）：`git fetch origin`，失败隔 2 秒、再隔 5 秒重试，三次都失败返回 `false`。读队列和核对都改用它（`readMainQueue` 跟着变成异步的）。
   - **开一棒之前**拉不下来：这一次不开棒（不建 `turns/`、不记账），当作没活，`run` 等 `idleSeconds` 再看。
   - **核对时**拉不下来：停下。`stoppedReason` 写「第 N 棒之后拉不下来 origin/main，没法核对」，记账那一行的 `violations` 记 `verify-fetch-failed`。
3. **要用户拍板**：两种角色的交代里都加一句（逐字）：「要用户拍板的事，不要自己定：把这一行的状态改成「等用户：<一句话说清要定什么>」，然后停。」状态以「等用户」开头的行 `decideNextTurn` 不给（现在就不给，加测试钉住），算进 `all-blocked`。
4. **飞书**：调度器的 `once` / `run` 用 `createNotifier(loadFeishuTarget(), state.notify)`；`state.notify`（`{ sent: {} }`）存在 `state.json` 里，限频跨命令保留。什么时候发：

   | 什么时候                                       | 发什么事件                                                                                                                                                                                                                |
   | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | 这一棒越界、或核对时拉不下来，停下了           | `stopped`：`reason` 是 `stoppedReason`，带 `taskId`、`task`                                                                                                                                                               |
   | 做完后这一行的状态以「等用户」开头             | `needs-user`：`taskId`、`task`、`status`（做完后的状态）                                                                                                                                                                  |
   | 这一棒撞上额度                                 | `paused`：`role`、`until`                                                                                                                                                                                                 |
   | `run` 里没活了：`queue-empty` 或 `all-blocked` | `idle`：`why`                                                                                                                                                                                                             |
   | 北京时间每天 21:00 之后第一次转到              | `daily`：当天（北京时间）的棒数、做完后状态以「已完成」开头的那些行的任务（去重，按先后）、当天 `usage.costUsd` 之和（一棒都没有就不带 `costUsd`）；`state.lastDailyDate` 记下日期（`10月21日` 那种写法），同一天只发一次 |
   - 日报拆成两个纯函数，好测：`dailyDue(state, now): string | null`（到点且今天没发过 → 返回今天的日期写法，否则 `null`）、`dailyEvent(ledger: LedgerEntry[], date: string, queueMd: string): RelayEvent`（第三个参数是 2026-10-22 整合方加的，见末尾）。放 `src/daily.ts`。
   - 发不出去、没配置：照跑，不影响调度（L3 的模块本来就不抛错）。

5. **配置样例**（`packages/relay/config.example.json`）换成真的形状，路径用占位符：

   ```json
   "integrator": {
     "argv": ["claude", "--restricted", "--tools", "PowerShell", "--allowedTools", "<白名单，见真机检查甲>",
              "--permission-prompts", "none", "--output-format", "json", "-p", "读 {prompt_file}，照里面做。"],
     "cwd": "<整合方工作目录>", "timeoutMinutes": 90,
     "quotaPatterns": ["usage_limit_reached", "session limit"], "quotaPauseMinutes": 120
   }
   ```

   `developer` 同样的形状（`cwd` 是开发 agent 的操作目录）。DSH 那一套写成注释里的备选（`dsh --profile headless --json "读 {prompt_file}，照里面做。"`），等用户定了凭据再启用。

## 约束

- 测试全用替身命令行、临时 git 仓库、本机起的假飞书（`127.0.0.1` 随机端口），**不调真的模型**。替身照 Claude / DSH 的真实输出形状造（见 L0、L0b 交付说明里的原样输出）。
- 数据目录用 `IXAEON_RELAY_DIR` 指到临时目录；**测试不许读用户本机真的 `feishu.json`、`config.json`**。
- 不往仓库外写（数据目录除外）；不改用户的 `~/.claude`、`~/.codex`、`~/.dsh`。
- 不用任何「跳过所有权限」的开关；`--permission-prompts none`（没人回答就自动拒）是必须的。
- 改动只在 `packages/relay/`、`scripts/real/`、交付说明里。L1、L1b、L3 已锁定的测试不改；它们要和这一单一起过。

## 验收条件

1. **Claude 的输出**：标准输出是一整个 JSON、`result` 里有两行 `RELAY-DONE`（中间隔着别的字）→ `doneLine` 是后一行；`total_cost_usd` 照记。**DSH 的输出**：JSONL 里 `final.text` 里有 `RELAY-DONE` → 认出来。普通文字的输出照旧。三种都没有 → `null`。
2. **开棒前拉不下来**：整合方目录的 `origin` 指到一个连不上的地址 → `once` 不开棒、不记账、不停下（`stoppedReason` 仍为空）、退出码 0；改回来之后照常开棒。测试里量一下用时（重试真的等了，≥ 6 秒）。
3. **核对时拉不下来**：开发替身在这一棒里把整合方目录的 `origin` 改成连不上的地址 → 停下，记账那一行 `violations` 里有 `verify-fetch-failed`，`stoppedReason` 里有「拉不下来」；之后 `once` 什么都不跑，`resume` 之后才接着（地址改回来以后）。
4. **等用户**：两种交代里都有第 3 条那句；替身把状态改成「等用户：要不要买新电脑」→ 记账 `statusAfter` 是它、假飞书收到一条 `needs-user`；下一次 `decideNextTurn` 不给这一行；只剩这一行时是 `all-blocked`。
5. **飞书**（假飞书 + 临时数据目录里的 `feishu.json`）：越界 → 收到一条 `stopped`，正文就是 `formatEvent` 那段；撞额度 → 一条 `paused`；`run --exit-when-idle` 转到 `queue-empty` → 一条 `idle`；连着两次 `once` 都越界停下（中间 `resume`）、30 分钟内 → 只收到一条 `stopped`（限频记录在 `state.json` 里，跨命令保留）；没有 `feishu.json` → 照跑、一条都不发、不报错。
6. **日报**：`dailyDue`：北京时间 20:59 → `null`；21:00 → 今天的日期；`lastDailyDate` 已经是今天 → `null`；第二天 21:00 → 第二天的日期。`dailyEvent`：给一份合成的记账（跨两天、有重复完成的行、有的棒没有 `costUsd`）→ 只算那一天的、完成的任务去重、`costUsd` 加总；那天一棒都没有 → `turns: 0`、`done: []`、不带 `costUsd`。
7. **配置样例**：`config.example.json` 是合法 JSON；把占位符换成存在的临时目录之后 `checkConfig` 放行；里面没有任何「跳过所有权限」的开关。

## 真机检查

**甲：白名单的写法（不依赖实现，可以先做；Claude 真调用不超过 6 次）**——`scripts/real/l2-claude-allowlist.mjs`，全在临时目录、临时 git 仓库里：

- L0b 只验过整条命令的写法（`PowerShell(node --version)`）。整合方那一棒要跑 `git …`、`node scripts/…`、`corepack pnpm …`、`gh run …`，得知道**前缀**怎么写才放行（`PowerShell(git:*)`、`PowerShell(git *)` 之类），以及没放行的会不会被拒。
- 每种写法一次真调用：让它跑一条放行的、一条没放行的（比如 `Remove-Item`），看 `permission_denials`。
- 结论写成「整合方 / 开发两套白名单」，填进交付说明和 `config.example.json`。

**乙：真 Claude 当整合方跑一棒（要实现；Claude 真调用不超过 2 次）**——`scripts/real/l2-claude-turn.mjs`：临时裸仓库 + 两个克隆，合成队列一行「测试待审（整合方）」，任务是合成的（「把这一行的状态改成已完成（合成）、提交、推送」）；配置用甲得出的白名单，开发是替身。`relay once` 之后：这一行在 `origin/main` 上变成了已完成；`doneLine` 认出来了；`usage.costUsd` 记上了；临时目录以外什么都没写；打印记账那一行（遮掉临时目录）。

**丙：DSH**：用户定了凭据（打开 headless 的凭据插件，或者给环境变量）之后，照乙跑一次 DSH 当开发；没定就写「没跑：等用户定 DSH 的凭据」。

**丁：飞书**：用户配好了 `feishu.json` 就让乙那一棒之后发一条真的（越界或者 `idle` 都行）；没配就写「没跑」。

## 整合方审测试时的改正与补充（2026-10-22）

整合方在 main 现有的实现上叠了一份一次性的 L2 实现（没提交）把测试跑通，再逐处改坏做了变异检查，补了漏的，然后锁定。L2（`l2-*`）、L2b（`l2b-*`）各锁各的，实现超不超 300 行都照这个分；L2b 的分支基于 L2。

### 定下来的说法

1. **日报写任务名，不写序号**（开发提的那件）：契约第 4 条的 `dailyEvent` 改成 `dailyEvent(ledger, date, queueMd)`——多收一份队列（调度器手上本来就有刚读的那份），按序号查主表「任务」那一格；查不到写「第 <序号> 行」。记账的字段不加。
2. **测试用的「现在」**：环境变量 `IXAEON_RELAY_NOW`（ISO 时间）有值时，调度器定下一棒、判断日报到没到点、飞书限频用它当「现在」；没有就用真的时间。只给测试用，用户的配置里不写它。撞额度歇到几点（L1b 的 `runTurn`）还是用真的时间，不动。
3. **什么时候发**：`idle` 只在 `relay run` 里发（`once` 不发）；日报 `once`、`run` 都发（到点之后的第一次）。日报在定下一棒之前发。
4. **核对时拉不下来**：`verifyTurn` 返回 `{ violations: ['verify-fetch-failed'], mainSha: null }`（这一次不再跑 `local-user`），`stoppedReason` 逐字是「第 N 棒之后拉不下来 origin/main，没法核对」，做完后的 `statusAfter` 记 `null`。
5. **白名单（甲的结论）**：整合方、开发先用同一串 `Write Edit PowerShell(git:*) PowerShell(node:*) PowerShell(corepack:*) PowerShell(gh:*)`，写进 `config.example.json`。**这一串是防手滑，不是围栏**：`node:*` 放行了 `node -e …`，`corepack:*` 放行了 `pnpm` 跑脚本，等于能跑任意代码、往任何地方写。真要把它关在一个目录里，得靠 Codex 那种系统级沙箱（见 L0b）。接力先这么跑，交付说明和用户都要知道这一点。

### 测试里改正的（原来实现写对了也过不了，或者测不到）

- 通知那份用 `spawnSync` 起调度器：假飞书跑在测试进程里，同步调用把测试进程卡住，假飞书回不了话，调度器一直等到超时。改成异步起。
- 「两次越界只发一条」：第二次越界时替身写的内容和第一次一样，没东西可提交，其实没有第二次越界，限频不写也能过。改成每次写不一样的内容。
- 「越界只收到一条 stopped」：晚上 9 点以后跑会多一条日报。改成用 `IXAEON_RELAY_NOW` 定在上午。
- 日报的 `costUsd` 是浮点数加总，`0.1 + 0.2 + 0.05` 不等于 `0.35`：改用 `toBeCloseTo`。

### 整合方补的

- 日报：北京时间跨天的边界（UTC 前一天 17:00 算北京的第二天，UTC 16:30 算北京的下一天）；当天的棒都没有 `costUsd` 时不带；`dailyDue` 在北京时间凌晨（UTC 还是前一天）的判断。
- 调度器真的在 21:00 之后发日报、记下 `lastDailyDate`、同一天不发第二次；20:00 不发。
- 核对时拉不下来、停下了 → 也发一条 `stopped`，原因里有「拉不下来」。
