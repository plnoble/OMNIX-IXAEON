# 规格 P6：文件夹的读取授权撤销之后，不再给这个项目建副本、派任务

档位：**B**（权限与隐私；另外改了 `propose_coding_task` 返回给模型的内容）。大小：小（≤100 行源码）。依赖：P5（提示里叫用户去「解除绑定、重新绑定」，那个按钮是 P5 加的）。来源：整合方 2026-10-06 写 P5 时读代码查到。

v2 规格：先把验收条件写成测试（`apps/desktop/test/acceptance/p6-*.test.ts`），**先只推测试**，整合方看过并锁定后再实现。

## 要什么

项目绑着文件夹，但这个文件夹的读取授权已经撤销了——这个状态今天就到得了：从这个文件夹导入过资料（首次设置向导登记项目时就会导入一次），在来源页对其中任何一份点「撤销读取」，撤销的是整条文件夹授权。

这时候：

- 项目页上这个项目照样显示绑着文件夹；
- 提编码任务、点「要做」、任务页批准，都照常通过。批准时应用把整个文件夹抄进任务副本，派发时交给 Codex 或者发给模型；
- 只有最后点「接受」时才报「没有这个项目目录的读取授权」。

授权撤销了，应用还在读这个文件夹，还在把里面的文件往外发。查授权的只有落地（D4）和看改动（U3）两处，建副本那一步只看项目有没有 `root_path`。

这一单：项目的文件夹不在有效授权之内时，和没绑文件夹一样，不建副本、不派发，并且说清楚原因。

## 契约（接口写死，不改名、不加字段）

1. **怎么算有授权**：项目的 `root_path` 在某条有效的授权之内，`permissions.activePermissionForPath(root_path)` 不是 null。上级文件夹的有效授权也算——和落地（`landing.ts`）、看改动（`taskChanges.ts`）的判断一致。

2. **那句话**（固定文案，下面叫「授权已撤销那句」）：

   > 这个项目文件夹的读取授权已经撤销：在项目页解除绑定、重新绑定之后，再派编码任务。

3. **批准之前拦**：P4 在 `AppRuntime` 上加的那道检查（`assertProjectFolderBound`，三个入口共用）多查一条——项目绑着文件夹但不在有效授权之内 → 报「授权已撤销那句」。三个入口的表现照 P4：
   - `propose_coding_task`：不建草案、不记审计，这句话作为工具错误返回；
   - 待办卡片点「要做」：不批准、不建副本、不派发，待办保持「等你拍板」；
   - 任务页「批准」：不批准、不建副本。

4. **派发之前也拦**（任务是早先批准好、排着队的，之后授权才撤销）：
   - 任务页点「派发」（`finishCodingTask(id, 'dispatch')`）：报「授权已撤销那句」，任务留在排队，执行器不调。
   - 自动派发（`CodingDispatch`）轮到这样的任务：跳过它，任务留在排队，接着派后面的；在发起它的对话里回报一次：

     > 「<目标的第一行>」停在排队里：<授权已撤销那句>

     回报的 `meta` 是 `{ kind: 'task_report', taskId, status: 'folder_missing' }`，同一个任务只写一次。`CodingDispatch` 怎么知道读不读得了：宿主（`CodingDispatchHost`）多一个可选的回调，

     ```ts
     /** P6：这个任务的项目现在读不了文件夹时，返回要告诉用户的那句话；读得了返回 null。 */
     folderGap?: (taskId: string) => string | null;
     ```

     没给这个回调的宿主行为不变。项目没绑文件夹（P4 那句）也经这个回调走同一条路。

5. **已经在执行的任务不管**。它用的是早先抄好的副本，不会再去读项目文件夹；要停，用户自己取消。

## 约束

- 不加迁移。核心层 `CodingOrchestrator`、`prepareWorkspace` 不动（理由同 P4：现有集成测试和回归直接在没发授权的项目上用它们）。
- 授权还在的项目，一切照旧。
- **整合方锁测试时会处理的一件事**：现有的锁定验收测试里，有的搭项目时只设了 `root_path`、没发文件夹授权（比如 D1）。这一单实现之后它们会被拦住。这些测试由整合方在锁 P6 的测试时补上授权并重锁；执行方不要动它们，实现时看到它们红了，先确认是不是这个原因，是就写进交付说明。

## 验收条件

1. 绑着文件夹、授权撤销了（对一份从这个文件夹导入的资料调 `revokeSourceReading` 造出来）：
   - `propose_coding_task` → 不建草案、不记审计，返回的错误就是「授权已撤销那句」；
   - 已有的草案点「要做」→ 报这句话；任务没批准，`workspace_path` 还是空的，数据目录里没有这个任务的副本目录；待办还是「等你拍板」；
   - 任务页批准 → 报这句话，同样没批准、没建副本。
2. 早先批准好、在排队的任务，之后授权撤销：任务页点派发 → 报这句话，任务还在排队，执行器没被调。
3. 同样的任务，自动派发轮到它：不派发，留在排队，对话里出现一条 `folder_missing` 的回报，内容是契约 4 那一句；再触发几次自动派发，回报还是一条。
4. 排在它后面的、别的项目（授权还在）的任务照常派发、做完。
5. 上级文件夹的授权还有效：算有授权，批准、派发照常。
6. 授权还在的项目：P4、D1、D3、D7b 的锁定测试照过（按「约束」里说的补过授权之后）。
7. 没绑文件夹的项目：报的还是 P4 那一句，不是这一句。
8. 已经在执行的任务，执行途中授权撤销：任务照常跑完（不被这一单拦下、不被取消）。

## 真机检查

改了返回给模型的内容，要用真 Hermes 问一次：

- 给 `scripts/real/hermes-ask.ts` 加一个 `--project-revoked`：建的合成项目绑着合成文件夹，随后把这个文件夹的授权撤销，其余和 `--project` 一样；
- `--project-revoked` 下问一个开发请求：没建草案，Hermes 的回答里转告了要去解除绑定、重新绑定；
- `--project` 下问同一个开发请求：照旧建出草案（确认没被误拦）；
- 原样贴两次的输出。

界面上再看一遍（临时数据目录、合成数据、`IXAEON_CODEX_EXE=none`，脚本 `scripts/real/p6-revoked-folder.mjs`）：绑定合成文件夹 → 从它导入一次资料 → 来源页对其中一份点「撤销读取」→ 任务页建草案、点批准：打印报的错，并查临时库确认任务没批准、副本目录没建（只输出状态和有没有）。
