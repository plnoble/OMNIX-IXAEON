# 规格 V2：端到端测试在 main 上 8 项失败——查清、修好、接进 CI

档位：**A**（测试与 CI 接线；若查出是真回归，按下面第 3 条停下交整合方）。大小：以测试和 CI 配置为主。依赖：无。来源：C3 交付说明「真机检查」一节（调研 agent 2026-09-30 实测：`node scripts/test-e2e.mjs` 在 main 上 8 失败 / 9 通过）。
v2 规格：验收以「端到端测试全绿 + 逐项处理记录」为准，记录写进交付说明；Codex 审查时核对有没有把真问题当成过时断言改掉。

## 要什么

CI（`.github/workflows/verify.yml`）只跑 `node scripts/verify.mjs`，`apps/desktop/e2e/` 下的端到端测试不进门禁，坏了没人发现。C3 实测 main 上 8 项失败：

```
e2e\d6-chat-ui.spec.ts:300       断言「排队中」实得「进行中」
e2e\m2-ui.spec.ts:427            可见性断言 ×2（S1/S2）
e2e\screenshots.spec.ts:128      可见性断言
e2e\smoke.spec.ts:132/138/158/231  总览端口、设置页 MCP 片段、MCP 握手超时 ×4
```

整合方初判（未验证）：冒烟那几项很像是端口 43191 被正在运行的 IXAEON 占着；`d6-chat-ui` 那项可能是 D3「点要做就自动开工」之后状态从「排队中」变成了「进行中」，测试没跟着改。都要复跑确认。

## 步骤

1. **在端口空闲时复跑**（先关掉本机正在运行的 IXAEON，确认 43191 没被占）：`node scripts/test-e2e.mjs`，原样贴结果。和上面的清单对比，记下哪些是端口冲突造成的。
2. **端口守卫**：端到端测试启动前照 C3 的 `apps/desktop/test/review/ui-port-guard.ts` 做同样的检查，端口被占就明确提示「先关掉正在运行的 IXAEON」，而不是跑出一堆含糊的失败。
3. **剩下的逐项定位**，每项归到下面一类，写进交付说明：
   - 断言过时：行为是被后来某个锁定规格明确改掉的——写明是哪个规格、哪一条，改断言；
   - 测试本身的问题（等待不够、选择器写错等）——改测试，写明原因；
   - **看起来是真回归**（现行为不对）——停下，不改测试也不改产品代码，列出来，队列改「待复审（整合方）」。
4. **接进 CI**：在 `verify.yml` 里 `verify.mjs` 之后加一步跑 `node scripts/test-e2e.mjs`（CI 上没有正在运行的 IXAEON，端口是空的）。

## 验收条件

1. 端口空闲时 `node scripts/test-e2e.mjs` 全绿，原样输出贴进交付说明。
2. 端口被占时，端到端测试开头就给出「先关掉正在运行的 IXAEON」的明确提示，不再跑出含糊的失败（实测一次，贴输出）。
3. 8 项失败每一项都有归类和处理记录；归为「断言过时」的，写明对应规格的哪一条。
4. CI 里多了端到端测试这一步，推送后 CI 是绿的（贴运行号）。

## 真机检查

即第 1、2 条的实测输出。
