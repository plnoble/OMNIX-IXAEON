# 规格 P5：解除项目和文件夹的绑定，撤销这个文件夹的读取授权

档位：**B**（权限：新增一个撤销文件夹授权、取消任务的入口）。大小：中（≤200 行源码）。依赖：无。来源：P4 留下的缺口；用户 2026-10-06 同意加。

v2 规格：先把验收条件写成测试（`apps/desktop/test/acceptance/p5-*.test.ts`），**先只推测试**，整合方看过并锁定后再实现。

## 要什么

P4 让项目页能给项目绑定文件夹，绑定时发一条这个文件夹的读取授权。绑上之后界面上就再也解不开了：项目行上只显示路径，没有解除绑定的地方，也没有撤销这条授权的地方。用户想让 IXAEON 不再读某个文件夹，办不到。

这一单：项目页上绑了文件夹的项目多一个「解除绑定」。点了先说清楚后果，确认之后：项目不再绑这个文件夹，这个文件夹的读取授权撤销，这个项目正在排队或执行的编码任务取消。已经做完的任务、任务的副本、已有的记忆都不动。

## 契约（接口写死，不改名、不加字段）

1. **类型**（`packages/contracts/src/entities.ts`）：

   ```ts
   /** 解除绑定之前先看一眼后果。只读，不改任何东西。 */
   export interface UnbindProjectFolderPreview {
     /** 现在绑着的文件夹。 */
     rootPath: string;
     /** 会被取消的编码任务数（排队、执行中、验证中的）。 */
     inFlightTasks: number;
     /** 做完了还没接受的任务数：解除之后再接受，改动落不到项目里。 */
     pendingAcceptTasks: number;
     /** 那条授权下导入过的资料数：授权撤销之后不再读它们的原文。不撤销时是 0。 */
     sourcesUnderGrant: number;
     /**
      * 授权怎么处理：revoke = 撤销；kept_other_project = 别的项目也绑着这个文件夹，不撤销；
      * none = 这个文件夹没有单独的有效授权，没有可撤销的。
      */
     grant: 'revoke' | 'kept_other_project' | 'none';
   }
   export interface UnbindProjectFolderResult {
     /** 解除之后的项目（root_path 是 null）。 */
     project: Project;
     /** 撤销了哪条授权；没撤销是 null。 */
     revokedPermissionId: string | null;
     /** 一并取消了的编码任务。 */
     cancelledTaskIds: string[];
   }
   ```

2. **两个接口**（`packages/contracts/src/ipc.ts`、`apps/desktop/src/main/ipc.ts`、`apps/desktop/src/preload/index.ts` 三处；业务逻辑放在 `AppRuntime` 上的同名方法，IPC 只转一下，测试直接测这两个方法）：

   ```ts
   previewUnbindProjectFolder(projectId: string): Promise<UnbindProjectFolderPreview>;
   unbindProjectFolder(projectId: string): Promise<UnbindProjectFolderResult>;
   ```

   输入只有项目 id，不用票据：绑定要票据是因为它会**发**授权，不能让渲染层随手给任意文件夹授权；这两个接口只会收回授权。

3. **「这个文件夹的授权」是哪一条**：有效的（`status = 'active'`）、文件夹类的、`locator` 和项目的 `root_path` 是同一个文件夹的那一条。比较办法照 `bindProjectFolder` 里的 `canon`（真实路径、统一斜杠、Windows 上不分大小写）。只覆盖它的**上级**文件夹的授权不算——那是用户为别的事另外发的，不动。

4. **`unbindProjectFolder` 做什么**，按这个次序：

   1. 取消这个项目在排队、执行中、验证中的编码任务（`coding.cancel`，再 `codingDispatch.onTaskSettled`，发起它的对话里会出现「取消了」的回报）。先取消，免得执行器还在读。
   2. 项目的 `root_path` 清空（`rebindRoot(id, null)`）。
   3. 撤销契约 3 说的那条授权（`permissions.revoke`）。两种情况不撤销：别的项目（不管什么状态）也绑着同一个文件夹；没有这样一条授权。
   4. 记一条审计 `project.folder_unbound`（项目 id、撤销的授权 id 或 null、取消了几个任务）。
   5. 让正在用的对话上下文失效（`invalidateContext()`，和 `revokeSourceReading` 一样）：项目近况是从这个文件夹读出来的，不能接着用。

   **不删任何东西**：草案、等批准的、等接受的、已经结束的任务都不动；任务的副本目录不删；来源、条目、对话都不动。

5. **授权撤销连带的**（不是这一单新加的规则，是撤销一条授权本来就有的效果，要在确认里告诉用户）：从这个文件夹导入过的资料挂在同一条授权下，授权撤销后它们在来源页显示「授权已撤销」，不再读原文，已经提炼出的理解保留。之后重新绑定发的是一条新授权，这些资料恢复不了，要再用得重新导入。

6. **拒绝**（报错，项目、授权、任务、审计都不改）：项目不存在；项目没绑文件夹（「这个项目没有绑定文件夹」）。

7. **界面**（`apps/desktop/src/renderer/src/pages/Projects.tsx`）：

   - 绑了文件夹的项目行，路径旁边有按钮「解除绑定」（`data-testid="project-unbind-folder-<项目 id>"`）。没绑的没有。
   - 点了先调预览，用 `window.confirm` 问一次。文字照下面写；带数字的三行，数字是 0 就不出现；讲授权的那一行按 `grant` 三选一：

     ```
     解除「<项目名>」和这个文件夹的绑定？

     <路径>

     解除之后：
     - IXAEON 不再读这个文件夹：不能再给这个项目派编码任务，对话里也不再带这个文件夹的项目近况。
     - 这个文件夹的读取授权一并撤销。
       （或）读取授权不撤销：另一个项目也绑着这个文件夹。
       （或）这个文件夹没有单独的读取授权，没有可撤销的。
     - 这条授权下导入过 <N> 份资料：不再读它们的原文，已经提炼出的理解保留。重新绑定也恢复不了，要再用得重新导入。
     - 有 <N> 个编码任务正在排队或执行，会被取消。
     - 有 <N> 个任务做完了还没接受：解除之后再点接受，改动落不到项目里。可以先去任务页接受，或者之后重新绑定再接受。

     已经做完的任务、它们的隔离副本（里面有当时的项目文件）和已有的记忆都不动。要清掉副本，在任务页逐个删除任务。
     ```

   - 取消确认：什么都不发生。
   - 确认：调 `unbindProjectFolder`，项目行马上变成「构想（未绑定目录）」和「绑定文件夹」按钮，不用重启；页面上显示一句结果（`data-testid="project-unbind-result"`）：「已解除绑定。」后面按实际情况接「这个文件夹的读取授权已撤销。」或「读取授权没有撤销。」，取消了任务再接「取消了 <N> 个编码任务。」
   - 出错：显示在这一页现有的报错条里，项目行不变。

## 约束

- 不加迁移。不删数据。
- P4 的绑定逻辑不动；`bindProjectFolder` 的锁定测试照过。
- 删除项目的行为不变。（删除项目不会撤销它绑的文件夹的授权，是已知缺口，这一单不做，交付说明里照写。）
- 测试、交付说明里的路径、项目名用合成的。

## 验收条件

1. 解除绑定：项目的 `root_path` 是 null；那条授权变成 `revoked`；审计 `project.folder_unbound` 一条（项目 id、授权 id、取消的任务数）；返回的项目没有路径，`revokedPermissionId` 是那条授权的 id。
2. 解除之后这个项目派不了编码任务：`propose_coding_task`、点「要做」、任务页批准，都报 P4 那句「这个项目还没绑定文件夹……」。
3. 解除时在排队、执行中、验证中的任务被取消（状态 `cancelled`，id 在 `cancelledTaskIds` 里，发起它的对话里有「取消了」的回报）。草案、等批准的、等接受的、已经结束的任务状态不变。所有任务的副本目录都还在。
4. 这条授权下导入过资料：解除之后这些资料的授权状态是已撤销；从它们提炼出的条目一条不少。
5. 别的项目也绑着同一个文件夹（路径大小写、斜杠方向不同也算同一个）：只清这个项目的 `root_path`，授权仍然有效，`revokedPermissionId` 是 null；预览的 `grant` 是 `kept_other_project`，`sourcesUnderGrant` 是 0。
6. 这个文件夹没有单独的有效授权（比如那条早先已经撤销，或者只有上级文件夹的授权）：照样解除，`revokedPermissionId` 是 null，上级文件夹的授权不变；预览的 `grant` 是 `none`。
7. 预览不改任何东西：调用前后项目、授权、任务、审计都不变。数字对：要取消的任务数、等接受的任务数、这条授权下的资料数、`grant`。
8. 拒绝：项目不存在；项目没绑文件夹。两个接口都拒绝，什么都不变。
9. 解除之后重新绑定同一个文件夹：能绑上，是一条新的有效授权（原来那条还是 `revoked`）；解除之前等接受的那个任务，这时点接受，改动能落进项目（建出分支）。
10. 解除绑定让对话上下文失效（调了 `invalidateContext`）。
11. 界面：绑了文件夹的项目行有「解除绑定」，没绑的没有；点了出确认，文字里有项目名、路径和契约 7 的各行，数字是 0 的行不出现，讲授权的那一行跟着 `grant` 变；取消确认不调 `unbindProjectFolder`；确认之后项目行变成「构想（未绑定目录）」和「绑定文件夹」，结果那句话如实（撤没撤销、取消了几个）。
12. IPC：`registerIpc` 注册了这两个接口，调它们得到的和 `AppRuntime` 上的方法一样。
