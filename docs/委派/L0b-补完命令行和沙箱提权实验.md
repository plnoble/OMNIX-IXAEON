# 规格 L0b：补完三个命令行的实验，加一次 Codex 沙箱提权（实验，不改应用）

档位：**B**（花少量真额度；一次提权会改系统里的沙箱设置）。大小：不改应用源码，只交实验脚本和结论。依赖：D2c、L0 ✅。来源：D2c、L0 的结论（见各自交付说明），用户 2026-10-20 定了三件：**试一次提权**；**DSH 的 DeepSeek key 用户已经配好**；推送照流水线规矩、不用每次问。

## 为什么

接力调度器要的三个角色，D2c、L0 之后各卡在一处：

- **统筹（Claude）**：后台不给权限就写不了文件。不开「跳过所有权限」，改用**只放行必要操作的白名单**行不行，没试过。
- **开发（DSH）**：L0 时没有 key，调不动。用户现在配好了。
- **审核 / 依赖档（Codex）**：新版沙箱不提权一律起不来；默认又不限它往哪儿写。**提权装一次之后，以后还要不要每次提权**——这一条决定 Codex 能不能关在目录里、V4 能不能做，是最关键的未知。

这一单把这几处补完，整合方据此写接力调度器接 CLI 的那一单、改 V4 的规格。

## 要回答的问题

### 甲、DSH（补 L0 那一列）

照 L0 找到的办法调 DSH（安装目录里的 `dsh.cmd`，`--profile headless --json`），回答 L0 的问题 2、3、5、6、7、8：

- 最小真调用能不能成（回一句固定的话）、结果从哪个字段取、用时、用量字段；
- **能不能关在一个目录里**：DSH 有哪些权限 / 沙箱设置（看它的帮助和 `~/.dsh` 下那套配置的**键名**，不看值），照 L0 的办法实测「目录里建文件」「往目录外建文件」；
- 能不能按会话号接着上一轮；
- 和 Claude 同时跑会不会打架（L0 当时没测成的那一组）；
- 跑前跑后 `~/.dsh` 下哪些文件变了（只比时间和大小）。
- **不许把它设成「完全放开、从不询问」**（Ekko 就是这么用 DSH 的，这里不照搬）。不放开就关不住的，如实写。

### 乙、Claude 用白名单写文件

L0 证明了 `claude -p` 不给权限就写不了。试**只放行必要操作**的办法（不许用 `--dangerously-skip-permissions`、`--allow-dangerously-skip-permissions`、`bypassPermissions` 这一类）：

- 命令行上的白名单（`--allowedTools` / `--permission-mode` 这类，查它的 `--help`）或项目目录里的权限设置文件，二选一或都试；
- 放行「改这个目录里的文件」和几条固定命令（比如 `git status`、`node --version`），实测：目录里建文件（应当成）、目录外建文件（应当被拒）、跑一条没放行的命令（应当被拒）；
- 白名单写在哪最稳（命令行 / 项目里的设置文件），会不会被它自己改掉。

### 丙、Codex 按会话号续（补 L0 的第 5 问）

`codex exec resume <thread_id>`：第二次能不能记得第一次说过的一个合成的词。

### 丁、Codex 沙箱提权一次（补 D2c 的 3、4、5、8 问和缺口 4）

**这一步会在用户电脑上弹一次 Windows 管理员确认，要用户本人点「是」。所以跑这一步之前必须先停下来，在对话里跟用户说清楚「接下来要弹管理员确认了，会装或更新 Codex 的沙箱账户、服务和防火墙规则」，等用户回「好」再跑。用户没回、或者说不行，就不跑，把前面的做完、这一步写「用户没同意」。**

1. 用一个**专门的 CODEX_HOME**（放在 `%TEMP%` 以外的一次性目录：D2c 查到新版不在 `%TEMP%` 下建辅助程序），照 D2c 的配方、加上提权的那个设置，跑**一次**空命令。用户点「是」。记下：弹了几次、成没成、装了 / 改了什么（服务、账户在不在、跑前跑后对比；不改它们）。
2. **装完之后，还要不要每次提权**：同一个 CODEX_HOME，再连跑 10 次（带提权设置、不带提权设置各试），看弹不弹窗、成不成。**这是这一单最要紧的答案。**再换一个**新的** CODEX_HOME 跑一次：看提权是「整台机器一次」还是「每个 CODEX_HOME 一次」。
3. 沙箱能用了之后，补 D2c 的问题 3、4、5、8：合成项目里跑一个合成的 vitest 测试（`node_modules` 用目录链接接进副本，照 D2 的做法）；联网挡不挡得住（本机端口、外网 443，只建连接不发数据）；往副本外写、经目录链接往真实依赖写挡不挡得住；沙箱里外的用时。
4. 顺带：用户自己的 `~/.codex/.sandbox-bin` 在 L0 时报过「加锁失败、访问被拒」。看提权装完之后，**用默认配置目录**跑 `codex exec -s workspace-write`（只回一句话、不改文件）还报不报这个错。**只看、不修**——要修也是用户的配置，写清楚就行。

- 花钱要省：DSH、Claude 各不超过 8 次真调用，Codex 不超过 4 次（沙箱命令不调模型，不算）。问题都用合成的、很短的。

- 不用任何「跳过所有权限 / 完全放开」的开关。
- 输出遮掉临时目录的两种写法和用户目录。
- 碰到预料之外的弹窗：不点、不绕，停下，原样写进交付说明。
