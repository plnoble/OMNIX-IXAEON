# 规格 L6：调度器替开发推送（DSH 只提交，调度器推）

档位：**B**（调度器开始用用户的 GitHub 登录态替模型推送；改发给模型的交代）。大小：中（约 160 行源码，超过 300 行拆 L6 / L6b）。依赖：L5。来源：L5 真机检查甲（[交付说明](交付/L5.md)）：DSH 的沙箱里，git 调凭据助手要经过 `sh.exe`，受限令牌下起不来，所以带登录的推送永远失败；用户 2026-10-22 定了「调度器替 DSH 推」。

v2 规格：先把验收条件写成测试（`packages/relay/test/acceptance/l6-*.test.ts`），**先只推测试**，整合方锁定后再写实现。真机检查「甲」不依赖实现，可以和测试一起先做。

## 要什么

1. **DSH 里的 git 连得上 GitHub**（拉取、看远端；不含登录）：L5 那条 `GIT_CONFIG_COUNT` 的路被 DSH 擦环境变量堵了。改用 git 自己传 `-c` 设置用的环境变量 `GIT_CONFIG_PARAMETERS`（名字里不带被擦的字样）。
2. **调度器替开发推**：开发只提交、不推；在输出里写清要推哪些；这一棒结束后，调度器用用户本机的登录态替它推。**只许推开发的 `dev/` 分支和不强推的 `main`，只许从开发的工作目录里推，不许强推、不许删远端分支。**推完照常核对越界。
3. 调度器原来的规矩「自己不改仓库、不推送」，从这一单起改成「**只替标了 `pushByRelay` 的角色、照上面的限制推送**」；别的照旧（不 checkout、不 pull 进整合方目录、不改文件）。

## 契约（接口写死，不改名、不加字段）

1. **启动器**（`packages/relay/bin/dsh.mjs`）：起 DSH 时在环境变量 `GIT_CONFIG_PARAMETERS` 末尾追加 `'http.sslBackend=openssl'`（原来有值就用一个空格隔开、原来的放前面；没有就只有这一项）。**不设** `GIT_CONFIG_COUNT`、`GIT_CONFIG_KEY_*`、`GIT_CONFIG_VALUE_*`。
2. **配置**：`RoleConfig` 加一个可选字段 `pushByRelay?: boolean`。`relay init` 生成的配置里开发角色写 `true`、整合方不写；`config.example.json` 同。
3. **交代**：`pushByRelay` 为真的角色，交代里加一段（逐字）：

   > 这一棒的推送由调度器替你做：你只提交，不要 git push。要推的，在最后一行之前每条写一行：`RELAY-PUSH <工作目录的绝对路径> <本地分支> <远端分支>`。远端分支只能是 main 或者以 dev/ 开头。

   别的角色的交代不变。

4. **推送**：`runTurn` 之后、`verifyTurn` 之前，对 `pushByRelay` 为真的角色：
   - 从输出里收 `RELAY-PUSH` 行（和 `RELAY-DONE` 一样认 Claude 的 `result`、DSH 的 `final.text`、普通文字；按出现的先后），函数 `parsePushLines(stdout): Array<{ dir: string; local: string; remote: string }>`，放 `src/push.ts`。
   - 每一条先查，有一条不过就**一条都不推**，停下（`stoppedReason` 写「第 N 棒替开发推送被拒：<原因>」）：`dir` 在这个角色的 `cwd` 里面（照 `isInside`）；`dir` 是调度器所在仓库的工作目录（`git -C <dir> rev-parse --git-common-dir` 和主检出的一样）；`remote` 是 `main` 或以 `dev/` 开头；`local`、`remote` 里没有 `+`、`:`、空格，不以 `-` 开头。
   - 都过了就按先后推：`git -C <dir> push origin <local>:refs/heads/<remote>`（不加 `--force`；`main` 不是快进 git 自己会拒）。有一条失败就停下（「第 N 棒替开发推送失败：<remote>」），后面的不推。
   - 记账加一个可选字段 `pushes?: Array<{ dir: string; local: string; remote: string; ok: boolean }>`。
   - 停下时照 L2b 发飞书 `stopped`。
   - `pushByRelay` 不为真的角色输出了 `RELAY-PUSH`：不推、不停，记账里不写 `pushes`。

## 约束

- 测试用替身和临时 git 仓库（裸仓库当 origin），不调真模型、不连 GitHub。
- 不改用户的 git 全局设置和凭据设置；不把令牌写进任何文件或环境变量。
- L1–L5 已锁定的测试不改，要和这一单一起过。

## 验收条件

1. **启动器**：替身打印收到的环境：没有 `GIT_CONFIG_PARAMETERS` 时 → 它是 `'http.sslBackend=openssl'`；原来是 `'core.autocrlf=false'` 时 → `'core.autocrlf=false' 'http.sslBackend=openssl'`；没有 `GIT_CONFIG_COUNT`。
2. **交代**：`pushByRelay` 为真 → 交代里有第 3 条那段原文；不为真 → 没有。`relay init` 写出的开发角色 `pushByRelay` 是 `true`。
3. **替推成功**：开发替身（`pushByRelay: true`）在它 `cwd` 里的克隆上提交到本地 `dev/x` 和 `main`（快进），**不推**，输出两行 `RELAY-PUSH` → `once` 之后裸仓库上有 `dev/x`、`main` 前进了；记账 `pushes` 两条都 `ok: true`；核对照常（这一笔不是「并入 B 档」就不越界）。
4. **替推被拒**：远端分支是 `release/x`、`dir` 在 `cwd` 外面、`local` 带 `+`——各一条：一条都没推（裸仓库没变）、停下、原因里写清。
5. **替推失败**：开发替身的本地 `main` 不是快进（先往裸仓库推一笔别的）→ 推送失败、停下、裸仓库的 `main` 还是那一笔（没被强推掉）、飞书收到一条 `stopped`（用假飞书）。
6. **没标的角色不推**：整合方（没标 `pushByRelay`）输出 `RELAY-PUSH` → 裸仓库没变、不停下、记账里没有 `pushes`。

## 真机检查

**甲：DSH 里的 git 能不能连 GitHub、`gh` 和 `codex` 登没登上（不依赖实现，可以先做；DSH 真调用不超过 2 次）**——`scripts/real/l6-dsh-tools.mjs`：起 DSH 时环境里带上第 1 条的 `GIT_CONFIG_PARAMETERS`（脚本里自己加），让它在临时目录里跑：`git ls-remote https://github.com/plnoble/OMNIX-IXAEON.git main`、`git clone --depth 1` 再 `git fetch`、`gh auth status`、`codex login status`（**都不调模型、不推送**），把每条的退出码和输出（遮掉用户目录、遮掉任何像令牌的东西）记下来。这决定 DSH 当开发时能不能自己看 CI（`gh`）、自己调 Codex 审查（A 档要）。

**乙：真 DSH + 调度器替推（要实现；DSH 真调用不超过 2 次）**——`scripts/real/l6-relay-push.mjs`：临时裸仓库 + 开发的工作目录根（里面一个克隆），合成队列一行「待领」；开发用真 DSH（`pushByRelay: true`），整合方用替身；`relay once`。看：DSH 有没有照交代只提交、写出 `RELAY-PUSH`；调度器推上去了没有；记账的 `pushes`。不连 GitHub。

## 整合方审测试时的改正与补充（2026-10-23）

整合方写了一份一次性实现（没提交）把测试跑通，再逐处改坏做变异检查，补了漏的，然后锁定（`l6-launcher` `l6-prompt` `l6-push`，连同共用骨架 `l6-harness.ts`）。

- **开发定的接缝，接受**：替推的测试不走 `bin/relay.mjs`（它把 `cwd` 固定在仓库根上，开发的 `origin` 就是真的 GitHub，测试会真往公开仓库推），而是用 jiti 直接起 `relay-main.ts`、把 `cwd` 设在临时的合成仓库上。所以实现里「`dir` 是调度器所在仓库的工作目录」要拿 `findSharedCheckout()`（照当前目录算）比，不要拿脚本位置算——生产里 `relay.mjs` 把 `cwd` 定在仓库根，两种算法结果一样。
- **交代里那一段是纯文字**：规格里的反引号只是排版，交代里不带反引号（测试按 `l6-harness.ts` 的 `PUSH_PARA` 三句核）。
- **`RELAY-PUSH` 行的切法**：最后两个词是本地分支、远端分支，前面剩下的整段是目录（目录里可能有空格）。
- 整合方补的：替推上去的「并入 B 档」照样认成越界（**先推后核对**，倒过来就漏了）；`dir` 在 `cwd` 里面但是另一个仓库 → 拒；同一个仓库的工作目录、但不在开发的 `cwd` 里 → 拒（原来那条用的是另一个克隆，会先被「不是同一个仓库」拦下，测不到这一道）。
- 真机检查甲的结论：DSH 里带上 `GIT_CONFIG_PARAMETERS` 之后 git 连得上 GitHub（`ls-remote`、`clone`、`fetch` 都成）；`gh auth status` 成（能看 CI）；`codex` 不在 PATH 上，但 `scripts/codex-review.mjs` 自己找 Codex 桌面版带的 `codex.exe`，A 档审查不受影响。
