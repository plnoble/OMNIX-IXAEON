# 规格 X1：提炼时从摘录里打捞真依据，别让一份资料白分析

档位：**B**（改提示词、改提炼规则 = 改变什么能进记忆）。大小：中（≤300 行源码）。依赖：无。
v2 规格：先把验收条件写成测试（`packages/core/test/acceptance/x1-*.test.ts`），**先只推测试**等整合方看过并锁定，再实现。

## 要什么

2026-09-20 看用户的真实库：**47 份资料里 31 份从没产出过任何记忆**，现有 94 条记忆只来自 16 份。分析任务历史失败 223 次，最大的一类是「模型给的依据对不上原文」（约 100 次）。

看了失败的例子：模型给的摘录是把原文里**不连续的几处拼起来**（一个 Markdown 标题 + 正文一句 + 代码块开头），校验判它不是原文里的话——**校验没判错**。现在的规则是：对不上的那条丢掉；一条都对不上时整份作废。于是一份资料白分析。

要做的是：判无效之前先**打捞**——模型的摘录里通常包含一段真的是原文的话，把那一段截出来当依据。

## 契约

1. `packages/core/src/extraction/extractor.ts`，在 `isExcerptGroundedInSegment` 旁边加并导出：

   ```ts
   export function groundExcerptInSegment(excerpt: string, segmentText: string): string | null;
   ```

   - 两边按现有那套规范化（去掉空白与零宽字符、统一中英文引号）；
   - 找出摘录里**真正出现在片段中的最长连续一段**；规范化后长度 ≥ 15 个字符才算打捞成功；
   - 返回的是**片段原文里的那一段原样文字**（保留原来的换行、标点、大小写），不是规范化后的串，也不是模型给的拼接串；
   - 打捞不到返回 `null`。
   - 实现提示：规范化时记住「规范化后的位置 → 原文位置」的映射，才能把原文切回来。

2. 提取流程：摘录 `isExcerptGroundedInSegment` 不通过时，先试 `groundExcerptInSegment`。
   - 打捞成功 → 用打捞出来的那段当 `excerpt` 入库，计入 `salvaged`；
   - 打捞失败 → 仍然算无效依据（现有逻辑不动）。
3. 审计 `extract.excerpt_salvaged`：`sourceId`、`salvaged`、`dropped`。资料页显示分析说明的地方加一句「N 条依据按原文截短后保留」（有才显示）。
4. 提示词（**措辞整合方定，一个字不改**）：`EXTRACT_SYSTEM_PROMPT` 里加一句——

   > 摘录必须从原文里逐字复制**连续的一段**：不要跨行拼接、不要改写、不要把两处并成一句。找不到能逐字复制的一段，就不要给这条结论。

   `EXTRACT_PROMPT_VERSION` 升到 `'v6'`。

5. 重新分析：核心层加 `requeueFailedExtractions(db)`——把最后一次失败原因里含「依据对不上原文」或「无效引用/依据」的来源重新排进分析队列（同一来源只排一个，沿用 A1 的「只看最新一条」规则），返回排了几个；其它失败原因（网络、限流、模型未配置）不碰。资料页顶部加按钮「重新分析失败的资料（N 份）」，N 为 0 时不显示。

## 约束

- 打捞出来的必须**真的在原文里、且连续**——这是底线，不许放宽成「词都出现过」。
- 不加迁移；不动 E2/E5 的回声判定与 `said_by` 规则；不动「全部都打捞不到就整份作废」。

## 验收条件

1. 模型的摘录把原文里两处拼在一起（中间夹了别的字）：打捞出其中最长的连续一段入库；入库的 `excerpt` 与原文逐字相同（含原来的换行），不是模型给的串。
2. 摘录整段都不在原文里（模型自己编的）：打捞不到，这条仍然不入库。
3. 打捞出的最长一段规范化后不足 15 字：算无效依据，不入库。
4. 一份资料 3 条结论：2 条靠打捞、1 条是编的 → 入库 2 条，丢 1 条，任务成功；审计里 `salvaged=2`、`dropped=1`。
5. 全部结论都打捞不到 → 整份作废，旧理解不变（现有行为不许改坏）。
6. `EXTRACT_SYSTEM_PROMPT` 含上面那句话；`EXTRACT_PROMPT_VERSION === 'v6'`。
7. `requeueFailedExtractions`：只排因依据问题失败的来源，每个来源一个任务；网络、限流失败的不动；返回值等于实际排的个数。

## 真机检查

提炼用的是设置页配置的模型，Key 在 Electron 加密存储里，脚本进程解不开——**执行方跑不了真机**，交付里如实写「待用户在应用里点一次『重新分析失败的资料』验证」。自动化必须覆盖上面 7 条（用假模型造出「拼接摘录」「编造摘录」两种输出）。
