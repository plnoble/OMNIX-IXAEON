# 规格 Q1：真机脚本体检——不花钱能跑的都跑一遍，过时的修好

档位：**A**（只改 `scripts/real/` 下的脚本和交付说明，不改应用源码）。大小：不计源码行数（脚本不计）。依赖：无。来源：整合方 2026-10-19 排的无人值守任务。

## 要什么

`scripts/real/` 下有 48 个真机检查脚本，是这一个多月里各个任务留下的。应用改了很多（设置向导、P6 之后绑文件夹要先有授权、各页的 testid……），这些脚本有多少现在还跑得通，没人知道。复审时一直拿它们当证据，过时了就是假证据（P6 复审时已经看到 `d3-auto-dispatch.ts`、`u4-open-task-from-report.mjs` 直接改库设路径、没发授权）。

这一单：把每个脚本读一遍、分类；**不花钱、只用合成数据**的那些，在最新的 main 上逐个跑；跑不通的查原因——脚本过时就照现在的规矩修好，应用有毛病就写清楚、不改应用。

## 步骤

1. 逐个读脚本，分五类（一个脚本只归一类，拿不准就归到更严的那类）：

   | 类   | 是什么                                                                                       | 这一单怎么办                     |
   | ---- | -------------------------------------------------------------------------------------------- | -------------------------------- |
   | 甲   | 只用合成数据、临时数据目录；不调真模型、不连网关、不跑真 Hermes、不让真 Codex 执行；不弹授权 | 跑                               |
   | 乙   | 调真模型或网关、跑真 Hermes、让真 Codex 执行任务（要花钱或用额度）                           | **不跑**，只列出来               |
   | 丙   | 会弹管理员确认、装系统账户或服务（比如 `d2b-e1-helper-auth.mjs`）                            | **不跑**，只列出来               |
   | 丁   | 读用户的真实数据，哪怕是副本、只输出数字（比如 `p6-folder-grant-counts.mjs`、`agent-sessions.ts`） | **不跑**，只列出来               |
   | 戊   | 一次性的实验记录（`d2-e*`、`d2b-e*` 这类）                                                   | 不跑，标「实验记录」             |

2. 先 `node scripts/build.mjs`，再把甲类逐个跑一遍，记退出码和 `RESULT` 那一行。**每个脚本跑之前核对它设了 `IXAEON_DATA_DIR` 指到临时目录**；没设的不许跑，先改成设了再跑（默认数据目录就是用户的真实数据）。
3. 没通过的查原因：
   - **脚本过时**（testid 变了、首次设置的步骤变了、P6 之后绑文件夹要先发授权、真机规矩没跟上……）：照现在的规矩改（照 `scripts/real/p7-revoke-reading.mjs` 的写法：临时数据目录、随机端口、`IXAEON_EMBED_MODEL=none`、`IXAEON_CODEX_EXE=none`、打印遮掉临时目录的两种写法、只有全都符合才写「通过」、`RESULT` 和退出码一致、脚本出错非零），改完重跑。
   - **应用的毛病**：不改应用。写清楚怎么复现（用合成数据）、期望看到什么、实际看到什么，贴原样输出。
4. 甲类里本来就没有 `RESULT`、或者 `RESULT` 和退出码对不上的老脚本：补上。

## 范围

- 只改 `scripts/real/*` 和交付说明。**不改 `apps/`、`packages/` 的源码**，不改测试，不改门禁。
- 不删脚本。过时到救不回来的，在清单里标「建议删」和理由，由整合方定。
- 乙、丙、丁类一个都不跑，也不「试一下」。

## 验收标准

1. 交付说明 `docs/委派/交付/Q1.md` 里一张表，48 个脚本每个一行：类别、跑没跑、结果（退出码 + `RESULT`）、改了什么（没改写「没改」）。
2. 甲类每一个：要么最后通过了，要么写清楚了没通过的原因（脚本的问题已修好重跑；应用的问题有复现步骤）。
3. 改过的每个脚本：贴改完后重跑的原样输出。
4. 输出里没有本机账户名、没有真实数据（本机 `node scripts/verify.mjs` 里的 `local-user` 一步要过）。
5. A 档：`node scripts/codex-review.mjs Q1`，照 AGENTS.md 合并。

## 风险

- 默认数据目录指向用户的真实数据：上面第 2 步的核对一步都不许省。
- 用户自己的 IXAEON 开着时：**不启动任何测试用的应用**，也不关用户的应用；把要启动界面的脚本标「这次没跑：用户的应用开着」，接着做不用启动界面的部分。
- 脚本里有写死的本机路径：改成现算（`os.tmpdir()`、`LOCALAPPDATA`），见 AGENTS.md「公开仓库」。
