# 规格 N2：研究页显示每条发现对你每条要求的判定和理由

档位：**A**（界面 + 只读查询，不新增模型调用、不改判定规则）。大小：小（≤150 行源码）。依赖：N1（已完成）。来源：用户 2026-09-26 选的下一步。
v2 规格：验收条件写成测试（`packages/core/test/acceptance/n2-*.test.ts`，界面部分放 `apps/desktop/test/acceptance/`），测试和实现一起交，Codex 审查时核对测试有没有漏掉条件。

## 要什么

N1 只在一条发现**对上全部要求**时才在总览提醒——这是用户要的。但对不上的时候，用户什么都看不到：09-26 真实库里判了 9 次（对不上 7、看不出来 2），用户没法知道模型判得对不对，也就没法信任「没提醒 = 真没有」。

在研究页每条发现下面，把判定摆出来：默认一行摘要，展开看每条要求的判定和理由。这是给用户看的信息，不需要用户做任何操作（用户不想逐条审核）。

## 契约

1. 核心层 `listFindingJudgments(db, topicId)`：返回这个主题每条发现的判定，按发现 id 分组；每组按要求的 `sort_order` 排，每项 `{ requirementId, text, verdict, reason }`。`verdict` 取 `meets` / `fails` / `unknown`；这条要求还没判过时 `verdict` 与 `reason` 为 `null`。主题没有要求时返回空。
2. `researchSnapshot()` 的每条发现带上 `judgments`（上面那组；没有要求的主题不带或为空数组）。
3. 研究页每条发现下面（仅限有要求的主题）：
   - 摘要一行：「对照你的 N 条要求：对上 a · 对不上 b · 看不出来 c · 还没判 d」，为 0 的那项不写。全部对上时写「全部对上（总览已提醒）」。
   - 「理由」可展开（`<details>`），逐条列：要求原文、判定（对上 / 对不上 / 看不出来 / 还没判）、模型给的理由。
   - 超过判定窗口（抓取时间早于 7 天，`MATCH_WINDOW_DAYS`）且一条都没判过的发现，不显示这一行（它不会再被判，写「还没判」会误导）。
4. `data-testid`：摘要行 `finding-judgments-<发现id>`，展开区 `finding-judgments-detail-<发现id>`。

## 约束

- 只读：不新增模型调用，不改 N1 的判定、窗口和提醒规则。
- 不加迁移。

## 验收条件

1. 三条要求、一条发现判了两条（一条对上、一条看不出来）、第三条没判：`listFindingJudgments` 按要求顺序返回三项，第三项 `verdict`、`reason` 为 `null`。
2. 没有要求的主题：返回空，研究页不显示判定行。
3. 研究页摘要行只写非 0 的项；全部对上时写「全部对上（总览已提醒）」。
4. 展开后逐条显示要求原文、判定和理由；没判的写「还没判」。
5. 窗口外且一条都没判过的发现不显示判定行；窗口外但判过的照常显示。

## 真机检查

用临时数据目录（`IXAEON_DATA_DIR`）启动应用，往库里塞合成的主题、要求、发现和判定（直接写表），截图或描述研究页的摘要行与展开内容。
