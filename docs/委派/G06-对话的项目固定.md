# 规格 G06：一个对话属于它创建时的项目，不跟着下拉框变

档位：**B**（决定哪个项目的记忆和简报发给模型）。大小：小到中（≤200 行源码）。依赖：无。来源：[全局审核 2026-09-20](交付/全局审核-2026-09-20.md) G06。
v2 规格：先把验收条件写成测试（`apps/desktop/test/acceptance/g06-*.test.ts`），**先只推测试**等整合方看过并锁定，再实现。

## 要什么

现在打开历史对话只恢复对话 id 和消息，不恢复它的项目；下一问用的是界面下拉框当前选的项目，后端也不校验。于是打开 A 项目的旧对话、下拉框停在 B 时，下一问按 B 的记忆和项目近况回答。审核在真实 Electron 里复现过。

**整合方定的规则：对话的项目固定。** 一个对话属于它创建时的项目；要换项目就开新对话。不做「对话中途转移项目」。

## 契约

1. 界面（`Ask.tsx`）：
   - 打开旧对话时，项目下拉框切到这个对话的项目，并在对话打开期间**锁定**（不可选），旁边一行灰字「换项目请开新对话」；
   - 新对话（还没发第一句）时下拉框可选，第一句发出去之后锁定；
   - 「新对话」按钮照常可用。
   - **整合方复审测试时定（2026-09-24）**：锁不锁看这个对话里**有没有消息**，不看有没有打开对话。「新对话」按钮按当时的下拉框立刻建一个空对话，这时下拉框仍可选。
2. 后端（`AppRuntime.ask()`）：以对话自己的 `project_id` 为准。调用方传来的 `projectId` 与对话的不一致 → `VALIDATION_FAILED`「这个对话属于另一个项目，换项目请开新对话」，不静默改用哪一个。
   - **整合方复审测试时定**：「全部项目」（`null`）和某个项目之间也算不一致。对话里**还没有任何消息**时（刚点了「新对话」），以第一问的 `projectId` 为准并写回对话；有了消息就固定。不这样的话，点了「新对话」再换项目，第一句就被拒。
3. 对话列表里每个对话显示它属于哪个项目（没有项目的写「全部项目」）。

## 约束

- 不加迁移（`conversations.project_id` 已有）；不改记忆选材本身。

## 验收条件

1. A、B 两个合成项目；界面当前选 B，打开 A 的旧对话：下拉框显示 A 且不可选，有「换项目请开新对话」。
2. 在这个对话里提问：派给引擎的是 A 的上下文（用替身截下发出的 `projectId`）。
3. 后端直接收到与对话不一致的 `projectId`：拒绝，什么都不发给模型。
4. 新对话：可以选 B；发出第一句后下拉框锁定为 B。
5. 对话列表里每个对话显示所属项目名。

## 真机检查

用临时数据目录（`IXAEON_DATA_DIR`）启动应用，照审核的复现步骤：建 A、B 两个合成项目，在 A 下开一个对话，切到 B，再打开 A 的对话，确认下拉框回到 A 且锁定。截图或描述。
