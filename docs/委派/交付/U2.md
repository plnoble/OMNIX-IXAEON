# U2 任务页自己跟上任务的状态；设置页写明现在生效的执行器——交付

- 整合方直接做的（没有委派）。档位 A（界面）。来由：用户 2026-10-05 在真实应用里试场景一。
- 没有单独的规格：条件写在两份验收测试开头。

## 用户遇到了什么

用户在聊天里说「在 README.md 末尾添加一行你好」，点了「要做」，然后在任务页看到「执行中 · 执行器 Codex」，等了很久，以为卡住了。查下来是两件事：

1. **任务其实三分多钟就做完了**（状态已经是「等你验收」，对话里也有回报），任务页却一直停在「执行中」。这一页只在打开时和点按钮之后读一次，任务是在后台跑的，做完了没人告诉它。
2. **做这件事的是 Codex，不是用户自己的模型。** 设置里「编码任务交给谁」保存的还是 Codex。这张卡片有自己的「保存」按钮，下拉框改了不点它不算数；页面上也看不出现在生效的到底是哪个。

用的是只输出状态的诊断脚本（`scripts/real/coding-task-status.mjs`，这次给它加了一列「对话里的回报」），没有读任务内容。

## 已实现

- `apps/desktop/src/renderer/src/pages/Tasks.tsx`：页面上有任务在排队、执行或验证时，每两秒读一次任务列表；都做完了就停，离开页面也停。只更新任务，不动用户正在看的报错条。
- `apps/desktop/src/renderer/src/pages/Settings.tsx`：「编码任务交给谁」卡片上加一行「现在生效的：……」（Codex / 我的模型（模型名）/ 我的模型但还没选模型）；下拉框和已保存的不一样时提醒「改了还没保存」。

## 真机通过

`scripts/real/u2-tasks-page-live.mjs`：真的应用、临时数据目录、假模型（回答前故意等 6 秒）、合成的小 git 项目。任务在后台开工后打开任务页，之后什么都不点，只看那张卡片。

改之前的构建（照出用户遇到的情况），原样输出：

```
刚打开任务页时： 执行中 · 版本 1 · 执行器 我的模型（fake-model-v1）
没点任何东西，之后变成： 执行中 · 版本 1 · 执行器 我的模型（fake-model-v1）

```
刚打开任务页时： 执行中 · 版本 1 · 执行器 我的模型（fake-model-v1）

任务实际状态： pending_accept
RESULT 通过：8.3 秒时页面自己变成了「待用户接受」

设置页那两处没有单独的真机检查脚本，只有验收测试。

## 已知缺口

- 任务页是每两秒读一次，不是任务一做完就推过来。够用，但不是即时的。
- 待办页、概览页如果也显示任务状态，没有查它们会不会同样停住。

四样分开：**已实现**（是）/ **自动化通过**（是）/ **真机通过**（任务页是；设置页没有单独跑）/ **用户接受**（还没有）。
