## 已知缺口

- **接口是测试先定的**：规格没写 `MobileServer` / `apply` / `address`、`mobile.enabled`、`mobile.port`、`saveMobileSettings`、`cockpit.mobileEnabled` / `mobilePort` 这些名字。整合方锁定时要认这套；要换名字或换层，先改测试再锁，别锁完再改。
- **条件 5 只做了结构核对**：仓库没有浏览器布局引擎，jsdom 算不出 390px 下是否横向滚动。测试核对 viewport、四列 `minmax(0,1fr)`、按钮顺序、没有 >390px 的 `min-width`；真正的截图按规格在实现那一棒的真机检查里跑。另：测试要求默认块带 `data-view="overview"`，这是测试的 DOM 钩子，规格没写。
- **条件 7 比规格字面多认一种 Host**：规格写「以 `.ts.net` 结尾」，浏览器访问 `http://机器名.某某.ts.net:43192` 时 Host 是带端口的 `…ts.net:43192`，所以测试两种都认 200；恶意后缀（`evil.ts.net.evil.example`）和不带 `.ts.net` 的照旧 421。请整合方确认这个口径。
- 条件 2 只检查 `address` 的绑定地址和回环连接，没有逐个网卡尝试连接；实现若绑 `0.0.0.0`，`address.host` 会露出来，测试会红。
- 43192 的测试假定这个端口没被别的进程占（CI 和默认关的本机都成立）；测试并行时手机页那份用 43193、改端口那条用 43194，避免互抢。
- 设置页保存后的「立即起停」是在 IPC 测试里用 `runtime.mobileServer.apply` 的替身核对的；真正由本棒临时实现串起来跑绿过，但那套实现没提交。应用完整启动时 `apply()` 的接线留给实现那一棒的真机检查。
- 没有测非法端口、端口被占用时的用户提示；规格没写，测试不自己加条件。
