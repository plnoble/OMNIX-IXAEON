# D3 点「要做」就开工并回报 交付

- 分支：grok/D3，基于 main c332365；档位 A
- 执行方：Grok

## 已实现

待办卡上点「要做」：照旧批准并排队，点击立即返回，随后自动派发。没有正在执行的编码任务就立刻开始；有就排着，前一个结束（完成、失败、取消都算）后按批准先后开始下一个。同一时间仍只有一个在执行。

任务走到等你验收、失败、取消时，往发起它的那个对话追加一条本地生成的回报（按 `origin_run_id` 找到那一轮所在的对话），`meta` 标 `{ kind: 'task_report', taskId, status }`，同一任务同一状态只写一次，不调用模型。打开着的窗口收到事件后重新读这一条，不用重开对话。没有 `origin_run_id` 的任务不往任何对话写。

找不到 Codex（`resolveCodexLocator()` 为空，且不是主动选替身）：不派发，任务留在已批准，回报「没找到 Codex，装好后在任务页点派发」。

和规格不一样的地方：

- 自动派发放到点击返回之后的下一个宏任务。点击返回时任务还停在已批准（排队），随后才开始。这样 T2b 锁定测试「拍板要做 = 批准并排队」仍然成立，同时满足「点击立即返回、不等执行结束」。
- `IXAEON_CODEX_EXE=none` 表示真机检查主动用执行器替身，不算「没找到 Codex」，不触发那条回报。`resolveCodexLocator` 会回落到本机默认安装路径，空串挡不住，所以需要这个明确的值。

源码改动 250 行（插入 + 删除，`apps/*/src` + `packages/*/src`），在规格的 250 行以内。验收测试、真机脚本、交付说明不计入。

## Codex 审查（A 档）

第一轮（d9da469）结论：需要修改。五条「必须改」：

1. 任务页手动派发的任务在执行时，自动调度直接退出，那个任务结束后不续派。已改：有任务在执行时记下，任务结束（自动派发、手动派发、取消都算）且没有任务在执行时再排空队列。
2. 回报只在自动派发返回后生成：排队中被取消的任务没有回报，手动派发的任务也没有。已改：取消和手动派发都走 `onTaskSettled`，按状态写回报。
3. 「同一状态只写一次」的测试在任务已是 `pending_accept` 时再排空队列，删掉去重判断也能过。已改：测试直接再调一次结算，断言回报仍是一条。
4. `note.txt` 同时出现在验收条件里，不列改动文件也能过。已改：验收条件改成不含文件名的句子，断言改动文件那一行的 `note.txt`。
5. 交付说明缺 verify 输出和 CI 结论。本轮补。

## 已知缺口

- 真机用的是执行器替身。真 Codex 的派发、隔离工作区、验证命令仍是原有路径，这次没有在真机上跑真 Codex。
- 回报里「验证没跑」只在验证输出不含「没有有效验证命令」时写原因；没有独立验收时一律写「还没有独立验收」。
