## 为了让测试能跑，我定的接缝（规格没写死，**请整合方重点看这一节**）

规格把「包在哪、数据目录长什么样、`RelayConfig` / `Turn` / `Idle` / `LedgerEntry` 的字段」写死了，但没写内部模块怎么分、函数签名长什么样。测试要用，我按下面这套写死（实现必须照这个来）：

1. **入口**：`packages/relay/src/index.ts` 把公开 API 都 re-export 出来；测试一律 `import … from '../../src/index.js'`。
2. **数据目录可以用环境变量换**：`IXAEON_RELAY_DIR` 有值时用它，否则 `<Worktrees>/IXAEON/relay/`。规格写的是后者；测试必须能换到临时目录，所以加了这一个环境变量（**这是我对契约的唯一一处加法**，如果整合方不接受，得换一种测试办法）。
3. `decideNextTurn(queueMarkdown, state, now)`、`checkConfig(config)`、`findSharedCheckout()`、`acquireLock(dataDir, pid?)`、`buildTurnPrompt(turn, { turnNumber })`、`writeTurnPrompt(turn, { dataDir, turnNumber })`、`runTurn(turn, config, state, opts?)`、`verifyTurn(turn, config, state, opts?)` 从 `src/index.ts` 出。
4. `runTurn` 的 `opts`：`{ dataDir?, turnNumber?, timeoutMs? }`。`timeoutMs` 就是条件 6 说的「测试里可以把单位换小」；不传时按 `config.roles[role].timeoutMinutes`。返回 `TurnResult`（`turn / role / kind / taskId / startedAt / endedAt / exitCode / timedOut / quotaHit / usage? / promptPath / stdoutPath / stderrPath / doneLine`）。
5. `verifyTurn` 的 `opts`：`{ dataDir?, sinceMainSha? }`，返回 `{ violations, mainSha }`；`violations` 里就是规格那三串字（`b-tier-merged-by-developer` / `b-tier-lock-changed-by-developer` / `local-user`）。**「这一棒开始时的 origin/main」**存在 `state.mainShaAtTurnStart`（运营方 `once` 跑之前 fetch 一次并写进去，再传给 `verifyTurn`）。
6. **档位从队列查**：`docs/委派/锁定验收.json` 里只有 `id` / `title` / `status` / `files`，**没有档位**，所以核对时按锁定清单里的 `id`（或提交说明里「并入 <任务号>」的那个任务号）去队列主表的「任务」那一格拿前导任务号对，读它的「档位」。对不上就当查不到、不算越界（宁可漏报也不误报，理由是误报会让调度器无缘无故停下）。
7. **锁文件**：`<数据目录>/lock.json`，内容是 `{ "pid": <进程号>, "startedAt": <ISO> }`；进程号还在就拒绝启动。
8. **交代里的固定字样**（测试会查）：`序号：<序号>`、`AGENTS.md`、`只做这一件，做到它的停点就停，不要接着领别的`、`RELAY-DONE <序号> <状态>`；整合方那份还要有 `docs/委派/整合方手册.md`。措辞可以自己写，但这些字样要在。
9. 命令：`relay once` / `relay run` / `relay status` / `relay resume` 都在 `packages/relay/bin/relay.mjs`；`once` 在 `stopped` 状态下不改任何东西、退 0。

## 已知缺口

1. **测试里的替身不等于真的三个命令行**：接真的 Claude / DSH / Codex（argv、权限白名单）是下一单，等 L0b 的结论。L0b 的结论是：Codex 沙箱要用得先 `codex sandbox setup --elevated` 装一次，之后每次调用都要带 `windows.sandbox="elevated"`；DSH 的 headless profile 凭据插件是关着的，后台调不动。
2. **「不写别的规矩进来」只能反向查几个字样**（`三条硬规矩` / `300 行` / `不许自己写自己的验收标准`），查不出「换了种说法又抄了一遍」。
3. **条件 9 的「锁定指纹」按文件内容哈希比对**：锁定清单里记的指纹与 origin/main 上那个文件的实际哈希不一致就算变了；如果某个文件在清单里登记了、但仓库里没有（比如被删了），也按变了算。
4. **共用检出目录的判断**用「从当前进程的工作目录往上找 `git rev-parse --git-common-dir`」，也就是 `scripts/worktree.mjs` 认的那个主检出；CI 上主检出就是仓库本身，所以 CI 里跑不到「cwd 是主检出」这条分支（测试用的是临时仓库，规避了这个差别）。
5. **`l1-prompt.test.ts` 的两条反向断言**依赖实现真的没有照抄规矩；实现写的时候要留意。
6. 队列里 `60` 这一行现在是「进行中（dev）」，测试和实现都还没写完；锁定之后我再来写实现，状态会改成「测试待审（整合方）」→ 等整合方锁。
