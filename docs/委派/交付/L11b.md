## 已实现

`packages/relay/src/queue-merge.ts`（新文件）：`mergeQueue(base, ours, theirs)` 按契约第 1 条合队列。

- 主表照 `parseMainTable` 的表头（序号 / 任务 / 委派单或规格 / 档位 / 依赖 / 状态）认；表头行、
  分隔行三份必须一字不差，否则 `null`。
- 行按第一格（序号）对上：`ours` 和 `base` 一样 → 用 `theirs`（`theirs` 没有这一行 → 删）；
  `theirs` 和 `base` 一样 → 用 `ours`；两边一样 → 用它；都不一样 → `null`。
- `base` 里没有的新行：先放 `ours` 新加的（照 `ours` 的先后），再放 `theirs` 新加的；两边都加
  同一个序号 → 一字不差放一次，不一样 `null`。
- 主表前面、后面的整段各自三方比：一边没改 → 用改的那边；两边改得一样 → 用它；否则 `null`。
- 换行照 `ours`（`\r\n` 还是 `\n`）。

`packages/relay/src/push.ts`：`rebaseThenPush` 里 rebase 冲突时先看
`git diff --name-only --diff-filter=U`（加 `-c core.quotepath=false`，否则中文路径会被 git 转义成
八进制、和 `docs/委派/队列.md` 对不上）。

- 只列出 `docs/委派/队列.md` 一个文件 → 取 `git show :1:` / `:2:` / `:3:` 交给 `mergeQueue`；
  合得起来就写回、`git add docs/委派/队列.md`、`git -c core.editor=true rebase --continue`
  （环境里同时设 `GIT_EDITOR=true`）；重放下一笔又冲突就再照这一条来一遍。
- `mergeQueue` 回 `null`、或者冲突的不只这一个文件 → 照原来 `git rebase --abort`，这一条算失败。
- 合成功、推上去的记账照 L13 写 `rebased: true`。
- 别的不变：不 `--force`、不碰 `dir` 以外的目录、`PushRecord` 没加字段。

`packages/relay/src/git.ts`：新增 `gitRaw`（**不 trim**，可选额外环境变量），给 `git show :1:…`
这种要保留末尾换行 / CRLF 的读取用；`git()` 改成调它再 trim，所有现有调用行为不变。

## 已知缺口

1. 分支 CI 在本棒看不到（调度器棒末才推）；本机 `verify.mjs` 与 CI 是同一条命令。
2. 真 GitHub 上相邻行改动的 rebase 冲突没有演练；合成测试里用的是同一形状的队列文本。
3. `mergeQueue` 只按主表逐行合；主表前后的大段说明按整段三方比（契约就是这么写的）——如果两边
   分别改了「已完成」表和别处的说明，会判 `null`、停下，交给下一棒处理。
4. 同一份里序号重复（正常队列不会有）时 `mergeQueue` 回 `null`，不做猜测；契约没写这种情况。
5. 契约只允许合 `docs/委派/队列.md`；其他任何文件冲突（包括队列旁边新加的文档）照旧 abort。
