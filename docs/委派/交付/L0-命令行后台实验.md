# L0 三个命令行后台跑通实验 交付

- 分支：`dev/L0`；档位 **B**（会花少量真额度，只交实验脚本和结论，不改应用）
- 规格：[L0-三个命令行后台跑通实验](../L0-三个命令行后台跑通实验.md)
- 版号：Claude Code **2.1.304**、DSH **0.2.1-rc.2**、Codex **0.163.0-alpha.10.2**
- 真调用次数（规格上限每个 ≤6）：Claude **6**、DSH **1**、Codex **6**

**一句话结论：三个命令行在后台都能起、都能拿到结构化输出；差别在「能不能干真活」——Claude 只肯答话、不肯写文件（非交互下写文件要批准，批准不了）；DSH 跑得起来但没模型凭据（`MISSING_CREDENTIAL`）；Codex 默认配置下能写工作目录之外（没有围栏），显式加 `-s workspace-write` 反而因沙箱 helper 起不来而挡住。三个都**不能靠默认值拿到「只许读写这个目录」的围栏**——这是接力调度器要自己管的事。**

## 每个命令行「后台调用的配方」

**Claude Code**

```
<claude.exe> -p "<任务>" --output-format json
# 续会话：<claude.exe> -p "<任务>" --resume <session_id> --output-format json
```

- 从 stdout 的那行 JSON 里取：`result`（最终回答）、`session_id`、`total_cost_usd`、`usage`、`is_error`、`permission_denials`。
- **要让它动文件，非交互下必须有权限来源**：要么交互批准（后台没有 TTY，不行），要么 `--allowedTools` 之类白名单，要么 `--dangerously-skip-permissions`（规格禁止）。所以「开发」这一棒如果要在后台改代码，Claude 这条路**不开跳过权限就跑不起来**——按规格停在这里，写清不绕。

**DSH**

```
<Install>\DeepSeek Harness.exe --expose-internals <Install>\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh-desktop-host\lib\cli.js --profile headless --json "<任务>"
# 等价于：<Install>\resources\runtime\cli\bin\dsh.cmd --profile headless --json "<任务>"
```

- 从 JSONL 里取：`type=session` 的 `sessionId`、`type=final` 的 `text`、`type=status` 的 `reason.error.code`。
- **现在这条路走不通**：headless profile 没有模型凭据（`MISSING_CREDENTIAL`）。桌面版能聊是因为它用的是另一套路由/凭据；命令行这边要么把 key 放进它的凭据服务（网页版 Models 页写的那种），要么在启动环境里给 `DEEPSEEK_API_KEY`（本机环境变量里**没有**这个变量）。**这属于「要配置」，按规格没替用户做。**

**Codex**

```
<codex.exe> exec --json --skip-git-repo-check "<任务>"
# 续会话：<codex.exe> exec --skip-git-repo-check resume <thread_id> --json "<任务>"
```

- 从 JSONL 里取：`thread.started.thread_id`、`item.completed`（`agent_message.text`）、`turn.completed.usage`。
- `--json` 是 JSONL；`--skip-git-repo-check` 只是「不在 git 仓库里也跑」，**不是**跳过权限。
- 沙箱：默认配置**没有**目录围栏（实测能写外面）；`-s workspace-write` 在本机坏（`helper_sandbox_lock_failed`，和 D2c 那单「新版沙箱要提权」是同一个根因）。
