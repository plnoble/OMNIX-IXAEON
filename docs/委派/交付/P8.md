## 已实现

删除项目时先照 P5 解除绑定（直接调 `unbindProjectFolder`），没绑文件夹的老数据照样先取消在途任务并回报，再删项目、清这个项目的任务副本，最后让对话上下文失效。确认框把这些说清楚，结果那句话显示在项目列表上面。

和规格不一样的地方：没有。条件 7、8、9 照锁定的做（用户 2026-10-19 定了「清掉任务副本」留着）。

写的时候照了规格末尾「整合方审测试时的改正与补充」：

- 绑着文件夹的项目直接调 `unbindProjectFolder`，没有把它的判断抄一遍。
- `project.deleted` 只由运行时记一条；IPC 的 `deleteProject` 改成只转给 `AppRuntime.deleteProject`，不再自己记。
- 没绑文件夹的项目删除也调 `invalidateContext`。
- 只删严格在 `<数据目录>/workspaces/` 里面的目录（`workspaces` 自己、用 `..` 绕出去的不删）；对整个目录调一次 `rmSync`；删不掉的计 `copiesLeft`、不拦事；早就不在的不计数。
- 确认框两段之间空一行。

`grok/P8` 原来那两份测试是锁定前的版本。rebase 到 main 时两份都取了 main 的，一个字没改（`acceptance-lock` 核对过）。

## 已知缺口

- 规格「约束」里提过：别的锁定测试要是对 `deleteProject` 的返回值或审计做了全等比较，实现之后会红。整合方锁定测试时用一次性实现跑过，已锁定的验收、单元、集成和各套回归都照过；本分支的 `node scripts/verify.mjs` 也全过。没有发现被这一单撞上的比较。
- 真机脚本指定了桌面应用自己装的 Electron（`executablePath`）。不指定时 Playwright 会去下它自己的一份，这一份没下完就报启动失败。
