## 已实现

来源的详情卡片里多一个「撤销读取」（放在「重新分析」后面）：点了先调只读预览 `previewRevokeSourceReading`，按结果三选一——域名授权只显示一句说明；有项目靠着这条授权时显示「到项目页解除绑定」那一句（项目名放同一对「」里、用「、」隔开）；其余用 `window.confirm` 问一次（确认框文字照契约 4 逐字，文件/文件夹两种说法），确认了才调 `revokeSourceReading`（这个接口一个字没动），撤销之后关掉详情卡片、重新读列表、页面上显示结果句「已撤销读取授权：<N> 份资料不再读原文。」。预览说已经撤销：不问、不撤销，列表重新读一遍。预览出错、撤销出错都显示在报错条里，详情卡片不关。

- `AppRuntime.previewRevokeSourceReading(sourceId)`：只读（授权表、项目表、资料表、审计都不动，不 invalidateContext）；返回 `{ scope, locator, status, sourcesUnderGrant, dependentProjects }`。`locator`/`scope`/`status` 取资料所在那条授权记录；`dependentProjects` = 绑着文件夹的项目（不管什么状态）里，文件夹在这条授权之内、而且除这条外没有别的有效授权覆盖它的，按名字排序；文件授权、域名授权、已撤销的授权都是空的。来源不存在报「来源不存在」（和 `revokeSourceReading` 一样的话）。
- IPC/preload/合约三处只转。

## 整合方复审（2026-10-19）

结论：实现照规格做了，并入。并入时改了两处源码、补了两条测试、重写了真机脚本的检查部分。

### 改了什么

- **预览**（`appRuntime.ts`）：行为不变，去掉了几段走不到的兜底。库里 `scope_type` 只能是 file / folder / domain、`status` 只能是 active / revoked、资料的 `permission_id` 不许空，原来「授权找不到就当域名」「状态不认识就当已撤销」那几支永远走不到；万一真找不到授权，现在直接报错，不再编一个答案。查授权改用 `PermissionService` 现成的 `get` / `list`，不再手写 SQL。
- **界面**（`Sources.tsx`）：那句说明（`source-revoke-note`）原来不记是哪份资料的。对一份网页采集的资料点了「撤销读取」，关掉详情、再打开一份本机文件，那句「这份资料不是读本机文件得来的」还挂在新的详情里。现在说明记着资料号，只在那份资料的详情里显示。另外，再点一次「撤销读取」时，先清掉上一次的结果句（这一处没有测试照到）。

### 补的测试（重锁 P7，标题不变）

- `p7-preview-revoke.test.ts` 加一条「归档了的资料也算」：`sourcesUnderGrant` 是「一共多少份」，归档了的资料也在这条授权下，撤了一样读不了原文。
- `p7-revoke-page.test.ts` 加一条「那句话只跟着点过的那份资料」：照上面那个错法写的，执行方交的实现过不了这一条。

P7 现在是 21 条（运行时 11、界面 10）。

### 真机脚本（`scripts/real/p7-revoke-reading.mjs`）

执行方交的版本跑出来是「通过」，但有三处不能当证据：

- **第 3 步用的不是另一个文件夹。** 目录对话框的替身在启动时就定死了 `synA`，项目绑的、第二次导入的都是第 1、2 步刚撤销过的那个文件夹（`synB` 建了没用上）。规格要的是「绑定另一个合成文件夹」。现在启动之后改主进程里的替身变量，第 3 步换成 `synB`。
- **结果那一行会把没通过说成通过。** 前面哪一步不符，最后照样写「通过：……」（退出码倒是 1）。和 P5 那次是同一个错，改成只有全都符合才写「通过」。
- **查的不是这条授权。** 原来看的是「库里还有没有有效的文件夹授权」，换一条授权也能过。现在按资料查它那条授权的状态。另外补了三处核对：第 1 步确认真的问了，第 3 步确认没问，结果句里的数字和库里这条授权下的资料数一样。
- 打印时把临时目录的两种写法（原样的、规范化过的）都遮掉。
