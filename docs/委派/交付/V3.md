# V3 独立验证（零依赖档）跑的程序连不出去——交付

- 整合方直接做的（没有委派）。档位 B（隐私：新堵上的一条外发途径）。
- 没有单独的规格：条件写在验收测试开头。

## 为什么做

用户 2026-10-05 同意做「验收先行」：点「要做」之后先让模型写测试，再写实现，做完自动跑测试。这会让「在用户机器上跑模型写的代码」成为常态，所以先查了现有的验证沙箱到底拦住什么。

零依赖档靠 Node 的权限模型。实测（Electron 44.1.1 自带的 Node 24.19，和本机的 Node 24.14 都一样）：

- 起子进程：拦住；读写副本外的文件：拦住；
- **联网：没拦**。验证程序里 `fetch` 一个本机端口，请求到了。

验证跑的是执行器（Codex 或用户的模型）写的代码，能读整份项目副本。能读又能联网，就能把副本发到任何地方——D7 小心翼翼只发批准范围内的文件，在这里等于白做。这个口子不是验收先行带来的（现在任务带验证命令时就有），但验收先行会把它变成每个任务都走的路。

## 已实现

`packages/core/src/execution/executor.ts`（零依赖档，`defaultCheck`）：

- 验证程序自己的代码之前，先加载一段断网的代码（`--import`，内容直接写在参数里，不落文件）：`net`、`dgram`、`dns`（含 `dns/promises`、`Resolver`）、`inspector.open`、`process.binding`、`fetch`、`WebSocket` 都换成抛错的。`http`、`https`、`tls`、`http2` 都走 `net`，一并拦住。
- 零依赖档只跑「node 脚本 [参数…]」和「node -e 代码」。脚本名之前带了别的启动参数就不跑，如实说明是哪个：预加载（`--require` / `--import` / `--loader`）和环境文件（`--env-file`，里面能写 `NODE_OPTIONS`）会抢在断网之前执行，调试端口会开监听。不逐个去认，没见过的一律不跑。命令自带的 `--permission` / `--allow-fs-*` 照旧去掉后照跑。

## 这不是什么

这是进程内的拦截，不是操作系统级的隔离。它挡的是「顺手把项目副本发出去」这类直接的写法；专门研究怎么绕的代码，不保证挡得住。操作系统级的隔离是依赖档的沙箱（Codex 提权沙箱，联网和越界写由系统拦），要先授权，授权入口（D6）还没做。

## 验收测试

`packages/core/test/acceptance/v3-verify-no-network.test.ts`（18 条）。先写的测试：改之前红 8 条（联网全通、预加载照样加载）。

变异检查 11 个，8 个被抓到。没抓到的 3 个查过，都是这段代码里多出来的保险，去掉了行为也不变：

- `process.binding`：权限模型自己已经拦了；
- 同步具名导出：这些模块在断网代码之前没被人用 `import` 引过，不同步也一样；
- 头一轮 `dgram` 没被抓到：它默认借 `dns.lookup` 解析地址，dns 拦了它就发不出去。自带解析函数就能绕开 dns，于是补了「自带解析」的用例，之后抓到了。

## 已知缺口

- 不是操作系统级的隔离（见上）。
- 验证程序里真要联网的测试（比如测一个下载工具真的能下载）现在跑不了，会失败并说明「验证程序不许联网」。这是有意的。

四样分开：**已实现**（是）/ **自动化通过**（是）/ **真机通过**（是）/ **用户接受**（不需要用户操作；用户同意的是验收先行）。
