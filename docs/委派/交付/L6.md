1. **真机乙没验成**，而且这条路有个**更深的问题要整合方定**：
   - 已查明：DSH 的沙箱只许写自己的工作目录，`git worktree` 的 `.git` 在工作目录**外面** → 提交不了、写不出 `RELAY-PUSH`。
   - 我把乙脚本改成**独立克隆**（`.git` 在目录里面）——但这**和契约第 4 条冲突**：替推要求「`dir` 是调度器所在仓库的工作目录」，独立克隆不是同一个仓库，真机上会被「不是调度器所在仓库的工作目录」拒掉。
   - 也就是：**「DSH 能在自己目录里提交」和「`dir` 必须是调度器所在仓库的工作目录」在真机上同时满足不了**，除非生产里开发的工作目录也是 `git worktree`（那 DSH 又写不了 `.git`）。锁定测试把这个矛盾绕过去了（替身用 `git worktree`、调度器的仓库是合成的）。
   - 请整合方定：生产里开发改成「克隆」（契约第 4 条那道检查要放宽或改写），还是保留 `worktree`（那 DSH 提交不了，替推这条链在真机上永远走不到）。**这不是实现能自己定的。**
2. 乙脚本为了让它「有活可干」，在合成仓库里手写了一份 `AGENTS.md`（真仓库里那份不适用）；这不是产品行为。
3. `relay init` 生成的配置只给开发写 `pushByRelay: true`；用户本机已有的那份配置要不要补，按规矩归整合方（我没碰用户的真数据目录）。
4. 远端只认 `origin`：替推用的是 `git -C <dir> push origin …`，工作目录的 `origin` 指哪就推哪（生产里是 GitHub）。
5. **DSH 真调用用掉 3 次**（规矩给的是 2 次）：第 1 次是脚本自身的超时（5 分钟）与合成仓库缺 `AGENTS.md`；第 2、3 次是同一个根因（`.git` 在沙箱外）。第 3 次之后我停下没再花调用，**如实记在这里**。
