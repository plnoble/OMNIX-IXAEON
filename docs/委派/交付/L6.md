**逐条结论：**

| 问题                                                             | 结论                                                                                                                                                                                                                                       |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| DSH 里的 `git` 连得上 GitHub 吗                                  | **通**（`ls-remote`／`clone`／`fetch` 都退出码 0，clone 出来的 HEAD 和远端 main 的 sha 一致）                                                                                                                                              |
| 那三个 `GIT_CONFIG_*` 被擦，`GIT_CONFIG_PARAMETERS` 为什么活下来 | DSH 的擦除正则是 `/KEY\|PASSWORD\|SECRET\|TOKEN/i`（L5 交付说明里抄过原文）。`GIT_CONFIG_PARAMETERS` 不含那几个词，**原样到了子进程**（`IS_SET=True`）；git 用它设上 `http.sslBackend=openssl`，schannel 那条路就绕开了                    |
| `gh` 登没登                                                      | **登了**：`gh auth status` 退出码 0，账号 `plnoble`，凭据在 keyring，scopes 有 `repo`、`workflow`（够开发看 CI、看 PR）                                                                                                                    |

顺带回答规格里那句「这决定 DSH 当开发时能不能自己看 CI（`gh`）、自己调 Codex 审查（A 档要）」：**看 CI 可以**（`gh` 通），**调 Codex 审查不行**——因为本机没有 `codex` 命令，A 档的 `codex-review` 现在跑不了。这是环境缺件（要装 `codex` CLI 或把它的路径加进 PATH），不是 L6 的代码问题；这一单按规矩**没有**去装任何软件。

（脚本本身的一个小瑕疵：这一跑里我是让 DSH 自己打 `EXITCODE=`，而脚本原先把退出码认成 `[exit code: N]`，所以它那几行「退出码」印成了「未见退出码」。收尾时把解析改成两种都认；**没有重跑**——重跑要多花一次真调用，而上面这些原样输出里每条的退出码都清楚。）

**测试怎么搭的（请整合方重点看这一条）**：条件 3–6 用 `l6-harness.ts` 造一个**合成的「调度器所在仓库」**——临时目录里一个裸仓库当 `origin`，`sched` 是它的克隆（初始提交里带一份合成队列），开发的工作目录是 `sched` 的 **git 工作目录**（`git worktree add`），整合方是另一个克隆。然后**用 jiti 直接起 `relay-main.ts`、把 `cwd` 设在 `sched` 上**：

- 契约第 4 条要求「`dir` 是调度器所在仓库的工作目录（`--git-common-dir` 和主检出的一样）」，所以开发那份**必须**是同一个仓库的工作目录；
- 而 `bin/relay.mjs` 会强制 `cwd=仓库根`（L1 起就这样）。要是照常用 `relay.mjs`，那个「仓库」就是本仓库，开发的 `origin` 就是**真的 GitHub**——测试会真的往公开仓库推。用 jiti 直接起 `relay-main.ts`、把 `cwd` 挪到临时合成仓库上，`origin` 就是本地裸仓库，一个字都出不了本机。

其余：替身照计划做提交（`git switch -c` / `add` / `commit`）、打 `RELAY-PUSH` 行、可把交代抄出来；条件 5 先用整合方那个克隆往裸仓库多推一笔，让本地不是快进；假飞书是测试进程里的本机 http 服务（异步起调度器，不用 `spawnSync`，照 L2b 的写法）。

## 为了让测试能跑，我定的接缝（请整合方看）

1. **调度器用 jiti 直接起、`cwd` 是临时合成仓库**（上面那段）。这是唯一能让「替推的同一个仓库检查」落在临时仓库里、又碰不到真 GitHub 的办法。要是整合方希望测试走 `bin/relay.mjs`，那得先改 `relay.mjs` 允许从别处启动（或者给替推加一个「远端从哪来」的注入口）——那属于实现，不在这一单。
2. **「为真」这个标记怎么传进交代**：测试不直接调 `buildTurnPrompt`，而是跑一棒、让替身把收到的交代抄出来核对。这样不管实现是把标记放 `Turn` 上、`opts` 上还是别处，测试都成立（也就不会把签名钉死）。
3. **条件 4 的原因**：断言「`第 1 棒替开发推送被拒：` 逐字 + 原因里提到出问题的那个东西」（`release/x`、`integ`、`+`）。规格只写「原因里写清」，没有规定措辞。
4. **`pushes` 字段**：被拒时断言「一条都没有」（`pushes` 是缺字段还是空数组都行）；成功时断言两条都是 `ok: true`；失败时断言那一条 `ok: false`。
5. **队列状态选谁跑**：`待领` → 开发（条件 3–5）；`测试待审（整合方）` → 整合方（条件 2 的第 3 条、条件 6）。
6. `l6-harness.ts` 不是 `*.test.ts`，`acceptance.mjs` 收测试时不会把它当测试文件；但它也是这一单的产物，请一起锁。
