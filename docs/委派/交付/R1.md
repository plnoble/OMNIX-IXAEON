## 已实现

恢复失败、磁盘回滚完整之后，`rebuildRuntimeServices()` 现在按新连接重建 `conversations` 和 `semanticIndex`（构造函数里那套 `IXAEON_EMBED_MODEL` / `none` 逻辑抽成 `createSemanticIndex`，两处共用）。旧索引的在途补向量引用丢掉，迟到的成功/失败不写新状态。懒建的 `askSessions` 也持旧连接，一并清掉。

和规格不一样的地方：

- 规格只点名 `conversations` 和 `semanticIndex`。顺手查构造函数：todos 已经在重建里换了；其它服务本来就从 `deps` 进来、重建时重赋。另外发现 `askSessions`（懒建、持旧 `this.db`）同样会让回滚后的提问写进已关连接，一起清了。测试桩用 `Object.create` 绕过构造函数时没有这个 Map，用可选链。
- 语义索引没有常驻定时器，后台工作只有按需补向量的 promise（`semanticBackfillRun`）。重建时把引用置空；旧 promise 的 then/catch/finally 都只在自己那一轮还挂着时才改状态，避免迟到失败把新索引标坏、或清掉新一轮补向量。
- 验收条件 2 的「检索」：完整 `score()` 要 Ollama 在线，CI 没有。测试用同一连接上的 `coverage` / `backfill`（0 条待补时不发网络请求）证明数据库段不抛错。
