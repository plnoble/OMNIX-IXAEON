## 已知缺口

1. 测试只按契约断言**可观察结果**；内部怎么算「新加的行」、`state.plan` 什么时候存盘、`queueHash` 对
   `readMainQueue` 的 trim 怎么处理，都由实现定。`queueHash` 只断言「64 位十六进制」和「同一队列第二次不再规划」，
   不硬编码某种规范化写法。
2. `planned` 的「不限频」是用 `createNotifier` 直接连发两条验的（不是在同一条 `relay run` 里造出两次真规划棒）。
   一次真 CLI 里，规划棒加完行之后队列就有「待领」了，下一次不会又是规划棒，造不出来。
3. 条件 1 的「换了北京日 count 从 1 起」只能从 `relay once` 看 `state.plan`（`decideNextTurn` 只负责派不负责记账）。
4. 越界场景的「主表已有的行」按「同一张主表、同一序号」认；规划棒如果重排了已有行、但每一格没变，
   这一支没有测试（规格只写「少了一行、或任何一格变了」）。
5. 条件 6 的 `relay init` 那条会真的 `git fetch` 一次（和 L5 的 init 测试一样），不是离线的。
6. 真机检查甲、乙都没跑（见上）。
