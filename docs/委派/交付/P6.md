## 已实现

项目绑着文件夹、但这文件夹已经不在有效授权之内时，和没绑文件夹一样不建副本、不派发，并说清楚原因：

- **批准之前拦**（P4 那道 `assertProjectFolderBound`，三个入口共用）：绑着文件夹但 `permissions.activePermissionForPath(root_path)` 是 null → 报「这个项目文件夹的读取授权已经撤销：在项目页解除绑定、重新绑定之后，再派编码任务。」。propose 不建草案、不记审计；点「要做」不批准、不建副本；任务页批准同样拦。没绑文件夹的项目照旧报 P4 那句。上级文件夹的有效授权也算有授权。
- **派发之前也拦**：`finishCodingTask(id, 'dispatch')` 先查（任务留在排队，执行器不被调）；`'cancel'` 不查——授权撤销的任务要取消得掉。
- **自动派发**（`CodingDispatch`）：宿主新增可选回调 `folderGap?: (taskId) => string | null`（`CodingDispatchHost`，AppRuntime 上实现了同名方法——没绑文件夹的 P4 那句也经它走同一条路）。拦下时跳过、留在排队、在发起对话里回报一次「<目标第一行>」停在排队里：<原因>（`meta.status 'folder_missing'`，`reportAlreadyWritten` 保证同一条只写一次），接着派后面的。没给回调的宿主不问、不拦；任务页建的任务（没有发起的对话）只跳过、不往哪儿写。授权回来了下一次轮到照常派，对话里再添一条做完的回报。
- **已经在执行的任务不管**（它用的是早先抄好的副本）。
