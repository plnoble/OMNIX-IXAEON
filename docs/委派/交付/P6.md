## 验收测试（v2 规格任务）

测试开头注释钉住的接缝：`assertProjectFolderBound` 的三个入口（propose / 点「要做」/ 任务页批准）多查「绑着文件夹但没有有效授权」；`finishCodingTask(id, 'dispatch')` 同样拦；自动派发经宿主新的可选回调 `folderGap?: (taskId) => string | null`，拦下时跳过、留在排队、接着派后面的，`meta.status 'folder_missing'` 回报同一任务只写一次；运行中的任务不受影响。

逐条对照规格验收条件：

1. propose 不建草案、不记审计、错误就是那一句；点「要做」与任务页批准报那句、没批准、没副本、待办还是「等你拍板」（2 条用例）。
2. 早先排着队、后来撤权：点派发报那句，任务留在排队，执行器没被调。
3/4. 自动派发轮到它：跳过、留在排队、对话里一条 `folder_missing` 回报（内容「<目标第一行>」停在排队里：<那句>），再触发几次还是一条；排在后面的别的项目照常派发、做完。
5. 上级文件夹的授权还有效：批准、派发照常。
7. 没绑文件夹的项目：报的还是 P4 那一句。
8. 执行途中授权撤销：任务照常跑完，不被拦下、不被取消。
