## 已实现

- `relay listen [--bind] [--under <pid>]`（契约第 4 条）：没配退出码 2；没绑定又没带 `--bind` → 「还没绑定：先跑 relay listen --bind」退出码 2；认的消息 → 记 `inbox.jsonl`（同一 id 只记一次）→ 往群里发「收到：<前 50 字>。下一棒交给整合方。」；不认 → 打「没理：<why>」不回；`--bind` → 第一条群里 @ 机器人的文字消息才算（别的群、别人、没 @ 的跳过），群号人写进 `feishu-app.json` 别的字段原样，打「绑好了」、发那句话、退出码 0；`--under` → 看门人没了每半分钟查一次自然退。源接口照测试缝的形状 `startEventSource(onEvent, opts)`，「收听中」在发起连接后打（不依赖源的就绪回调）；连接层报错遮蔽（`<已隐藏>`）后退出码 1。
- 看门人管收听（契约第 5 条）：feishu-app.json 四项齐才起收听子进程（同一份代码），退出后隔 `idleSeconds` 重起、打「收听 <pid> 退出 <码>」；看门人退出（含 `--exit-when-idle`）前先停掉、退出后不再重起。
- 飞书回复棒（契约第 6 条）：`inbox.jsonl` 里没办过的（只看最后 200 行）派在普通棒之前；交代按时间先后排、北京时间 月日 时:分；核对越界（只许改 `docs/`，违规 `inbox-touched-code`）；RELAY-DONE 才记 `state.inboxDone`（留最近 200 个）并往群里发「整合方处理了你的回复：<summary>」（不限频）；记账 `{statusBefore: <n> 条, statusAfter: <summary>}`。
