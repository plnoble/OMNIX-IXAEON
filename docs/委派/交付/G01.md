和规格不一样的地方（写死在测试开头注释里，实现照此）：

1. **契约 1 的方法签名**：规格举例 `willReuseSession(contextRef)`。适配器不持有数据库，披露版本由调用方算好传入，测试锁定为 `willReuseSession(contextRef: string, permissionVersion: string): boolean`——同一 contextRef 有活着的长驻会话、启动参数与该披露版本都没变才返回 true。
2. **契约 2 的记忆版本算法**（规格说具体怎么算由执行方定、测试写明）：`getDisclosureEpoch` 的记忆段不再统计 current/disputed 的数量与最大更新时间，改为「收回可见性指纹」五段：rejected（confirmation='rejected' 的条数与 max(updated_at)）、superseded（state='superseded'）、ended（time_status='ended'）、scope（updated_at > created_at 的条目按 id 排序的 `id:scope` 串，纯新增 created_at 等于 updated_at 不计入）、removed（累计删除条数，由 getDisclosureEpoch 在 app_settings 的 `disclosure.items_seen` 与 `disclosure.items_removed` 两个键里惰性维护：消失的 id 计数，新增的 id 只更新 seen 不计数）。授权段、披露段、设置段照旧。

## 验收测试（v2 规格任务）

`packages/core/test/acceptance/g01-session-rebuild.test.ts`，协议替身（PassThrough），不断言内部状态，只看 `session.create` 次数与 `prompt.submit` 的文字：

| 用例 | 规格条件 |
| --- | --- |
| 新增一条无关记忆后第二轮仍复用同一会话，不重复补历史 | 条件 1 |
| 把记忆标成「不对」后下一轮新开会话并补上前几轮（含口令） | 条件 2 |
| 授权撤销后新开会话并补历史 | 条件 3 |
| 关掉「个人记忆给聊天用」后新开会话并补历史 | 条件 3 |
| 应用重启后重开旧对话补历史 | 条件 4 |
| 同一会话连续复用时每一轮都不重复补历史 | 条件 5 |
| willReuseSession 只在会话会复用时为真 | 契约 1 |
| 新提炼一条记忆不改变版本 | 契约 2 |
| 拒绝、标过时、被取代、改范围、删除都会改变版本 | 契约 2 |

当前（实现前）实跑结果：条件 4、条件 5 通过（既有行为，不许退化）；其余 7 条按预期失败——失败点都是「实现缺失」：条件 1 新增记忆后重建了会话（spawns 2≠1），条件 2/3 重建了但派出去的文字里没有「本对话此前的内容」，契约 1 方法不存在，契约 2 仍是旧的计数算法。
