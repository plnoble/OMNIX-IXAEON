# M1 慢模型不再超时 交付

- 分支：grok/M1，基于 main `e1ccd72`；档位 A
- 执行方：Grok

## 已实现

`OpenAIResponsesProvider` 的两条路（`/responses`、`/chat/completions`）都改成 `stream: true`，按服务端推送事件读。网关一开始生成就先把响应头发回来，慢模型思考超过 100 秒不再被按「没回应」掐断。

```
packages/core/src/extraction/model/openai.ts | 109 行新增、8 行删除
```

源码改动计入 300 行上限。没有新增迁移，没有改提示词、发给模型的内容和聊天（Hermes）那条路。

行为：

- `/responses`：累加 `response.output_text.delta`，`response.completed` 结束；`response.failed` 与 `error` 事件抛 `ModelError`，限流和服务端类（`rate_limit`、`server_error`、`overloaded`、`unavailable`、`timeout`、5xx）算暂时性。
- `/chat/completions`：累加 `choices[0].delta.content`，`data: [DONE]` 结束。
- 事件按空行切分，被拆在两次读取之间的能拼回去。
- 网关不支持流式：返回的不是 `text/event-stream` 就按原来的非流式解析；对 `stream` 报 400 就记住「这个实例不支持」，去掉 `stream` 重发一次，之后不再带。
- 没有另加超时，Node 自带的 300 秒没收到字节照旧算网络错误。429 / 5xx 与网络错误的一次重试不变。

和规格不一样的地方：无。

## 真机通过

`scripts/real/m1-slow-stream.ts`（2026-09-27）：本机起一个假的流式服务，立刻回响应头，隔 110 秒再吐文字。两条路都拿到完整结果，没有中途断开：

```
HEADERS_RECEIVED_AFTER_SECONDS 0
RESPONSES_TEXT 慢模型的完整回答
RESPONSES_SECONDS 110
CHAT_TEXT 兼容端点的回答
```

响应头在第 0 秒就到（服务端 `flushHeaders()` 立刻刷出），文字在第 110 秒才到，中途没有断。
