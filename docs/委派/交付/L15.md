# L15 做完一件就告诉用户；「没活」一天只说一次、说清要不要用户做什么；早报 交付

- 分支：`dev/L15`，基于 main `45530f6`；档位 A
- 执行方：dev

## 已实现

- **做完一件就发一条**：`RelayEvent` 加 `done`；`runOnce` 在一棒结束、没停下，且这一行的状态从「不以已完成开头」变成「以已完成开头」时发它。棒数、时长、整合方花费都从记账（`ledger.jsonl`）里按这一行的序号现算；规划棒（`taskId` 是 `plan`）不发。
- **「没活」一天一次**：`RelayState` 加 `idleDay`（按北京日子，`queue-empty` / `all-blocked` 各记一份）。`run`（`once --under`）要发 idle 时先看这个日子，同一天不再发。原来「只有 `run` / `--under` 才发」的规矩没动。
- **「被挡着」说清要不要用户做什么**：`idle` 加可选 `waiting`。发 `all-blocked` 时从主表里挑状态以「等用户」开头的行（按表里先后）；一行都没有就带空数组。`formatEvent` 在没有 `waiting` 字段时和原来一字不差（锁定的 L2b / L3 / L9 测试照过）；有行时接「要你回答的：」和逐行「- 第 N 行 <任务>：<状态去掉「等用户」前缀>」，空数组时写「没有要你回答的，你不用做什么。」。
- **早报**：`RelayConfig` 加可选 `morningReport`（没有或 `false` 不发）；`RelayEvent` 加 `morning`；`RelayState` 加 `lastMorningDate`。北京时间 9:00 之后、今天还没发过，就在定下一棒之前（和日报同一处）发。`turns` / `done` / `costUsd` 照日报的算法，只算北京时间昨天 21:00 到现在开始的棒；`doing` 是主表里「进行中」「测试待审」「待复审」的任务。`relay init` 从 `config.example.json` 复制，示例里写了 `true`。
- 飞书限频不变（30 分钟、按 kind 加 taskId / role / why）；`done`、`morning` 和原来的 `planned`、`daily` 一样不限频。
- `README.md`「它什么时候会停下来找你」一节补了 `done` 和早报两条，并把「没活」改成一天一次、说明会列出「要你回答的」；数据目录那张表补了 `idleDay` / `lastMorningDate`。

## 已知缺口

- 早报的日期是按发送时刻现算的（事件里没有 date 字段，见上面「和规格不一样的地方」）；如果一条早报在午夜前构造、午夜后才格式化，日期会跨天。调度器是发之前现构造、现格式化，这个窗口不存在。
- 这一棒自己的 `startedAt/endedAt` 是真实钟表，其余棒是记账里的时间；`hours` 用二者相加后的一位小数，所以「刚做完」那一棒按秒计入，显示通常不受影响。
- `done` 只在「没停下」时发：如果这一棒同时越界停下，用户先收到 `stopped`，不会收到 `done`（规格写的是「一棒结束、没停下」）。
- 已经生成过的本机 `config.json` 不会自动多出 `morningReport`：不写就是不发早报，用户要自己加 `"morningReport": true`（和 L9 的 `planPerDay` 一样）。
- 没连真飞书发过；真飞书上的实际收到效果要等用户本机的配置和 webhook。
