`quotaPauseMinutes`；只有 `quotaPatterns` 对上时照原来的算法。没有这个字段或空数组时行为和现在一字不差。

  最近一个北京时间（UTC+8，不考虑夏令时）周四 04:00:00.000。

## 验收测试（v2 规格任务）

新文件 `packages/relay/test/acceptance/l19-weekly-quota.test.ts`，13 个 `it`，逐条对应规格「验收」：

- 条件 1（5 个例子 + 1 条性质）：北京周四 03:59 → 当天 04:00；北京周四 04:00 整 → 下周四；
  北京周三 23:00 → 第二天 04:00；北京周四 04:00:00.001 → 下周四；北京周日中午 → 接下来那个周四；
  7 个采样点的返回值都是 UTC 周三 20:00:00.000，且和 `now` 的差在 (0, 7 天] 里。
- 条件 2：替身角色输出 `WEEKLY QUOTA EXCEEDED`、配置写 `Weekly Quota Exceeded`（大小写不同）→
  `quotaHit` 为 `true`；`pausedUntil` 是 UTC 周三 20:00:00.000、晚于现在、不超过 7 天。
- 条件 3：`quotaPatterns`（`session limit`）和 `weeklyQuotaPatterns`（`weekly quota exceeded`）同时对上 →
  仍按周额度歇（`pausedUntil` 落在周三 20:00:00.000）；`quotaPauseMinutes` 特意设成 30 分钟，
  避免和会话额度的算法混淆。
- 条件 4：只对上 `quotaPatterns` → `pausedUntil` 约等于现在 + `quotaPauseMinutes`（200 分钟，±5 秒）。
- 条件 5：周额度字样只出现在 DSH 的 `tool_result` 行里 → `quotaHit` 为 `false`、不歇；
  `RELAY-DONE` 仍从 `final` 里取到。
- 条件 6：`[""]` 和 `["  "]` → 什么都不认（输出里写着 `weekly quota exceeded` 也不触发）；
  `weeklyQuotaPatterns` 是字符串（不是数组）或数组里有数字 → `checkConfig` 拒绝，两个角色都试过，
  原因逐字等于 `<角色> 的 weeklyQuotaPatterns 必须是字符串数组`；没有这个字段、`[]`、
  `["weekly quota"]`、`["", "  "]` → 放行。
