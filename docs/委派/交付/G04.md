## 已实现

编码任务记住是哪一轮提问产生的，回答只带这一轮自己的任务。三处：

1. `packages/core/src/execution/taskStore.ts`：新增 `withAskRun` / `currentAskRunId`（异步上下文）。`CodingTaskStore.create` 建任务时把当前提问的 runId 写进 `origin_run_id`（迁移 35 已加的列，本版不加迁移）。不在提问里建的（任务页手动建、旧数据）为 null。
2. `packages/core/src/runtime/broker.ts`：`propose_task` 建完任务后按这次调用的 `ctx.runId` 再写一次 `origin_run_id`，与上面一致。
3. `apps/desktop/src/main/appRuntime.ts`：`ask()` 把这一轮的 `session.run` 包进 `withAskRun(runId)`；找任务的查询从「创建时间晚于本轮开始」改成 `origin_run_id = 本轮 runId`。

并发的两轮各有各的异步上下文，不串。

```
packages/core/src/execution/taskStore.ts | +24 -2
packages/core/src/runtime/broker.ts      | +7 -1
apps/desktop/src/main/appRuntime.ts      | +19 -11
packages/core/src/index.ts               | +6 -1
```

和规格不一样的地方：规格写「propose_task 建任务时写上 ctx.runId」。只写这一处的话，T2b 的锁定验收会全挂——它的会话替身是在这一轮里直接 `coding.create`，不经过 propose_task，任务没有归属，回答上就没有待办卡。所以归属写在 `CodingTaskStore.create` 里，凡是提问期间建的任务都带上（propose_task 再按 ctx.runId 写一次，结果相同）。T2b 的锁定验收 5 条照过。
