## 接缝契约（测试侧钉死的形状，实现必须兼容）

条件 3/4/5/7 通过 `defaultCheck` 的**第 6 个可选参数**注入（与 V1 的第 4/5
参数注入同一套路），测试文件里以类型收窄的方式把契约写成测试：

```ts
interface SandboxSeam {
  checkAuth: () => Promise<{ ok: true } | { ok: false; reason: 'unauthorized' | 'codex_missing' | 'unsupported_platform' }>;
  spawnCommand: (cmd, args, opts: { cwd; env; signal?; timeoutMs? }) => Promise<{ exitCode: number | null; stdout; stderr }>;
  dataDir: string; // 专用 CODEX_HOME 在 <dataDir>/codex-sandbox-home
}
```

要点：

- 生产 `checkAuth` 照 `scripts/real/d2b-e3-auth-check.mjs` 只读检查（cap_sid /
  helper / setup 标记 / 服务状态），**绝不弹窗**；
- 生产 `spawnCommand` = codex.exe sandbox windows elevated + `-C` 副本 +
  `-- <node> <副本>/node_modules/vitest/vitest.mjs run --config-loader runner`；
- 条件 3 断言了命令的逐位形状（档案名非空即可，未钉死名字）、TMP/TEMP
  指到副本内；条件 4/5 断言 0 次派生 + `ran=false` + 原因进输出
  （编排层 `!ran → verify_status='not_run'` 的现有映射负责落库，见
  executor.ts verify()）；
- 条件 7 断言 `<dataDir>/codex-sandbox-home/config.toml`：`enabled = false`、
  真实依赖子树 read、副本子树 write。

契约文档（契约 4）还要求核心层提供「检查」与「发起授权」两个函数给 D6
接口——验收条件 1–7 没有直接覆盖「发起授权」，实现时补该函数与真机检查
（见规格「真机检查」三条）。规格冲突或测试本身有错，本分支不改，交整合方。

## 整合方审测试（2026-09-30，锁定前改写与补全）

执行方的测试把契约 2 读成了「副本一复制好就带链接」。整合方据此改正了规格（见规格末尾「整合方审测试时的改正与补充」），测试相应改写：

- `d2-copy-junction`：改为「复制副本本身不建链接；依赖档派生那一刻两处链接都在、副本根有空 `pnpm-workspace.yaml`（项目自己有就原样保留）；跑完（通过 / 没通过 / 派生出错 / 取消）副本和跑之前一模一样，真实依赖一个不少」。拆干净的那几条同时断言「确实派生过、派生时链接确实在」，防止实现前就白白通过。
- `d2-tier-zero-dep`：执行方的 4 条保留；补条件 8——副本里有目录链接（子目录里也算）就不跑。整合方实测过：现有零依赖档会顺着目录链接把文件写到副本外（退出码 0，文件落在链接那头），这是 D2 之前就有的漏洞。
- `d2-sandbox-tier`：接缝改成第 6 个参数 `{ projectRoot, dataDir, checkAuth?, spawnCommand? }`（依赖档要知道真实项目在哪，不能再靠副本里的链接反推）；路径比较先取真实路径（CI 的临时目录是 8.3 短名）；命令参数原样在最后，产品在中间加的参数若有路径只许在副本内（给缓存目录留位置）；补条件 9、10、12；条件 7 补子包的只读条目、档案名与派生参数一致。
- 新增 `d2-wiring`（条件 11）：编排层把项目根目录与数据目录交给验证；不替换任何东西的生产路径在没授权过的数据目录上记 `not_run`；`checkSandboxAuth` 三种原因且不写文件。
