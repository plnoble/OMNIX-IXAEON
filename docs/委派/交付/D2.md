phase2 里执行方放宽了授权检查两处，整合方的处理：
- **`workspace_by_cwd` 允许为空：保留。** 授权刚完成时它是空的，跑过之后才有内容；phase2 换了好几份新副本都无人值守跑通，说明新目录不用重新授权。
- **helper「有任何 command-runner 就算」：改回严格的版本配对。**
  - 根因其实是解析版本号的正则：`codex --version` 输出末尾带换行，`[^ ]*` 把换行吃进了版本号，拼出的文件名永远不存在。改成到第一个空白为止，抽成 `parseCodexVersion`，补了单元测试（LF、CRLF、正式版、没有版本号）；
  - 版本配对的 helper 是提权 setup 生成的，D2b 实测过缺 helper 时 Codex 会去申请提权。Codex 升级后新版本的 helper 还不在，照实判「没授权」，宁可让用户再点一次授权，也不能在无人值守时弹窗；
  - 整合方在 phase2 早先一次尝试留下的、已授权的合成配置上做了被动检查（只读、不弹窗）：那份配置里的 helper 就叫 `codex-command-runner-0.130.0-alpha.5.exe`；严格配对返回已授权，新的空目录返回没授权。

- Codex 每次升级后，依赖档会先判「没授权」，要用户再点一次授权。授权入口和提示文案在 D6 做。如果以后实测升级后不用提权就能补上 helper，再放宽；
- 验收测试中途失败时会在系统临时目录里留下 `ixaeon-d2-*` 目录，phase2 的几次失败尝试也留了 `ixa-d2-real2-*`。删的时候用 Node 的 `rmSync`，不要用资源管理器或 PowerShell 5.1 的 `Remove-Item`：目录里有链接，后两者可能顺着链接删到外面；
