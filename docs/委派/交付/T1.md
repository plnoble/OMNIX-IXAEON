# T1 交付说明：本机同一时间只跑一个完整 verify

分支 `dev/T1`，A 档。

## 已实现（scripts 约 110 行）

- `scripts/lib/verify-lock.mjs`（新）：`acquireVerifyLock({ path?, wait?, pollMs?, maxWaitMs?, log? })`。
  - 锁文件默认 `<os.tmpdir()>/ixaeon-verify.lock`，内容只有 `{ pid, startedAt }`，不写工作目录；
  - 用 `openSync(path,'wx')` 独占创建；拿不到按 `pollMs`（默认 10 秒）轮询，每分钟最多打印一次「另一次 verify 正在跑（进程 <pid>，<HH:MM> 开始），等它跑完」；
  - 锁里的 pid 已不在（`ESRCH`）或内容读不懂 → 删掉重拿，打印「上一次 verify 留下的锁已失效，接手」；
  - 最多等 60 分钟，仍拿不到返回 `{ busy: true, holder }`；
  - `release()` 只删自己的锁（先读 pid 比对）；`wait:false` 拿不到立刻返回。
- `scripts/verify.mjs`：一开始拿锁（`process.env.CI` 有值时整段跳过）；拿不到时打印「另一次 verify 正在跑（进程 <pid>），本次不跑，退出」并退出码 4；`exit` / `SIGINT` / `SIGTERM` 都释放自己的锁。各步骤与超时未改。

## 真机通过

两个工作目录（`T1`、`T1b`，同一分支）：

- 第二个在开头打印并等着：`另一次 verify 正在跑（进程 27468，21:58 开始），等它跑完`；
- 第一个跑到一半按 Ctrl+C：锁文件被删掉（`Ctrl+C 后锁已删掉`），第二个**马上**拿到锁继续跑（锁的 pid 换成第二个进程后立刻开始 lint）。

## 本机一个环境限制（不是锁的问题）

本机 `localServer.test.ts` 绑 `127.0.0.1:43991` 会 `EADDRINUSE`，即使**没有任何进程监听**也照样失败：

```
$ node -e "const net=require('net');..."   # 监听 43991 探针
ERR EADDRINUSE
```

`netsh int ipv4 show excludedportrange protocol=tcp` 里没有 43991；该端口像是被 Windows 动态保留（WSL / Hyper-V 一侧），`net stop winnat` 需要管理员权限、本会话拿不到。因此本机完整 verify 会固定红在这一条集成测试上（与 T1 改动无关：分支改的只是 `scripts/`，同一份 integration 在 main 上也一样）。CI（windows-latest）没有这个保留段，以 CI 为门禁口径。
