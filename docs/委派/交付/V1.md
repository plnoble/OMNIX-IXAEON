## 已实现

- `packages/core/src/execution/executor.ts`：
  - `electronRunAsNodeEnv(exe, execPath, versions)` 纯函数：被派生的可执行文件
    就是本进程自己且本进程是 Electron（versions.electron 有值）时返回
    `{ELECTRON_RUN_AS_NODE:'1'}`，否则空；
  - `defaultCheck(argv, cwd, signal?, envFn?)`：envFn 默认就是上面的纯函数，
    计算结果注入验证子进程（在既有 minimalChildEnv 白名单之上，只加这一项，
    不放宽任何规则）；envFn 参数供验收测试做「配线级」验证；
  - `spawnArgv` 增加 `extraEnv`（默认空）。
- `apps/desktop/src/main/appRuntime.ts`：`stopServer(reason:'normal'|'restore')`
  ——正常退出写「本地服务已停止」，只有 restoreData 路径写
  「本地服务已停止（数据恢复）」。
- 未改验证判定规则、未加可执行程序、无迁移。

## Codex 审查

第一轮（2026-09-29）结论「需要修改」，四条意见全部处理：

1. Electron 用例只测辅助函数返回值、删掉注入调用测试仍会过 → 新增两条
   「配线级」用例：`defaultCheck` 传入 FORCE_RUN_AS_NODE / FORCE_NONE 的
   envFn 做**真实派发**，子进程打印 RUN_AS_NODE=1（证环境确实传进子进程，
   删了注入就红）；空注入下退出码 7 如实。
2. 窗口计数只见当前进程 → 真机脚本补三重观察（窗口数 + `--permission`
   electron 进程计数 + 日志文件计数，见「真机通过」），并重跑通过。
3. 锁定清单/`acceptance.mjs run V1` 缺说明 → 如实写明：A 档合并前未登记是
   流程内状态（锁定是整合方步骤），并提供 vitest 指定运行的原样输出。
4. 输出只有摘要 → 验收、真机原始输出已原样贴入本节。

## 已知缺口

- 打包版（NSIS 安装后）同一检查未做：注入逻辑按 versions.electron 判定，
  与开发版无差别，但打包版真机复核留待整合方/用户后续打包验收。
- 普通 node 环境（本仓库 CI）里跑的都是 node.exe，本单的注入分支只在
  Electron 环境与配线级测试中验证。
