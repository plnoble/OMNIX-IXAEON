## 已知缺口

1. **`IXAEON_RELAY_CODE` 有值时我连 `fetchMain` 也跳过**（契约只说「不建、不更新、不装依赖」）。理由：测试/临时调试不该去连真 GitHub；不跳过的话每次都会对真仓库发一次 HTTPS fetch。整合方的锁定测试按「有这个开关就完全不动代码根」的语义写的（骨架里还把 `IXAEON_WORKTREES` 指到临时目录兜底），与我的实现一致；如果以后想保留 fetch，改动是把 `if (!codeEnv)` 里的 fetch 拆出来。
2. **看门人不管 `relay-run` 的清理**：它一直复用那份工作目录；`worktree remove` 只在真机脚本收尾时做（第一次因刚装完依赖、Windows 文件被占失败，脚本重试后直接删目录 + `prune`）。产品代码里没有这条重试。
3. **数据目录不自动搬**（契约第 6 条）：用户现有数据还在桌面版转存目录 / `%LOCALAPPDATA%\IXAEON\relay`，`relay status` 只提醒、不动手。
4. **第一次 `relay run` 会为 `relay-run` 装一次依赖**（本机 store 热时约 17s；冷启动要下载）。`relay init` 不预建 `relay-run`。
5. 开机自启只在 README 里给了 `schtasks` 示例，**没有替用户建任何计划任务**（规格要求）。
