### 测试里定下的接缝（规格没写死，请整合方锁定前看一眼）

1. **`buildCockpitSnapshot` 的签名不变**（照 K2：`(db, { relayDir, ixaeonRepo, now? })`），K4 的两个新设置项由它从
   `app_settings` 直接读：`cockpit.quotahub_url`、`cockpit.manual_quotas`。理由：手动额度的 zod 校验和「坏了记
   error、不抛错」都在快照层；设置页只负责写这两个键。K2 的 `ixaeonRepo` 仍只认参数，没有动已有接口。
2. **`cockpit.manual_quotas` 的 JSON 形状**（规格只列了表单字段，没写序列化形状）：

   ```json
   [{ "account": "显示名", "window": "5 小时", "resetAt": "ISO", "expiresAt": "ISO", "registeredAt": "ISO", "note": "可选" }]
   ```

   每项一个窗口；`registeredAt` 映射到 `QuotaCard.collectedAt`（界面的「登记于 N 天前」要用它，不能拿快照时间冒充）。
   `provider` 规格没给来源，测试只要求它是字符串、不限制取值。
3. **`quotahub_url` 只认 `http://127.0.0.1:<端口>` / `http://localhost:<端口>`**：测试除了条件 3、8 写的
   `http://example.com`、`/api/refresh`、用户名密码，还拒绝了带查询串的地址（规格「约束」写了带查询也拒绝）。
4. **倒计时**：契约里没有倒计时字段，快照只保留 `reset_at` 对应的 `resetAt`；测试断言它是可解析的 ISO 时刻，
   倒计时由界面按它算。规格条件 2 的「倒计时按 reset_at 算」在核心层只能测到这里。
