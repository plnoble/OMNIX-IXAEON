## 已实现（按判定与规格步骤）

1. **smoke 套件 serial 化**：`test.describe.configure({ mode: 'serial' })`——
   前面挂掉后面直接跳过，不再在新 worker 的新实例上乱跑（判定根源）。
2. **三类过时断言修正**：
   - smoke 总览 + screenshots 总览：`state-card/state-server/state-setup`
     → `page-overview` 可见 + `overview-coverage` 含「项目 1」 + 页面含
     「本地服务 127.0.0.1:43191」（W1b 6adc15e / E1 4871054 重写总览页）；
   - d6-chat-ui 待办卡「排队中」→「进行中」（D3 规格第 1 条：点要做后
     自动派发立刻开工）。
3. **m2-ui S1/S2 改理解页操作**（E6 83af882 后待讨论页只放冲突等条目）：
   confirm/reject 分支从 `nav-inbox` 改 `nav-understanding`，按钮按
   `^(采纳|确认正确)$` / `不采纳`（AI 说的显示「采纳」，其余「确认正确」，
   都有「不采纳」）。落库、简报前后断言原样未动；冲突类 S4 仍在待讨论页
   （原样通过）。
4. **步骤 2 端口守卫**：新增 `apps/desktop/e2e/global-setup.ts`（照 C3
   ui-port-guard 判定：只有 ECONNREFUSED 算空闲，不跟随重定向），挂在
   `e2e/playwright.config.ts` 的 `globalSetup`。端口被占时一条明确提示后
   全部测试不跑（实测见下）。
5. **步骤 4 接进 CI**：`.github/workflows/verify.yml` 在 verify.mjs 之后
   新增一步 `node scripts/test-e2e.mjs`（CI 无运行中的 IXAEON，端口空闲；
   build 步骤产物供 e2e 用）。
6. **serial e2e 的调用修复**（复跑中新发现的前置缺口）：
   `apps/extension/e2e/serial-real.cjs` 调用 `completeSetup` 缺
   `apiBaseUrl` 字段（主进程读 `input.apiBaseUrl.trim()` 抛 IXA0000）。
   补齐为 `apiBaseUrl: ''`——本就是 test 侧调用过时（上游只为 interface 标了
   可选，trim 假设必有）。与 V2 产品代码无关（main 上本来就会挂，C3 时
   e2e 在 desktop 段即停，从未跑到 serial）。
