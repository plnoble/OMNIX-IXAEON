## 已实现

- `packages/core/src/execution/modelExecutor.ts`（新，`ModelCodingExecutor` 实现
  `CodingExecutor`，`name = model:<模型名>`）：
  - **发什么**：只发批准范围内的文件、根 README、目标里写了相对路径的文件；范围外
    又没点名的只进清单；二进制、密钥类文件名、链接那头的东西不发；单文件 64 KB
    截断、内容总量 12 万字符、清单 400 条上限。
  - **要回什么**：一次 `chatStructured`（zod schema 只描述结构；最多 20 处、单处
    20 万字符的上限由执行器自己核、原因自己给）；`content` 允许不带或 null。
  - **怎么改**：全部改动先验后写——范围外/绝对路径/带 .. /路径上有链接/写到目录上/
    删不存在的文件/不许盲改（要覆盖内容没发全的已有文件），有一处不合格整批不写，
    原因带那条路径；全合格再写/删。不起子进程、不自己联网；`raw` 截到 8000 字符。
  - **超时与取消**：超过 `task.timeout_ms` 到时限就失败（不等模型回来）；开工前已
    取消不发请求；等待中取消、或超时之后才回来的响应都不写。
  - 模型自己说没做成：不写，报告照它说的。

## 整合方复审（2026-10-03）

结论：**并入，实现由整合方改过**。锁定的测试没有被改动；真机检查脚本可用。下面是复审照出来的问题，都有对应的新测试（在执行方的实现上是红的），细则写在规格末尾「整合方复审实现时补」。

「不许盲改」上的三处漏洞（原来的锁定测试没盯住，是整合方的测试漏了）：

1. 「发没发全」是按文件大小算的（不超过 64 KB 就算发全），和实际发没发无关：总量放不下而没发出去的文件，模型照样能整份覆盖。
2. 文件存不存在是在清单里按字符串找的。Windows 不分大小写，把 `src/big.md` 写成 `src/BIG.md` 就绕过了检查，原文件被覆盖。
3. 密钥类文件名不进清单，于是副本里已有的 `.env` 被当成不存在，可以被覆盖。

一处不合格整批不写：

4. 路径中间是个文件（`src/other.txt/child.txt`）没拦，写到这一处才报错，前面合格的改动已经写进去了。

和规格不一样的地方：

5. 截断没有标明，模型分不清哪些文件给全了；比总量上限还大的文件被整个跳过，没有发开头。
6. README 只认 `README.md`。
7. 目标里点名是按英文词切的，中文路径和后面紧跟标点的路径认不出来。
8. 模型说没做成时还先去核它给的改动，用户看到的是路径错，不是模型说的原因。

别的：

9. 取消之后要等模型回来才结束，期间编排层「同时只跑一个」的位置被占着。
10. 副本里每个文件都整份读进内存，读两遍。
11. 靠匹配错误文字（`/format/` 之类）区分「没按格式」和「请求失败」。
12. 超时用的定时器没有清掉。
