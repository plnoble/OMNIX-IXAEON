## 验收测试

`packages/core/test/acceptance/d4-apply-branch.test.ts`，9 条，对应规格的验收条件。直接测 `CodingOrchestrator.accept` 之后的落地：临时目录里的真 git 仓库（或普通文件夹）、执行器替身、git 全局配置隔开。

1. 改一个文件、加一个文件 → 分支 `ixaeon/<任务 id 前 8 位>`，提交正好这两处，标题和正文按规格；当前分支、HEAD、工作区、暂存区不变 → 条件 1
2. 同名分支已存在 → `ixaeon/<前 8 位>-2` → 条件 2
3. 批准快照之后，项目里又提交了同一个文件 → 不建分支，改动包，`apply_error` 列出该文件，仓库不动 → 条件 3
4. 快照时这个文件有没提交的改动 → 同条件 3 → 条件 4
5. 不是 git 仓库 → 改动包，清单里有改了的和新增的，改动后的文件按原路径在 → 条件 5
6. 文件夹授权已撤销 → 不落地，`apply_error` 含「没有这个项目目录的读取授权」，不建分支、不生成改动包 → 条件 6
7. 隔开全局 git 身份后仍能提交，作者是 IXAEON / ixaeon@localhost → 条件 7
8. pre-commit 拒绝提交 → `applied_ref` 指向改动包，`git worktree list` 只剩原来的工作树 → 条件 8
9. 替身没改任何文件 → 不建分支、不生成改动包 → 契约 2（这次没有改动）

没钉死的：改动包清单的文件名。只要求目录里能读到路径和改动后的内容。

`node node_modules/vitest/vitest.mjs run packages/core/test/acceptance/d4-apply-branch.test.ts --project acceptance`：8 条失败、1 条通过。失败都是断言 `applied_ref` 仍为空、改动包目录还不存在——落地还没做。通过的那条是「没有改动就不落地」，现状本来如此，实现之后仍要成立。
