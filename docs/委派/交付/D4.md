9. 条件 5 删除：非 git 项目里删掉的文件，清单 `deleted` 列出，目录里没有这个文件。
10. 条件 6（六条）：授权在开流程前撤销、授权在派发后接受前撤销、有效授权在别处（项目不在其内）、**授权目录只是字符串前缀相同但并不包含项目**（钉住必须用 `isPathInside` 这类目录包含判断，不能用字符串前缀误判）、**接受时项目没有根目录**（派发后把 root_path 置空）→ 都不落地，`apply_error` 含「没有这个项目目录的读取授权」，不建分支、不生成改动包；授权给项目根的**父目录**（项目在授权范围之内，`isPathInside`）→ 照常建分支。
11. 条件 7：隔开全局 git 身份后仍能提交，作者是 IXAEON / ixaeon@localhost，正文同样带任务 id 和验证结果。
12. 条件 8（两条）：pre-commit 钩子拒绝、post-checkout 钩子拒绝（都设了执行位，否则 POSIX 上钩子会被跳过；post-checkout 让 `git worktree add` 确定性失败，且半成品工作树与已建分支 git 不会自己回收）→ 都没有残留临时工作树、没有 `ixaeon/*` 分支，改走改动包且清单分类正确。
13. 契约 2：替身没改任何文件 → 不建分支、不生成改动包，`applied_ref` 与 `applied_at` 都为空。
14. 只在接受之后落地：每条走 `runTask` 的用例在批准后、派发后各查一次，此时没有分支、没有改动包、`applied_ref`/`applied_at` 为空。

## Codex 审查

B 档，审查不作为合并关卡（锁定仍由整合方做）。用户 2026-09-28 说可以审、Codex 有额度，已跑三轮 `node scripts/codex-review.mjs D4`（0.158.0，对照 `docs/委派/D4-接受后在项目里建分支.md`），记录在 `docs/委派/交付/D4-Codex审查.md`（该文件每轮覆盖，最新一轮为 11:56）。第一轮结论「需要修改」，十条「必须改」都是测试漏条件或放宽条件，已全部改，对应关系：

- 钩子文件没有执行位 → POSIX 上 Git 会跳过：`chmodSync(hook, 0o755)`。
- 工作区保护从干净仓库起测、指纹只看状态：仓库先备好已暂存/未提交修改/未跟踪三种内容，指纹改为分支、HEAD、`git status`、`git diff --cached`、`git diff` 全文加脏文件内容。
- 条件 3 的提交发生在派发之前：改为派发之后、接受之前提交。
- 授权只测了提前撤销：补派发后接受前撤销、有效授权在别处、父目录授权有效（这种要正常落地）三条。
- 改动包只查路径文字和 `note.txt`：清单钉为 `manifest.json`（`changed`/`added`/`deleted`/`conflict`），补 `hello.txt` 内容、删除场景，`applied_ref` 经 `resolve` 后必须等于补丁目录本身。
- 条件 8 只测了提交失败：补「建工作树这步失败」（post-checkout 钩子拒绝——`git worktree add` 确定性失败且半成品工作树与分支 git 不会自己回收，实现必须清干净）一条，两条都断言工作树清干净、没有残留 `ixaeon/*` 分支、改走改动包。
- 批准、派发后没查是否尚未落地：`runTask` 在批准后、派发后各查一次。
- 没有远端、没查推送副作用：挂空的本地 bare 远端，断言落地后 `git ls-remote` 为空。
- 没断言 `applied_at`、正文只查任务 id：成功落地断言 `applied_at` 可解析为时间；正文断言含任务 id 和验证结果（`passed`，验证命令用真的 `node -e 'process.exit(0)'`）。
- 契约 6 完全没测：新增桌面验收测试（见上）。

- 桌面测试直调 `runtime.acceptCodingTask`，没覆盖真实 IPC 入口：补一条经真实 `registerIpc` 注册的 `ixaeon:acceptCodingTask` 通道调用，断言同样追加落地回报。

- 冲突只测了原有文件：补一条——派发后用户提交了执行器要新增的文件（基线记为不存在），断言也算冲突、改动包里放执行器版本、用户版本留在原地。

第四轮（f51f37e）结论仍是「需要修改」，一条「必须改」、两条建议，都已改：
