## Codex 审查（A 档）

第一轮结论「需要修改」，逐条处理如下（这次修改都按 Codex 意见收紧，没有放宽任何条件；锁定的核心测试按修正内容重锁）：

1. linkOnPath 不查根目录本身 → 已改：`isLinkAt` 先查根目录，再逐段查（`taskChanges.ts`）。
2. 授权检查排在链接/普通文件检查之后 → 已改：每个文件先查授权，撤销授权时统一提示没有授权，两边路径连 lstat 都不探。
3. 授权条件允许 root_path 是普通文件 → 已改：`rootIsDir` 只认还在的目录。
4. 新增/删除空文件误报 same → 已改：same 分支要求两边都存在。
5. trimTail 吞掉末尾空行、行数限制被绕过 → 已改：`linesOf` 只豁免文件末尾一个终止换行，其余空行照算。
6. CRLF/LF 差异按归一后文本判定成「一样」→ 已改：norm 后行相等但原文不同时写「只有换行符不同」，原文一字不差才写「已经合并过了」；条件 5 测试补了两种情形。
7. baseHashes 缺项与「null=当时没有」混淆 → 已改：报告里没有这一项的，不写漂移 note（并加了用例）。
8. 条件 1 断言没验证 3 行上下文边界 → 已加：filler2/filler6 必须在、filler3/4/5 不得出现。
9. 安全用例只查输出没查「确实没读」→ 已加：mock readFileSync 记录调用，断言被禁的路径（越界/密钥/目录内容/超大/链接）从未被 readFileSync 读过；条件 7 同样断言没授权时两边的 calc.mjs 从未被读。
10. 真机没跑 → 见上「真机通过」：证据在 U3b 交付说明里，合并前两分支一起交，满足「没跑不能合并」的门槛。
11. 建议：GitHub verify 运行号 → 合并前在队列/交付说明里补上。

修改后 `node scripts/acceptance.mjs run U3`、`node scripts/verify.mjs` 全绿。审查小结见 `docs/委派/交付/U3-Codex审查.md`。
