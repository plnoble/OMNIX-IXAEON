# M3 换了 API 地址，旧 Key 不带到新地址——交付

- 分支：prep/M3，基于 main c423f9b（领 M3）；档位 B（隐私）
- 执行方：prep
- 锁定的验收测试：main 上由整合方改正补全并锁定（m3-key-scope.test.ts + m3-settings-ui.test.ts，共 27 条），实现只让它通过、没改一条。

## 已实现

- `apps/desktop/src/main/appRuntime.ts`：
  - `normalizeOrigin`（来源 = 协议 + 主机 + 端口；主机名不分大小写、去尾斜杠、
    默认端口 http 80 / https 443 写不写都算同一来源、空地址 = 官方默认；
    解析不了的按字面比）；
  - `saveModelSettings`：地址来源变了且这次没填新 Key、又确实存过 Key 时，清掉
    已保存的 Key（`apiKeyEncrypted = null`、`apiKeyPresent = false`），返回
    `{ ok: true, keyCleared: true }`；其余情况 `keyCleared: false`（本来没 Key 不谎报）。
    换个来源同时填新 Key 照常保存新的。清 Key 只动模型的 Key，模型名 / 聊天模型 /
    已保存清单 / 搜索 Key 都不动。
- `packages/contracts/src/ipc.ts`：`saveModelSettings` 返回类型加 `keyCleared: boolean`。
- `apps/desktop/src/renderer/src/pages/Settings.tsx`：这次保存返回 `keyCleared === true`
  且重载后确实没有 Key 时，模型接入卡片显示提示（`data-testid="settings-apikey-cleared"`，
  文案含「地址变了，原来的 Key 没有带到新地址」）；普通保存不显示；补填 Key 再保存
  提示消失。`reload` 返回刚拉到的视图，提示判定不用猜状态。

```
UPSTREAM_A http://127.0.0.1:61471/v1 UPSTREAM_B http://127.0.0.1:61472/v1
A_AUTHS ["Bearer sk-m3-synthetic"]
B_KEY_STATUS 未配置（提示已显示）
```

1. 地址甲 + 合成 Key 保存、检测：甲收到这个 Key；2. 地址改成乙、Key 留空保存：
