第一轮（3760fab）：需要修改。四处必须改都改了：

1. 执行报告是 JSON `null`、或者 `summary` 不是字符串时，`executorExplanation` 会抛。现在这两种都返回 null，补了测试。
2. 条件 2、4（回报逐字）原来只靠已锁定的旧测试。补进 `apps/desktop/test/acceptance/u5-tasks-card.test.ts`，重新 lock。两句函数本身测的是契约，留在 `packages/contracts/test/acceptance/`；规格写的「两句共用的话也在 desktop 验收文件里测」，由条件 2、4 那两条承担。
3. 交付说明里的行数是收回缩进之前的。`Tasks.tsx` 那次被格式化重排，显示新增 148 行；缩进已收回，现在是新增 61、删除 2。四个源码文件合计新增 97 行。
4. verify 的结果补上了。D5a 端到端要真应用，随分支 CI 的端到端一步跑，推送后看。

建议的一条：`verifyLabel` 对 `failed` 返回「验证没通过」，而旧的 `verifyLine` 对这个状态返回「还没有独立验收」。查过：验证失败的任务状态是 `failed`，回报走 `failed()`，里面不写验证那一句（输出贴在原因下面）。`pending_accept` 才写验证那一句，而这个状态的 `verify_status` 不会是 `failed`（`executor.ts` 里进 `pending_accept` 的只有通过、没跑、以及验收测试不肯跑）。所以真实回报到不了这句，文字不变。没改回去。
