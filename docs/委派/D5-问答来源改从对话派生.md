# 委派单 D5：ask_session 来源改从对话派生

任务来源：[三周任务单](../三周任务单.md) D5。大小：**小到中（≤200 行改动）**。

前置：D1–D4 已并入（迁移 26、`ConversationStore`、`ask()` 按对话隔离）。

## 背景

用户和 IXAEON 的每次问答都会存进 `sources` 表（provider = `ask_session`），走既有提取管线生成理解候选。

现在的做法是**每问一次建一条来源**：`ImportService.captureAsk()` 用 `externalId: input.runId`，一问一答就是一个独立的 `source` + 2 个 `segment`。

聊 20 轮就是 20 条互不相干的来源。检索时看到的是 20 个碎片，谁也不知道它们本来是一次连续的对话。

D1 已经确立了「**messages 是权威记录，来源从对话派生**」。本任务落实它：**一个对话一条来源，后续轮次追加上去。**

## 关键：必须复用既有的追加机制，不要新写

`SourceStore.appendCapturedTurns(sourceId, turns, opts)` 已经存在，并且已在生产使用（`localServer.ts:855` 和 `:914`，Chrome 扩展采集 ChatGPT 网页对话走的就是它）。它已经处理好了：

- 按 `external_node_id` + `content_hash` 去重，重复提交不重复入库；
- 同一位置出现新指纹（编辑/重新生成）→ 旧版本转为非活动分支，保留历史；
- 旧指纹重新激活（分支切回）视为内容变化；
- 正确递增 `content_revision`，让提取管线知道有新内容要分析；
- 刷新 `imported_at` / `captured_at`。

**不要为问答另写一套追加逻辑。** 这一条是本任务的核心要求——如果你发现自己在写去重或分支处理的代码，说明走错了。

## 要改的地方

### 1. `ImportService.captureAsk()`（`packages/core/src/import/importService.ts:505`）

改成按对话工作：

- 入参把 `runId` 换成 `conversationId`（`runId` 可保留用于审计字段，但不再作为 `externalId`）；
- `externalId` 改为 `conversationId`；
- 先查这个 `conversationId` 是否已有 `ask_session` 来源：
  - **没有** → 走现有的建来源路径（首轮），拿到 `source.id`；
  - **已有** → 调 `appendCapturedTurns(sourceId, turns)` 追加本轮的两条（user / assistant）；
- `turns` 的 `order` 用 **message 的 `seq`**（`ConversationStore` 给每条消息的顺序号）。这样同一轮被重复提交时能正确去重，而不是每次追加都当新内容；
- 标题：首轮用第一个问题的前 80 字（与现状一致）；后续轮次不改标题。

返回值保持 `{ created: boolean; source: Source }` 的形状，`created` 表示本次是否**新建**了来源。

### 2. `appRuntime.ask()`（`apps/desktop/src/main/appRuntime.ts`）

- 调用 `captureAsk` 时传 `conversationId` 与两条消息的 `seq`；
- 首次建来源后调 `this.conversations.setSourceId(conversationId, source.id)`，把来源挂到对话上（`conversations.source_id` 列已存在，迁移 26 建好的，目前一直是 null）；
- 提取入队（`enqueueExtract`）保持调用，让新增内容进提取管线。

### 3. 不要动的

- 授权逻辑：`ensureAskCapturePermission()` 的撤销/恢复语义完全不变。撤销后不得隐式重建授权（这是 A03 审核的成果，`a03-ask-capture.test.ts` 和 `restructure-20260913.test.ts` 都在守）。
- 迁移：本任务**不需要新增迁移**。`conversations.source_id` 已存在。如果你认为需要改表，先停下来说明原因，不要自行加迁移。
- `provider` 枚举：`ask_session` 已在迁移 20 加好，不要改 CHECK 约束。

## 验收条件（由整合方写定，不得自行修改或增补）

1. **一个对话一条来源**：在同一对话里连问 3 轮，`SELECT COUNT(*) FROM sources WHERE provider='ask_session'` = 1，且该来源下 `segments` 有 6 条（3 问 3 答），`sequence` 递增无重复。
2. **对话挂上了来源**：`conversations.source_id` 不为 null，且等于那条来源的 id。
3. **两个对话两条来源**：分别在两个对话各问一轮，得到 2 条来源，各自 2 个 segment，内容不串。
4. **重复不复制**：对同一对话、同样的 `seq` 和同样的正文再调一次 `captureAsk`，来源数不变、segment 数不变（`deduplicated` > 0）。
5. **内容版本递增**：追加新的一轮后，该来源的 `content_revision` 比追加前大。
6. **撤销授权后不落库**：撤销 `ask.ixaeon.local` 后提问，`ask_session` 来源数不增加，且授权不被隐式重建（保持 revoked）。
7. **复用证明**：`captureAsk` 的实现里调用了 `appendCapturedTurns`。新增代码中**不含**自己写的去重或分支切换逻辑。
8. `tsc --noEmit`、`eslint .` 退出码 0；`node scripts/verify.mjs` 全部门禁通过，**跳过数不得增加**。

验收 1–6 请写成一个新测试文件 `packages/core/test/integration/d5-ask-source-derivation.test.ts`。
