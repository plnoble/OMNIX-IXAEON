# 委派单 D6：把问答页重写成连续聊天

任务来源：[三周任务单](../三周任务单.md) D6。大小：**中（≤300 行改动；超了就拆，先交对话列表 + 消息流）**。

前置：D1–D4 已并入。后端已经能连续对话，IPC 契约已定死。**现在缺的只是界面。**

## 背景

`apps/desktop/src/renderer/src/pages/Ask.tsx`（194 行）现在是一个**单轮搜索框**：输入一个问题 → 出一个回答 → 再问一次，上一轮直接消失（`setAnswer(null)`）。

整个产品的目标是「我照常聊天，你逐渐理解我」「换个窗口，你记得相关的事」。后端已经做到了（消息落库、历史注入、按对话隔离引擎会话），但用户看不到——界面上仍然只有一个孤零零的回答。

本任务把它变成**像 ChatGPT 那样的连续聊天**。

## 已经给你准备好的 IPC（不要改契约，直接用）

全部在 `packages/contracts/src/ipc.ts` 的 `IxaIpcApi` 里，渲染层通过 `api`（`apps/desktop/src/renderer/src/api.ts`）直接调用，已经是类型安全的：

```ts
askQuestion(input: { conversationId?: string | null; projectId: string | null; question: string })
  → AskAnswer & { conversationId, userMessageId, messageId }

cancelAsk(conversationId?: string | null)
listConversations(input?: { includeArchived?: boolean; limit?: number }) → ConversationSummary[]
getConversation(id) → { conversation: Conversation; messages: ConversationMessage[] }
createConversation(input?: { title?: string; projectId?: string | null }) → Conversation
renameConversation({ id, title }) → Conversation
archiveConversation(id) / unarchiveConversation(id) → Conversation
deleteConversation(id) → { deleted: true }
```

`ConversationMessage` 的关键字段：`role`（user/assistant/system）、`content`、`status`（streaming/complete/failed/cancelled）、`citations`、`meta`、`errorMessage`、`seq`。

`meta` 里有 `notice`、`usedChars`、`coverage`、`steps`、`proposedTasks`——就是现在页面底部那些信息，重开对话时从这里还原。

## 要做成什么样

### 布局

左右两栏。左侧对话列表约 240px，右侧消息流占满剩余宽度。

**左侧：**

- 顶部一个「新对话」按钮；
- 对话列表按 `updatedAt` 倒序（`listConversations` 已经排好了，别再排一次）；
- 每项显示 `title` 和 `lastMessagePreview`；当前选中项高亮；
- 每项有改名 / 归档 / 删除入口（右键菜单或悬停按钮都行，删除要二次确认）；
- 列表为空时显示引导文案，不要空白。

**右侧：**

- 消息按 `seq` 正序从上往下排，**上一轮不消失**；
- 用户消息与助手消息在视觉上分开（对齐或底色，别只靠一个小标签）；
- 底部输入框 + 发送按钮；`Enter` 发送，`Shift+Enter` 换行；
- 发送中显示等待态，并给出取消按钮（调 `cancelAsk(conversationId)`）；
- 新消息到达后滚动到底部；用户手动往上翻时**不要**强制拉回底部。

### 必须保留的现有能力

现在 `Ask.tsx` 里这些东西不能丢：

1. **引用可展开核验**：`citations` 逐条列出，点击展开 `excerpt`；`isUserCorrection` 的要标出「用户纠正」。这是产品硬要求，回答必须可核验。
2. **项目视角选择**：个人视角（不选项目）/ 指定项目。放在输入框附近或对话头部。选定后随 `askQuestion` 一起传。
3. **行动批准卡**：`meta.proposedTasks` 里的待批准任务，渲染成卡片，有「批准并排队」按钮（调 `api.approveCodingTask(id)`），批准后状态变成「已排队执行」。
4. **引擎/模型/覆盖信息**：`engine`、`modelName`、`meta.usedChars`、`meta.coverage`、`meta.steps` 仍要能看到，可以折叠起来放在每条助手消息下面。

### 状态必须看得见

这条单独列出来，因为最容易被做丢：

- `status === 'failed'`：显示失败样式 + `errorMessage`。**不能渲染成空气泡。**
- `status === 'cancelled'`：显示已取消，并保留已经写出来的那半截 `content`。
- `status === 'streaming'`：本任务里不会出现（流式是第 2 周的 S1/S2），但**渲染逻辑要先留出这个分支**，显示为「正在回答…」，不要 crash。

### 重开对话要能还原

选中一个对话 → 调 `getConversation(id)` → 把 `messages` 全部渲染出来，包括引用和元数据。关掉应用重开，对话和消息都还在。

## 不要做的

- **不做流式**。`askQuestion` 目前是一次性返回整段回答。S1/S2 是第 2 周的事，不要提前造事件通道。
- **不做待办列表**。T1–T3 是第 2 周的事。
- **不改 IPC 契约**。缺什么先说，不要自己加方法。
- **不引入新依赖**。不要装 markdown 渲染库、状态管理库、UI 框架。用仓库已有的 `ui.tsx`（`Card` / `Button` / `Empty` / `ErrorBanner` / `Spinner`）和 `styles.css`。
- **不动别的页面**。只改 `Ask.tsx` 和 `styles.css`（可追加样式），必要时加一两个小组件文件。

## 验收条件（由整合方写定，不得自行修改或增补）

1. **连续三轮不消失**：在一个对话里问 3 次，页面上同时能看到 3 问 3 答共 6 条消息，顺序正确。
2. **切换对话**：新建第二个对话，问一次；点回第一个对话，看到的是第一个对话的 6 条消息，没有第二个对话的内容。
3. **重开还原**：关闭应用重新打开，进入问答页，之前的对话在列表里，点开消息、引用、引擎信息都还在。
4. **失败可见**：把一条消息在库里改成 `status='failed'` + `errorMessage='引擎超时'`，页面显示失败与错误文案，不是空气泡。
5. **取消可见**：`status='cancelled'` 的消息显示为已取消，且已写出的 `content` 仍然显示。
6. **引用可展开**：点击引用编号展开原文摘录；`isUserCorrection` 的有「用户纠正」标识。
7. **批准卡可用**：带 `meta.proposedTasks` 的消息渲染出卡片，点击批准后状态变为已排队。
8. **既有 UI 测试不回归**：`node scripts/verify.mjs` 全部门禁通过，三套真实 Electron 套件全绿，**跳过数不得增加**。
9. `tsc --noEmit`、`eslint .`、`prettier --check` 退出码 0。

验收 1–7 写成一个新的 Playwright 规格 `apps/desktop/e2e/d6-chat-ui.spec.ts`，按仓库既有 e2e 的写法（参考 `apps/desktop/e2e/m2-ui.spec.ts`）。
