# 规格 K4：额度与项目活动

档位：**B**（新的本机访问）。大小：中（≤300 行源码；超了把页面部分拆成 K4b）。依赖：K2、K3。
v2 规格：先只推测试（`packages/core/test/acceptance/k4-*.test.ts`），等整合方锁定后再实现。

## 要什么

驾驶舱加两块：**额度**和**项目最近活动**。

### 额度

**QuotaHub**（`D:\Agent\Project\OMNIX-QuotaHub`，已支持 Codex、火山、Grok）
- 新设置项 `cockpit.quotahub_url`，默认空，表示关闭。用户在设置页填 `http://127.0.0.1:8787` 才启用。
- 请求 `GET <url>/api/snapshots`，超时 3 秒。路径写死，**不调 QuotaHub 的别的接口**（它还有 `POST /api/refresh`、`/api/volcengine/cookie`）。
- 返回形如 `{ server_time, refreshing, accounts: [...] }`（见 QuotaHub 的 `quotahub/server.py`）：只从 `accounts[]` 每一项里取这些字段：`provider`、`account_name`、`status`、`plan.name`、`plan.expires_at`、`quota_windows[].{name, used, remaining_percent, reset_at}`、`collected_at`。`used` 是已用百分比（0–100），可能是 `null`（比如 Grok 限额未知）。

**手动登记**（Claude 等 QuotaHub 还不支持的）
- 设置页加"手动额度"表单：账号显示名、窗口名（5 小时 / 每周 / 其他）、下次重置时间、订阅到期日、备注。
- 用 `setSetting` 存成一个 JSON 设置项 `cockpit.manual_quotas`。

**页面**
- 每个账号一张卡：状态、各窗口用量条、重置倒计时、订阅到期日。
- QuotaHub 的 `collected_at` 超过 15 分钟 → 标黄"数据旧了"。
- 手动条目标"手动 · 登记于 N 天前"；重置时间已经过了 → 提示"可能已重置，请更新"。

### 项目最近活动

- 只对已经做过目录登记读取的项目，读最后一次提交的时间和最近 7 天的提交数。「能不能读」照 `packages/core/src/runtime/projectBrief.ts` 的判断：有 `project_snapshot` 来源、对应授权是 `active`、授权的目录在项目的 `root_path` 里面——把这段判断抽成一个函数两处共用，不另写一份。git 调用方式和 10 秒超时也照它。
- 没登记读取的项目显示"未授权读取"，不跑 git。
- 项目卡片加一行"最后提交 N 天前 · 7 天 M 次"。

## 契约

- `CockpitSnapshot` 增加：
  - `sources.quotas: SourceHealth`；
  - `quotas: QuotaCard[]`；
  - `ProjectCard.activity: { lastCommitAt: string | null, commits7d: number | null, readable: boolean }`。
- `QuotaCard = { source: 'quotahub' | 'manual', provider, account, status, plan: string | null, expiresAt: string | null, windows: { name, usedPercent: number | null, resetAt: string | null }[], collectedAt: string }`

## 约束

- **新的本机访问只有 `quotahub_url` 一处**，默认关闭；只认 `http://127.0.0.1:<端口>` 或 `http://localhost:<端口>` 这种只有协议、主机、端口的地址，带路径、查询、用户名密码的，别的主机的，一律拒绝、不发请求。
- 手动额度的设置项 JSON 用 zod 校验，坏了就当没有、`quotas` 来源记 `error` 写原因，不抛错。
- 不发任何外网请求；不读 QuotaHub 的 `credentials\`、`data\` 目录；QuotaHub 返回里没列出的字段一律丢弃。
- 不加迁移。

## 验收条件

1. 没配 `quotahub_url` → `quotas` 来源为 `missing`，note 是"未连接 QuotaHub"；其他部分正常。
2. 测试里起一个合成 HTTP 服务返回 2 个账号的快照 → 字段映射正确；倒计时按 `reset_at` 算。
3. `quotahub_url` 设成 `http://example.com` → 被拒绝，测试证明没有发出请求。
4. 合成服务 5 秒才响应 → 3 秒超时，来源为 `error`，快照照常返回。
5. 合成返回里夹带 `cookie: "COOKIE-XYZ"`、`token: "TOKEN-XYZ"` → 快照 JSON 里找不到这两个值。
6. 手动登记一条 Claude 额度 → 出现在 `quotas` 里，`source = 'manual'`。
7. 合成 git 项目（有 `project_snapshot` 来源，7 天内 3 次提交、20 天前 1 次）→ `commits7d` 是 3、`lastCommitAt` 是最近那次；没有登记读取的项目 `readable = false`，测试证明没跑 git。
8. `quotahub_url` 设成 `http://127.0.0.1:8787/api/refresh` 或 `http://user:pw@127.0.0.1:8787` → 被拒绝，没发请求。
9. 授权被撤销（`permissions.status` 不是 `active`）的项目 → `readable = false`，没跑 git。

## 真机检查

本机 QuotaHub 在运行、设置填好 URL 后，运行 K2 的 `scripts/real/cockpit-snapshot.ts`：**只输出数字**（额度来源 status、账号数、窗口数、可读项目数）。另外截图驾驶舱的额度区：用合成数据，不用真实账号截图。

## 整合方审定（2026-10-30）

对照 main（`b56516b`）和 QuotaHub 的代码（只看了 `quotahub/server.py`、`schema.py`，没碰 `credentials\`、`data\`）改准，档位 B 不变。

- QuotaHub 返回的外层是 `{ server_time, refreshing, accounts }`，字段名和草稿一致；`used` 是百分比、可能为 `null`。
- 地址只认「协议 + 本机主机 + 端口」，路径写死 `/api/snapshots`：QuotaHub 还有改状态的 `POST /api/refresh` 和管 Cookie 的接口，不许经这个设置碰到。补验收第 8 条。
- 「能不能读项目目录」和 `projectBrief.ts` 共用一个判断（含授权撤销），补验收第 9 条。
- 草稿验收第 7 条「10 天内 3 次」和「7 天的提交数」对不上，改成「7 天内 3 次」。

**用户 10-30 的决定，审定时一条没改**：驾驶舱是 IXAEON 的一个项目、走快车道；IXAEON 是唯一的项目 / 目标 / 决定记录处；手机只读、默认关闭、只开一个独立端口、经 Tailscale（不用 funnel）；这不等于解冻「多设备」；额度来源用 QuotaHub、Claude 先手动登记；不读凭据、聊天内容、会话正文；验收按「真机通过 / 用户接受」分开报。

## 整合方审测试时的改正与补充（2026-10-31，第 64 棒）

对着一份一次性实现（不提交）把两份测试跑通、逐处改坏做变异检查之后锁定。

**改正（原样写对了实现也过不了）：**

1. **`buildCockpitSnapshot` 改成异步**：`(db, { relayDir, ixaeonRepo, now? }) => Promise<CockpitSnapshot>`。原测试按同步调用，可条件 2、4、5 的合成 QuotaHub 和快照在同一个进程里：同步等 HTTP 回答会卡住事件循环，服务永远回不了话，条件 2、5 怎么写都过不了。随之：
   - K2 已锁定的三份测试（`k2-cockpit-snapshot`、`k2-cockpit-review`、`k2-cockpit-ipc`）由整合方改成 `await` 调用、本地类型认 `CockpitSnapshot | Promise<CockpitSnapshot>`，同步、异步两种实现都能过，用原标题重锁；
   - 实现要改的调用方：`apps/desktop/src/main/ipc.ts` 的 `getCockpitSnapshot`（`await`）、`scripts/real/cockpit-snapshot.ts`（`await`）。
2. **项目活动测试的「现在」取整到秒**：git 的提交时间只到秒，原来带毫秒的「1 天前」和 git 读回来的几乎永远差几百毫秒。
3. **`withGitTrace` 等快照出来再恢复 `GIT_TRACE`**：快照异步之后，git 可能在 `await` 之后才跑。

**改严 / 补充：**

4. QuotaHub 请求**经全局 `fetch` 发**（条件 2 里钉住，照转给真 `fetch`）：条件 3 拦 `fetch` 才证明得了「没发请求」，不然换成 `node:http` 发到 example.com 也是绿的。超时用 `AbortSignal.timeout(3000)` 这类就行。
5. 条件 3、8：配了地址却被拒 → 来源 **`error`** 且写原因（原来只要求「不是 ok」）；没配才是 `missing`。
6. 条件 8 补拒绝：`/api/snapshots` 写进地址里的（路径由代码写死，地址不许带）、`#x`、只有用户名的、`https://`、没写端口的（`http://127.0.0.1`、`http://localhost`）；合成服务连 TCP 连接都不许收到。
7. 补：QuotaHub 回 500、回的不是 JSON → `error`、不抛错、快照照常。
8. 补：QuotaHub 和手动登记同时有 → 两边的卡都在、来源 `ok`。
9. 补：暂缓那组的项目卡片也带 `activity`。

**接缝（执行方在测试里定的，整合方认）：**

- 两个新设置项 `cockpit.quotahub_url`、`cockpit.manual_quotas` 由核心从 `app_settings` 读（zod 校验和「坏了记 error」在快照层），设置页只写这两个键。`ixaeonRepo` 照 K2 仍走参数，不动。
- `cockpit.manual_quotas` 是数组，每项一个窗口：`{ account, window, resetAt, expiresAt, registeredAt, note? }`；`registeredAt` → `QuotaCard.collectedAt`；`note` 不进快照。`provider`、`status`、`plan` 测试没钉，建议 `provider: 'manual'`、`status: 'manual'`、`plan: null`。
- 契约里三处新字段（`sources.quotas`、`quotas`、`ProjectCard.activity`）**在 `@ixaeon/contracts` 里写成可选**：K3 已锁定的页面测试用契约类型拼模拟快照，写成必选它们的类型检查会红；快照运行时照常每次都给（K4 测试钉住了）。页面要按「可能没有」处理。
