# 规格 P4：给已有项目绑定文件夹；没绑文件夹的项目不派编码任务

档位：**B**（新增一个会发文件夹授权的入口——权限；另外改了 `propose_coding_task` 返回给模型的内容）。大小：小（≤150 行源码）。依赖：无。来源：用户 2026-09-30 更新应用后准备试场景一，整合方查出只有首次设置向导能给项目绑文件夹。
v2 规格：先把验收条件写成测试（`apps/desktop/test/acceptance/p4-*.test.ts`），**先只推测试**等整合方看过并锁定，再实现。

## 要什么

场景一（聊天里提编码任务 → 点「要做」→ 做完回报 → 接受后在项目仓库建分支）要求项目绑了文件夹，并且这个文件夹在有效的授权内。现在的情况：

- 界面上只有首次设置向导能给「第一个项目」绑文件夹。项目页新建的项目都是「构想（未绑定目录）」；核心层有 `ProjectService.rebindRoot`，应用里一处都没调用。
- 没绑文件夹的项目照样能提编码任务。点「要做」后副本是空的（快照记成 `empty:<任务 id>`），Codex 在空目录里干活，到接受时才报「没有这个项目目录的读取授权」。

## 契约

1. **项目页**：没绑文件夹的项目行上有「绑定文件夹」按钮；已经绑了的显示路径、不显示按钮。
2. **绑定**：点按钮 → 选文件夹（`pickFiles('directory')`，拿到目录票据）→ 新接口 `bindProjectFolder({ ticket, projectId })`（写进 `packages/contracts` 的 `IxaeonApi` 和 preload）：
   - 只收票据，照现有规矩消费（`consumeTicket(ticket, 'import')`），渲染层直接传路径不认——这个接口会发文件夹授权，不能让渲染层随手给任意文件夹授权；
   - 项目的 `root_path` 设成选的文件夹（`rebindRoot`）；
   - 给这个文件夹一条有效的文件夹授权（`grantFolder`，已经有就复用）；
   - **不导入**：不建来源、不排提取任务、不调模型。要把文件夹里的文件当资料，照旧用来源页的「导入文件夹」。首次设置向导那条路会顺手导入项目快照，本单不改它；
   - 记一条审计 `project.folder_bound`（项目 id、授权 id）；
   - 返回更新后的项目，项目页马上显示路径，不用重启。
   - 业务逻辑放在 `AppRuntime.bindProjectFolder(projectId, folderPath)`，IPC 只负责消费票据后调它，测试直接测这个方法。
3. **拒绝**（原样报错，项目、授权、审计都不改）：
   - 项目已经绑了文件夹：本单不做换绑。换绑牵涉已派发的任务该落到哪个仓库，另议；
   - 这个文件夹已经绑在别的项目上：路径规范化后比较，Windows 上不分大小写、不分斜杠方向。提示里写是哪个项目；
   - 项目不存在；文件夹不存在；票据无效或已经用过。
4. **没绑文件夹的项目不派编码任务**。三个入口都拦，报同一句话：「这个项目还没绑定文件夹：先在项目页点「绑定文件夹」，再派编码任务。」
   - D1 聊天里提编码任务（`propose_coding_task`）：不建草案、不记审计，把这句话作为工具错误返回，Hermes 会转告用户；
   - 待办卡片点「要做」（`acceptTodo`）：不批准、不派发，待办保持「等你拍板」，绑好文件夹后再点就能开工；
   - 任务页「批准」（IPC `approveCodingTask`）：同样不批准。IPC 改成调 `AppRuntime` 上带这道检查的方法，不再直调 `coding.approveAndQueue`。
   - 只在「查得到这个任务、而且它的项目没绑文件夹」时拦。查不到任务的，交给原来的批准流程报错（`t2b-followups` 用替身批准的那几条测试靠这个）。
   - 核心层 `CodingOrchestrator.approveAndQueue` / `prepareWorkspace` 不动：现有集成测试和审核回归在没文件夹的项目上用它们。
5. **绑定之后照已有规则生效的**（不是本单新加的行为，写在这里让用户知道）：
   - 这个项目的对话会带上文件夹的项目近况（P3：git 提交标题、编码会话数、任务数），和「第一个项目」一样；
   - 编码客户端经 MCP 可以用这个文件夹路径指代项目（原来就能用项目名、项目 id），能看到的内容照现有授权规则，不变。

## 约束

- 不加迁移（`projects.root_path`、`permissions` 都已有）。
- 首次设置向导、来源页「导入文件夹」的行为不变；现有测试照过。
- 授权页（设置里）能看到这条新授权，撤销走现有入口，本单不改。

## 验收条件

1. 没绑文件夹的项目调 `bindProjectFolder`：`root_path` 是选的文件夹；有一条有效的文件夹授权覆盖它（原来就有的复用，不重复建）；审计 `project.folder_bound` 一条（项目 id、授权 id）；返回的项目带着路径。
2. 不导入：绑定前后来源数、提取任务数不变，没有模型调用。
3. 拒绝：已经绑了文件夹的项目；文件夹已经绑在别的项目上（大小写、斜杠方向不同也算同一个，提示里有那个项目的名字）；项目不存在；文件夹不存在。每种都报错，项目、授权、审计都不变。
4. D1：没绑文件夹的项目对话里调 `propose_coding_task` → 不建草案、不记审计，返回的错误就是契约 4 那句话；绑好文件夹之后同一个对话再调就能建出草案。
5. D3：没绑文件夹的项目上已有的编码草案，点「要做」→ 报契约 4 那句话，任务没批准、没派发，待办还是「等你拍板」；绑好之后再点「要做」→ 批准并开工。
6. 任务页「批准」：没绑文件夹的项目 → 报同一句话，任务没批准；有文件夹的照旧批准。
7. 只收票据：`bindProjectFolder` 的输入只有 `ticket` 和 `projectId`，没有路径字段；伪造的票据被拒，项目和授权都不变。票据在 IPC 闭包里、单元测试够不着，这一条由真机检查第 2 步验，交付说明里贴输出。

1. 项目页新建一个项目 → 显示「构想（未绑定目录）」和「绑定文件夹」按钮 → 点按钮 → 马上显示合成文件夹的路径，按钮消失；来源页数量不变；设置里的授权多了这个文件夹。
2. 在页面里直接调 `window.ixaeon.bindProjectFolder({ ticket: '伪造', projectId })` → 报错，项目和授权都不变。
3. 再建一个项目，绑同一个文件夹 → 被拒，提示里有第一个项目的名字。
