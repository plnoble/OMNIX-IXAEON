# 规格 M2：模型管理——检测上游、勾选保存、各处都从已保存的里选、随时重检

档位：**A**（设置页与本地配置；检测用的是已有的 `listAvailableModels`，不加新的外发）。大小：中（≤250 行源码）。依赖：无。来源：用户 2026-10-01 的原话：
> 软件的模型，需要：我输入地址和 api，可以检测上游的所有模型，然后我选择保存哪些模型（选择，不是手输），然后软件就可以调用这些模型，然后我还可以不时的重新检测（有些模型会变），然后不需要再输入 api，除非我自己的 api 有变动。

v2 规格：验收条件写成测试（`apps/desktop/test/acceptance/m2-*.test.ts`，界面部分可放 `apps/desktop/e2e/`），测试和实现一起交，Codex 审查时核对有没有漏条件。

**这不是 AGENTS.md 里暂停的「模型池」**：没有自动挑模型、没有成本或权重、没有失败自动换下一个，只有一张用户亲手勾选的清单，供各处下拉框选择。别的都不做。

## 现状

- 设置页「模型接入」能填 API 地址和 Key（Key 用 safeStorage 加密落盘，留空保持不变），这一条已经满足用户的最后一句；
- 「获取可用模型」调 `listAvailableModels`（`GET {地址}/models`），结果只放在这一次页面的内存里，不保存；
- 「模型名称」要先获取一次才变成下拉框，否则是手输框；「聊天模型」一直是手输框。

## 契约

1. **已保存的模型清单**：配置里加 `model.savedModels: string[]`（默认空数组；配置有 zod 默认值，旧配置照常读得出来，不加迁移）和 `model.modelsCheckedAt: string | null`（上次检测时间）。
2. **检测**：「检测模型」按钮调现有的 `listAvailableModels`，Key 留空就用已保存的（现有规则：仅限地址没变）。检测结果以勾选清单显示：
   - 已保存的默认打勾；
   - 本次新出现的标「新」；
   - 已保存但上游这次没列出来的照样显示，标「上游已没有」，不自动删掉；
   - 上游可能有几百个，清单上方要有按名字筛选的输入框。
3. **保存选择**：「保存选择」把勾上的写进 `savedModels`，同时记下检测时间。保存只认清单里勾选的项，不提供手输模型名的入口。
4. **各处都从已保存的里选**：设置页的「模型名称」（分析用）和「聊天模型」改成下拉框，选项只有 `savedModels`；「聊天模型」另有一项「跟随分析模型」（即现在的空串）。之后要加的编码执行器模型（D7）也从这张清单里选。
   - 当前在用的模型如果不在清单里（老配置、或上游已没有），下拉框照样显示它并标「不在已保存清单」，不悄悄改成别的；用户自己选了别的才改。
5. **重新检测**：随时能再点「检测模型」，规则同第 2 条。检测不改任何当前在用的模型，只更新清单上的标记。
6. **Key 不用重输**：沿用现有行为——Key 留空保存时保持原值；地址改了才需要重新填 Key 再检测。

## 约束

- 不改 Key 的保存方式，不在界面或日志里显示 Key。
- 检测失败（网关不通、Key 错）如实显示上游的错误，清单和当前模型都不变。
- 首次设置向导这次不改。

## 验收条件

1. 检测后：清单列出上游全部模型；已保存的打勾；新出现的标「新」；已保存但上游没列出的标「上游已没有」、不被删除。
2. 保存选择：`savedModels` 正好是勾上的那些，检测时间被记下；重启应用后清单和勾选状态还在。
3. 「模型名称」「聊天模型」都只能从已保存的清单里选（聊天多一项「跟随分析模型」）；界面上没有手输模型名的入口。
4. 当前在用的模型不在清单里时，下拉框照样显示它并标明，不被悄悄换掉。
5. 重新检测不改当前在用的模型。
6. Key 留空时检测和保存都用已保存的 Key；界面和日志里看不到 Key。
7. 检测失败：显示错误，清单和当前模型都不变。

## 真机检查

设 `IXAEON_DATA_DIR=<临时目录>` 启动应用。用一个本地的假上游（测试里起一个只回 `/models` 的小服务；不要拿用户的真实网关做真机检查）走一遍：
1. 检测；
2. 勾两个保存；
3. 让假上游少一个、多一个，再检测，看标记；
4. 在两个下拉框里选；
5. 重启应用后再看。
