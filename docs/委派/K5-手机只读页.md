# 规格 K5：手机只读页（经 Tailscale）

档位：**B**（新的对外访问路径）。大小：中（≤300 行源码）。依赖：K3（K4 并入后手机页自动显示额度）。
v2 规格：先只推测试，等整合方锁定后再实现。

**用户 2026-10-30 的决定**：允许"手机只读查看驾驶舱"，经 Tailscale 访问。这**不等于解冻"多设备"**：不做多设备协作，手机上不能做任何操作。

## 要什么

用户在手机（iPhone）上打开一个网页，看到驾驶舱。

- 设置页加开关"手机查看"，**默认关**。
- 打开后，桌面版另起一个只读监听，**只绑 `127.0.0.1`**，端口默认 `43192`（可在设置里改）。它只提供两样东西：
  - `GET /m`：手机页（一个 HTML，样式和脚本都内联）；
  - `GET /m/snapshot`：K2 的 `buildCockpitSnapshot` 的结果（主进程里直接调，和桌面版驾驶舱同一份）。
  
  其他路径一律返回 404，非 GET 返回 405。
- 设置页显示一条命令和说明，由**用户自己执行**，把这个端口发布到自己的 tailnet：
  
  ```
  tailscale serve --bg 43192
  ```
  
  这条写法已于 2026-10-30 对照本机 Tailscale 1.98.8 的 `tailscale serve --help` 核对过（`--bg` 表示后台运行，只在自己的 tailnet 内可见）。**不许用 `tailscale funnel`**：那会把服务暴露到公网。
- 手机页：
  - 顶部显示"N 分钟前更新"，数据陈旧时变红；
  - 下面四个**并排按钮**：总览 / 等你处理 / 额度 / 项目，点哪个显示哪块；
  - 默认显示"总览"：三个数字，加上等你处理的前 3 条；
  - 每 60 秒刷新一次。

## 约束

- 不绑 `0.0.0.0`，不绑局域网地址；主服务 `127.0.0.1:43191` 不暴露，它的任何路由都不能经新端口访问。
- **防 DNS 重绑定**：只认 `Host` 是 `127.0.0.1:<端口>`、`localhost:<端口>` 或以 `.ts.net` 结尾（Tailscale 的机器名）的请求，别的一律 421；响应**不带** `Access-Control-Allow-Origin`。否则用户电脑上随便一个网页都能借重绑定读到快照。
- 设置页的说明里写清怎么关：`tailscale serve status` 看现在发布了什么；`tailscale serve reset` 会清掉**全部** serve 配置，别的服务也经 serve 发布时要注意。
- 只读，没有任何写操作；快照内容和桌面版一样（已经脱敏）。
- 设置页的说明里要写明：tailnet 里的所有设备都能打开这个页面；如果把设备共享给了别人，先在 Tailscale 里限制访问。
- 不引入新依赖；不加迁移。

## 验收条件

1. 开关关闭时，`43192` 端口没有监听。
2. 打开后只监听 `127.0.0.1:43192`（测试检查绑定地址）。
3. `GET /m`、`GET /m/snapshot` 返回 200；`GET /api/cockpit`、`GET /api/health` 等其他路径经这个端口返回 404；`POST /m/snapshot` 返回 405。
4. 同一时刻 `/m/snapshot` 和 `buildCockpitSnapshot` 的结果一致（`generatedAt` 除外）。
5. 手机页在 390px 宽的视口下，四个按钮排成一行，没有横向滚动（截图）。
6. 关掉开关后端口立即关闭。
7. `Host: evil.example` 请求 `/m/snapshot` → 421、没有快照内容；`Host: 机器名.某某.ts.net` → 200；任何响应都没有 `Access-Control-Allow-Origin` 头。
