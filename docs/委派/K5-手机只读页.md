# 规格 K5：手机只读页（经 Tailscale）

档位：**B**（新的对外访问路径）。大小：中（≤300 行源码）。依赖：K3（K4 并入后手机页自动显示额度）。
v2 规格：先只推测试，等整合方锁定后再实现。

**用户 2026-10-30 的决定**：允许"手机只读查看驾驶舱"，经 Tailscale 访问。这**不等于解冻"多设备"**：不做多设备协作，手机上不能做任何操作。

## 要什么

用户在手机（iPhone）上打开一个网页，看到驾驶舱。

- 设置页加开关"手机查看"，**默认关**。
- 打开后，桌面版另起一个只读监听，**只绑 `127.0.0.1`**，端口默认 `43192`（可在设置里改）。它只提供两样东西：
  - `GET /m`：手机页（一个 HTML，样式和脚本都内联）；
  - `GET /m/snapshot`：K2 的 `buildCockpitSnapshot` 的结果（主进程里直接调，和桌面版驾驶舱同一份）。

  其他路径一律返回 404，非 GET 返回 405。

- 设置页显示一条命令和说明，由**用户自己执行**，把这个端口发布到自己的 tailnet：

  ```
  tailscale serve --bg 43192
  ```

  这条写法已于 2026-10-30 对照本机 Tailscale 1.98.8 的 `tailscale serve --help` 核对过（`--bg` 表示后台运行，只在自己的 tailnet 内可见）。**不许用 `tailscale funnel`**：那会把服务暴露到公网。

- 手机页：
  - 顶部显示"N 分钟前更新"，数据陈旧时变红；
  - 下面四个**并排按钮**：总览 / 等你处理 / 额度 / 项目，点哪个显示哪块；
  - 默认显示"总览"：三个数字，加上等你处理的前 3 条；
  - 每 60 秒刷新一次。

## 约束

- 不绑 `0.0.0.0`，不绑局域网地址；主服务 `127.0.0.1:43191` 不暴露，它的任何路由都不能经新端口访问。
- **防 DNS 重绑定**：只认 `Host` 是 `127.0.0.1:<端口>`、`localhost:<端口>` 或以 `.ts.net` 结尾（Tailscale 的机器名）的请求，别的一律 421；响应**不带** `Access-Control-Allow-Origin`。否则用户电脑上随便一个网页都能借重绑定读到快照。
- 设置页的说明里写清怎么关：`tailscale serve status` 看现在发布了什么；`tailscale serve reset` 会清掉**全部** serve 配置，别的服务也经 serve 发布时要注意。
- 只读，没有任何写操作；快照内容和桌面版一样（已经脱敏）。
- 设置页的说明里要写明：tailnet 里的所有设备都能打开这个页面；如果把设备共享给了别人，先在 Tailscale 里限制访问。
- 不引入新依赖；不加迁移。

## 验收条件

1. 开关关闭时，`43192` 端口没有监听。
2. 打开后只监听 `127.0.0.1:43192`（测试检查绑定地址）。
3. `GET /m`、`GET /m/snapshot` 返回 200；`GET /api/cockpit`、`GET /api/health` 等其他路径经这个端口返回 404；`POST /m/snapshot` 返回 405。
4. 同一时刻 `/m/snapshot` 和 `buildCockpitSnapshot` 的结果一致（`generatedAt` 除外）。
5. 手机页在 390px 宽的视口下，四个按钮排成一行，没有横向滚动（截图）。
6. 关掉开关后端口立即关闭。
7. `Host: evil.example` 请求 `/m/snapshot` → 421、没有快照内容；`Host: 机器名.某某.ts.net` → 200；任何响应都没有 `Access-Control-Allow-Origin` 头。

## 整合方审测试时的改正与补充（2026-10-31）

dev 交的四份测试（14 个 it）基本扎实。整合方写了一份一次性实现（不提交）跑通，再逐处改坏 40 处：原测试漏了 5 处，已补，补完 40 处全红。然后锁定。

**补的（只加、只改严，没删条件）：**

- 条件 2：`address` 是实现自己报的，绑 `0.0.0.0` / `::` 照样能报 `127.0.0.1`。补：真去连 `::1` 和本机每块网卡的 IPv4 地址，必须连不上。
- 条件 3：「非 GET」不只是 POST。补 PUT / DELETE / PATCH → 405。
- 条件 4：原来没设仓库路径，实现写死 `ixaeonRepo: ''` 也能过。补：设置项 `cockpit.ixaeon_repo` 指向一个合成的空目录，手机快照必须和用同一路径直接调 `buildCockpitSnapshot` 的结果一致（桌面版驾驶舱读的就是这一项）。
- 条件 7：只查「以 `ts.net` 结尾」的写法（漏了点）能过。补 `evilts.net`、`evilts.net:43192`、`localhost:43193`、`127.0.0.1.evil.example:43192`、`localhost.evil.example:43192` → 421。
- 60 秒刷新：原来只查脚本里有 `60000`，算「N 分钟前」时的 `/60000` 就让 30 秒刷新也能过。改严成 `60000` 必须是 `setInterval` 的间隔参数。

**认下的口径：**

- 测试定的接口名照认：`apps/desktop/src/main/server/mobileServer.ts` 的 `MobileServer({ db })`、`apply()` / `stop()` / `address`；设置项 `mobile.enabled`（`'true'`/`'false'`）、`mobile.port`；`SettingsView.cockpit.mobileEnabled` / `mobilePort`；IPC `saveMobileSettings({ enabled, port })` 存完立刻 `runtime.mobileServer.apply()`。
- `Host` 认 `…ts.net` 带不带端口都行（浏览器直连 `机器名.ts.net:43192` 时带端口）；恶意后缀照旧 421。
- 条件 5 的自动化部分只核对结构（viewport、四列 `minmax(0,1fr)`、按钮顺序、样式脚本内联）。390px 截图按真机检查第 1 步做，复审时整合方亲手看。

**给实现的提醒（测试管不到，复审时要看）：**

- `buildCockpitSnapshot` 在 K4 并入后会变成异步。实现里要 `await` 它（同步、异步都能用）。整合方的临时实现在这里栽过：对同步返回值调 `.then`，请求处理一抛错，`/m/snapshot` 就一直挂着不回。快照出错时要回 500，不能挂住。
- 应用启动时按设置项 `apply()` 一次，退出（`runtime.stop()`）时 `stop()`；数据恢复后重建运行时（`rebuild`），`MobileServer` 要换成新库，不能还拿着旧的 db 引用（照 `localServer.rebindDeps`）。
- 端口被占（`EADDRINUSE`）或端口不合法时，保存要给出看得懂的错，不能把主进程搞崩；规格没写具体文案，测试也不管，用设置页现有的错误条就行。
- 手机页本身的行为（陈旧变红、点按钮切换、总览三个数字 + 等你处理前 3 条）测试没覆盖，真机检查第 1 步四张截图要能看出来。
