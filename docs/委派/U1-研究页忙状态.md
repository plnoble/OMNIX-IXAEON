# 规格 U1：研究页——按钮各管各的忙，长操作看得见

档位：**A**（只改界面状态与提示，不碰数据、提示词、权限）。大小：小到中（≤200 行源码）。依赖：无。
v2 规格：把验收条件写成测试（`apps/desktop/test/acceptance/u1-*.test.ts`，jsdom），测试和实现一起交，Codex 审查时核对测试有没有漏掉条件。

## 要什么

2026-09-20 用户实测：点了某个关注的「立即检查」，那次检查跑了约 3 分钟。期间**整页按钮全是暗的**（包括下面「新建关注」的创建按钮），界面上没有任何「正在检查」的字样。用户的原话是「创建为什么是暗的」——他以为按钮坏了。

研究页现在用一个页面级的 `busy` 控制所有按钮（`apps/desktop/src/renderer/src/pages/Research.tsx`）。

## 契约

1. `busy` 拆成互不影响的几份：
   - 新建关注表单（创建按钮只看自己这一份）；
   - 每个主题自己的操作（检查、启用/暂停、加来源、改预算……）按主题 id 分别记；
   - 「帮我想想该关注什么」（W1a）单独一份。
     一个主题在检查时，只有这个主题的按钮变暗，别的主题和新建表单照常能用。
2. 正在检查的主题显示 `research-checking-<主题 id>`：「正在检查…（已 N 秒）」，秒数每秒涨。
3. 等待超过 5 分钟：这一行改成「检查还没回来，可能是模型或网络慢；它会在后台继续跑完」，并出现「停止等待」按钮 `research-stop-waiting-<主题 id>`——点了界面不再等（这个主题的按钮恢复可用、提示消失），**检查本身继续在后台跑**（核心层没有中止接口，不要假装中止）。
4. 这次检查的结果里带降级信息时（`run.error` 非空，例如「模型研读失败 1 次，已降级为规则研读」），在这个主题下面显示一行黄字 `research-run-notice-<主题 id>`，不能只写进库让用户看不到。
5. 出错照旧用 `ErrorBanner`，但错误要带上是哪个主题。

## 约束

- 只改渲染层；不改 IPC、不改核心层的检查流程。
- 不引入全局状态库，用现有的 `useState` / `useRef` 就够。

## 验收条件

1. 一个主题在检查（IPC 未 resolve）时：这个主题的「立即检查」按钮不可点，**新建关注的创建按钮仍可点**，另一个主题的按钮也仍可点。
2. 检查期间显示「正在检查…（已 N 秒）」，秒数会涨；检查返回后这行消失。
3. 等待超过 5 分钟：文案变成「还没回来…后台继续跑」，出现「停止等待」；点它之后这个主题的按钮恢复可用、提示消失；后来 IPC 真的返回时不报错、照常刷新列表。
4. 返回的运行记录里 `error` 非空：这个主题下面显示那行黄字，内容含降级说明；`error` 为空时不显示。
5. 检查失败（IPC reject）：只影响这个主题的按钮，错误提示里能看出是哪个主题。

## 真机检查

用临时数据目录（`IXAEON_DATA_DIR`）启动应用，造一个没有来源、也没配搜索的合成主题，点「立即检查」（会立刻失败）：确认失败提示挂在这个主题上、新建表单的按钮全程可点。截图或描述。
