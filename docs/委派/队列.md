# 委派队列

执行方（Grok）按顺序领活，不用等人派，也不用用户转话。怎么领、做完的标准、怎么合并，见 [AGENTS.md](../../AGENTS.md)「用户的原则」和「委派流水线 v2」。

规则摘要：

- 领第一个「待领」且依赖都已完成的任务：**直接在 main 上**把这一行的状态改成「进行中（你的名字）」，提交推送（只改这一行；在你自己的操作目录里做——`node scripts/worktree.mjs ops` 建好并打印路径——不在共用的检出目录里提交，见 AGENTS.md）。任务分支里不改这个文件；**依赖没完成的不能领**；
- 每个任务在自己的分支和工作目录里做（`node scripts/worktree.mjs add <任务号> <你的名字>`，统一建在 `Worktrees/IXAEON/` 下，不放进放项目的文件夹）；日志写进工作目录的 `.logs/`；合并的人合并后跑 `node scripts/worktree.mjs clean`；
- 「规格」任务先把验收条件写成测试：A 档测试和实现一起交；B 档**先只推测试**，状态改「测试待审（整合方）」，接着领下一个；
- 做完的标准：验收测试、`node scripts/verify.mjs`、分支 CI 绿、规格要求的真机检查（**没跑的不能合并**），交付说明写进 [交付/](交付/README.md)；
- **A 档**：`node scripts/codex-review.mjs <任务号>` 结论「可以合并」且 CI 绿 → 你自己合并（步骤见 AGENTS.md）。Codex 额度用完 → 状态「待审（Codex 额度）」，先领下一个，**不许跳过审查**；
- **B 档**：推送分支，状态「待复审（整合方）」，接着领下一个；
- **锁定的验收测试不许改**（指纹在 [锁定验收.json](锁定验收.json)）。觉得测试或规格本身有错：停下，写进交付说明。

状态只用这几种：待领 / 进行中（名字） / 测试待审（整合方） / 待审（Codex 额度） / 待复审（整合方） / 已完成（日期）。
