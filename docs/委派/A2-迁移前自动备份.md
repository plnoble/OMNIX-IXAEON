# 委派单 A2：迁移前自动备份

任务来源：[三周任务单](../三周任务单.md) A2。档位：**B**（碰启动与迁移路径、会删旧备份，整合方复审后合并）。大小：小（≤150 行）。

## 背景

迁移只追加，但有的迁移会改、会删数据（如迁移 30 清掉聊天存档的回声），上线前一直靠整合方手动备份。以后只要有待执行的迁移，应用就先自动把数据库和配置复制一份，再迁移。

## 契约（写死，照着实现，不改名）

1. 新文件 `packages/core/src/db/backup.ts`，导出下面的函数，并从 `packages/core/src/index.ts` 导出：

   ```ts
   backupBeforeMigrate(
     db: CoreDatabase,
     opts: { backupsDir: string; configPath?: string; keep?: number; now?: Date },
   ): string | null
   ```

   - 读 `schema_migrations` 的最大版本。没有这张表或没有记录（全新库）→ 返回 `null`，不建任何目录。
   - 已经是最新版本（`MIGRATIONS` 最后一项的 id）→ 返回 `null`，不建任何目录。
   - 否则建 `backupsDir/pre-migration-<当前版本>-<最新版本>-<YYYYMMDD-HHmmss>`（`now` 的本地时间），返回这个目录的完整路径。目录里放：
     - `ixaeon.db`：用 `VACUUM INTO` 做一致的副本，库开着也行；
     - `config.json`：`configPath` 存在时复制过去。
   - 只留最近 `keep`（默认 5）份名字形如 `pre-migration-…-YYYYMMDD-HHmmss` 的目录，按名字末尾的时间排，更早的删掉。其它目录一律不动。

2. `apps/desktop/src/main/appRuntime.ts`：三处 `migrate(...)` 之前都调用它：`AppRuntime.create()`、`rebuildRuntimeServices()`、`completeSetup()`（新库会返回 null，不影响）。
   - `backupsDir` 用 `ensureDataDirLayout(...)` 给的 `backupsDir`，`configPath` 用应用的 config.json。
   - **备份失败就不迁移**：抛出带原因的错误，让启动失败可见。不能在没有备份的情况下迁移。
   - 备份成功记一条日志和一条审计：`migration.backup`，detail 里只放目录名。

## 验收（锁定，执行方不改）

- `node scripts/acceptance.mjs run A2` 全过（`packages/core/test/acceptance/a2-backup-before-migrate.test.ts`）；
- `node scripts/verify.mjs` 全过；
- 真机：用一份停在旧版本的**合成**库启动一次，列出 backups 目录。不要拿用户的真实库试。

## 不要做

- 不加迁移、不加依赖，不改 `migrate()` 本身；
- 不删 backups 里不是 `pre-migration-` 开头的任何东西；
- 不改锁定的验收测试。

## 交付

改动文件与行数；验收与 verify 的输出；真机结果；已知缺口。推送你的分支，**不要自己合并**（B 档由整合方复审）。
