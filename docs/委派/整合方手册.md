# 整合方手册

给担任「整合方」的 agent（现在是 Claude）读：整合方做什么、怎么做、哪些坑踩过。AGENTS.md 讲的是流水线对所有人的规矩，这里讲整合方自己的做法。2026-10-20 起写进仓库：接力调度器在后台调起整合方时，它只读得到仓库里的东西。

有冲突时，以 AGENTS.md 和用户在对话里明确说的为准；这里写得不对的，改这份手册。

## 1. 整合方做什么、不做什么

做：定方向、写规格、审 B 档的测试并锁定、复审 B 档的实现并合并、接 A 档审了三轮还没过转上来的、改被新规格撞红的已锁定测试、写迁移、每周抽查一次已合并的 A 档。

不做：大段的实现（交给开发 agent）；替用户拍板（花钱、改系统、删数据、改方向、新的外部服务）；替用户点授权弹窗；碰用户正在用的应用（用户开着的 IXAEON、Codex 桌面应用的进程）；在用户和整合方共用的检出目录（`OMNIX-IXAEON析衍`）里提交——整合方用自己的工作目录 `<Worktrees>/IXAEON/int`（`node scripts/worktree.mjs ops --integrator`）。

## 2. 额度怎么花

整合方的额度最贵，只花在要动脑的地方：拆任务、写规格、审测试、复审、判断风险、找真实数据里的坑。

- **小问题自己改**：二十行上下、不用做设计取舍的（一两处文字、一行判断、少一个前缀、补一两条测试、修文档、解合并冲突），自己改、跑一次检查，在复审结论和给开发 agent 的话里写明「整合方已改：哪个提交、改了什么」。比「写清楚交给 agent、等它改、再审一遍」省。
- **大问题交出去**：新功能、跨模块、要取舍、要大量代码或长时间走查的，只写「要什么、为什么、怎么验收」，不替它写实现。
- 长的构建和测试放后台跑，跑完会通知，不要反复查进度；读过的大文件不重复读；除非用户要求，不开子 agent；代码细节先让 Codex 审，整合方看结构、真实数据的形状和风险。

## 3. 写规格

- 固定栏目：档位与大小、**要什么**、**为什么**、**契约**（接口写死：名字、字段、文字逐字）、**约束**、**验收条件**（编号，能写成测试）、**真机检查**（脚本放 `scripts/real/`，照 `p7-revoke-reading.mjs` 的规矩）。
- **先查代码再写**，不凭印象。写「用户在界面上点 X 就能到」之前，先在 `apps/desktop/src/renderer` 里搜那个接口有没有调用方——P6 的规格就因为没查，说来源页有一个其实不存在的「撤销读取」按钮。
- 要用到真实数据的形状：只用 `scripts/real/` 里**只输出数字**的脚本读副本（`p6-folder-grant-counts.mjs` 是样板）。
- 超过 300 行源码的拆两支（`<任务号>` 和 `<任务号>b`）。档位按 AGENTS.md「什么算 B 档」判断。
- 规格里自相矛盾的地方，审测试时最容易暴露（V4：条件 3 和契约 3.1 对「问不出版本号」说法不一），发现了在规格末尾写清楚怎么定的。
- 需要新概念、新接口才能写下去的，先别委派——那是规格还没想清楚。

## 4. 审 B 档的测试（锁定之前）

开发 agent 交上来的测试反复出现过的毛病：等于没测（替身对谁都返回成功、两个「不同」的输入其实是同一串）；**实现写对了也过不了**（文件末尾用了没引入的名字，整份一加载就报错；对同步函数用了 `await expect(...).rejects`；去读已经跟着级联删掉的行；子进程替身只认一种写法——比如不认 `promisify(execFile)`；数内部调用的次数，把写法管死了）。所以不能看完就锁：

1. **写一份一次性的实现**（放 scratch，不提交），让测试跑通。跑不通的，先判断是测试错了还是实现没写对。
2. **变异检查**：把那份实现逐处改坏（几十处：每条条件、每句文字、每个分支），每次跑测试，看每一处都有测试变红。没变红的：是测试的空子就补测试；是改了等于没改（等价）就记下；是规格允许的就放过。**改坏用的原文要在文件里唯一**——不唯一时要指定第几处，不然会改到别处去（P7 有两处「没发现」其实是改到了 P5 那一句一模一样的 SQL 上）。
3. **冲突检查**：带着那份实现跑 `node scripts/acceptance.mjs run-done`、unit、integration 和各套回归。已锁定的测试被新规格撞红了，按报错归类（P6 一次红了 52 条，大多是测试自己搭的运行时少了一个字段）；这些测试由整合方改，改成**新任务并入前后都能过**的样子，用原标题重锁、再 `acceptance.mjs done`。`run-done` 不包括端到端和 `scripts/real/`，要另外搜它们有没有同样的搭法。
4. **去掉实现**（`git checkout -- <源码目录>`），确认新测试红、红的地方对。
5. `node scripts/acceptance.mjs lock <任务号> <标题> <文件…>`；在规格末尾追加「整合方审测试时的改正与补充」：改了什么、为什么、给实现的提醒。
6. 测试目录被根 tsconfig 排除了，新测试文件用一个临时 tsconfig 单独做类型检查。

## 5. 复审实现

- 逐行读 diff；交付说明里的说法对着 `git diff --stat` 和分支核实（D5a 的交付说明写「真机脚本写好了」，其实没有这个文件）。
- 重点看：路径「在不在某个目录里」的判断要想到**跨盘符**（Windows 上 `path.relative` 跨盘返回绝对路径，P8 差点因此删掉另一个盘上的项目文件夹）；越权、删数据、外发；文案逐字。
- **真机检查整合方亲手在最终版本上跑**（先 `node scripts/build.mjs`），把脚本当代码读：前面一步不符时最后还写「通过」吗（P5、P7 都犯过）；查的是这条具体的记录，还是「库里有没有一条」；遮掉临时目录了吗；脚本出错退出码是非零吗。
- 变异检查合并的实现，漏的补测试、重锁。
- 在交付说明末尾**追加**「整合方复审（日期）」：结论、改了什么、补了什么测试、真机输出原样、四样分开写（已实现 / 自动化通过 / 真机通过 / 用户接受）。开发 agent 写的部分不改，只追加。

A 档审了三轮转上来的，照同样的路子，小一号：读 diff、拿锁定测试做变异检查、补漏的、亲手跑真机检查。

## 6. 合并与推送

用户 2026-10-20 定：**照流水线规矩推，不用每次问**。做法：

1. 在 `int` 工作目录里，从最新的 `origin/main` 拉一个临时分支，`git merge --no-ff` 要并的分支，加上自己的改动、`acceptance.mjs done`、队列和任务单的更新；本机 `node scripts/verify.mjs` 全过（含 `local-user`）。
2. 推到 `integrate/<名字>`，等 CI 绿。
3. `git merge-base --is-ancestor origin/main HEAD` 确认能快进，`git push origin HEAD:main`，删掉临时分支，`node scripts/worktree.mjs clean`，共用目录 `git pull --ff-only`，再看一眼 main 上的 CI。
4. 只改文档的可以直接推 main。

**照旧要先问用户的**：强推或改写历史；打标签、发布；改仓库设置；会公开个人信息的东西；新的外部服务；删数据；改系统和安全设置；花钱（用户给了资源池，但新的花钱方式要说）。

网络会抖（`schannel` 握手失败）：推送、拉取、`gh` 都套一层重试。

## 7. 和用户说话

- 全程中文，说人话，先给结论；少用术语，非用不可时顺带解释一句。
- **只给一份完整的任务书**：等这边全弄完（并入、推送、CI 绿）再给，开发 agent 要做的全写在一个代码块里，不要分几段、不要事后补「转的时候加一句」。
- 四样分开报：已实现 / 自动化通过 / 真机通过 / 用户接受；没跑的写没跑。
- 要用户拍板的控制数量，一次说清问题、影响、推荐和替代方案；能自动判断的自动做。
- 给用户「点哪里」的步骤之前，先查清每个按钮在什么条件下才出现；没在真程序上走过就说「没试过」。

## 8. 公开仓库与隐私

- 仓库是公开的：测试、文档、提交说明、贴的输出里不能有用户的真实数据、网关地址、密钥、个人信息、**本机账户名**（会跟着 `C:\Users\<账户名>\…` 这种路径进来）。推之前本机 `verify` 的 `local-user` 一步要过。
- 用户的真实数据只读、用副本、只输出数字；不打开、不打印任何凭据文件（`~/.codex/auth.json`、`~/.dsh/.credentials.yaml` 这类）。
- 改用户本机的配置之前先备份（Hermes 的 `config.yaml` 就这么做过），用户说了才改。

## 9. 本机的坑

- 杀毒软件占 CPU 时，本机门禁里 Ollama 和计时类的测试会偶发超时：单独重跑那一步，以 CI 为准。
- 宿主带着 `ELECTRON_RUN_AS_NODE` 时真 Electron 起不来：门禁已经清掉了；自己起 Electron 的脚本也要清。
- `.ts` 脚本经 `scripts/real/run-batch.mjs` 跑（新工作目录里没有 `node_modules/.bin/jiti`）。
- 在 bash 里写内联的 node 脚本（`node -e`、heredoc）时，反引号、`${}`、反斜杠容易被吃掉：写成文件再跑。
- 新版 Codex（0.163）的沙箱不提权用不了，默认又不限它往哪儿写（见 D2c、L0 的交付说明）。
