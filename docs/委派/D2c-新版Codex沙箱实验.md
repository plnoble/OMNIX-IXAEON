# 规格 D2c：新版 Codex 沙箱实验（调研，不改应用）

档位：**B**（碰系统里的沙箱；结论决定依赖档验证怎么隔离模型写的代码）。大小：不改应用源码，只交实验脚本和结论。依赖：无。来源：V4 复审时查到的（2026-10-20），用户定「直接上新版」。

## 为什么要做

依赖档验证（D2）跑的是模型写的测试代码，手里拿着项目副本。9 月的 D2b 实验在当时的 Codex（0.130）上确认了：提权沙箱（`codex sandbox windows … -c windows.sandbox="elevated"`）挡得住联网、挡得住往副本外写、经目录链接写不穿真实依赖，才定了现在这套做法（专用 CODEX_HOME、一次授权、四样被动检查）。

用户定了用最新版 Codex。V4 的真机检查发现：本机最新版 0.163 的 `codex sandbox` 已经换了用法——

- 没有 `windows` 子命令了，用法是 `codex sandbox [OPTIONS] [COMMAND]...`，说明写的是「在 Windows 受限令牌沙箱里跑命令」；
- 选项里有 `-P/--permission-profile`、`-C/--cd`、`-c`、`--sandbox-state-disable-network` 等；
- 多了一条 `uninstall`：「卸掉旧版 Windows 沙箱装在机器上的账户和网络规则」。

所以现在这套调用在新版上跑不起来；新版的新沙箱**挡不挡得住、要不要授权，都没验过**。受限令牌这种做法在 Windows 上本身不挡联网（旧版正是为此才要装防火墙规则），新版另想了什么办法，帮助里没写。没验过之前不能让模型写的代码在里面跑。

这一单：像 D2b 那样，在本机上把新版沙箱验一遍，回答下面的问题，给出「依赖档该怎么调新版」的配方。

## 要回答的问题

用本机 `bin` 下最新版的 `codex.exe`（找法照 V4：顶层和每个子目录里的都问 `--version`，取最大的；交付说明里写版本号）。

1. **怎么调**：新版下，「用一个专用 CODEX_HOME 里的 permissions profile、在副本目录里、跑一条命令」的完整 argv 是什么。profile 的 `config.toml` 写法和旧版（见 `verifySandbox.ts` 的 `ensureSandboxProfileConfig`）一样不一样。
2. **要不要授权**：不提权（不用 `elevated`）能不能跑起来；要不要管理员确认；会不会往机器上装东西。
3. **vitest 跑不跑得起来**：合成项目，`node_modules` 用目录链接接到副本里（照 D2 的 `prepareDependencyCopy`），在沙箱里跑一个合成的 vitest 测试。
4. **联网挡不挡得住**：沙箱里的进程能不能连上（a）脚本在沙箱外开的一个本机端口，（b）一个外网地址的 443 端口（只建连接、不发数据）。分别试 profile 里 `network.enabled=false` 和 `--sandbox-state-disable-network`。
5. **往外写挡不挡得住**：往副本外的一个临时目录写文件；经 `node_modules` 那个目录链接往真实依赖目录里写文件。写之前、写之后数一下目标目录里的文件个数。
6. **有没有不弹窗、不写东西的检查办法**：要是需要什么前提（授权、装东西），能不能被动地查出来「这台机器准备好了没」。
7. **无人值守**：同一个配方连着跑 10 次，次次成功、中途不弹窗。
8. **开销**：同一个合成测试，沙箱里、沙箱外各跑几次，用时多少。
9. **结论落到哪**：照这个结论，D2 的调用（`executor.ts` 里依赖档派生那段、`verifySandbox.ts`）、检查口径（还要不要 cap_sid / helper / setup 标记 / 服务那四样）、V4 设置页那一块（还要不要「授权」按钮）分别该怎么改。只写建议，不改代码。

## 硬规矩（每一条都不许破）

- **每次调用 Codex 都设 `CODEX_HOME` 指到临时目录里的专用目录**，绝不用默认的（用户的）`~/.codex`，也不读、不改它。V4 那次的探针（`codex sandbox windows --help`）没设 CODEX_HOME，去动了用户的 `~/.codex/.sandbox-bin`（被拒了，没改成）——不许再发生。
- **不提权**：不用 `-c windows.sandbox="elevated"`，不跑任何要管理员确认的东西。不提权就挡不住的（比如联网），如实写「不提权挡不住」，**停在这里**：要不要试提权，由用户定。
- **不跑 `codex sandbox uninstall`**：它会删机器上的账户和网络规则，那是系统改动，用户的 Codex 桌面应用也可能在用。
- **不调模型、不跑 `codex exec`**：只跑 `codex sandbox …` 和 `codex … --help`。
- 不改系统和网络设置，不装软件；全用合成项目和临时目录；输出里不能有本机账户名（遮掉临时目录的两种写法）。
- 碰到任何弹窗、任何「要管理员」的提示：不点、不绕，停下，把看到的原样写进交付说明。
