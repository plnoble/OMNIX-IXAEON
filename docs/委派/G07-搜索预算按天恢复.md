# 规格 G07：关注方向的搜索额度按天恢复

档位：**B**（自动网络访问与花费）。大小：小到中（≤150 行源码）。依赖：迁移 35（整合方已加 `research_topics.daily_request_cap`、`request_budget_day`）。来源：[全局审核 2026-09-20](交付/全局审核-2026-09-20.md) G07。
v2 规格：先把验收条件写成测试（`packages/core/test/acceptance/g07-*.test.ts`，界面部分放 `apps/desktop/test/acceptance/`），**先只推测试**等整合方看过并锁定，再实现。

## 要什么

W1a 的关注方向卡片写「每天自动找一次，最多搜 3 次」，实际是累计 3 次：检查器每搜一次就把 `request_cap` 减 1，永不恢复。审核用四个日期模拟：前三天搜了，第四天不搜，主题照旧启用——等于三天后悄悄停了。

**用户 2026-09-24 定：每天 3 次，第二天自动恢复。** 手动建的关注（「预批搜索次数上限」）照旧是累计额度，不偷偷扩大自动搜索。

## 契约

1. 迁移 35 已加两列（**不要再加迁移**）：`daily_request_cap`（空 = 累计额度；有值 = 每天的额度）、`request_budget_day`（上次按天恢复是哪天，本地日期 `YYYY-MM-DD`）。
2. W1a 的「关注」建主题（搜索已配置时）：`daily_request_cap = 3`、`request_cap = 3`、`request_budget_day = 今天`。
3. 每次检查（定时或立即）开始前：`daily_request_cap` 有值且 `request_budget_day` 不是今天 → `request_cap = daily_request_cap`、`request_budget_day = 今天`。其余扣减逻辑不变。
4. 研究页每个主题显示额度：按天的写「今天还能搜 N 次（每天 3 次）」，累计的写「还能搜 N 次（总额度）」；用完时写「今天的搜索额度用完了，明天恢复」或「搜索额度用完了，要继续请调高上限」。

## 约束

- `daily_request_cap` 为空的主题行为完全不变（累计扣减、不恢复）。
- 「今天」按用户本地时区算。

## 验收条件

1. 按天的主题：四个不同日期各检查一次，每天都发起搜索（`[true, true, true, true]`）。
2. 按天的主题：同一天检查第 4 次时不搜（额度 3 用完）。
3. 累计的主题：额度用完后换一天也不恢复。
4. W1a「关注」建出的主题：`daily_request_cap = 3`；搜索没配置时仍是 `paid_budget_mode = 'none'`（W1a 的锁定验收照过）。
5. 研究页按主题类型显示对应的额度文案与用完提示。

## 真机检查

不需要真搜索：用受控的搜索替身跑自动化。交付里写「规格不要求真机检查」。
