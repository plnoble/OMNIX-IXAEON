# 规格 L9：没活时整合方自己找活（规划棒）

档位：**B**（让模型自己往队列里加任务；新的交代）。大小：小（约 120 行源码）。依赖：无。来源：接力第 6 棒（2026-10-23）并入 L8 之后，队列里除了暂停的 V4 没有能接的活，调度器只能空转等人。用户 2026-10-23 定的方向：**多个 agent 不间断自主开发**。

v2 规格：先把验收条件写成测试（`packages/relay/test/acceptance/l9-*.test.ts`），**先只推测试**，整合方锁定后再写实现。

## 要什么

1. 没人能接的活时（`decideNextTurn` 原来要回 `queue-empty` 或 `all-blocked`），派一棒给整合方：**规划棒**。整合方照 [整合方手册](整合方手册.md) 第 11 节，从三周任务单里挑下一批（最多 3 件），每件写一页规格、在队列主表末尾加一行，然后停。拿不准方向的，只加一行「等用户：<一句话的问题>」。
2. 规划有限度，不会自己转圈：每个北京日最多 `planPerDay` 棒；队列和上一次派规划棒时一字不差（上次没加出东西、之后也没人改过）就不再规划，照原来空转。
3. 规划棒之后调度器核对：它只在主表末尾加了行、只改了 `docs/`；越界就停。
4. 规划棒加了行，飞书发一条，列出新加的几行。
5. 顺手：普通棒的交代里写明任务号。第 4 棒 DSH 把序号 70 当成了任务号，分支建成了 `dev/70`。

## 契约（接口写死，不改名、不加字段）

1. **类型**：`TurnKind` 加 `'integrator-plan'`。规划棒的 `Turn` 是 `{ role: 'integrator', kind: 'integrator-plan', taskId: 'plan', task: '找下一批活', status: <原来要回的 idle 原因：'queue-empty' 或 'all-blocked'> }`。
2. **配置**：`RelayConfig` 加可选字段 `planPerDay?: number`。没有、或不大于 0 → 不规划（和现在完全一样）。`relay init` 生成的配置和 `config.example.json` 里写 `2`。`checkConfig`：有这个字段但不是非负整数 → 不过。
3. **状态**：`RelayState` 加可选字段 `plan?: { date: string; count: number; queueHash: string }`。`date` 是北京时间的日子（照 `daily.ts` 的写法，如 `10月23日`），`count` 是那天派过几棒规划，`queueHash` 是最近一次派规划棒时队列全文的 sha256（十六进制）。
4. **派活**：`decideNextTurn(md, state, now, opts?: { planPerDay?: number })`。原来要回 `queue-empty` / `all-blocked` 时，下面三条都成立就回规划棒，否则照原来回 idle：
   - `opts.planPerDay` 大于 0，整合方没在歇；
   - `state.plan` 没有、或它的 `date` 不是今天、或 `count < planPerDay`；
   - `state.plan?.queueHash` 不等于这一次队列全文的 sha256。

   `all-paused`、`stopped` 不规划。`runOnce` 把 `config.planPerDay` 传进去；派了规划棒就更新 `state.plan`（换了日子 `count` 从 1 起），跑之前存盘。

5. **交代**（规划棒；下面这段逐字，接着是「这是第 N 棒。」、普通棒同样的那段 `ASK`、停点、最后一行）：

   > 你是整合方（统筹）。这一棒是规划棒：队列里现在没有谁能接的活。照 docs/委派/整合方手册.md 第 11 节，从 docs/三周任务单.md 里挑下一批活，最多 3 件：每件写一页规格放进 docs/委派/，在 docs/委派/队列.md 主表末尾加一行，状态写「待领」；拿不准方向的，只加一行「等用户：<一句话的问题>」，不写规格。只改 docs/ 下面的文件，不动主表里已有的行。做完照手册推到 main。

   停点一句：`停点：加完行、推上 main 就停。` 最后一行：`做完在最后一行输出：RELAY-DONE plan <加了几行>`。

6. **核对**（`verifyTurn`，只对规划棒加下面两条；`local-user` 照旧任何一棒都查）：比开棒时的 `origin/main`（`state.mainShaAtTurnStart`）和现在的 `origin/main`：
   - 改了 `docs/` 以外的任何文件 → `plan-touched-code`；
   - 主表里开棒时已有的行，有一行少了、或任何一格变了；新加的超过 3 行；新加的行状态不是以「待领」或「等用户：」开头 → `plan-changed-rows`。

   `Violation` 加这两个。照原来的规矩：有越界就停下，`stoppedReason` 是「第 N 棒越界（integrator）：…」，发 stopped。

7. **飞书**：规划棒没越界、加了至少一行 → 发 `{ kind: 'planned', rows: Array<{ no: string; task: string; status: string }> }`（按主表里的先后）。`formatEvent` 第一行 `整合方排了 <N> 件新活：`，之后每行一条 `- 第 <no> 行 <task>（<status>）`。不限频。一行都没加 → 不发 planned（之后照常空转，原来的 idle 照发）。
8. **记账**：规划棒那一条 `kind: 'integrator-plan'`、`taskId: 'plan'`、`statusBefore` 是 idle 原因、`statusAfter` 是 `加了 <N> 行`（核对时拉不下来照原来写 `null`）。
9. **普通棒的交代**：在「序号」那一行后面加一行（逐字，`<任务号>` 是任务一栏的前导词，照 `leadingId`）：`任务号：<任务号>（分支、工作目录、交付说明都用它；序号只是它在队列里第几行）`。

## 约束

- 只改 `packages/relay/`（`src`、`bin`、`config.example.json`、`README.md` 里讲规划棒的一段）。整合方手册第 11 节整合方已经写好。
- 调度器自己照旧不改仓库：规划棒里的提交、推送是整合方自己做的，调度器只核对。
- 已锁定的验收测试不改。`planPerDay` 不配时一切照旧，L1 那几条「没活」的测试应该原样能过；如果有锁定测试和这一单冲突（比如逐字比整份交代、或比整份生成的配置），停下，写进交付说明，由整合方改。

## 验收条件

1. 派活（契约第 4 条）：`queue-empty`、`all-blocked` 两种都派规划棒；`planPerDay` 没配、整合方在歇、当天次数到了、队列和上次一字不差 → 各自照原来回 idle；换了北京日次数重算；`all-paused`、`stopped` 不规划；派了之后 `state.plan` 照契约第 3、4 条更新。
2. 交代：规划棒的交代逐字含契约第 5 条那段、停点那句和最后一行的写法；普通棒的交代含 `任务号：L8（分支、工作目录、交付说明都用它；序号只是它在队列里第几行）`（用一行任务一栏以 `L8 ` 开头的合成队列测）。
3. 核对：用合成仓库（照 `l2b-notify` 的做法：bare origin、整合方和开发各一个克隆、替身脚本当整合方），替身分别：(a) 主表末尾加 2 行、只改 `docs/` → 不停；(b) 改了 `packages/` 下一个文件 → 停、`plan-touched-code`；(c) 改了已有一行的状态 → `plan-changed-rows`；(d) 加了 4 行 → `plan-changed-rows`；(e) 新行状态是「进行中（dev）」→ `plan-changed-rows`；(f) 删了已有的一行 → `plan-changed-rows`。
4. 飞书：(a) 那种 → 假飞书收到一条 planned，正文就是 `formatEvent` 拼出来的那段；替身一行没加 → 不发 planned。
5. 记账：规划棒那一条的 `kind`、`taskId`、`statusBefore`、`statusAfter` 照契约第 8 条。
6. `relay init` 生成的配置、`config.example.json` 里 `planPerDay` 是 `2`；`planPerDay: -1`、`1.5`、`"2"` → `checkConfig` 不过。

## 真机检查

- **甲（开发做）**：一个临时仓库（bare origin + 克隆），里面放合成的 `docs/三周任务单.md`（两件排着的活、一件写在「明确不做」里）、全是「已完成」的合成队列，再从本仓库复制一份 `docs/委派/整合方手册.md` 和 `AGENTS.md`。数据目录用临时目录、不配飞书，整合方用 `relay init` 生成的那条真 Claude 命令（`cwd` 改成临时克隆），跑一次 `relay once`。贴出：输出的那一行、加了几行、`git diff --stat`、核对结果、「明确不做」的那件有没有被排进去、这一棒花了多少钱。临时目录跑完删掉，贴出来的路径遮掉用户目录。
- **乙（整合方合并后做）**：在用户本机的真队列上跑第一棒真规划，看它排的活合不合方向，结论追加到这份规格末尾。

## 整合方审测试时的改正与补充（2026-10-24，接力第 13 棒）

做法照手册第 4 节：写了一份一次性实现（不提交），开发交的 36 条里 35 条过、1 条和契约相反；补测试之后 40 条全过；带着实现跑 `packages/relay` 全部 38 份验收测试（251 条）全过，**和已锁定的测试没有冲突**（普通棒交代多出的「任务号」那一行，L1、L6 的交代测试都是按「含」比的，不受影响）。然后逐处改坏实现（42 处）看测试红不红，结果记在交付说明「整合方审测试」。

**改正（测试和契约相反）**

1. `l9-decide`「换了北京日 → 次数重算，照样派（昨天派满、队列没变也派）」：契约第 4 条三条要**同时**成立，队列和上次一字不差就不派，换没换日子都一样。改成两条：昨天派满、队列变了 → 派；换了日子、队列一字不差 → 不派。
   给实现的提醒：「上次规划没加出东西、之后谁也没动过队列」会一直空转到有人改队列为止，这是规格要的（要什么第 2 条），不是 bug。

**补充（变异检查查出的空子）**

2. 契约第 4 条「跑之前存盘」没测到：替身加了 `snapshotState`，开跑时抄一份 `state.json`，断言里面已经是这一次的 `plan`（`count` 涨了、`queueHash` 换成这次的）。
3. 交代只查了「含」，没查先后和多余的东西：补规划棒的交代以契约第 5 条那段开头、以最后一行收尾、中间顺序照契约；不含普通棒的停点、不含「序号：」、只有一句停点。
4. 核对只认 `docs/` 这个目录：补一条改 `docs-extra/x.md` → `plan-touched-code`（防 `startsWith('docs')`）。
5. 「任何一格变了」原来只测了状态那一格：补改已有一行的**任务**一格、和**委派单或规格**一格（`parseMainTable` 不读这一格，只比它那几栏的实现会漏）→ `plan-changed-rows`。
6. 越界时不发 planned：命令行那条越界测试的替身同时加了一行合规的「待领」，断言假飞书里没有「整合方排了」。

**没改的（开发写的缺口，整合方同意）**：已有行只重排、每格没变，不算越界（规格没要求）；`planned` 不限频用 `createNotifier` 直接验；`relay init` 那条会真 `git fetch` 一次。
