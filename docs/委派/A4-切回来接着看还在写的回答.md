# 规格 A4：回答还在写的时候切走再切回来，页面要接着跟上，答完自动显示

档位：**A**（只改对话页的显示与刷新，不改回答流程、不改发给模型的内容）。大小：小（≤100 行源码）。依赖：无。来源：用户 2026-10-01 第一次试场景一。
v2 规格：验收条件写成测试（`apps/desktop/test/acceptance/a4-*.test.ts` 或 `apps/desktop/e2e/` 下的界面测试），测试和实现一起交，Codex 审查时核对有没有漏条件。

## 要什么

用户在项目对话里提了一个开发请求，界面一直转着「正在回答…」，等了十来分钟没有结果，最后把应用关了。整合方查过：
- Hermes 85 秒就答完了（中途连模型网关失败两次、自动重试成功）；
- 回答 09:39:41 已经存进库，状态是「完成」，没有错误；
- 界面上那个不带秒数的「正在回答…」，说明显示这个对话的不是发起提问的那个页面——等回答期间页面重新加载过（最可能是切到别的页面再切回来）。

现在的写法里，只有发起提问的那个页面实例会：
- 接收这一轮的分段、进度（`onAskDelta` / `onAskProgress` 只认 `waiting.current`）；
- 在 `askQuestion` 返回后从库里重新拉这个对话。

重新加载出来的页面从库里读到一条「回答中」的消息，之后既不接分段、也没有任何东西通知它答完了，就一直转下去，直到用户手动重开这个对话。

## 契约

1. 对话页正在显示的对话里有「回答中」的消息，而这一页不是发起这一轮的页面时，要**跟上这一轮**：
   - 收到属于这条消息的分段，就接着显示在气泡里；
   - 这一轮结束（完成、失败、取消都算）后几秒内，从库里重新拉这个对话，显示最终结果。
2. 怎么得知「这一轮结束了」，实现方定（比如主进程在 `finishMessage` 之后发一个「这一轮结束」的事件，或者对话页每隔约 2 秒查一次，直到没有回答中的消息为止），但不许改主进程回答流程本身的逻辑和顺序。
3. 不是这一页发起的一轮，等待标签不显示「正在准备 / 正在思考（N 秒）」这类假装知道阶段的字样；现在的「正在回答…」可以保留。
4. 发起提问的那一页从头到尾没离开过：行为不变。

## 约束

- 不加迁移，不改 `messages` 的状态含义。
- 应用重启后，上一轮被打断的消息照旧由启动时的 `failInterruptedMessages` 收尾成失败，不转圈（现有行为不变）。
- 跟上的时候只认这一个对话、这一条消息：别的对话、别的消息的分段不许串进来。

## 验收条件

1. 发问后马上切到别的页面再切回这个对话：回答结束后几秒内，页面显示最终回答，不用手动重开对话。
2. 切回来时回答还在写：之后到来的分段照常出现在气泡里，答完后的内容与库里一致（不重复、不缺）。
3. 回答以失败告终（比如模型出错）：切回来的页面在结束后显示失败和错误信息，不再转圈。
4. 切回来时打开的是另一个对话：那个对话不受这一轮的分段影响。
5. 发起提问的那一页没离开过：现有的对话页测试照过。

## 真机检查

设 `IXAEON_DATA_DIR=<临时目录>`、用执行器替身和假模型启动应用（需要的话给假模型加一个只在测试里生效的延迟，让一轮回答持续几秒）。发问后立刻切到「项目」页再切回「对话」，截图或描述：切回来时在转圈、分段在出现、答完自动换成最终回答。原样贴进交付说明。
