# 规格 L1：接力调度器（核心：看队列定下一棒、跑一棒、核对有没有越界）

档位：**B**（它把任务交给模型，带着写死的交代；它决定谁能动 main）。大小：中，超过 300 行就拆成两支（见「拆法」）。依赖：无（用替身 CLI 测；接真的三个命令行是下一单，等 L0b 的结论）。来源：用户 2026-10-20 定的方向（见 [L0 规格](L0-三个命令行后台跑通实验.md)开头「为什么要做」），用户同意「照流水线规矩推，不用每次问」。

v2 规格：先把验收条件写成测试（`packages/relay/test/acceptance/l1-*.test.ts`），**先只推测试**，整合方锁定后再写实现。

## 要什么

一个**普通代码写的调度器**，在后台一直转：

1. **看队列定下一棒**：读 `docs/委派/队列.md` 主表，按流水线规矩算出「现在轮到谁、做哪一行」；
2. **跑一棒**：给那个角色写一份这一棒的交代（提示词文件），用配置里写好的命令行把它调起来，等它做完或超时；
3. **核对**：这一棒做完，拉一下 main，查它有没有越界（比如开发角色并了 B 档）。越界就整个停下，等用户；
4. **记账**：每一棒记一行（谁、哪一行、多久、退出码、用量、做完后那一行的状态）；某个角色撞上额度，就让它歇到点再接着。

**交接靠队列，不靠群聊里互相 @**；关卡写在代码里。调度器自己**不改仓库、不推送**——改和推都是被调起来的那个角色照 AGENTS.md 做的。

这一单只做核心，用**替身命令行**（测试里写的小脚本）测；接真的 Claude / DSH / Codex（命令行参数、权限白名单）是下一单，等 L0b 的结论。飞书通知也是另一单（新的外部服务）。

## 契约（接口写死，不改名、不加字段）

1. **位置**：新包 `packages/relay/`（`@ixaeon/relay`，TypeScript，照 `packages/core` 的写法）。命令行入口 `packages/relay/bin/relay.mjs`，跑 TS 照 `scripts/real/run-batch.mjs` 找 jiti 的办法。
2. **数据目录**：`<Worktrees>/IXAEON/relay/`（`<Worktrees>` 照 `scripts/worktree.mjs` 现算，本机是 `D:\Agent\Worktrees`），里面：`config.json`（用户本机的，不进仓库）、`state.json`、`ledger.jsonl`、`turns/<编号>/`（这一棒的 `prompt.md`、`stdout.txt`、`stderr.txt`）。仓库里提交一份 `packages/relay/config.example.json`。
3. **配置**（`config.json`）：

   ```ts
   interface RelayConfig {
     /** 角色 → 怎么调起它。argv 里的 {prompt_file} 换成这一棒交代文件的绝对路径。 */
     roles: Record<
       'integrator' | 'developer',
       {
         argv: string[];
         cwd: string; // 在哪个目录里调起它（整合方工作目录 / 开发 agent 的操作目录）
         timeoutMinutes: number;
         /** 输出里出现这些文字（不分大小写）就算撞上额度。 */
         quotaPatterns: string[];
         /** 撞上额度后歇多久再试。 */
         quotaPauseMinutes: number;
       }
     >;
     /** 没活干时多久再看一次队列。 */
     idleSeconds: number;
     /** 核对用的命令（测试里换成替身）：默认 ["node", "scripts/check-local-user.mjs"]，在 roles.integrator.cwd 里跑。 */
     localUserCheck?: string[];
   }
   ```

   **配置检查**（不过就拒绝启动、说清楚哪一条）：argv 里有「跳过所有权限」一类的开关（至少：`--dangerously-skip-permissions`、`--allow-dangerously-skip-permissions`、`--dangerously-bypass-approvals-and-sandbox`、`danger-full-access`、`--full-auto`、`bypassPermissions`）→ 拒绝；`cwd` 是用户和整合方共用的检出目录（仓库里 `scripts/worktree.mjs` 认的那个主检出）或不存在 → 拒绝。

4. **定下一棒**（纯函数，不碰文件）：

   ```ts
   type Turn = {
     role: 'integrator' | 'developer';
     kind: 'integrator-review' | 'developer-claim' | 'developer-continue';
     taskId: string; // 队列「序号」那一格
     task: string; // 「任务」那一格
     status: string; // 「状态」那一格
   };
   type Idle = { idle: 'stopped' | 'queue-empty' | 'all-blocked' | 'all-paused' };
   function decideNextTurn(queueMarkdown: string, state: RelayState, now: Date): Turn | Idle;
   ```

   只看主表（表头是「序号 | 任务 | 委派单或规格 | 档位 | 依赖 | 状态」的那一张）。次序：

   1. `state.stoppedReason` 有值 → `{ idle: 'stopped' }`。
   2. 状态以「测试待审（整合方）」或「待复审（整合方）」开头的第一行 → `integrator-review`（整合方在歇着就跳过这一条）。
   3. 状态以「进行中（」或「待审（Codex 额度）」开头的第一行 → `developer-continue`（开发在歇着就跳过）。
   4. 状态是「待领」、而且依赖都完成了的第一行 → `developer-claim`（开发在歇着就跳过）。依赖那一格：「无」或以「无（」开头 → 没依赖；否则按「、」「，」「,」切开，每一项是「<序号或任务号> ✅」就算完成；不带 ✅ 的，去表里找任务号对得上的那一行，状态以「已完成」开头才算完成。
   5. 都没有：表里还有没完成的行 → `all-blocked`（全被依赖或暂停挡着）；角色都在歇着 → `all-paused`；否则 `queue-empty`。

   状态以「暂停」「已完成」开头的行一律跳过。「谁在歇着」看 `state.pausedUntil[role]` 晚于 `now`。

5. **这一棒的交代**（发给模型的提示词，B 档）：写进 `turns/<编号>/prompt.md`。三种 `kind` 各一份，**每份都要有**：
   - 角色和名字（整合方 / 开发 agent，名字 `dev`）；
   - 「照 AGENTS.md 做」；整合方那份另加「照 `docs/委派/整合方手册.md` 做」；
   - 只做这一行：序号、任务、当前状态，原样写进去；**「只做这一件，做到它的停点就停，不要接着领别的」**；
   - 停点是什么：整合方——这一行复审完（并入 main，或者把状态改成你给的结论）；开发——这一行到了 AGENTS.md 说的停点（B 档推了测试或实现、A 档审过合并、或者转给整合方）；
   - 最后一行输出 `RELAY-DONE <序号> <这一行现在的状态>`。
   - 不写别的规矩进来（规矩在 AGENTS.md 和手册里，不在提示词里另抄一份——设计规约「提示词只写形状级规则」）。
6. **跑一棒**：`runTurn(turn, config, state) → TurnResult`，照配置调起，`cwd` 用配置里的；超时就杀**它自己拉起的那一棵进程树**（照 `run-batch.mjs`），记 `timedOut: true`；输出存进 `turns/<编号>/`；输出里出现 `quotaPatterns` 里的字 → `state.pausedUntil[role] = now + quotaPauseMinutes`。
7. **用量**：标准输出里有一行 JSON 带 `total_cost_usd` → 记成 `usage.costUsd`；有 JSONL 事件带 `usage.input_tokens` / `usage.output_tokens` → 加总记成 `usage.inputTokens` / `usage.outputTokens`；都没有就不记。
8. **核对**（一棒做完之后）：`git fetch` 之后，看这一棒开始时的 `origin/main` 到现在的 `origin/main` 之间：
   - **开发这一棒并了 B 档**：提交说明以「并入 <任务号>」开头、而那个任务在队列里档位是 B → 越界（`b-tier-merged-by-developer`）；
   - **开发这一棒动了 B 档任务的锁定指纹**：`docs/委派/锁定验收.json` 里档位是 B 的任务，它的文件指纹在这一棒里变了 → 越界（`b-tier-lock-changed-by-developer`）；
   - **任何一棒之后**：在 main 上跑 `localUserCheck` 不过 → 越界（`local-user`）。
     越界：`state.stoppedReason` 写上是哪一条、哪一棒，之后 `decideNextTurn` 一律 `stopped`，直到用户 `relay resume`。
9. **记账**：每一棒往 `ledger.jsonl` 追加一行：

   ```ts
   interface LedgerEntry {
     turn: number;
     role: string;
     kind: string;
     taskId: string;
     startedAt: string;
     endedAt: string;
     exitCode: number | null;
     timedOut: boolean;
     quotaHit: boolean;
     usage?: { costUsd?: number; inputTokens?: number; outputTokens?: number };
     statusBefore: string;
     statusAfter: string | null; // 做完后重读队列，这一行的状态
     doneLine: string | null; // 输出里的 RELAY-DONE 那一行
     violations: string[];
   }
   ```

10. **命令**：`relay once`（定一棒、跑、核对，然后退出）；`relay run`（一直转：有活就跑，没活就等 `idleSeconds` 再看，`stopped` 就退出）；`relay status`（打印 `state.json` 和最近 5 棒）；`relay resume`（清掉 `stoppedReason`）。**同一时间只许一个调度器在转**：数据目录里放一个锁文件（写进程号），已有活着的就拒绝启动；进程号已经不在了就当没锁。

## 约束

- 调度器自己**不改仓库、不推送、不调 Codex**（Codex 审核照 AGENTS.md 由开发 agent 自己调 `codex-review.mjs`）。
- **一次只跑一棒**（不并发）。
- 不带任何密钥；配置里不放密钥（DSH 的 key 在 DSH 自己那里）。
- 不碰用户的真实数据；不往仓库外的任何地方写（数据目录除外）。
- 测试全用替身命令行和临时 git 仓库，**不调真的模型**。
- 拆法：超过 300 行源码就拆成 **L1**（第 3、4、5、8 条：配置检查、定下一棒、交代、核对——都能当纯函数测）和 **L1b**（第 6、7、9、10 条：跑一棒、用量、记账、命令和锁），L1b 基于 L1。

## 验收条件

1. **定下一棒的次序**：合成的队列里同时有「待复审（整合方）」「进行中（dev）」「待领」三行 → 先给整合方；整合方在歇着 → 给开发「进行中」那行；没有「进行中」→ 给开发第一个依赖都完成的「待领」。
2. **依赖**：「无」「无（说明）」没依赖；「P5 ✅」算完成；「D2c」去表里找、状态「已完成（…）」才算；依赖没完成的「待领」跳过、去看下一行；全被挡着 → `all-blocked`。
3. **跳过的**：「暂停（…）」「已完成（…）」的行不给；`stoppedReason` 有值 → `stopped`；两个角色都在歇着 → `all-paused`；表里全是已完成 → `queue-empty`。只认主表，别的表（「已完成」「整合方正在设计」那几张）里的行不给。
4. **交代**：三种 `kind` 的 `prompt.md` 各有第 5 条要的每一项（序号、任务、状态原样在；「只做这一件」那句在；整合方那份提到手册；最后一行的格式）。
5. **跑一棒**：替身命令行收到了 `{prompt_file}` 换成的真路径、在配置的 `cwd` 里跑；标准输出、错误输出存进 `turns/<编号>/`；记账那一行字段齐全。
6. **超时**：替身命令行自己再拉起一个子进程、然后一直不退 → 超过 `timeoutMinutes`（测试里可以把单位换小）之后，它和它的子进程都被杀掉；记账里 `timedOut: true`。
7. **额度**：替身输出里有配置的额度字样 → 那个角色歇到点；下一次 `decideNextTurn` 跳过它；到点后又能轮到它。
8. **用量**：替身输出 Claude 那种带 `total_cost_usd` 的 JSON → 记 `costUsd`；输出 Codex 那种带 `usage` 的 JSONL → 记 token 数。
9. **核对**：临时 git 仓库里造出——开发这一棒有一笔「并入 X」而 X 是 B 档 → 越界、停下；X 是 A 档 → 不越界；开发这一棒改了 B 档任务在 `锁定验收.json` 里的指纹 → 越界；`localUserCheck` 换成一个退出码非 0 的替身 → 越界。越界之后 `once` 什么都不跑，`resume` 之后才接着。
10. **配置检查**：argv 里有第 3 条列的任何一个开关 → 拒绝启动；`cwd` 是共用检出目录 → 拒绝；`cwd` 不存在 → 拒绝。
11. **只许一个**：锁文件里的进程还活着 → 第二个拒绝启动；进程不在了 → 能启动。

### 规格里没说清、现在定下的

1. **都没活时的次序**：两个角色都在歇着 → `all-paused`；否则表里还有不是「已完成」的行（暂停的、被依赖挡着的、只因一个角色歇着没给的都算）→ `all-blocked`；否则 `queue-empty`。
2. **队列从哪读**：在 `roles.integrator.cwd` 里 `git fetch` 之后读 `origin/main` 上的 `docs/委派/队列.md`（`git show`），**不读工作区**——开发在自己的目录里推，整合方的目录不会跟着变。做完之后的 `statusAfter` 也这样重读。测试已经改成开发在另一个克隆里提交。
3. **「锁定指纹变了」怎么算**：比这一棒开始和结束两个 `origin/main`。B 档任务在 `锁定验收.json` 里那一条有**任何**变化（新增、删掉、文件或指纹变了、状态变了——开发自己 `done` 也算），或者它登记的文件在两次之间有改动 → `b-tier-lock-changed-by-developer`。**不拿「文件内容 vs 清单里的指纹」比**：开发自己重锁一遍，指纹就对上了，那样查不出来。
4. **「并入 X」**：这一棒范围里的每一笔都查，不只最后一笔。`X` 以 `b` 结尾、表里又没有 `X` 时，按去掉 `b` 的任务号查档位（`并入 L3b` 算 L3 的）。**只查开发那一棒**：整合方那一棒并 B 档、改锁定，是整合方的活，不算越界。
5. **配置检查**：两个角色都查；开关写在别的参数里面也认（按子串：`--permission-mode=bypassPermissions`、`-c sandbox_mode="danger-full-access"`）；`cwd` 在共用检出目录**里面**（子目录、大小写不同、末尾带分隔符）也拒绝。
6. **`relay run --exit-when-idle`**：第一次没活（`queue-empty` / `all-blocked` / `all-paused`）就退出、退出码 0。给测试和真机检查用；不带它时照第 10 条一直转。
7. **额度字样**：标准输出和错误输出都查，不分大小写。
8. 配置不过、锁被占着：`once` / `run` 退出码非 0，说清是哪一条 / 哪个进程号，什么都不跑（不建 `turns/`、不记账）。

### 给实现的提醒

- 路径「在不在某个目录里」照 P8 的教训，不用 `path.relative`（跨盘符会返回绝对路径）；Windows 上不分大小写。
- 调度器自己不改仓库：读队列、读锁定清单都用 `git show <提交>:<路径>`，不 checkout、不 pull 进整合方的工作区。测试会查一棒之后整合方目录的工作区是干净的。
- 交代里测试会查的字样：`序号：<序号>`（替身靠它找序号）、`AGENTS.md`、`只做这一件，做到它的停点就停，不要接着领别的`、`RELAY-DONE <序号>`；整合方那份有 `docs/委派/整合方手册.md`、「复审」和「并入 main / 把状态改成」；开发那份的停点写出「B 档」「A 档」「转给整合方」。
- `local-user` 照第 3 条在 `roles.integrator.cwd` 里跑，查的是那个目录的检出，不一定是最新的 main。接真命令行那一单（L2）再定要不要先把那个目录更新到 `origin/main`。
- 测试目录在根 tsconfig 外：自己用一个临时 tsconfig 做类型检查（见整合方手册第 4 节）。
