# 规格 M1：核心模型请求改成边生成边返回，慢模型不再在网关超时

档位：**A**（只改传输方式，不改发什么、发给谁、提示词）。大小：中（≤250 行源码）。依赖：无。来源：用户 2026-09-26 选的下一步；第四次真实使用反馈。
v2 规格：验收条件写成测试（`packages/core/test/acceptance/m1-*.test.ts`），测试和实现一起交，Codex 审查时核对测试有没有漏掉条件。

## 要什么

09-24 用户的核心模型是 `grok-4.6`：分析资料的请求在网关一再失败（524 = 网关等了 100 秒没收到回应；还有 502），20 份资料从 09-18 排队到 09-24。换成 flash 模型后几分钟就全跑完了。

原因是 `OpenAIResponsesProvider`（`packages/core/src/extraction/model/openai.ts`）两条路（`/responses`、`/chat/completions`）都是等整段结果一次拿回来：慢模型思考超过 100 秒，网关前面的 Cloudflare 就断开。改成流式（`stream: true`，服务端推送事件），网关一开始生成就先把响应头和首批字节发回来，就不会被按「100 秒没回应」掐断。

这是推断：如果网关在模型思考期间一个字节都不发，流式也救不了。那就如实报告，再换别的办法（比如分析用快模型、只有判断类的活用慢模型）。

## 契约

1. 两条路都发 `stream: true`，按服务端推送事件（`text/event-stream`）读：
   - `/responses`：累加 `response.output_text.delta` 的文字；收到 `response.completed` 结束；`response.failed` / `error` 事件 → `ModelError`（能看出是限流或服务端错误的算暂时性）。
   - `/chat/completions`：累加 `choices[0].delta.content`；`data: [DONE]` 结束。
   - 事件可能被拆在两次读取之间、一次读取里也可能有多个事件：按行和空行正确拼接。
2. 兼容回退：网关不支持流式时（返回的不是 `text/event-stream` 而是普通 JSON，或对 `stream` 报 400），按现有的非流式方式解析或重发一次；**同一个 provider 实例记住**「不支持流式」，之后不再尝试。
3. 不另加超时：Node 自带的请求超时（300 秒没收到字节）已经存在，报错照旧按「网络错误」算暂时性、交给队列重试。别设得更短——慢模型长时间思考时会被提前掐掉。
4. 其余语义不变：结构化输出的校验与重试、429 / 5xx 的一次立即重试、网络错误的一次重试、`/responses` 与 `/chat/completions` 的探测与缓存、错误信息的格式（队列与界面按前缀认错误类别）。

## 约束

- 不改提示词、不改发给模型的内容、不加新的服务；聊天（Hermes）不走这里，不改。
- 不加迁移。

## 验收条件

1. `/responses` 流式：替身分三次读取吐出「created → 两段 delta（其中一段被拆在两次读取之间）→ completed」，拿到完整文字，结构化结果校验通过。
2. `/chat/completions` 流式：多段 `delta.content` + `[DONE]`，拿到完整文字。
3. 网关忽略 `stream` 返回普通 JSON：照旧解析成功；对 `stream` 报 400：去掉 `stream` 重发一次成功；之后同一个实例的请求不再带 `stream`。
4. 流中收到 `response.failed`（或 `error` 事件）：抛 `ModelError`；限流 / 服务端类的 `retriable = true`。
5. 429 / 5xx、网络错误的重试次数与原来一致（现有相关测试照过）。

## 真机检查

模型 Key 在 Electron 加密存储里，执行方跑不了真网关——交付里如实写「待用户验证」。能跑的照跑：用本机起一个假的流式服务（`scripts/real/` 里的脚本：立刻回响应头，隔 110 秒再吐文字），确认拿到完整结果、中途没有断。

用户验证：在设置页把核心模型临时换回 `grok-4.6`，在「来源」页对一份资料点重新分析，看是否还报 524；验完换回。
