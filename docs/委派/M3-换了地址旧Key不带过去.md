# 规格 M3：换了 API 地址，旧 Key 不带到新地址

档位：**B**（隐私：密钥会不会被发给另一个服务）。大小：小（≤60 行源码）。依赖：无。来源：M2 执行方查出、Codex 判为隐私问题，交整合方（`docs/委派/交付/M2.md`「已知缺口」，`m2-saved-models.test.ts` 里那条 `it.skip`）。
v2 规格：先把验收条件写成测试（`apps/desktop/test/acceptance/m3-*.test.ts`），**先只推测试**，整合方看过并锁定后再实现。

## 要什么

现在保存模型设置时，Key 留空就保持原值，不管地址改没改。于是：
1. 用户把 API 地址改成另一家，Key 没填，点了保存：旧 Key 留着，配的却是新地址；
2. 之后检测模型时 Key 留空，规则是「地址和已保存的一致就复用已保存的 Key」：地址确实一致，旧 Key 就被发给了新地址；后台分析、兜底问答同样会带着它去请求新地址。

也就是把上一家的密钥发给了另一家。用户说的是「不需要再输入 api，除非我自己的 api 有变动」——地址变了，就是有变动。

## 契约

1. **保存时**：地址的来源（协议 + 主机 + 端口）和已保存的不同，这次又没填新 Key，就清掉已保存的 Key（`apiKeyEncrypted = null`、`apiKeyPresent = false`），不留给新地址。填了新 Key 就照常保存新的。
2. 来源没变、只改了路径（比如 `/v1` 改成 `/v2`），或者地址没变：Key 留空照旧保持原值。
3. 比较前先规范化：主机名不分大小写，去掉结尾的斜杠，默认端口写不写都算同一个；空地址表示官方默认地址，按它的来源比。
4. **界面**：保存后如果 Key 因此被清掉，设置页显示「未配置」，并提示一句「地址变了，原来的 Key 没有带到新地址；这个地址需要 Key 的话请重新填」。
5. 检测模型的现有规则不变（Key 留空只在地址和已保存的一致时复用）。有了第 1 条，已保存的地址和已保存的 Key 永远是一对。
6. 不动 Hermes 自己的网关配置，不动首次设置向导。

## 约束

- 不加迁移。
- 界面、日志里都不显示 Key。
- M2 锁定的测试文件执行方不动；里面那条 `it.skip` 由整合方在并入本单时处理。

## 验收条件

1. 换了来源、Key 留空保存：已保存的 Key 被清掉；之后 Key 留空去检测，新地址收不到带旧 Key 的请求。
2. 换了来源、同时填了新 Key：保存的是新 Key。
3. 只改路径、Key 留空：Key 保持原值。
4. 地址没变、Key 留空：Key 保持原值（现有行为）。
5. 规范化：主机名大小写不同、结尾多一个斜杠、写不写默认端口，都算地址没变。
6. Key 被清掉后，设置页显示「未配置」和第 4 条的提示。

## 真机检查

设 `IXAEON_DATA_DIR=<临时目录>` 启动应用，起两个本地假上游（不同端口，会记下收到的 `Authorization`），不用用户的真实网关：
1. 地址填甲、填 Key、保存、检测：甲收到这个 Key；
2. 地址改成乙、Key 留空、保存：界面显示「未配置」和提示；
3. Key 留空检测：乙没有收到带旧 Key 的请求。
