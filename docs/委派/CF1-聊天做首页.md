# 规格 CF1：聊天做首页，驾驶舱放第二

档位：**A**（界面）。大小：小（约 30 行源码）。依赖：无（排在 CF0 之后做）。来源：用户 10-31 定（[三周任务单](../三周任务单.md)「总体升级」一节）：Chat First，打开 IXAEON 先是聊天；改掉 10-30「驾驶舱放导航第一位、启动默认页」那条。升级第 1 阶段第二单。

v2 规格：先把验收条件写成测试（`apps/desktop/test/acceptance/cf1-*.test.ts`），和实现一起交，Codex 审查。

## 要什么

1. 应用启动后的默认页是聊天页（现在的「问答」页，`App.tsx` 里的 `'ask'`），不是驾驶舱。
2. 导航第一项是聊天，**显示名改成「聊天」**；第二项是驾驶舱。其余各项的先后不变。
3. 驾驶舱页本身一点不改。

## 约束

- 只改 `apps/desktop/src/renderer/src/App.tsx` 和导航相关的那几行；不改页面内部，不改路由以外的东西。
- **K3 锁定的验收测试里有一条写死了「导航第一项是驾驶舱、默认页是驾驶舱」**：执行方不改它（锁定测试只有整合方能改）。实现做完、你自己的 CF1 测试都过之后，在交付说明里列出撞红的锁定测试（文件、用例名），状态改「待复审（整合方）」，由整合方改 K3 那条并合并。别的锁定测试、e2e 里如果有按「问答」这个名字或「默认页是驾驶舱」找元素的，同样列出来，不改。
- 以后要不要在聊天页顶上加一条「调度器在转 / 有 N 件等你处理」，不在这一单里做。

## 验收条件

1. 应用启动（没有任何保存的页面状态）→ 当前页是聊天页。
2. 导航第一项的文字是「聊天」，点它打开聊天页；第二项是驾驶舱，点它打开驾驶舱页。
3. 导航里其余各项的先后和改之前一样（测试里把改之前的顺序写死比对）。

## 真机检查

设 `IXAEON_DATA_DIR=<临时目录>` 启动应用，截图打开后的第一屏（应是聊天页、导航第一项「聊天」、第二项「驾驶舱」），贴进交付说明，遮掉临时目录。
