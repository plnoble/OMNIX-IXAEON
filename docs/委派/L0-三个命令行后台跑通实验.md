# 规格 L0：Claude Code、DSH、Codex 三个命令行在后台跑通（实验，不改应用）

档位：**B**（把任务交给三家模型；会花少量真额度）。大小：不改应用源码，只交实验脚本和结论。依赖：用户先装好 Claude Code 命令行并登录（见文末）。来源：用户 2026-10-20 定的方向——「接力」。

## 为什么要做：接力调度器

现在的委派流水线是这样转的：整合方（Claude）写任务书 → 开发 agent 做 → Codex 审 → 返修 → 整合方复审合并、写下一单。**每一棒之间都是用户在复制粘贴转话。**用户要的是把自己从转话里拿出来：在一直开着的电脑上，这几个 agent 一棒接一棒地自己干，24 小时不停；只在真需要用户拍板时找他（用飞书）。

整合方定的做法（2026-10-20，用户同意「你来开发，借鉴思路，不依赖 Ekko」）：

1. **不做群聊里互相 @ 的那种。** Ekko 的群聊就是那样：agent 想 @ 谁就 @ 谁，防循环只靠「最多交接 4 棒」，要 24 小时跑就得设成「不限」——中间没有任何关卡。这一个多月的教训都是规矩没被代码管住（执行方自己合并 B 档、自己锁自己的测试；全绿不等于能用；跑到一半额度用完）。
2. **交接靠队列，关卡写在代码里。** 「轮到谁」就看 `docs/委派/队列.md` 那一行的状态（现在就是这么转的）。一个调度器（普通代码，不是模型）看状态、调起对应角色的命令行、给它这一棒的交代、等它做完、核对它有没有越界（比如开发角色动了锁定清单、合并了 B 档），越界就停下来找用户。
3. **分工（用户 2026-10-20 定）**：

   | 角色 | 谁 | 干什么 |
   | ---- | -- | ------ |
   | 统筹 | Claude（Pro） | 写任务书、复审 B 档、裁决分歧 |
   | 审核 | Codex（Plus） | 审代码细节（额度不够时分层，见后续单子） |
   | 开发 | DSH（DeepSeek 的 token plan） | 大量的开发、测试、真机检查 |
   | 调度 | 普通代码 + 便宜模型 | 轮转、记额度、排期、超时、汇报 |

4. **额度**：用户给资源池、不设上限，但调度器要会算——比如 Claude 每周四凌晨 4 点刷新，刷新前要用起来；用完了就停那个角色，到点再接着跑。

要把这些写成调度器，先得知道三个命令行在这台机器上**到底怎么在后台跑**。这一单只回答这个。

## 要回答的问题

三个命令行：**Claude Code**（`claude`）、**DSH**（DeepSeek Harness，`@deepseek-ai/dsh`；本机 `~/.dsh` 下有 `profiles/headless`，说明装过，但命令不在 PATH 上）、**Codex**（`%LOCALAPPDATA%\OpenAI\Codex\bin` 下最新版，找法照 V4）。

1. **在哪、什么版本、登录了没有**：找到可执行文件（写出找的办法，路径用占位），版本号；登录状态只看「登录了 / 没登录」，**不打开、不打印任何凭据文件**（`~/.dsh/.credentials.yaml`、`~/.claude` 里的令牌、`~/.codex/auth.json` 这类）。
2. **后台怎么调**：每个各用一条命令在后台跑一次最小的真调用——在一个临时空目录里，让它只回一句固定的话（比如「回 OK」）。记下：完整的命令行（不交互、不弹窗）、输出能不能拿到结构化的结果（JSON/JSONL）、退出码、用时、输出里有没有用量（token / 费用 / 额度）字段。
3. **能不能关在一个目录里**：各自有什么权限 / 沙箱选项，能不能做到「只许读写这个工作目录、不许往外写」。实测：在临时目录里放一个合成项目，交代它「在项目里建一个文件」（应当成）和「往项目外的另一个临时目录建一个文件」（应当被拦或被拒）；看结果、数文件。**不许用「跳过所有权限」这类开关**（`--dangerously-skip-permissions`、`danger-full-access` 等）——要是不开就跑不起来，如实写「不开跑不起来」，停在这里。
4. **额度用完时什么样**：**不许故意把额度用完。**从文档和第 2 步拿到的输出结构里找：额度快满 / 用完时，输出里有没有字段或固定的提示、退出码是什么、有没有给出重置时间。找不到就写找不到。
5. **下一棒能不能接着上一棒的会话**：同一个临时目录里，第二次调用能不能接着第一次的会话（各自的 resume / session 参数），第二次能不能记得第一次说过的一个合成的词。
6. **两个一起跑会不会打架**：Claude Code 和 DSH 同时在两个不同的临时目录里各跑一次，有没有锁、配置互相覆盖的问题。
7. **会不会改用户自己的配置**：每次调用前后，比对 `~/.claude`、`~/.dsh`、`~/.codex` 下配置文件的修改时间和大小（只比时间和大小，不读内容）；有被改的写出是哪个文件。
8. **一次调用大概花多少**：第 2、3、5 步里记下的用量加起来，按各家的计费口径写一个大概的数（拿不到就写拿不到）。

## 硬规矩

- **花钱要省**：每个命令行一共不超过 6 次真调用；问题都用合成的、很短的；不交代它做任何真活。
- **全用临时目录和合成内容**；不在 IXAEON 仓库、不在用户的任何项目里跑这些调用。
- **不装软件、不升级、不登录、不改任何配置**（Claude Code 命令行由用户自己装好、登录好；没装好就停，写清楚缺什么）。找不到 DSH 的命令行就写怎么找的、没找到，不要去 npm 装。
- **不打开、不打印、不复制任何凭据文件**；输出里遮掉临时目录的两种写法和用户目录。
- 不推送 IXAEON 以外的任何东西；不连别的服务。
- 碰到弹窗、要登录、要授权：不点、不绕，停下，原样写进交付说明。
