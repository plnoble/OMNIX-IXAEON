# 委派单 L11b：替推时 rebase 撞上队列里的行冲突，两边改的不是同一行就自己合

档位：**A**（还是推开发自己的提交、只快进、不强推；只多认一种冲突怎么合）。大小：小（约 90 行源码）。依赖：L13b。来源：用户 2026-10-24 定「IXAEON 的开发都走调度器」，接着做 L11（整合方和 DSH 两条道同时跑）。两条道同时改队列时，几乎总是改挨着的两行（比如第 71、72 行）。git 把挨着的两行算成冲突，L13 的 rebase 一冲突就停下整个调度器。

## 要什么

调度器替开发推 `main` 被拒、rebase 时（L13 / L13b 那一段）冲突了：**只有 `docs/委派/队列.md` 冲突**，而且两边在主表里改的**不是同一行**，就按行合起来，接着 rebase，再推。别的冲突照原来 `--abort`、停下。

## 契约（接口写死，不改名、不加字段）

1. 新文件 `packages/relay/src/queue-merge.ts`，导出 `mergeQueue(base: string, ours: string, theirs: string): string | null`。`base` 是共同祖先上的队列，`ours` 是 rebase 的目标（别人推上去的 main），`theirs` 是正在重放的那一笔开发的提交。合不了回 `null`。
   - 主表照 `parseMainTable` 认表头；表头那一行和分隔行三份必须一字不差，否则 `null`。
   - 主表的每一行按第一格（序号）对上。三份各有一个序号 → 行：
     - `ours` 和 `base` 一样 → 用 `theirs` 的（`theirs` 里没有这一行 → 删掉）；
     - `theirs` 和 `base` 一样 → 用 `ours` 的；
     - `ours` 和 `theirs` 一样 → 用它；
     - 都不一样 → `null`。
   - `base` 里没有的新行：先按 `ours` 里的先后放 `ours` 新加的，再按 `theirs` 里的先后放 `theirs` 新加的；两边加了同一个序号：一字不差就放一次，不一样就 `null`。
   - 主表**前面**的整段、**后面**的整段各自三方比：`ours` 段 = `base` 段 → 用 `theirs` 段；`theirs` 段 = `base` 段 → 用 `ours` 段；两边一样 → 用它；否则 `null`。
   - 换行照 `ours` 的（`\r\n` 还是 `\n`）。
2. `push.ts` 里 rebase 冲突那一步：`git diff --name-only --diff-filter=U` 只列出 `docs/委派/队列.md` 一个文件 → 取 `git show :1:docs/委派/队列.md`、`:2:`、`:3:` 交给 `mergeQueue`；不是 `null` → 写回、`git add docs/委派/队列.md`、`git -c core.editor=true rebase --continue`（环境里设 `GIT_EDITOR=true`），重放下一笔时又冲突就再照这一条来一遍；是 `null`、或者冲突的不只这一个文件 → 照原来 `git rebase --abort`、这一条算失败。合成功、推上去了，记账照 L13 写 `rebased: true`。
3. 别的不变：不 `--force`、不碰 `dir` 以外的目录、`PushRecord` 不加字段。
