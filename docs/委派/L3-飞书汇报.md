# 规格 L3：飞书汇报（接力调度器找用户用）

档位：**B**（新的外部服务：往用户的飞书群发消息）。大小：小（≤150 行源码）。依赖：无（独立的一个模块，接进调度器是之后的事）。来源：用户 2026-10-20 定「进度用微信或者飞书」，整合方推荐飞书（有正式的机器人接口）。

v2 规格：先把验收条件写成测试（`packages/relay/test/acceptance/l3-*.test.ts`），**先只推测试**，整合方锁定后再写实现。

## 要什么

接力调度器 24 小时跑，用户不在电脑前。这些事要用飞书告诉他：

- **停下来了**：某一棒越界（比如开发并了 B 档）、出错；
- **要你拍板**：某一行停在等用户的状态；
- **歇着了**：某个角色撞上额度，歇到几点；
- **没活了**：队列空了、或者全被依赖挡着；
- 每天一条**日报**：今天跑了几棒、完成了哪几行、花了多少。

这一单只做「把一件事发到飞书」这个模块，用飞书的**自定义机器人**（群里加一个机器人，拿到一个 webhook 地址和签名密钥）。只往外推消息，不收用户的回复（收回复要另一种机器人，之后再说）。

## 契约（接口写死，不改名、不加字段）

1. 位置：`packages/relay/src/notify/feishu.ts`（`packages/relay` 这个包 L1 也在用；这一单只新建这个文件和它的测试，不依赖 L1 的代码）。
2. 事件和文字：

   ```ts
   type RelayEvent =
     | { kind: 'stopped'; reason: string; taskId?: string; task?: string }
     | { kind: 'needs-user'; taskId: string; task: string; status: string }
     | { kind: 'paused'; role: 'integrator' | 'developer'; until: string }   // until 是 ISO 时间
     | { kind: 'idle'; why: 'queue-empty' | 'all-blocked' }
     | { kind: 'daily'; date: string; turns: number; done: string[]; costUsd?: number };

   /** 事件 → 发出去的那段文字。只用事件里给的字段，第一行固定是「【IXAEON 接力】」。 */
   function formatEvent(e: RelayEvent): string;
   ```

   每种一句话，逐字照下面写（`<…>` 换成字段值；时间按北京时间写成 `10月21日 04:00`；可选字段没有就不写那一截）：

   | kind | 第二行起的文字 |
   | ---- | -------------- |
   | `stopped` | `停下来了：<reason>。`（有 taskId 再接一行 `第 <taskId> 行：<task>`） |
   | `needs-user` | `要你拍板：第 <taskId> 行「<task>」现在是「<status>」。` |
   | `paused` | `<统筹 / 开发>撞上额度，歇到 <until>。` |
   | `idle` | `queue-empty` → `队列空了，等你排新活。`；`all-blocked` → `剩下的都被依赖或暂停挡着，等你看一眼。` |
   | `daily` | `<date> 日报：跑了 <turns> 棒，完成 <done 用「、」连起来；一个都没有写「无」>。`（有 costUsd 再接一行 `Claude 用量折合约 <costUsd 保留两位> 美元`） |

3. 发送：

   ```ts
   interface FeishuTarget { webhookUrl: string; secret: string }
   /** 发一条。成功（飞书回 code 0）返回 { ok: true }；失败返回 { ok: false, error }，不抛错。 */
   function sendFeishu(text: string, target: FeishuTarget, opts?: { fetch?: typeof fetch; now?: () => Date }): Promise<{ ok: true } | { ok: false; error: string }>;
   ```

   - 照飞书开放平台「自定义机器人使用指南」的**签名校验**：`timestamp` 是当前秒数（字符串），把 `timestamp + "\n" + secret` 当作 HMAC-SHA256 的**密钥**、对**空内容**算签名，再 Base64，作为 `sign`。请求体 `{ "timestamp", "sign", "msg_type": "text", "content": { "text": <text> } }`，`POST` 到 `webhookUrl`，`Content-Type: application/json`。（写测试之前先读一遍官方文档核对这一段；和官方说法不一致的，以官方为准，写进交付说明。）
   - 失败（网络错、HTTP 非 2xx、飞书回的 `code` 不是 0）**重试 2 次**（隔 2 秒、再隔 5 秒；测试里可换小），还不成就返回失败。**任何情况下都不抛错**——调度器不能因为通知发不出去就停。
   - **限频**：同一种事件（`kind` 加上 `taskId` / `role` / `why`）30 分钟内只发一次（`daily` 除外）。限频状态放在调用方给的一个对象里（`createNotifier(target, store)` 之类，名字由实现定），不放全局。
4. **不外发别的**：发出去的只有 `formatEvent` 拼出来的那段文字。不发路径、不发命令输出、不发提交内容、不发任何别的字段。日志里**不写 webhook 地址和密钥**（要写就写「已配置 / 没配置」）。
5. 配置：webhook 地址和密钥放在用户本机的一个文件里（`<Worktrees>/IXAEON/relay/feishu.json`，不进仓库），读它的函数在找不到文件时返回「没配置」，调用方就只记本地不发。

## 约束

- 测试全用本机起的一个**假的 HTTP 服务**（`127.0.0.1` 随机端口）充当飞书，不连真的飞书。
- 不加新的依赖包（用 Node 自带的 `fetch` 和 `crypto`）。
- 测试、文档里的 webhook 地址和密钥都用合成的。

## 验收条件

1. **文字**：五种事件各一条，`formatEvent` 的结果逐字对（含可选字段有 / 没有两种、`done` 为空写「无」、时间换成北京时间的写法）。
2. **签名**：假服务收到的请求体里，`timestamp` 是秒数字符串；`sign` 等于测试里照第 3 条的算法独立算出来的值；`msg_type`、`content.text` 对。
3. **成功**：假服务回 `{"code":0}` → `{ ok: true }`，只发了一次。
4. **重试**：假服务前两次回 HTTP 500 / `{"code":19021}`、第三次回 `code 0` → 成功，一共收到 3 次；三次都失败 → `{ ok: false }`、一共 3 次、**没有抛错**；连不上（端口没人听）→ `{ ok: false }`、没有抛错。
5. **限频**：同一种事件 30 分钟内第二次不发；换一个 `taskId` 照发；过了 30 分钟（`now` 换成 31 分钟后）照发；`daily` 不限。
6. **不外发别的**：请求体里除了第 3 条那几个字段没有别的；日志 / 返回的错误文字里不含 webhook 地址和密钥。
7. **没配置**：`feishu.json` 不存在 → 读配置返回「没配置」，不发、不抛错。

## 真机检查

`scripts/real/l3-feishu-send.mjs`：用户配好了 `feishu.json`（在飞书群里加一个自定义机器人，打开签名校验，把地址和密钥写进去）就发一条合成的测试消息（「【IXAEON 接力】这是一条测试消息，不用回。」），打印「发成了 / 没发成 + 错误码」（不打印地址和密钥）。**没配置就不跑**，交付说明写「没跑：用户还没配飞书机器人」。
