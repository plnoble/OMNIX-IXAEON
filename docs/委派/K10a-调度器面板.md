## 要什么

驾驶舱加一张卡片「调度器与模型」，一行一个角色：

| 角色 | 显示 | 能选的 | 改的是哪儿 |
|---|---|---|---|
| 开发（DSH） | provider / model，比如「baidu / deepseek-v4.1-flash-1017」 | **DSH 桌面版配置**（DG1 起接力每棒从这里取网关段）里 `llm-pi-ai` 那段 `providers:` 下**登记的全部网关和各自的模型**（每个网关一节，如 `newapi:`、`baidu:`、本地的 `magpie:`，下面 `models:` 里的 `- id:`），按「网关 / 模型」列出、按网关分组 | 补丁文件最下面 `agent-default-model` 那段的 `provider:`、`model:` 两行 |
| 整合方（Claude） | 启动参数里 `--model` 的值，没有就显示「默认」 | 默认 / opus / sonnet / haiku | 调度器配置 `roles.integrator.argv` 里的 `--model <值>`（选「默认」就去掉） |
| 审查（Codex） | 调度器配置 `review.codexModel`，没有就显示「跟 Codex 自己的设置」 | 一个文本框（只许字母、数字、`.`、`-`、`_`），空 = 跟 Codex 自己的设置 | 调度器配置 `review.codexModel`；**不碰** `~/.codex/config.toml` |
| 替补审查 / 替补整合方（K9a、K9b 并入后才有） | 各自补丁里的 provider / model；没配就显示「没配」 | 同开发那一行 | 各自的补丁文件 |

每一行旁边写「下一棒生效」。卡片上方另起一行「现在在跑」：第几棒、哪个角色、哪一行任务、跑了多久、这个角色当前配置的模型（取 K2 快照的 running 和上面读到的配置）。

另外：`scripts/codex-review.mjs` 读调度器配置的 `review.codexModel`，有值就给 `codex exec` 加 `-m <值>`；没值行为不变。

## 契约

- `packages/core/src/cockpit/relayModels.ts`：
  - `readRelayModels(opts: { relayDir: string }): RelayModels`——`{ roles: Array<{ role: 'developer' | 'integrator' | 'reviewer' | 'reviewerSubstitute' | 'integratorSubstitute'; agent: 'dsh' | 'claude' | 'codex' | 'other'; current: string | null; options: string[]; configured: boolean; note: string | null }> }`。
  - `setRelayModel(opts: { relayDir: string }, input: { role; value: string | null }): void`——值必须在 `options` 里（Codex 那一行按上面的字符规则校验），不在就抛 `VALIDATION_FAILED`、文件不动。
- DSH 补丁文件的路径从 `roles.<角色>.argv` 里 `--patch` 后面那一项取；不认识的 argv 形状 → 这一行 `configured: false`、`note` 说明，不猜。
- 改文件前先在同目录写一份 `<原名>.bak-<YYYYMMDD-HHmmss>`；写入用「写临时文件 → 改名」，不留半截文件。DSH 补丁只改 `agent-default-model` 那段下面的 `provider:`、`model:` 两行，别的字节一个不动。
- IPC：`getRelayModels(): Promise<RelayModels>`、`setRelayModel(input): Promise<{ ok: true }>`（contracts 加类型、preload 暴露）。`relayDir` 照 K2 的取法（默认 `~/.ixaeon/relay`，`IXAEON_RELAY_DIR` 覆盖）。

## 约束（隐私是这单的重点）

- **补丁文件、调度器配置里有密钥**：只读出 provider / model 名字、`--model` 的值、`review.codexModel`；IPC 返回、界面、日志、报错里**不许出现**文件的其他内容（密钥、网关地址、整段 argv）。报错只写「补丁文件读不懂」这类话，不带原文。
- 不读 `feishu.json`、`feishu-app.json`、`inbox.jsonl`（照 K2）。
- 不改用户平时用的 DSH 桌面版配置（只改调度器 argv 里 `--patch` 指向的那份）；不改 `~/.codex/config.toml`。
- **不假设只有一个网关**（用户 10-31：「你不能一个网关管所有，我可能有很多网关，我还有本地的 magpie」）：网关有几个列几个，选项是「网关 / 模型」对。
- 不新增依赖（仓库里没有 YAML 库）：按行认 `providers:` 下一层缩进的 `<网关名>:`、它下面 `models:` 里的 `- id: <模型>`；只取这两种名字，网关那一节里的 `baseURL`、`apiKeyEnv` 等一律不读出来。认不出就只显示当前值、下拉框里只有当前值。开头的注释表不当依据（那是手抄的，会过时）。

## 验收条件

1. 合成 relay 目录：`config.json` 的开发角色 argv 带 `--patch <合成补丁>`，整合方 argv 没有 `--model`，`review.codexModel` 没设；合成补丁 `providers:` 下登记 3 个网关（`gw-a` 两个模型、`gw-b` 一个、本地 `magpie` 两个），末尾 `agent-default-model` 是其中之一，每个网关那节里有 `apiKeyEnv: SECRET-XYZ` 和 `baseURL: https://gw.example.invalid`，开头注释表故意只列 1 个组合 → `readRelayModels` 返回开发 = 当前组合、选项正好 5 个（按网关分组，不受注释表影响）；整合方 = 「默认」；审查 = 「跟 Codex 自己的设置」；返回的 JSON 里找不到 `SECRET-XYZ`、`gw.example.invalid`。
2. 把开发改成另一个组合 → 补丁文件除了那两行，其余字节和原来一样（逐字节比）；同目录多了一个 `.bak-` 备份，内容等于改之前。
3. 整合方选 sonnet → argv 里有且只有一对 `--model sonnet`，其余参数顺序不变；再选「默认」→ `--model` 那一对去掉。
4. 传不在选项里的值 / Codex 那行传 `gpt;rm -rf` → 拒绝，文件不动、没有备份文件。
5. argv 里没有 `--patch` 的开发角色 → `configured: false`，`note` 有说明，不抛错。
6. `codex-review.mjs`：`review.codexModel` 设成 `demo-model` → Codex 替身收到的参数里有 `-m demo-model`；不设 → 没有 `-m`。
7. 界面：卡片四行（没配替补时替补两行显示「没配」）；选了开发的新组合 → 调用 `setRelayModel`、刷新后显示新值、写着「下一棒生效」。
8. 「现在在跑」那一行：快照里有一棒在跑（开发）→ 显示棒号、任务、分钟数、开发当前的模型。

## 真机检查

设 `IXAEON_DATA_DIR=<临时目录>`、`IXAEON_RELAY_DIR=<合成 relay 目录>`（合成 config 和合成补丁，**不碰用户真实的 relay 目录和 DSH 配置**）启动应用：截图卡片；在界面上把开发换一个组合、整合方换 sonnet，截图之后的卡片，再贴出合成补丁和合成 config 改动前后的 diff（只有那两处）。
