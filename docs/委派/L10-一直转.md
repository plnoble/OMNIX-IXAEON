# 规格 L10：一直转（每棒用最新代码、崩了接着转、开棒前装好依赖、数据目录挪出 AppData）

档位：**B**（调度器开始自动跑 main 上的新代码、自动装依赖；数据目录换位置）。大小：中（约 220 行源码；超过 300 行就拆，L10b 放契约第 5、6 条）。依赖：无。来源：接力第 1–6 棒（2026-10-23）：

- 调度器只能从 Claude 桌面版里起才找得到配置。桌面版会把它起的进程往 AppData 里写的东西转存到自己的包目录（`…\Packages\Claude_…\LocalCache\Local\…`）；从普通终端起的调度器看到的是另一个数据目录，那里没有配置。
- 并进 main 的调度器改进要有人重启才生效（第 3 棒之后的两处修复，是整合方手动重跑的）。
- 第 5 棒整合方的工作目录没装依赖，一条测试没跑成。
- 调度器进程一崩就没了，没人知道。

v2 规格：先把验收条件写成测试（`packages/relay/test/acceptance/l10-*.test.ts`），**先只推测试**，整合方锁定后再写实现。

## 要什么

1. **`relay run` 改成看门人**：每一轮先把调度器自己的那份代码（`<工作目录根>/relay-run`，一个停在 `origin/main` 的工作目录）更新到最新，再从那里起一个子进程跑一棒（`relay once`），等它退出，再看下一轮。并进 main 的改进下一棒就生效，不用重启。
2. **崩了接着转**：子进程退出码不是 0，算崩一次；隔 `idleSeconds` 的 1、5、15 倍再试（默认就是 1、5、15 分钟）；连着崩 3 次就停下，照原来的停下发飞书。中间有一轮正常退出就清零。
3. **开棒前装好依赖**：整合方的工作目录、`relay-run`，`pnpm-lock.yaml` 和上次装依赖时不一样（或者还没装过）→ 先装。装不上就当这一轮没开（打一行日志，不停下，等下一轮）。
4. **配置里的命令可以写 `{relay_root}`**：跑的时候换成正在跑的这份调度器代码的仓库根。`relay init` 生成的开发命令改用它，DSH 启动器也跟着新代码走。
5. **数据目录挪出 AppData**：默认改成 `~/.ixaeon/relay`（Windows 上是 `%USERPROFILE%\.ixaeon\relay`，不在 AppData 下面，桌面版不会转存）。`relay status` 的旧位置提醒多认一处 `%LOCALAPPDATA%\IXAEON\relay`。不自动搬。

## 契约（接口写死，不改名、不加字段）

1. **看门人**（`relay run [--exit-when-idle]`）：
   - 照原来查配置、拿锁；开头打一行 `看门人 <自己的进程号>`。
   - 每一轮：`fetchMain`（照原来的重试）→ 用 `updateCodeCheckout` 把 `relay-run` 更新到 `origin/main` → 用 `ensureDeps` 给 `relay-run` 装依赖 → 起子进程 `node <代码根>/packages/relay/bin/relay.mjs once --under <看门人的进程号>`，`cwd` 是代码根，环境变量原样传下去，输出原样转出来 → 子进程退出后打一行 `子进程 <进程号> 退出 <退出码>`。
   - 退出码 0：重读 `state.json`。`stoppedReason` 有值 → 退出；这一轮没跑棒（`turns` 没变）→ 有 `--exit-when-idle` 就退出，没有就等 `idleSeconds`；跑了棒 → 马上下一轮。
   - 退出码不是 0：崩一次。第 1、2 次各等 `idleSeconds × 1`、`× 5`；第 3 次不再等，写 `stoppedReason`「调度器连着崩了 3 次：<最后一次错误输出的第一行，不超过 200 个字>」，发 stopped，退出。
   - **代码根**：环境变量 `IXAEON_RELAY_CODE` 有值 → 直接用那个目录，不建、不更新、不装依赖（测试和临时调试用）；没有 → `<工作目录根>/relay-run`。
2. **`relay once --under <pid>`**：锁文件里的进程号就是 `<pid>`、而且那个进程还在 → 当作已经拿到锁（不再拿、退出时也不放）；否则照原来拿锁（拿不到就被拒）。带 `--under` 时没活照 `run` 的样子发 idle（`sendIdle: true`）。
3. **更新代码**：`src/selfupdate.ts` 导出 `updateCodeCheckout(repo: string, dir: string): { sha: string | null; note: string }`。`repo` 是调度器所在仓库（主检出）。`dir` 不存在 → `git -C <repo> worktree add --detach <dir> origin/main`；存在 → 在 `dir` 里 `git switch --detach origin/main`。`dir` 里有没提交的改动 → 不动它，`note` 说明，`sha` 是它现在的提交。返回更新后的提交号。
4. **装依赖**：`src/deps.ts` 导出 `ensureDeps(dir: string, install?: string[]): 'ok' | 'skipped' | 'failed'`。记号文件 `<dir>/node_modules/.relay-lock-sha256` 里存装依赖时 `pnpm-lock.yaml` 的 sha256。没有记号、或和现在的不一样 → 跑 `install`，成功了写记号、回 `'ok'`，失败回 `'failed'`、不写记号；一样 → `'skipped'`。`install` 默认是 `corepack pnpm install --frozen-lockfile --prefer-offline`（Windows 上 `corepack` 是 `.cmd`，照 `scripts/worktree.mjs` 的起法）；环境变量 `IXAEON_RELAY_INSTALL`（JSON 数组）有值就用它（测试用）。
   - 看门人每一轮给代码根调一次（`IXAEON_RELAY_CODE` 有值时不调）。
   - `runOnce` 定下是整合方的棒之后、跑之前，给整合方的 `cwd` 调一次；`'failed'` → 这一棒不开（不建 `turns/`、不记账、不停下），打一行 `没开棒：整合方的工作目录装不上依赖`，回 `'idle'`。
5. **`{relay_root}`**：`runTurn` 换 `{prompt_file}` 的地方一起换，值是正在跑的这份代码的仓库根（`relay-main.ts` 里的 `REPO_ROOT`）。`relay init` 生成的开发命令第二项写 `{relay_root}/packages/relay/bin/dsh.mjs`。
6. **数据目录**：`defaultRelayDir()` 在所有系统上都是 `join(homedir(), '.ixaeon', 'relay')`；`IXAEON_RELAY_DIR` 照旧优先。`relay status` 的旧位置提醒照原来查 `oldRelayDir()`，Windows 上再查 `<LOCALAPPDATA>/IXAEON/relay`，哪一处有 `config.json`、`state.json`、`feishu.json` 之一就照原来的写法多打一行（照 L8 遮掉用户目录）。不自动搬。

## 约束

- 只改 `packages/relay/`（含 README）。看门人不碰共用检出目录（`OMNIX-IXAEON析衍`）里的文件，只用它的 git 建 `relay-run`。
- `relay-run` 只由看门人建和更新，哪个角色都不在里面干活。
- 不建 Windows 计划任务、不改系统设置。开机自己起来由用户决定：README 写一条用户自己可以照着建的命令，不替用户建。
- 已锁定的验收测试不改。已知会冲突的：L4 的「没有 IXAEON_RELAY_DIR → 用 LOCALAPPDATA 下的 IXAEON/relay」（契约第 6 条改了这个位置），L5 / L6b 里如果比了开发命令的第二项（契约第 5 条）。整合方锁 L10 的测试时一起改这些；实现时撞上别的，停下写进交付说明。

## 验收条件

1. 看门人（契约第 1 条）：`IXAEON_RELAY_CODE` 指向本仓库、合成仓库加替身角色（照 `l2b-notify` 的做法），`relay run --exit-when-idle` 跑两棒再转到没活：输出里有 `看门人 <pid>`、至少两行 `子进程 <pid> 退出 0`，子进程号互不相同、也不等于看门人的；记账里有这两棒；退出码 0。
2. 崩：`IXAEON_RELAY_CODE` 指向一个假代码目录（它的 `packages/relay/bin/relay.mjs` 打一行 `炸了` 到错误输出、退出码 1），`idleSeconds` 设成 0 或 1：看门人试 3 次后退出；`stoppedReason` 是「调度器连着崩了 3 次：炸了」；配了假飞书就收到一条 stopped。再测一次「崩一次、下一轮正常、再崩两次」→ 不停（中间清零了）。
3. `--under`（契约第 2 条）：锁里的进程号是一个活着的进程、`once --under <它>` → 照常跑一棒，锁文件跑完还在、内容不变；`once --under <别的进程号>` → 照原来被拒。
4. 更新代码（契约第 3 条）：用临时的 bare origin 加一个克隆当 `repo`：`dir` 不存在 → 建出来，`HEAD` 是 `origin/main` 的提交、不在任何分支上；往 origin 推一个新提交、在 `repo` 里拉一次 → 再调一次就到了新提交；`dir` 里改一个文件不提交 → 不动它，`note` 不为空。
5. 装依赖（契约第 4 条）：`install` 用一个写下记录的 node 小脚本：第一次 → `'ok'`、装了、记号写了；锁文件不变 → `'skipped'`、没装；锁文件变了 → 又装；装的命令退出码 1 → `'failed'`、记号没写。整合方的棒：`IXAEON_RELAY_INSTALL` 设成退出码 1 的命令 → 这一棒没开（没有 `turns/`、记账没多一条），输出含 `没开棒：整合方的工作目录装不上依赖`。
6. `{relay_root}`：替身把自己收到的参数写下来，配置里写 `{relay_root}/x` → 收到的是 `<IXAEON_RELAY_CODE 那个目录>/x`。`relay init` 生成的开发命令第二项是 `{relay_root}/packages/relay/bin/dsh.mjs`。
7. 数据目录（契约第 6 条）：不设 `IXAEON_RELAY_DIR`、把 `USERPROFILE` / `HOME` 指到临时目录 → `relay status` 打出来的数据目录是 `~/.ixaeon/relay` 那一处；（Windows）`LOCALAPPDATA` 指到临时目录、它下面 `IXAEON/relay/state.json` 存在 → 多打一行旧位置提醒。
