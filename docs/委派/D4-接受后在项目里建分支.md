# 规格 D4：点「接受」之后，改动在项目仓库里建分支提交

档位：**B**（第一次往用户的项目仓库里写东西，权限）。大小：中（≤300 行源码）。依赖：迁移 38（整合方已加 `applied_ref`、`applied_at`、`apply_error`）、D3（回报用它的写消息）。来源：场景一；用户 2026-09-27 选「在项目仓库里建分支提交；不是 git 仓库的生成补丁」。
v2 规格：先把验收条件写成测试（`packages/core/test/acceptance/d4-*.test.ts`），**先只推测试**等整合方看过并锁定，再实现。

## 要什么

编码代理在项目的**副本**里干活；现在点「接受」只是把任务标成完成，改动留在副本里，回不到你的项目。用户定的落地方式：**在项目仓库里建一个新分支，把这次的改动提交上去**——不碰你正在用的工作区和当前分支，合不合、什么时候合由你定。不是 git 仓库的项目，生成一个「改动包」。

## 契约

1. 触发：`coding.accept(taskId)` 成功之后。
2. 前提：项目有根目录，且根目录在某个**仍有效的文件夹授权**之内（`isPathInside(授权路径, 根目录)`，同 G02）；否则不落地，`apply_error` 写「没有这个项目目录的读取授权」。这次任务没有改动文件：不落地，回报里写「没有改动」。
3. 冲突核对：派发时记下每个改动文件**改之前**的指纹（`dispatch` 里已有的 `hashWorkspace(before)`，存进执行报告，例如 `baseHashes`；新文件记为不存在）。落地时与项目当前 `HEAD` 里的版本比对；有一个不一样（你在这期间提交过、或快照时有没提交的改动），就不建分支，改走第 5 条的改动包，`apply_error` 写明是哪些文件。
4. git 仓库（`git -C 根目录 rev-parse --show-toplevel` 成功）：
   - 分支名 `ixaeon/<任务 id 前 8 位>`，已存在就加 `-2`、`-3`……
   - 从当前 `HEAD` 用 `git worktree add -b <分支> <临时目录> HEAD` 建临时工作树；把副本里这些改动文件的最终内容写进去（删掉的文件照删），`git add` 这些路径，提交：标题「IXAEON：<目标第一行>」，正文写任务 id 和验证结果。仓库没配置提交人时用 `-c user.name=IXAEON -c user.email=ixaeon@localhost`。最后 `git worktree remove` 清掉临时工作树。
   - **不推送；不切换、不修改你的工作区、当前分支和暂存区。**
   - 成功：`applied_ref` = 分支名，`applied_at` = 时间。
5. 改动包（不是 git 仓库、或第 3 条有冲突、或建分支失败）：`<数据目录>/patches/<任务 id>/` 下按原路径放改动后的文件，外加一份清单（改了、新增、删除哪些文件，以及冲突说明）。`applied_ref` = 这个目录。
6. 回报：用 D3 的对话回报追加一条——「已在项目仓库建分支 ixaeon/…（没有推送，也没动你的工作区）。要合并：git merge ixaeon/…」；或「没能建分支（原因），改动包在 …」。任务页同样显示。
7. git 命令用 `execFile` 传参数组，不拼 shell 字符串；任何一步失败都要清掉临时工作树。

## 约束

- 只在用户点「接受」之后落地；不自动合并、不推送、不改工作区。
- 不加迁移（迁移 38 已由整合方加好）。

## 验收条件

1. 临时 git 仓库做项目，执行器替身改一个文件、加一个文件 → 接受 → 仓库里多出分支 `ixaeon/<前 8 位>`，分支上的提交正好包含这两处改动；当前分支、`HEAD`、工作区、暂存区都没变。
2. 分支名已存在 → 用 `-2`。
3. 派发后你在项目里提交过同一个文件 → 不建分支，生成改动包，`apply_error` 列出这个文件。
4. 快照时这个文件有没提交的改动（与 `HEAD` 不同）→ 同第 3 条。
5. 不是 git 仓库 → 生成改动包，清单列出改动。
6. 项目根目录不在有效的文件夹授权里 → 不落地，`apply_error` 写明原因。
7. 仓库没配置提交人 → 用 IXAEON 的兜底身份照样提交成功。
8. 任何一步失败后没有残留的临时工作树（`git worktree list` 只剩原来的）。

## 真机检查

在临时目录建一个合成的 git 仓库当项目，用脚本走「建任务 → 执行器替身改文件 → 接受」（不调用真 Codex），贴 `git branch`、`git log --stat <分支> -1`、`git status` 的输出，证明分支建好、工作区没动。
